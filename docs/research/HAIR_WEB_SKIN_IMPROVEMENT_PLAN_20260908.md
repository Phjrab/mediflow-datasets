# Hair·Web Skin 후속 개선 방향 종합 계획

기준일: 2026-09-08. **아래는 후속 연구 제안이며 새 기법을 구현하거나 성능 개선을 측정한 결과가 아니다.** 기존 후보와 Test 결과는 보존한다. 이전 [Hair 고급 기법 보류 기록](../archive/planning/HAIR_ADVANCED_METHODS_BACKLOG_20260907.md)을 Web Skin까지 확장하고 현재 실험 근거에 맞춰 우선순위를 정리했다.

현재 완료된 실험의 원리와 효과는 [실험 해설](HAIR_WEB_SKIN_EXPERIMENT_EXPLAINED_20260908.md), Web Skin 진행 전체는 [총정리](WEB_SKIN_FULL_SUMMARY_20260908.md)를 참고한다.

## 1. 출발점: 지금까지 확인한 것과 아직 모르는 것

| 항목 | Hair | Web Skin |
|---|---|---|
| 보존할 후보 | B1 / 256 / LS 0.05 / Stage 2 총 15 Epoch | B0 / 256 / CE / Stage 2 최고 8번째 |
| 후보 Validation | 0.7771565318107605 | 0.796 |
| 후보 Test | 0.7883386581469649 | 0.8825 |
| 주요 관찰 | 미세각질·비듬·피지과다 혼동, 연장 이득 한 장 | 아토피·여드름·건선 혼동, 연장 이득 없음 |
| 데이터 관련 성과 | 완전 동일 이미지 정리, Train 증강 출처 기록 | 기존 파일·픽셀 감사 통과 분할 유지 |
| 핵심 미검증 | 사람/세션, 원천 복수 라벨, 정상 클래스, 실제 장비 | 사람/세션, 원본·증강 연결, 실제 웹캠, 범위 밖 입력 |

‘사진들이 비슷해 보이니 80%가 상한이다’라고 단정할 근거는 없다. 시각적 유사성 외에도 사진에 필요한 특징이 충분히 담겼는지, 라벨이 일관적인지, 출처와 사람 단위로 분리됐는지, 모델이 배경을 이용하는지 구분해야 한다.

더 큰 모델·높은 해상도·긴 학습은 검토할 도구지만 우선 해결책으로 확정하지 않는다. 기존 실험에서 그 이득은 작거나 지표별로 달랐다. 새로운 기법으로 90% 이상을 보장하지 않는다.

## 2. 권장 진행 순서

| 우선순위 | 작업 | 기존 사진만으로 가능한가 | 결과물·완료 기준 |
|---|---|---|---|
| 1 | 현재 후보와 학습 설정 보존 | 완료됨 | 모델·해시·클래스·전처리·평가 패키지 |
| 2 | Train/Validation 라벨·사진 품질·출처 검토 | 일부 가능, 라벨 확정에는 원천 정보 필요 | 의심 사례 목록과 확인 근거, 자동 수정 없음 |
| 3 | 사람·병변·세션 및 증강 연결 정보 확보 | 이미지 해시만으로 불가 | 원본 단위 그룹 목록, 확인 못 한 부분 표시 |
| 4 | 소수 후보의 Seed 반복 | 현재 분할로 가능 | 같은 Seed끼리 비교, 평균·변동성과 개별 결과 |
| 5 | Grad-CAM·가림 실험으로 참고 영역 확인 | Train/Validation 사진으로 가능 | 실패 유형과 다음 단일 가설 |
| 6 | 전체+부분 정보 또는 대조학습 중 하나 | 라벨·원본 품질 확인 후 가능 | 동일 분할과 학습 예산 기준 비교 |
| 7 | 실제 장비 데이터 확보 | 현재 불가 | 독립 촬영 데이터와 메타데이터 |
| 8 | 장비 차이 분석, 맞춤 증강·적응 | 장비 데이터 확보 후 | 별도 튜닝/평가 분리와 실제 성능 검증 |
| 9 | 점수 보정·범위 밖 처리·통합 | 일부 준비 가능, 유효성은 추가 검증 필요 | 오류 처리와 입력/출력 계약, 검증된 적용 범위 |

현재 추가 학습을 반드시 시작해야 하는 것은 아니다. 두 후보는 보관을 완료했다. 연구를 재개한다면 2번의 의심 라벨·품질 검토와 4번의 작은 차이 재현성 확인을 우선한다. 이는 완료된 ZIP 중복 검사를 다시 하는 것과 다르다.

## 3. 라벨·사진 품질 점검과 Confident Learning

### 목적과 원리

모델이 계속 틀리는 이유가 구분 능력 부족인지, 잘못된 정답·흐림·강한 반사·판단할 영역 부족인지 나눈다. Confident Learning은 모델 예측과 데이터 라벨 사이의 불일치를 이용해 라벨 오류 의심 표본을 찾아 검토하는 방법이다. 이는 전문가의 정답 판정을 대신하지 않는다. [원논문](https://arxiv.org/abs/1911.00068).

### Hair에 적용

미세각질↔비듬, 비듬↔피지과다와 관련된 Train/Validation을 우선 확인한다. 예전 Test 오답 감사의 혼동은 문제 인식의 근거로만 보존하고 그 사진을 고쳐 새 점수를 만드는 방향으로 사용하지 않는다. 하나의 사진에 여러 상태가 함께 있을 가능성은 원천 JSON이나 확인 가능한 라벨 근거로 검토한다.

### Web Skin에 적용

Validation의 여드름→건선 22장, 아토피→건선 18장, 여드름→아토피 14장을 검토 우선순위로 삼는다. 얼굴 전체·확대 비율, 초점, 조명, 배경, 피부 표현 정도, 원본 출처를 기록한다. 사진의 외관만으로 실제 질환 라벨이나 합성 여부를 확정하지 않는다.

### 실행 조건과 효과 확인

- Train을 여러 묶음으로 나누어 각 사진을 학습하지 않은 모델의 예측을 얻는 방식(out-of-fold)을 사용한다. 같은 원본과 증강본은 같은 묶음에 둔다.
- Hair는 새 증강 원본 연결 기록을 활용할 수 있다. Web Skin은 증강 원본 연결이 충분히 확보되지 않으면 파생본이 섞인 교차검증을 공정한 평가로 주장하지 않는다.
- 모델과 다르다는 이유로 자동 삭제하거나 라벨을 바꾸지 않는다. 확인 근거·작업자·변경 전후 버전과 제외 사유를 기록한다.
- 의미 있는 라벨 변경을 했다면 새로운 데이터 버전이다. 분할도 바뀌면 이전 모델이 새 평가 사진을 이미 봤을 수 있으므로 ImageNet부터 새 기준선을 구성한다.
- 클래스별 지표와 라벨 확인 건수, 미확인 건수를 보고한다. 수정 후 정확도 상승을 미리 약속하지 않는다.

## 4. Seed 반복 — 한두 장 차이가 재현되는지 먼저 확인

같은 설정이라도 초기 가중치와 학습 순서가 달라지면 결과가 달라질 수 있다. 여러 조건을 더 늘리기 전에 후보 몇 개의 차이가 반복되는지 확인하는 제안이다.

첫 반복 후보는 Hair의 B1 연장 전/후, Web Skin의 B0 224/256처럼 한 변수만 다른 쌍이 적절하다. 예를 들어 Seed 42·43·44로 각 쌍을 비교하되 이는 새 계획이다. 기존 결과와 같은 설정·데이터·학습 예산을 지키고 모든 실행을 보고한다. 동일한 Seed의 공통 부모 체크포인트가 있으면 연장 비교에서 재사용한다.

평가 자료는 Validation Accuracy/Macro F1, 클래스별 Recall/F1, 서로 맞히고 틀리는 사진, 계산 비용이다. 평균뿐 아니라 개별 결과와 변동성도 남긴다. 작은 차이를 여러 번의 최고값만 모아 과장하지 않는다. 반복 Seed 역시 이미 선택에 사용한 Validation의 독립성을 새로 만들어 주는 방법은 아니다.

## 5. Grad-CAM과 가림 실험 — 모델이 어떤 영역에 의존하는지 점검

Grad-CAM은 분류 점수에 관련된 위치를 시각화하는 방법이다. [원논문](https://arxiv.org/abs/1610.02391). 표시된 영역은 모델 설명을 돕는 단서이지 실제 병변 위치의 정답이나 인과적 증거는 아니다.

Hair에서는 두피 표면·모발·반사광 중 어디에 반응하는지, Web Skin에서는 얼굴 피부 외에 머리카락·배경·옷 등에 의존하는 경향이 있는지 살펴본다. 정답과 오답을 함께 보고 선택된 몇 장으로만 결론내리지 않는다. 얼굴의 신원 추정은 필요하지 않다.

관심 영역을 가렸을 때 변화가 있는지 보조적으로 확인할 수 있지만 가림 자체가 새로운 이상 입력을 만든다는 한계도 기록한다. 다음 실험 가설을 만드는 단계이며, 시각화만 수행했다고 정확도가 개선된 것은 아니다. Grad-CAM 지도를 정답 마스크로 삼아 자동 라벨링하지 않는다.

## 6. 전체 이미지 + 부분 확대 / Attention MIL

### 적용 가설

전체 사진의 맥락을 유지하면서 작은 부분의 질감을 함께 보면 헷갈리는 상태를 더 잘 구분할 수 있는지 검토한다. Attention 기반 MIL은 여러 부분의 특징을 모아 전체 사진의 라벨을 예측하는 방법이다. [원논문](https://proceedings.mlr.press/v80/ilse18a.html). 이 논문의 성과를 우리 데이터의 성과로 옮겨 주장하지 않는다.

Hair에서는 전체 두피·모발 정보를 유지하면서 각질·모낭 주변의 여러 부분을 함께 보는 가설이 적절하다. 부분마다 사진 전체 라벨을 강제하지 않는다. 병변이 없는 부분도 있을 수 있기 때문이다.

Web Skin에서는 얼굴 전체의 분포와 함께 이마·볼 등 부분 정보를 검토할 수 있다. 얼굴 전체 분포가 중요하다는 프로젝트 배경을 유지하며, 병변 하나만 잘라 전체를 대체하는 YOLO+Crop 방식으로 곧바로 돌아가지 않는다. 모든 원본에서 영역을 안정적으로 얻을 수 있는지 먼저 확인한다.

### 실험 설계

원본 해상도가 충분하고 부분이 실제로 유효한지 확인한다. 이미 작은 사진을 단순 확대해 새로운 정보가 생긴다고 가정하지 않는다. 전체만 사용하는 기준선과 전체+부분 모델을 비교하면서 원본 단위 분할, Backbone, Loss, Seed, 증강을 고정한다. 부분 개수·범위·결합 방식·학습량 증가를 명시하고, 늘어난 계산 예산을 맞춘 전체 모델 대조군도 고려한다.

추가 파라미터와 추론 시간·메모리를 기록한다. Hair는 미세각질·비듬의 Validation F1과 혼동, Web Skin은 아토피·여드름·건선의 Validation Recall/F1을 중점 확인한다. 전체 지표가 나빠지는지도 함께 본다.

## 7. 지도 대조학습(Supervised Contrastive Learning)

같은 클래스의 특징은 가까워지고 다른 클래스는 멀어지도록 학습 목표를 추가하는 방법이다. [원논문](https://arxiv.org/abs/2004.11362). 겉모습이 비슷한 클래스의 특징을 더 잘 구분할 수 있는지는 두 데이터에서 검증해야 할 가설이다.

Hair에서는 미세각질·비듬·피지과다, Web Skin에서는 아토피·여드름·건선이 주요 검토 대상이다. 잘못된 라벨이 있으면 잘못된 경계를 더 강하게 학습할 수 있으므로 라벨 검토 뒤에 진행한다.

데이터, Backbone, 해상도와 증강을 고정하고 학습 목적함수 추가를 주된 변수로 둔다. 추가 투영부·학습 단계·배치 구성이 필요하면 동반 변경으로 기록한다. 기존 분류 학습에 같은 시간·학습량을 더 준 대조군을 고려한다. 전체+부분 학습과 처음부터 함께 적용하지 않는다. 어떤 변화가 효과를 냈는지 구분하기 어려워지기 때문이다.

## 8. 미세조정 범위·학습률·증강의 제한된 후속 실험

현재 마지막 30개 계층과 학습률 1e-5가 최적이라고 확인한 것은 아니다. 다만 광범위한 탐색보다 실패 유형을 확인한 뒤 좁은 실험을 제안한다.

| 새 가설의 예 | 고정할 조건 | 한 번에 바꿀 조건 | 주의점 |
|---|---|---|---|
| 더 많은 후반부 적응이 필요하다 | 데이터·LR·Epoch·입력·Loss | 해제 범위 | 실제 학습 파라미터 수와 BN 고정 기록 |
| 현재 조정 폭이 너무 크다 | 데이터·해제 범위·Epoch | 미세조정 LR | LR과 Epoch를 동시에 여러 값으로 바꾸지 않음 |
| 높은 해상도가 작은 특징을 보존한다 | Backbone·Loss·분할 | 입력 크기 | 원본 품질·메모리·시간 확인, 기대 성능 보장 없음 |
| 조명 변화에 더 견고해야 한다 | 모델·분할·학습량 | 제한된 밝기/대비 증강 | 질환 판단 정보를 지울 정도의 변환 금지 |

Hair는 실제 장비의 초점·반사광·배율, Web Skin은 얼굴 거리·노출·색감·배경 차이를 우선 조사한다. 지금 실제 장비 사진이 없으므로 어떤 증강이 현실적이라고 확정할 수 없다. 현재 데이터에서의 변형 실험은 민감도 확인이지 실제 장비 검증이 아니다. 특히 붉은색이나 미세 질감이 단서일 수 있어 강한 색상·흐림 변환을 무조건 늘리지 않는다.

추가 Backbone이나 두 모델의 점수 결합도 장기 후보지만 당장 우선하지 않는다. 기존 후보들의 오답이 서로 다른지 Validation에서 확인하고 계산 비용을 감당할 이유가 있을 때, 별도 고정된 결합 규칙으로 실험한다. Test를 보고 가중치를 조정하지 않는다.

## 9. 다중 라벨·정상 클래스·범위 밖 입력 — 데이터가 먼저 필요한 변경

| 변경 | 왜 필요한가 | 시작 조건 | 현재와 비교할 때 주의 |
|---|---|---|---|
| Hair 정상 클래스 추가 | 현재는 정상 사진도 5종 중 하나로 출력 | 확인된 정상 두피와 적절한 분할 | 5-class와 새로운 과제의 Accuracy를 직접 비교하지 않음 |
| 다중 라벨 분류 | 한 사진에 여러 상태가 기록될 수 있음 | 원천 복수 라벨 또는 확인 근거 | 미기록 상태를 음성으로 만들지 않음 |
| 범위 밖 입력 거부 | 얼굴·두피가 아니거나 범위 밖 상태를 강제로 분류하지 않기 | 유효/무효 입력의 별도 검증 자료 | 낮은 softmax만으로 안전한 거부를 보장하지 않음 |

현재 폴더 이름만으로 새로운 정상·복수 라벨 정답을 만들지 않는다. Medical VLM이나 생성 모델의 판단도 확인 없이 정답으로 사용하지 않는다. 다중 라벨로 바꾸면 각 상태의 존재 여부를 따로 예측하고 클래스별 Precision/Recall, F1, PR-AUC와 임계값을 새로 정의해야 한다. 이것은 같은 5-class 모델의 단순 성능 개선 실험이 아니다.

## 10. 점수 보정과 ‘판단 보류’

현재 softmax 점수는 실제 정답 확률로 검증되지 않았다. Temperature Scaling은 별도 보정 데이터로 점수의 강도를 조절하는 방법이다. [원논문](https://proceedings.mlr.press/v70/guo17a.html).

양의 단일 온도로 softmax 이전 점수인 logits를 조절하면 클래스 순위는 유지되므로 이것만으로 top-1 정답률이 높아지는 방법은 아니다. 목적은 점수 해석과 의사결정의 신뢰성을 개선하는 것이다. 현재 모델의 softmax와 일치하는 logits 또는 동등한 점수 변환을 얻을 수 있는지도 구현 시 확인한다.

보정에 사용한 자료와 평가 자료를 구분한다. 지금의 작은 Validation을 무작정 나누면 평가가 불안정해질 수 있으므로 추가 자료 또는 Train 내부의 적절한 분리 예측을 검토한다. Test로 온도·임계값을 고르지 않는다. 신뢰도 그래프, NLL/Brier Score와 보류율 대비 오류율을 함께 기록한다.

판단 보류는 일부 어려운 사진에 답을 내지 않는 기능이다. 남은 사진만의 정확도와 전체 사진 중 처리한 비율을 함께 보고해야 하며, 거부한 사진을 빼고 전체 정확도가 개선됐다고 주장하지 않는다. 보정과 범위 밖 탐지도 서로 다른 검증 과제다.

## 11. 실제 장비 검증과 Domain Gap — 자료가 확보되면 진행

Domain Gap은 학습·평가에 사용한 공개 사진과 실제 장비 사진의 분포가 다른 현상이다. 현재는 실제 USB 현미경·웹캠 검증 데이터가 없으므로 아래는 자료 확보 후의 순서다.

1. 익명 사람 ID, 부위, 촬영 세션, 장비 종류, 조명·초점·거리·배율 정보를 함께 기록한다. 불필요한 신원 정보는 수집하지 않는다.
2. 튜닝에 사용할 장비 데이터와 최종 평가용 자료를 사람·세션 단위로 미리 나눈다.
3. 고정한 후보를 독립 장비 자료에서 평가해 클래스별 성능과 조건별 실패를 파악한다.
4. 실제 차이를 근거로 제한된 증강 또는 미세조정 실험을 한다. 장비 최종 평가 자료는 학습·의사라벨 생성에도 넣지 않는다.
5. 설정을 고정한 뒤 별도 장비 평가를 보고한다. 반복해서 본 장비 자료도 더 이상 독립 최종 평가라고 부르지 않는다.

소규모 정상 사진만으로 질환 클래스 성능을 검증할 수는 없다. 확보 범위를 명시하고 현재 모델이 지원하는 클래스와 촬영 환경을 구분한다.

## 12. 실험 기록 양식

후속 실험마다 아래 내용을 남긴다. 기록은 ‘좋아졌다’라는 말보다 원인과 재현 가능성을 설명해야 한다.

| 필드 | 적을 내용 |
|---|---|
| 도메인·실험 ID | Hair/Web Skin을 분리한 고유 이름 |
| 문제 근거 | 어떤 Validation 오류에서 출발했는가 |
| 가설 | 한 문장으로 검증할 변화 |
| 대조 모델 | 후보/기준선 체크포인트와 SHA-256 |
| 고정 조건 | 분할·클래스·전처리·학습량·Seed·Backbone·Loss |
| 주요 변경 | 한 가지 연구 변수 |

| 실행 정보 | 코드 commit, 미커밋 코드 사본, 환경 버전, 설정, Seed |

| Test 정책 | 후보 고정 후 평가, 탐색 기록과 독립 평가 구분 |

현재 기본 제안은 Accuracy를 주 기준으로 유지하고 Macro F1·혼동 클래스 Recall을 보조로 보고하는 것이다. 이후 Macro F1을 주 기준으로 삼으려면 실험 전에 변경을 명시한다. 현재 후보를 사후에 다른 기준으로 다시 선정한 것으로 기록하지 않는다.

## 13. 당장 권하지 않는 작업

- 모든 고급 기법을 한 번에 적용하거나 가능한 모델을 무작정 모두 학습하기.
- 큰 모델이나 높은 해상도만으로 특정 정답률 도달을 보장하기.
- 모델이 틀렸다는 이유로 해당 사진을 삭제하거나 라벨을 자동 변경하기.
- 이미 확인한 Test 결과를 기준으로 손실함수·임계값·증강을 계속 고르기.
- 공개 Test 성능을 실제 USB 현미경·웹캠 정확도로 발표하기.
- Hair와 Web Skin의 클래스나 입력 처리를 합치고 장비 정보만으로 모델을 고르기. 통합 때는 장비와 촬영 부위를 함께 사용한다.

## 14. 두 모델별 권장 재개 지점

**Hair:** 기존 Test 감사에서 발견한 혼동을 연구 배경으로 보존하고, Train/Validation의 라벨·영상 품질을 먼저 확인한다. 원본 연결 기록으로 증강 누수를 막은 분리 예측을 만들 수 있는지 살펴본다. 그다음 전체+부분 정보를 하나의 독립 가설로 검토한다. 지도 대조학습·다중 라벨은 라벨 신뢰성과 추가 정보가 갖춰진 뒤 진행한다.

**Web Skin:** Validation의 아토피·여드름·건선 혼동을 검토하고 배경·얼굴 비율·조명 및 원본 출처를 기록한다. 한두 장 차이였던 B0 224/256의 반복성과 주목 영역을 확인한 뒤, 필요할 때 전체 얼굴+부분 정보 또는 제한된 증강을 각각 실험한다. B1 추가 Epoch를 바로 더 늘릴 근거는 현재 약하다.

두 모델 모두 현재 후보를 보관한 상태에서 후속 실험을 별도로 만든다. 이 문서 작성으로 새 학습, 라벨 변경, 실제 장비 검증, 자동 추론 모델 교체가 수행된 것은 아니다.

## 15. 추가 용어

| 용어 | 뜻 |
|---|---|
| 특징 표현 | 모델이 사진을 구분하기 위해 내부에서 계산한 정보 |
| Attention | 여러 부분의 정보를 얼마나 반영할지 가중치를 주는 방식 |
| 임계값 | 점수가 어느 수준일 때 출력하거나 보류할지 정하는 경계 |
| NLL | 실제 정답에 낮은 점수를 줄수록 커지는 벌점 |
| Brier Score | 클래스별 점수와 정답 표시 사이의 차이를 제곱해 평가하는 지표 |
| PR-AUC | 임계값을 바꾸며 Precision과 Recall의 관계를 요약하는 지표 |
| 보정 | 모델 점수와 관측되는 정답 비율이 더 잘 맞도록 조정하는 작업 |
| 독립 평가 | 학습이나 설정 선택에 사용하지 않은 자료로 하는 확인 |
