## 1. 유사 후보를 처리한 방법

새 Source 이미지를 눈으로 일부 확인한 것만으로 나머지 후보를 정상 처리하지 않았다.
기존 64-bit dHash Hamming ≤3 검사와 기록된 원본·증강 이력으로 연결된 후보들을 묶고,
불확실한 연결도 보수적으로 격리한다. A–B와 B–C가 연결되면 A–B–C를 한 묶음으로 다룬다.
이것은 동일 인물·병변·촬영 사례라는 확정이 아니라 누수 위험을 줄이기 위한 데이터 선택 정책이다.

우선순위는 **원본 Test 보존 → Validation 유지 → Train 유지**다. Test에 연결된 묶음에서는
Train과 Validation의 해당 원본을 새 실험 목록에서 제외한다. Test가 없는 Train/Validation
묶음에서는 Train 쪽을 제외한다. 원본 파일을 지우거나 다른 분할로 옮기지 않는다.
같은 Test 안에 여러 유사 사진이 남을 수 있으며 독립 표본 수의 한계는 계속 기록한다.

기존 offline 증강본은 새 실험의 학습에 사용하지 않는다. 특히 Web Skin에는 원본 추적 정보가
없는 증강본이 있어, 특정 원본 두 장만 제외하면 파생본까지 모두 제거했다고 말할 수 없다.
새 실험은 추적 가능한 original Train만 사용하고, 학습 중 적용하는 촬영 변화만 비교한다.

| 분야 | 기존 원본 Train | 제외 Train | 사용할 Train | 기존 Validation | 제외 Validation | 사용할 Validation | 원본 Test |
|---|---:|---:|---:|---:|---:|---:|---:|
| skin | 7249 | 496 | 6753 | 1000 | 100 | 900 | 700 유지 |
| web_skin | 3600 | 65 | 3535 | 500 | 1 | 499 | 400 유지 |

이 수치는 기존에 검증한 ZIP 해시·전체 Train 측정 목록·분할 수량·후보 기록으로 산출했다.
로컬 기록 기준으로 제외 후 서로 다른 분할에 남은 후보 연결은 두 분야 모두 **0개**다.
Drive 원본 ZIP에서 실제 적용한 목록의 전체 픽셀·해시 재검사는 새 Colab의 첫 단계에 실행한다.
새 유사 후보·중복·클래스 누락·Source/Target 겹침이 발견되면 학습을 시작하지 않는다.

## 2. 기존 모델의 과거 노출 이력 처리

Train에서 앞으로 사진을 제외하더라도, 기존 모델이 이미 학습한 내용은 없어지지 않는다.
그래서 두 분야는 기존 MediFlow 가중치에 이어서 학습하는 대신 다음 순서로 진행한다.

1. 기존과 같은 계열의 구조를 ImageNet 사전학습 backbone과 새 분류층으로 구성한다.
   Skin은 EfficientNet-B0 224, Web Skin은 PMG · EfficientNet-B0 256이다.
2. 새 Train/Validation 목록으로 head 15 epoch, 후반부 일부 10 epoch를 학습한다.
   이 일정은 기존 프로젝트의 두 단계 학습 틀을 사용한 고정 실험 설정이며 최적값이라는 뜻은 아니다.
3. 원본 Validation Macro-F1으로 새 기준 모델을 정한다. 이 단계에서는 Source Test 분류 결과를 보지 않는다.
4. 같은 새 기준 모델에서 대조군·밝기만 반영·측정 복합 변환을 각각 3 epoch 추가 학습한다.

새 기준 모델의 경로와 해시를 계약에 고정하고, 결과를 PC로 옮겨도 그 모델을 불러오도록 수정했다.
기존 선정 모델을 자동으로 다시 불러오는 경로를 피했다. 이전 모델의 보고 성능은 새 모델의
메타데이터로 복사하지 않는다. 새 모델은 새로운 학습·검증 목록을 사용하므로 과거 보고 수치와
단순히 차이를 빼서 어댑테이션 향상 폭이라고 표현하지 않는다.

## 3. 얼굴 검출 실패와 밝기 설정 수정

기존 Source 얼굴 3600장 중 552장에서 자동 얼굴 영역을 찾지 못했다.
이는 부분 얼굴·이마 구도 등을 포함하며, 질환 라벨 오류나 사용 불가 판정은 아니다.
검출 실패를 이유로 이 사진들을 삭제하지 않았다. 새 Train 3535장에도 해당 552장이 남아 있다.

이전 얼굴 밝기 설정은 검출에 성공한 Source 피부 영역의 클래스별 밝기와 Target의 차이에
의존했다. 클래스별 가중치를 같게 해도 검출 성공 사례의 선택 편향과 합성 데이터·질환·부위
차이를 제거할 수는 없다. 그래서 새 실험은 **같은 참여자의 ref/alt 촬영 조건 간 밝기 변화**로
변환 범위를 정한다. Source의 얼굴 영역 통계는 결측률을 포함한 진단 자료로 유지한다.

얼굴에서 관찰된 참여자별 ref→alt 중앙 밝기 변화는 다음과 같다.
`[32.560543060302734, 38.91480255126953, 33.98937225341797, 10.20164680480957]`.
관측 변화의 사분위수에 0.5를 곱하고 기존 제한을 적용한다.

| 분야 | 밝기 가산 제안 범위, RGB 0–255 단위 | 대비 | 좌우 조명 변화 | 입력 정책 |
|---|---|---|---|---|
| web_skin | [13.485409498214722, 17.61036491394043] | [1.15, 1.15] | [13.776813507080078, 15.418357372283936] | 중앙 정사각형 후 256 |
| skin | [-1.3492517471313477, -0.7292451858520508] | [0.9399699904076788, 0.957350048293398] | [0.0, 0.0] | 기존 전체 리사이즈 224 |

얼굴은 과거 전역 밝기 차이에 기반한 음수 범위에서 양수 범위로 바뀌었다. 이는 같은 사람의
촬영 조건에서 관측된 변화 방향을 반영한 결과다. **Source 전체를 Target의 전역 밝기 분포에
일치시킨다는 의미는 아니다.** 관측된 전역 도메인 차이는 남아 있으며, 이를 전부 조명 효과로
해석하지 않도록 실험 가설을 제한했다. 0.5배·제한값은 고정한 보수적 설정이지 검증된 최적값이 아니다.

범위 밖 값을 바로 자르는 대신 `bounded_additive_v3`로 경계에 부드럽게 접근시킨다.
모델 입력은 float32 RGB 0–255이고 외부 `/255`는 추가하지 않았다.
색·흐림·노이즈·모발 마스크·인공 배경 확대 같은 변수를 새로 추가하지 않았다.

## 4. 변환 검사와 실제 검토 범위

후보 격리 대상 Train 사진은 변환 강도 검토에서도 제외했다. 이전에 확보한 미리보기 중
Skin 17장·Web Skin 2장을 제외하고 다음 자료를 생성했다.

| 분야 | 수치 검사 표본 | 직접 본 묶음 페이지 | 새 경계값 비율 최댓값 | 설정 끝값의 경계 근처 비율 최댓값 |
|---|---:|---|---|---|
| skin | 223 | 1, 4, 7, 10, 13, 16, 19, 22, 24, 27 | 0.0 | 0.0 |
| web_skin | 118 | 1, 4, 6, 7, 10, 11, 13, 15 | 0.0 | 0.06446329752604167 |

수치는 전체 341장과 밝기·대비·방향 조명의 범위 끝 조합에 대해 계산했다.
시각 검토는 각 클래스의 대표 표본과 변화가 큰 얼굴 사례를 포함한다. 모든 원본이나 모든
341장의 시각 검토를 완료했다고 주장하지 않는다. 미리보기에서 큰 병변 경계 소실이나
인공 기하 변화는 관찰하지 못했지만, 임상 라벨 보존이나 정확도 향상의 검증은 아니다.
얼굴의 큰 경계 근처 변화 사례 Q0045에서는 의복·밝은 부분도 영향을 받았다.

정확한 0·255가 생기지 않는 것은 연산의 설계 특성이다. 경계 근처 압축과 색·대비 변화는
여전히 가능하다. 승인 범위는 고정한 제한적 비교 실험이며 실제 질환 성능은 새 학습으로 평가한다.
사진 전후와 Target 분포는 각 분야 `transform_qa/before_after_target.svg`에 함께 표시했다.

## 5. 고정 조건과 비교 변수

세 적응 학습 군에서 데이터 버전·제외 목록·분할·클래스 순서·새 출발 모델·입력 정책·seed 42·
batch 16·Adam learning rate 0.00001·3 epoch·후반 30개 층/BatchNorm 고정 조건을 공유한다.

- `baseline`: 새 Train으로 재구축한 기준 모델. 이전 MediFlow 선정 모델이 아니다.
- `source_only`: 같은 새 기준 모델에 촬영 변환 없이 추가 학습.
- `brightness_only`: 같은 조건에 측정 밝기 변환만 확률 0.5로 적용.
- `target_guided`: 같은 조건에 관측 근거가 있는 밝기·대비·방향 조명의 조합을 적용.

주 가설은 측정된 촬영 조건 변화를 반영한 추가 학습이 원본 성능을 유지하면서 설정된
촬영 변화에 대한 대응을 개선하는지다. 원본 목록만 사용하고 기준 모델을 새로 만드는 것은
분할·이력 문제 처리에 필요한 동반 변경이다. 모든 비교군에 공통으로 적용하며, 이를 기존
보고 성능 대비 어댑테이션 효과로 혼동하지 않는다.

Validation으로 모델을 정한 기록·Source 목록·프로필·체크포인트 해시를 고정한 다음에만
원본 Source Test와 별도로 표시한 촬영 변화 Source Test를 평가한다. Test의 사진은 학습 전
이미지 파생 누수 확인에는 사용하지만 분류 성능으로 설정을 고르지는 않는다.

Colab에서 최종 노트북을 열고 GPU를 선택한 뒤 **모두 실행**한다.
파일 선택 창에서 이번 실행 ZIP 하나를 선택하고 기존 Source가 있는 Drive를 연결한다.
코드·DOMAIN·REVIEW_NOTE 수정은 필요 없다. 피부 → 얼굴 순서로 별도로 실행한다.
새 기준 모델을 만들기 때문에 단순 3 epoch 추가 학습보다 오래 걸리며, 최초에는 ImageNet
가중치 다운로드가 필요할 수 있다. GPU가 없으면 학습을 시작하지 않는다.

Source 원본 ZIP은 Drive에서 실행 공간으로 복사해 읽기만 한다. 결과는 Drive의 새
`mediflow_skin_web_adaptation_<실행ID>` 폴더에 저장하고 두 분야를 담은 ZIP 하나를 내려받는다.
분야별 `RESULTS.md`, `status.json`, `final_evaluation/comparison.json`과 로그를 포함한다.
실패한 분야는 실패로 남기고 다른 분야를 계속 진행한다. 기존 결과를 덮어쓰지 않는다.
실제 촬영 사진 원본은 실행 ZIP에 포함하지 않았다.

재사용 코드는 `src/mediflow_datasets/domain_adaptation_resolution.py`,
준비·패키지 생성기는 `scripts/build_skin_web_resolution.py`,
`scripts/package_skin_web_training.py`다. 기존 실행기의 새 기준 모델 경로·선정 고정 검사를
보완하고 `train_variant=original`을 지원했다. 새 모델에 과거 점수를 붙이지 않는 검사도 추가했다.

- 최종 전체 pytest: **163개 통과, 3개 건너뜀, 실패 0개**.
  건너뛴 3개는 기존 선택 라이브러리 matplotlib가 없는 노트북 검사다.
- 작은 임의 이미지·모델로 새 기준선 학습부터 적응 비교·선정 고정·Test 평가까지 실제 실행했다.
  제외 경로와 기존 가중치가 새 학습에 사용되지 않음, 이동 후 새 기준 모델 로드,
  과거 성능 필드 제외, Source 목록 변조 시 평가 거절을 확인했다.
- 로컬 후보 연결 기준 잔여 교차 분할 0, 모든 Train 클래스 유지 확인.
- 기존 선정 모델 세 개의 해시는 기존 색인과 일치한다. 공통 `common_engine.py`와
  기존 노트북의 내장 소스는 유지했다.
- 새 실험의 진행 기록에만 파일 잠금 재시도를 적용했다. 이전 파일을 유지하면서 제한된 횟수만
  재시도하며 지속적인 오류는 실패로 알린다. 관련 검사 2개를 추가했다.

검사 과정의 Windows 파일 잠금·긴 임시 경로와 개발 중 공통 코드/기존 노트북 소스 불일치는
원인을 구분해 처리했다. 최종 검사는 짧은 프로젝트 임시 경로와 복원된 공통 코드에서 통과했다.
기존 노트북을 재생성해 검사를 통과시킨 것이 아니다.

기준 Git commit은 `ffd71eca68ff1e21c145ed56158f4cfa77f7f037`이고 이번 코드는 미커밋 상태다.
실행 파일과 검토 근거 자체 및 해시를 묶어 포함했다. Git commit·push는 하지 않았다.
실제 새 분류 모델 학습을 Colab에서 실행하거나 새 질환 정확도를 측정한 것은 아니다.
전체 Source 원본 재검사는 노트북 실행 시 학습 전에 수행되며, 그 결과를 미리 성공으로 표시하지 않는다.

## 다음 단계와 사용자가 할 일

사용자가 할 일은 최종 노트북에서 피부·얼굴 새 기준선 및 비교 학습을 실행하고 결과 ZIP을
다운로드하는 것이다. 이전 분석을 다시 실행하거나 데이터셋 ZIP을 PC에서 다시 올릴 필요는 없다.
결과를 확보하면 Validation의 고정 선택, 원본 성능 유지, 촬영 변화 성능, 클래스별 Recall·
Confusion Matrix를 검토하고 PC의 실제 촬영 사진으로 예측 변화·MMD·CORAL을 후속 계산한다.

과거 모델의 Source/Target 특징을 새 모델 특징으로 재사용하지 않도록 실행 ZIP에서 과거 예측·
특징 배열을 제외했다. 실제 촬영 질환 정답과 독립 참여자 평가 자료가 없으므로 Target
Accuracy·Macro-F1은 계산하지 않는다. 네 사람 모두 calibration에 사용했으며 독립 Target Test로
다시 이름 붙이지 않는다. 특징 거리·예측 확신도 변화만으로 실제 환자 성능 향상을 주장하지 않는다.
MMD/CORAL 특징 정렬 학습과 LLM·VLM 확장은 보류 상태를 유지한다.
