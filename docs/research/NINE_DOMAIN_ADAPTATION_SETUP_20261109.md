## 비교할 아홉 개의 조건

| 분야 | A: lighting | B: expanded | C: aligned |
|---|---|---|---|
| skin | 기존 측정 기반 조명 변화 | A + 색·미세 대비·약한 흐림 | B + MMD·CORAL 결합 손실 |
| web_skin | 기존 측정 기반 조명 변화 | A + 색·미세 대비·약한 흐림 | B + MMD·CORAL 결합 손실 |
| hair | 기존 측정 기반 조명 변화 | A + 색·미세 대비·약한 흐림 | B + MMD·CORAL 결합 손실 |

GPU 하나에서 두피 → 얼굴 → 피부, 각 분야 A → B → C 순으로 자동 실행한다.
아홉 개의 모델을 동시에 GPU 메모리에 올리는 구성은 아니다. B와 C는 같은 사진에 같은
난수로 정확히 같은 영상 변환을 적용한다. C에만 특징을 정렬하는 학습 손실을 더한다.
MMD와 CORAL을 **함께 사용하는 조건 하나**이므로 각각의 효과는 분리할 수 없다.

A는 이전 준비된 조명 중심 변환을 그대로 사용한다. 분야에 따라 밝기뿐 아니라 대비와
좌우 조명 차이도 포함하므로, 엄밀한 의미의 Brightness-only라고 표기하지 않는다.

세 조건은 각각 다음 가설을 점검한다.

1. A: 작은 조명 변화로 추가 학습한 모델이 원본 성능을 유지하면서 촬영 변화 평가에 대응하는가?
2. B 대 A: 같은 학습량에서 측정한 색·미세 대비·초점 변화 묶음을 더하면 도움이 되는가?
3. C 대 B: 같은 영상 변환과 학습량에서 MMD·CORAL 결합 손실을 더하면 도움이 되는가?

A와 출발 기준 모델 사이에는 추가 학습량 차이도 있다. 추가 학습만 한 별도 대조군은
이번 아홉 조건에 넣지 않아, 이 비교로 조명 변환만의 효과를 분리하지 않는다.
B의 색·질감·초점 개별 효과도 이 묶음 실험만으로 분리하지 않는다.

## 시작 모델과 고정 조건

| 분야 | 구조·입력 | 클래스 | 시작점 | 학습 자료 |
|---|---|---|---|---|
| skin | EfficientNet-B0 · 224 | 10, 정상 없음 | 제외 목록 적용 후 새 공통 기준 모델 | 남겨진 원본 Train |
| web_skin | PMG · EfficientNet-B0 · 256 | 5, 정상 포함 | 제외 목록 적용 후 새 공통 기준 모델 | 남겨진 원본 Train |
| hair | EfficientNet-B1 · 384 | 기존 5, 정상 없음 | 기존 v2 선정 체크포인트 | 기존 augmented Train |

피부·얼굴은 이전 중복·유사 사진 연결 목록을 적용한 뒤 ImageNet 초기값에서 기준 모델을
분야당 한 번 준비한다. 분류 부분 15 epoch, 뒷부분 10 epoch를 학습하고 원본 Validation으로
선택한다. 이전 학습 이력이 있는 선정 가중치를 초기값으로 쓰지 않는다.
이 기준 모델 준비 두 건은 아홉 개의 적응 조건 수에 포함하지 않는다.
구조·클래스 순서 계약과 두피 초기값은 `results/CANDIDATE_INDEX.json`으로 확인한다.

각 분야의 A/B/C는 같은 기준 모델에서 각각 시작한다. 세 조건을 앞 모델에 이어 붙이지 않는다.
고정값은 seed 42, batch 8, 3 epoch, Adam 학습률 0.00001, 영상 변환 적용 비율 0.5,
기울기 전체 크기 제한 1.0이다. 동일한 Train 순서와 갱신 횟수를 사용한다.
뒷부분 30개 층 중 Batch Normalization을 제외한 층과 분류 부분을 추가 학습한다.
두피는 Label Smoothing 0.05, 나머지는 CE를 유지한다.
PMG는 기존 네 갈래 학습 순서(격자 8·4·2, 마지막 결합 갈래 손실 2배)를 유지하며,
정렬 손실은 마지막 결합 갈래 갱신에만 더한다.

입력은 float32 RGB 0–255다. 기존 모델의 내부 Rescaling을 유지한다.
Lab 색 측정·변환 함수 안에서만 필요한 범위를 사용하고 모델 앞에 외부 `/255`를 추가하지 않는다.
얼굴은 모든 조건에서 같은 중앙 정사각형 입력 정책을 쓴다.

## 실제 차이와 확장 범위의 근거

이전 Colab의 전체 Source 원본 Train 측정값과 실제 촬영 124장을 사용했다.
피부·얼굴은 제외 목록에 해당하는 Train 측정값도 제외했다. 평균·분산·분위수는
각 `extended_profile.json`의 `evidence`에 보존한다. Source Test를 변환 범위 결정에 쓰지 않았다.

관찰된 차이에는 다음이 포함된다.

- 피부: Source 대비 Target의 대비와 미세한 명암 변화가 작고, Lab 색 분포가 다르다.
- 얼굴: Target의 얼굴 폭 비율과 미세한 명암 변화가 작으며, b 색축 분포와 조명 변화가 다르다.
  남겨진 Source Train 3,535장 중 얼굴 검출 성공 2,983장의 ROI 통계다.
  검출 실패 552장을 학습에서 제거하지 않았고 ROI 수치 비교의 한계로 기록한다.
- 두피: Target의 대비와 미세 명암 변화가 크고 색 분포도 다르다.
  어두운 가는 구조 비율은 모발 가림의 참고값이며 검증된 모발 분할 정답이 아니다.

이 전역 차이는 질환·부위·모발·구도 차이를 포함한다. 이를 모두 카메라 차이라고 간주해
Source의 질환 색이나 질감을 Target 전체 평균으로 옮기지 않는다.
확장 범위는 같은 사람 안에서 측정된 변화로 작게 제한한다.

| 항목 | 계산 방법 | 적용 방법 |
|---|---|---|
| 색 | 사람별 alt/ref Lab a·b 중앙값 차이 네 개의 사분위 범위 × 0.5 | a·b에 작은 오프셋, 절대값 상한 3 |
| 미세 대비 | 사람별 alt/ref의 detail/contrast 중앙값 비율의 사분위 범위 | 1에서 변화 절반만 반영, 범위 0.85–1.15 안으로 제한 |
| 초점 참고값 | 같은 사람·같은 조건 안의 영상으로 64×64 ROI의 정규화 detail 변화를 흐림으로 근사 | 근사 σ의 Q75 절반을 상한으로 사용, 64 ROI 기준 최대 0.75 |

얼굴은 얼굴 폭이 비슷한 세 장, 두피는 어두운 가는 구조 비율이 비슷한 세 장을 비교해
초점 근사의 구도 혼입을 줄였다. 피부는 같은 사람·조건의 사진을 비교했다.
분야마다 여덟 조건 그룹에서 근사했고 검색 상한에 걸린 그룹은 없었다.
이 값은 광학적 초점이나 장비의 실제 point spread function을 보정한 수치가 아니다.
피부 구조·모발·위치 차이가 남고, 질감과 초점 지표도 서로 독립적인 측정은 아니다.

파라미터의 정확한 float 값은 JSON이 기준이다. 다음 값은 구현된 blur 범위다.

| 분야 | 64 ROI σ | 입력 영상 환산 배율 |
|---|---|---|
| skin | 0–0.30000000000000004 | 1.75 |
| web_skin | 0–0.2 | 1.9375 |
| hair | 0–0.35625 | 3.0 |

얼굴 크기·두피 모발 가림·노이즈를 임의로 합성하는 변환은 추가하지 않았다.
관찰된 차이의 존재와 이를 질환 정보를 해치지 않고 재현하는 방법의 타당성은 별개다.
범위는 네 사람의 초기 조사에서 정한 파일럿 설정이며 일반적인 장비 분포가 아니다.

## 특징 정렬의 실제 학습

C는 Source의 질환 분류 손실에 미분 가능한 MMD와 CORAL을 더한다.
MMD는 여러 폭의 RBF 커널에서 두 특징 분포의 평균 차이를, CORAL은 특징 공분산 차이를 줄인다.
두 손실 모두 실제 모델 가중치로 기울기가 전달된다. 단순히 지표만 기록하는 코드가 아니다.

Source Train에서 클래스당 최대 8장의 고정 특징으로 평균·표준편차 좌표를 만든다.
MMD의 기준 폭은 이 Source Train과 Target 학습 참여자별 평균 특징 사이 거리의 중앙값이며,
그 0.25·1·4배 폭 커널의 평균을 사용한다. Test나 Target Test로 이 값을 정하지 않는다.
출발 모델에서 각 정렬 손실이 Source 분류 손실의 0.05 정도가 되게 계수를 정하되
계수 최대값을 10으로 제한한다. 값과 계산 근거는 실행 시 `baseline_setup.json`에 저장한다.
두 초기 손실이 모두 0이면 서로 다른 정렬 실험이라고 주장하지 않고 중단한다.

Target은 P01–P04에서 한 장씩 네 장을 묶고, epoch마다 사람별 사진을 최대 한 번씩만 쓴다.
한 분야의 모든 Source 배치마다 같은 사람 사진을 반복하지 않도록 Source 갱신 위치를 나눠 배치한다.
추가 Source 갱신을 만들지 않으며, A/B/C의 최적화 갱신 횟수는 같다.
Target 정답·의사 라벨로 분류 손실을 계산하지 않는다.

특히 피부·두피 5클래스에 정상 클래스가 없어 Target과 클래스 구성이 다를 수 있다.
무조건 특징을 가깝게 만들면 질환 구분력이 떨어질 위험이 있다. 따라서 작은 조사 규모의
탐색 실험으로 기록하고 원본 Validation의 Macro-F1·클래스별 Recall 저하 조건을 검사한다.
정렬 지표 감소나 예측 점수 상승만으로 실제 장비 성능 향상을 판정하지 않는다.

## 분할·평가·개인 사진

피부 6,753/900/700장, 얼굴 3,535/499/400장의 원본 Train/Validation/Test 목록을 사용한다.
두피 원본은 10,032/1,252/1,252장이고 학습에는 기존 augmented Train 15,047장을 쓴다.
원본 Test는 물리적 파일과 평가 목록 모두 보존한다. 증강으로 만든 Test는 별도 조건으로 표기한다.
전체 ZIP을 Colab에서 다시 읽어 해시·중복·유사 사진·확인 가능한 분할 충돌을 검사하며,
미해결 항목이 있으면 학습 전에 중단한다. 사람·병변·원본 파생 관계 메타데이터가 없는
Source의 모든 누수를 배제했다고 주장하지 않는다.

각 epoch의 원본·확장 변화 Validation Macro-F1 중 작은 값으로 최적 checkpoint를 고른다.
그 후 원본 Macro-F1 하락 0.01, 클래스별 Recall 하락 0.05 이내와 변화 성능 증가 0.005를
기준으로 기존 선택 함수를 적용한다. 세 조건을 모두 마치면 선택·입력·모델 해시를 고정하고,
이후에만 기준 모델과 A/B/C를 원본 Test·조명 변화 Test·확장 변화 Test로 평가한다.
동일한 원본에서 만든 세 평가 조건은 독립적인 세 Test 데이터셋이 아니다.
Accuracy, Macro-F1, 클래스별 Recall, Confusion Matrix, 예측 점수와 특징 배열을 저장한다.

**새 실행 ZIP에는 실제 촬영 124장의 모델 입력 배열이 포함된다. 얼굴은 식별 가능하다.**
기존 수치만 전달하던 패키지와 다르며, 새 ZIP을 사용자가 Colab에 선택하면 영상 배열도 전송된다.
지금 PC에서 Drive나 Colab으로 업로드한 것은 아니다. 원본 촬영 파일은 그대로 보존한다.
Target 전원은 이미 촬영 분석에 사용한 calibration 자료이며 C에서는 정렬 학습에도 사용한다.
독립 Target Test가 아니다. Target Accuracy/Macro-F1은 `null`로 기록한다.
예측 변화·특징 거리·PCA는 학습에 관여한 Target에 대한 기술적 비교다.
네 사람과 다른 정답 확인 참여자 자료를 나중에 확보해야 실제 장비 성능을 평가할 수 있다.

## 중단·재실행과 재현

노트북은 TensorFlow 2.20.0·Keras 3.13.2 호환 환경을 검사한다. 호환되지 않는 Colab 기본 환경을
삭제하지 않고 별도 환경을 구성한다. GPU가 없으면 안내 후 학습 전에 멈춘다.
Drive의 기존 Source ZIP을 찾고 확인값을 검사하므로 PC에서 질환 데이터 ZIP을 다시 올릴 필요가 없다.

결과는 Drive의 `mediflow_nine_…`에 기록한다. 같은 새 ZIP으로 재실행하면 해당 실행을 찾아
완료된 모델의 확인값을 검증해 재사용한다. 중단된 조건은 새 시도 폴더에서 다시 시작하며
이전 부분 결과를 삭제하지 않는다. 기준 모델 준비가 완료되기 전에 중단되면 기준 준비도 새로 시작한다.
Test 평가가 완료된 실행을 이어받으면 완료 결과를 재사용한다.
한 조건·한 분야가 실패해도 나머지 실행을 시도하며, 실패를 완료로 표시하지 않는다.
코드·설정·seed·환경·클래스·입력 목록·기준 모델·검토 근거와 확인값을 저장한다.
전체 완료 수는 `summary.json`의 `arms_completed: 9`, `all_completed: true`로 확인한다.
완료·실패 로그와 모델을 포함한 결과 ZIP 하나를 내려받는다.

## 로컬 점검과 남은 일

- `ruff check src tests` 및 새 빌드·호환성 확인 스크립트 점검 통과.
- 자동 테스트 171개 통과, matplotlib 미설치에 따른 기존 선택 검사 3개 건너뜀.
- 작은 시험 모델로 실제 아홉 조건의 학습·평가·중간 실패·완료 모델 재사용 경로를 실행했다.
- NumPy 독립 계산과 MMD/CORAL 손실이 일치하고 두 도메인으로 기울기가 전달되는 것을 확인했다.
- 실제 선정 모델 세 개에서도 원래 입력 크기와 특징 차원으로 유한한 정렬 손실·기울기를 확인했다.
  이 확인에서 모델 가중치를 갱신하거나 저장하지 않았고 원본 모델 확인값도 일치했다.
  호환성 확인 수치는 소수 입력의 시험값이며 전체 도메인 거리나 성능 결과가 아니다.
- 남겨진 Source Train 미리보기 461장(피부 223, 얼굴 118, 두피 120)을 수치 점검했다.
  새로 생긴 정확한 0/255 채널 비율의 최댓값은 세 분야 모두 0이었다.
  전체 미리보기 수치 점검과 별도로 클래스별 예시·극단 사례의 접촉 시트 14쪽을 눈으로 확인했다.
  461장 전부를 육안 검토했다고 주장하지 않으며 임상적 정보 보존을 검증한 것도 아니다.
- 실제 Source 전체 학습과 GPU 환경·Drive 연결·브라우저 다운로드는 사용자 Colab 실행이 남아 있다.
  GPU 메모리·세션 제한·네트워크 오류까지 발생하지 않는다고 보장할 수는 없다.
