# Web Skin PMG 최종 배포 후보 선정

## 결정

Web Skin의 최종 Test 및 배포 패키징 대상은
`PMG·EfficientNet-B0·256·CE·Adam`의 `stage2_best.keras`로 고정했다.
`PMG·B1·384`는 Validation 성능이 더 높았지만, 입력 연산량과 모델 크기, 학습곡선의 변동을
고려해 연구 성능 선두로 보존하고 현재 배포 후보에서는 제외한다. 이 결정 이후 Test 결과를
보고 후보를 다시 바꾸지 않는다.

## 같은 Validation에서 측정한 비교

| 항목 | PMG·B0·256 | PMG·B1·384 | 차이/비율 |
|---|---:|---:|---:|
| Validation Accuracy | 0.8500 | 0.8660 | B1 +0.0160 |
| Validation Macro F1 | 0.8473279632397033 | 0.8643216544321994 | B1 +0.0169936911927931 |
| 입력 픽셀 수 | 65,536 | 147,456 | B1 2.25배 |
| 파라미터 수 | 8,872,375 | 11,398,043 | B1 약 1.285배 |
| 모델 파일 크기 | 36,377,179 bytes | 46,828,176 bytes | B1 약 1.287배 |
| 기록된 학습 시간 | 983.6290965초 | 2453.2392815초 | B1 약 2.494배 |

두 모델은 augmented train, 동일한 원본 Validation 500장, CE, Adam, seed 42와 PMG 구조를
사용했다. B1 실험은 메모리 때문에 batch 16을 사용했고 B0는 batch 32를 사용했다. 따라서
Backbone과 입력 크기뿐 아니라 필수 batch 변경이 동반된 scale 조합 비교다.

## 선택 근거

- B1·384의 Macro F1 개선은 약 1.70%p로 측정됐다.
- B1·384는 입력 픽셀이 2.25배이고 모델 파일도 약 29% 크다.
- B1·384의 Train Accuracy는 거의 1.0까지 올랐지만 Validation 값과 loss가 흔들려 마지막
  epoch 대신 중간 최고 checkpoint가 선택됐다.
- 현재 목표는 웹캠 얼굴 사진 한 장을 분류해 팀 시스템에 연결할 수 있는 후보 파일을 만드는
  것이다. 이 단계에서는 B0·256의 0.8473 Macro F1과 더 낮은 실행 비용의 균형을 선택했다.

이 판단은 B1·384가 성능상 열등하다는 뜻이 아니다. B1·384는 공개 Validation 성능 선두이며,
추후 실제 웹캠 데이터와 목표 장비에서 정확도·지연시간·메모리를 함께 측정할 때 다시 비교할
연구 후보로 보존한다.
