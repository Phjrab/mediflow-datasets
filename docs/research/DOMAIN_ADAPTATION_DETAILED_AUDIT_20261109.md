# MediFlow 어댑테이션 상세 점검과 남은 작업

2026-11-09 · 로드맵 3단계 분석 및 4·6단계 실험 준비

**현재 완료한 것은 촬영 환경 차이의 기술적 분석과 변환 초안 생성이다. 추가 학습이나
실제 장비의 질환 분류 성능 개선을 완료한 상태는 아니다.** 분석 자료는 확보했으나 바로
학습하기 전에 고칠 구현 오류와 보완할 실험 설계가 있다.

이 문서는 기존 보고서·측정값·모델을 수정하지 않고 새로 추가한 점검 기록이다.
[실제 Colab 결과 검토](DOMAIN_ADAPTATION_COLAB_REVIEW_20261109.md)와
[상세 점검 근거 JSON](../../camera_capture/_review/domain_adaptation_detailed_audit_20261109/audit_evidence.json)을
함께 읽는다. 아래에서 Source는 기존 질환 학습 자료, Target은 실제 장비 촬영 자료,
Train은 학습 자료, Validation은 조건·모델 선정 자료, Test는 선정 후 최종 평가 자료다.

## 1. 목표와 현재 접근법

목표는 기존 질환 사진을 실제 장비에서 관찰한 촬영 특성에 맞게 변환하고, 같은 조건으로
추가 학습한 뒤 원래 성능과 촬영 변화 대응 성능을 비교하는 것이다. 얼굴·피부·두피는
클래스와 장비·부위가 다른 독립 과제로 유지한다. LLM·VLM은 이후에 진행한다.

현재 구현한 학습 후보는 **Target-guided Augmentation**, 즉 실제 촬영 자료를 참고한 증강과
기존 질환 라벨을 이용한 추가 학습이다. 아직 이것을 실제 데이터로 학습하지 않았다.
MMD/CORAL 특징 정렬 학습이나 Target 질환 사진을 이용한 미세조정을 실행한 것은 아니다.

증강도 넓은 의미의 환경 대응 수단이지만, 라벨 없는 Target 특징을 학습 손실에 넣어 분포를
정렬하는 UDA와 방법·증거를 구분한다. 현재 상태를 “UDA 학습 완료”로 표현하면 안 된다.

- 얼굴 크기·위치와 두피 어두운 경계 비율의 보조 측정, 분포·분산·분위수 그림 생성.
- 실제 사진의 기존 모델 예측과 특징 추출, 일부 Source 특징과의 거리·PCA 비교.
- 원본/증강 Train·Validation·Test의 파일·픽셀·기록된 원본 ID 검사.
- 측정값을 이용한 변환 초안과 클래스별 Train 미리보기.
- Colab에서 Hair·Skin 순차 실행, 결과 ZIP 생성·다운로드, 완료 및 코드·모델 해시 검증.

원본 Train 통계는 전체를 읽었지만 **특징 추출은 전체 Train이 아니다.** Hair는 클래스당
8장씩 Source 40장, Skin은 Source 80장과 각각의 Target 전체를 비교했다. Web Skin의 현재
간단 검토 ZIP에는 전체 Source 표본 기반 특징 진단 JSON이 없어서 해당 수치는 보완이 필요하다.
역사적으로 측정한 예시 기반 수치를 그 자리에 대신 넣지 않는다.

## 3. 측정한 차이와 해석 가능한 범위

밝기는 원본 전체 프레임이 아니라 모델 크기로 바꾼 뒤 얼굴의 볼 또는 현미경 중앙 영역에서
계산한 0–255 영상 지표다. 물리적 조도·노출 시간·센서 응답을 직접 측정한 값이 아니다.
아래 비성능 지표는 설명을 위해 반올림했고 정확한 값은 원본 JSON을 보존했다.

Source 얼굴·피부는 프로젝트 배경에 기록된 AI Hub 합성 데이터다. 차이에는 장비 외에도
합성 영상의 외관, 질환 구성, 인물·부위·구도 차이가 포함될 수 있다. 모든 차이를
“카메라 차이”로 부르거나 카메라 변환 하나로 해결된다고 가정하지 않는다.

### 색·질감과 질환 특징의 혼동

실제 Source만 보아도 지표는 클래스마다 다르다. 예를 들어 피부 클래스의 밝기 중앙값은
혈관종 약 55.03, 표피낭종 약 109.62이고, 두피의 Lab a 중앙값은 모낭사이홍반 13.875,
피지과다 -4.9765625다. Target의 전체 색을 따라 모든 Source 색을 이동시키면 구분에
쓰이는 붉은 기 등이 변할 수 있다. 이는 현재 자료에서 예상되는 혼동 위험이며,
특정 변환이 실제로 성능을 떨어뜨렸다는 실험 결과는 아니다.

미세 경계량은 카메라 초점만 나타내지 않는다. 모발 윤곽이 선명해도 두피 표면은 흐릴 수
있다. 어두운 경계 비율 역시 모발·그림자·질감이 섞인 보조 지표로, 검증된 모발 가림 면적이
아니다. 현재 사진만으로 실제 배율과 센서 노이즈, 피부 표면 초점 성능을 분리해 확정하지 못했다.

## 4. 변환 코드가 실제로 하는 일

[보정 함수](../../src/mediflow_datasets/domain_adaptation_analysis.py)는 다음 규칙을 쓴다.

| 항목 | 현재 산출 방법 | 의미와 한계 |
|---|---|---|
| 얼굴 밝기 | Target 각 그룹의 볼 밝기 − Source Train 볼 밝기, 25–75% 구간의 절반, 최대 절댓값 32 | Source→Target 차이를 약하게 반영하는 초안이다. 절반·상한 32는 설계 가정이며 장비에서 검증된 상수가 아니다. |
| 피부·두피 밝기 | 같은 참여자의 변경 − 기준 밝기, 그룹 변화의 25–75% 구간 절반 | Target 내부 조건 변화를 재현한다. 전체 Source→Target 밝기 수준을 맞추는 것이 아니다. |
| 대비 | 네 사람의 조건 변화가 같은 방향일 때 비율을 완화, 0.90–1.15 범위 | 현재 코드는 두피를 제외한다. 단순히 다른 차이를 관찰하지 못해서 제외한 것은 아니다. |
| 얼굴 크기 | 전체 얼굴 검출률 70% 이상일 때 크기 비율 차이의 절반 반영 | 클래스별 검출 편향과 비율 유지 여부는 이 조건만으로 확인하지 못한다. |
| 얼굴 좌우 조명 | 네 사람의 변경 방향이 같으면 좌우 차이의 절반 반영, 절댓값 최대 24 | 장면 전체에 선형 명암 경사를 더하는 근사 모델이다. 실제 광원의 물리적 재현은 아니다. |
| 색·흐림·노이즈·모발 | 현재 변환에 넣지 않음 | 질환·부위·촬영 크기와 분리한 근거가 부족하다. 분석에서 차이가 없었다는 뜻은 아니다. |

예를 들어 피부의 실제 Target 밝기는 Source보다 높지만 현재 적용할 초안은
`-1.3492517471313477`~`-0.7292451858520508`이다. 오류로 부호를 바꾼 것이 아니라
Target 내부 조명 변경의 작은 감소만 가져온 결과다. **이것만으로 피부의 전체 도메인 차이에
적응하는 설정을 완성했다고 설명하면 잘못이다.**

현재 두피 초안은 밝기 `-0.6363735198974609`~`12.4506196975708`이고 나머지는 항등 변환이다.
따라서 현재 Target-guided 변환과 Brightness-only는 같은 변환이다. GPU 학습의 수치 차이가
나더라도 이를 서로 다른 변환 방법의 효과로 해석할 수 없다.

현재 코드는 기존 Augmented Train을 공통으로 사용한다. 여기의 “밝기만”은 **추가한 촬영
변환이 밝기만**이라는 뜻이다. 기존 데이터에 이미 들어 있는 다른 증강까지 없다는 뜻이 아니다.

## 5. 학습 전에 반드시 보완할 항목

### 5.1 재현한 구현 오류: 적용 여부와 강도 난수의 결합

[학습 코드](../../src/mediflow_datasets/domain_adaptation_experiment.py)는
`default_rng(seed).random() < 0.5`인 경우 변환하고,
[변환 함수](../../src/mediflow_datasets/domain_adaptation_experiment.py)는 같은 seed의
첫 번째 난수로 밝기 강도를 뽑는다. 같은 난수 u가 적용 여부와 강도에 두 번 쓰인다.

설정 범위가 [a, b]일 때 u < 0.5를 통과한 변환은 [a, (a+b)/2)만 사용한다.
설정 전체 범위가 학습에 쓰이지 않고 평가에서는 전체 범위를 쓰게 되는 문제다.

기존 함수를 그대로 호출해 RGB 128의 작은 float32 입력, seed 0–4095를 검사했다.
2,043개 seed가 적용 조건을 통과했으며 다음을 확인했다.

| 분야 | 설정한 범위 | 적용된 경우 관찰한 범위 |
|---|---|---|
| 얼굴 | -32.0 ~ -25.583170413970947 | -31.996620178222656 ~ -28.79259490966797 |
| 피부 | -1.3492517471313477 ~ -0.7292451858520508 | -1.3489227294921875 ~ -1.0393447875976562 |
| 두피 | -0.6363735198974609 ~ 12.4506196975708 | -0.6294784545898438 ~ 5.905059814453125 |

**재현 완료, 수정 전이다.** 적용 결정용과 강도용 난수를 분리하고, 조건부로 선택된 표본도
설정 전체 범위를 쓰는지 확인하는 검사가 필요하다. 실제 추가 학습은 하지 않아 학습 결과를
폐기할 상황은 아니다. 이 오류는 Train 통계·Colab 분석 완료 기록 자체에는 영향을 주지 않는다.

### 5.2 얼굴의 인위적 배경과 종횡비

현재 크기 변환은 얼굴을 가로·세로로 다르게 줄이고 빈 공간을 단색으로 채운다.
미리보기에서 실제 촬영 환경에 없는 테두리를 확인했다. 얼굴이 작아진다는 측정 근거와
해당 구현의 타당성은 별개이므로 현재 구도 변환을 그대로 승인하지 않는다.

Source는 1024×1024, Target은 1280×720이다. 현재 모델은 둘 다 정사각형으로 직접
크기 변경하므로 Target의 비율도 달라진다. 비율을 유지하는 공통 입력 정책을 먼저 검토해야 한다.
후보로 Target의 중앙 정사각형 영역을 사용하는 경우, 기록된 얼굴 상자 42개는 모두
자르기 안에 들어감을 계산했다. 이는 기하학적 확인이며 성능 검증이나 전처리 확정이 아니다.
최종 전처리를 바꾸면 모든 비교 모델에 같은 정책을 적용하고 기존 결과와 조건 차이를 기록한다.

### 5.3 얼굴 검출의 클래스별 편향

Source 얼굴 검출 성공은 전체 3,048/3,600장이지만 클래스별로 크게 다르다.

| 클래스 | 전체 Train | 얼굴 영역을 찾은 수 |
|---|---:|---:|
| 건선 | 720 | 362 |
| 아토피 | 720 | 603 |
| 여드름 | 720 | 676 |
| 정상 | 720 | 719 |
| 주사 | 720 | 688 |

밝기·색·얼굴 크기 통계가 클래스별로 균등하게 대표하지 못할 수 있다. 검출 실패는
무작위 누락이라고 가정할 수 없다. 실패 표본의 실제 구도, 같은 얼굴 검출 기준의 적용 여부,
클래스별 유효 영역 통계를 확인해야 한다. 크기·해상도 통계까지 무효라는 뜻은 아니다.

### 5.4 두피는 밝기 이외의 근거를 더 확인해야 함

두피의 변경/기준 대비 비율은 네 사람에서 각각
`0.8349346135268774`, `0.9838388163990097`, `0.9404178369422747`,
`0.8889063036430638`로 모두 감소했다. 반면 코드에는 두피 대비를 제외하는 조건이 있다.
따라서 “두피에는 밝기 차이만 있다”는 결론은 맞지 않는다.

다만 P02·P03 등에서는 어두운 경계량도 조건 사이에 바뀌어 모발·시야 구성 변화가 섞였다.
비슷한 두피 노출·구도에서의 대비·색·표면 경계 변화를 다시 확인하고, 근거가 확인된
변수만 묶음에 넣는다. 충분한 근거가 없으면 중복 실험군을 합치고 현재 결과의 제한된
범위를 명시한다. 수를 맞추기 위해 임의의 색·흐림을 넣지 않는다.

### 5.5 변환 후 분포 검증이 아직 부족함

현재는 클래스별 첫 Train 표본 5장 또는 10장의 미리보기다. 변환된 Train 전체 또는
고정된 클래스별 표본에서 밝기·대비·색·얼굴 크기·클리핑을 다시 측정한 자료는 없다.
몇 장의 육안 확인만으로 범위 전체가 적절하고 병변 단서가 보존된다고 보장하지 않는다.
원본 → 변환본 → Target의 분포와 클래스별 변화, 초점·구도 이상 표본을 포함한 민감도 검토가 필요하다.

## 6. 데이터 분할과 유사 사진 점검

| 분야 | 확정된 파일·픽셀·기록 ID 문제 | dHash 유사 후보 | 폴더명 차이를 제외한 경로 그룹 |
|---|---:|---:|---:|
| 얼굴 | 0 | 484쌍 | 159 |
| 피부 | 0 | 7,770쌍 | 2,556 |
| 두피 | 0 | 0쌍 | 0 |

뒤의 그룹 수는 내용 중복 판정이 아니다. dHash는 작은 흑백 패턴 검사이므로 유사한 구도·배경이
걸릴 수도 있고 모든 파생본을 찾는 것도 아니다. 원본·증강 이력 및 더 높은 해상도의 후보
사진을 확인하고 판단 근거를 남겨야 한다. 현재 검토 ZIP에는 후보 원본 전체가 없다.

사람·병변·세션 ID가 없다는 한계는 별도로 남긴다. Source의 일부 증강 원본 ID도 불완전하다.
Test를 보고 변환 강도를 고르는 대신, 여기서는 동일 사례·파생본 여부만 확인한다.

실제 누수가 확인되면 기존 자료를 보존한 새 데이터 버전을 만든다. 기존 모델이 이미 그
누수 자료를 학습했다면 Train 파일만 제외하고 이어 학습해도 기존 가중치의 이력이 사라지지
않는다. 이때는 오염되지 않은 별도 평가 자료 또는 새 기준 모델 학습이 필요할 수 있다.
현재 유사 후보 수만으로 이런 재학습이 필요하다고 확정하지는 않는다.

## 7. MMD·CORAL 및 UDA의 역할

MMD는 특징 분포의 커널 평균 임베딩 차이를, CORAL은 특징의 공분산 차이를 다루는 방법이다.
[DAN 원 논문](https://proceedings.mlr.press/v37/long15.html),
[Deep CORAL 원 논문](https://arxiv.org/abs/1607.01719)을 참고했다.
지금 코드는 거리만 계산하며 그 값을 줄이도록 최적화하는 학습은 구현·실행하지 않았다.

라벨 없는 Target으로도 UDA 학습은 가능하다.
[DANN 원 논문](https://jmlr.org/papers/v17/15-239.html)은 라벨 있는 Source와 라벨 없는 Target을
함께 사용한다. 여기서 정렬 학습을 보류한 이유는 “Target 정답이 없으면 불가능”해서가 아니다.
네 사람의 제한된 표본, 불명확한 질환 구성, Skin·Hair-5의 정상 클래스 부재 때문이다.

Source·Target의 클래스 구성이나 조건부 분포가 다르면 도메인 불변 특징만으로 성공을 보장하지
못한다는 [연구](https://proceedings.mlr.press/v97/zhao19a.html)가 있다. 이를 근거로 현재
전체 특징의 무조건 정렬에 주의한다. MediFlow에서 정렬로 성능이 실제 하락했다는 측정은 아니다.

현재 MMD²는 편향된 RBF 추정량이며 표본 수·기준 스케일·클래스 구성에 영향을 받는다.
참여자 평균 네 개로 계산한 값과 이미지 40개로 계산한 값을 단순 비교하지 않는다.
특징 거리 감소, PCA에서의 겹침, 예측 점수 상승은 정확도 개선의 증거가 아니다.

## 8. 지금 권하는 실험 설계

이번 단계의 가설은 “실제 장비에서 확인한 촬영 변환 묶음이 추가 학습만 하거나 밝기만
추가한 경우보다 촬영 변화 대응을 높이고 원래 성능을 유지하는가”이다.
묶음 전체를 실험 변수로 삼을 수 있으므로 모든 기법을 하나씩 따로 시험할 필요는 없다.
이 비교만으로 각 구성 요소의 개별 효과를 알아냈다고 주장하지 않는다.

| 비교군 | 역할 |
|---|---|
| Baseline | 현재 저장 모델 그대로. 기존 성능 기준. |
| Source-only 추가 학습 | 같은 기존 Augmented Train과 같은 횟수로 추가 학습. 단순 추가 학습 효과 분리. |
| Brightness-only | 위 조건에 실제 측정에 근거한 추가 밝기 변환만 적용. |
| Target-guided 묶음 | 위 조건에 근거가 확인된 추가 변환 묶음을 적용. 동일한 군은 합침. |
| MMD/CORAL 정렬 | Target 클래스 범위·규모·평가 조건이 갖춰질 때 별도 가설로 검토. 현재 필수 실행군 아님. |

데이터 버전·분할·클래스 순서·시작 모델·공통 전처리·기존 증강·학습 횟수·난수·선정 규칙은
고정한다. 현재 설정은 seed 42, 3 epoch, batch 16, Adam `1e-5`, 변환 적용률 0.5,
backbone 뒤 30개 층 조정과 BatchNorm 고정이다. PMG는 기존 jigsaw·fusion 절차를 유지한다.
이 값들은 초기 조건이며 최적값이나 성능 향상으로 검증되지 않았다.
현재 저장 모델의 입력은 RGB float32 0–255를 유지하고 외부 `/255`를 추가하지 않는다.

Validation에서 원본 Macro-F1 하락 0.01 이내, 클래스별 Recall 하락 0.05 이내,
변환 Macro-F1 개선 0.005 이상을 보는 초안이 코드에 있다. 이는 설계 기준이며 통계적으로
유의한 개선을 보장하는 임계값이 아니다. 조건을 고정해 실행하고 결과 후 임의로 바꾸지 않는다.
첫 실행 후 필요한 경우 같은 조건을 다른 seed로 반복해 개선이 단순 변동인지 확인한다.

## 9. 남은 작업의 우선순위와 완료 기준

| 순서 | 남은 작업 | 완료 기준 |
|---|---|---|
| 1 | 학습 전 구현 오류 수정 | 적용 여부와 강도 난수 분리, 조건부 강도 범위 검사 통과. 기존 분석·모델은 보존. |
| 2 | 유사 사진·파생본 확인 | 얼굴·피부 후보의 근거 있는 판정, 실제 누수 대응 및 모르는 ID 명시. |
| 3 | 분야별 입력·변환 확정 | 얼굴 테두리·비율·검출 편향 해결, 피부·두피의 내용 차이 분리, 두피 중복 실험 조건 정리. |
| 4 | 변환 후 분포·품질 검증 | 클래스별 고정 Train 표본에서 원본·변환·Target 지표 비교, 클리핑·병변 경계·구도 검토. |
| 5 | 재현 가능한 비교 학습 | 같은 조건으로 실험군 실행, Validation으로 저장본과 최종 후보 고정, 코드·환경·seed 기록. |
| 6 | 최종 Source 평가 | 원본 Test와 변환 복사본에서 Accuracy·Macro-F1·Recall·혼동행렬을 따로 계산. |
| 7 | 실제 사진의 전후 비교 | 같은 촬영 자료에서 예측·특징 변화 기록. 정답이 없으면 정확도 미산출. |
| 별도 | 실제 장비 질환 성능 검증 | 미사용 인물·세션의 정답 확인 Target Test를 확보해 평가. |

변환 Test는 같은 Source Test 사진의 복사본이므로 원본과 합쳐 독립 표본 두 배로 계산하지
않는다. 해당 결과는 설정한 촬영 변환에 대한 대응 성능이다. 실제 환자 촬영 성능으로 이름을
바꾸지 않는다. 기존 Source Test가 과거 평가에 사용된 이력도 유지한다.

## 10. 지금 가능한 일과 추가 자료가 필요한 일

현재 자료로 가능한 것은 코드 수정, 기존 Train의 고해상도 후보 검사, 변환 검증,
비교 학습과 합성 촬영 변화 평가다. 현재 단계에 환자 사진이 없다고 모든 학습을 멈출 필요는 없다.

추가 정보가 있으면 개선할 수 있는 부분은 촬영 거리·배율·노출·자동 보정 상태 및
같은 시야의 조명 변화다. 우선 기존 사진과 촬영 기록에서 확인하고, 꼭 필요한 변수를
분리하지 못한 경우에만 짧은 보완 촬영을 고려한다. 지금 4명의 사진을 전부 다시 찍으라는
의미가 아니다. 색·질감 차이 전체를 장비 효과로 확정할 수 없다는 한계를 유지한다.

실제 장비의 질환 정확도가 개선됐다는 결론에는 독립적인 정답 확인 촬영 자료가 필요하다.
일반 참여자 사진이나 모델의 높은 예측 점수로 질환 정답을 대신 만들지 않는다.

지금 사용자가 즉시 실행하거나 다시 업로드할 자료는 없다. 다음 Colab 작업에는 이미 Drive에
있는 Source 사진의 후보 검토와 Web Skin 진단 파일 보완이 필요하다. 후속 실행 코드를 준비한
뒤 한 번에 처리하도록 구성하는 것이 적절하다. 이 문서 작성 과정에서는 그 후속 Colab 실행,
난수 오류 수정, 새 모델 학습을 완료하지 않았다.
