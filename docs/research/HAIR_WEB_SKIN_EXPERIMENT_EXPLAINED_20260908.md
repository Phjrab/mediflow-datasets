# Hair·Web Skin 실험 해설 — 무엇을, 왜 바꿨고, 실제로 무엇이 달라졌나

기준일: 2026-09-08. 머신러닝 용어를 처음 접하는 발표자도 설명할 수 있도록 원리와 실제 결과를 연결했다. 기술의 일반적인 효과는 가능성이며, 우리 데이터에서의 효과는 별도 수치로 구분한다.

전체 진행 기록: [Hair 기존 총정리](HAIR_EXPERIMENT_SUMMARY_20260907.md), [Web Skin 최신 총정리](WEB_SKIN_FULL_SUMMARY_20260908.md). 앞으로의 실험은 [개선 계획](HAIR_WEB_SKIN_IMPROVEMENT_PLAN_20260908.md)에 따로 정리했다.

## 1. 두 모델의 목표는 다르다

| 항목 | Hair | Web Skin |
|---|---|---|
| 입력 | USB 현미경 두피 확대 | 얼굴 정면 전체 |
| 클래스 | 모낭사이홍반, 미세각질, 비듬, 탈모, 피지과다 | 건선, 아토피, 여드름, 정상, 주사 |
| 이번 학습 데이터 | Clean Train 15047장 | 기존 검사 통과 Train 7200장 |
| Validation / Test | 각각 1252장 | 500장 / 400장 |
| 현재 후보 | B1 / 256 / LS 0.05 / Stage 2 총 15 Epoch | B0 / 256 / CE / Stage 2 최고 8번째 Epoch |
| 패키징 | 완료, 후보 ZIP 보관 | 완료, 후보 ZIP과 실제 모델 로드 검증 |

Hair와 Web Skin의 절대 정확도를 비교해 어느 모델이 더 좋은 기술이라고 평가할 수 없다. 클래스, 사진, 표본 수, 과제가 서로 다르기 때문이다. 같은 모델의 같은 데이터 분할 안에서 설정을 비교해야 한다.

## 2. 용어를 먼저 정리하면

| 용어 | 쉬운 설명 | 이번 프로젝트에서의 의미 |
|---|---|---|
| Train | 모델이 연습하는 사진 | 원본과 증강본을 함께 사용 |
| Validation | 설정과 모델을 고르는 사진 | 비교 실험의 선정 기준 |
| Test | 선택을 끝낸 뒤 결과를 확인하는 사진 | 반복해서 설정을 맞추지 않아야 함 |
| Accuracy | 전체 중 맞힌 비율 | 후보 선정의 사전 기준 |
| Recall | 실제 해당 클래스 사진을 얼마나 찾아냈는가 | 놓치는 클래스 확인 |
| Precision | 그 클래스로 예측한 사진 중 실제로 맞는 비율 | 잘못 분류하는 방향 확인 |
| Macro F1 | 클래스마다 Precision·Recall의 균형을 계산한 뒤 동일 비중 평균 | 특정 클래스만 잘하는지 함께 확인 |
| Backbone | 사진의 특징을 추출하는 모델 본체 | EfficientNet-B0 또는 B1 |
| Head | 특징을 받아 최종 클래스를 고르는 분류부 | 마지막 5개 출력 부분 |
| Loss | 모델의 예측이 정답과 얼마나 어긋났는지 학습에 사용하는 벌점 | CE, Label Smoothing, Focal 비교 |
| Epoch | Train 전체를 한 번 학습하는 단위 | 기본 15회 + 미세조정 10회 |
| Learning Rate | 한 번에 가중치를 얼마나 바꾸는가 | 기본 1e-4, 미세조정 1e-5 |
| Checkpoint | 특정 학습 시점의 모델 저장본 | 마지막보다 Validation 최고 모델을 보존 |
| Seed | 초기화·무작위 처리를 재현하기 위한 시작값 | 42로 고정, 반복 Seed 실험은 미수행 |

Validation을 계속 사용하면 그 데이터에도 설정이 맞춰질 수 있다. Validation으로 선택했다는 것만으로 독립 실제 장비 검증을 대신할 수는 없다.

## 3. 데이터 검사·재구성 — 점수를 높이기 전에 믿을 수 있는 평가를 만들기

**왜 했나:** 연습한 사진이 시험에 그대로 나오면 새로운 사진을 잘 분류하는지 알기 어렵다. 같은 사진에 다른 클래스가 붙으면 학습도 혼란스러워진다.

**Hair에서 한 일:** 파일명 대신 파일 내용의 해시를 비교해 Train–Validation 195, Train–Test 178, Validation–Test 16의 겹침을 확인했다. 이 수들은 쌍별 집계이므로 단순히 더한 수가 전체 제거 이미지 수는 아니다. 기존 증강본을 새 실험에서 재사용하지 않고, 원본을 정리·재분할한 뒤 Train에서만 새 증강본을 만들었다. 기존 ZIP을 물리적으로 삭제했다는 뜻은 아니다.

**Web Skin에서 한 일:** 감사에서 파일·RGB 픽셀 중복과 라벨 충돌 등이 발견되지 않아 기존 데이터 분할을 유지했다. 학습 때는 검사한 ZIP과 같은지만 확인했다.

**무엇이 좋아졌나:** Hair에서는 완전 동일 사진을 학습과 평가가 공유하던 문제를 줄이고 증강 원본 연결 기록을 만들었다. 이것은 평가 신뢰성의 개선이다. Clean 전후의 데이터 분할이 바뀌었으므로 점수 변화 전체를 학습 기술의 향상이라고 비교하면 안 된다. 두 모델 모두 사람·병변·세션 단위의 겹침까지 해결됐다는 뜻은 아니다.

발표 문장: “성능 비교 전에 데이터 중복을 확인했고, 문제가 있던 Hair는 새 분할을 구축했으며 문제가 발견되지 않은 Web Skin은 기존 분할을 유지했습니다.”

## 4. ImageNet과 부분 미세조정 — 일반 이미지 특징을 우리 사진에 맞추기

**ImageNet 사전학습 모델과 기존 질환 모델의 차이:** EfficientNet은 구조 이름이다. 같은 B0라도 ImageNet에서 시작한 가중치와 이미 Hair/Web Skin으로 학습된 가중치는 다르다. 이번 Clean Hair 및 Web Skin 자동 실험의 새 기준선들은 ImageNet 가중치에서 시작했다.

**왜 미세조정했나:** 기존 방식은 특징 추출부를 고정한 채 마지막 분류부만 학습했다. 피부색·각질·모낭 등 우리 사진에서 필요한 구분을 본체까지 일부 조정하면 좋아질 수 있다는 가설이었다.

```text
ImageNet에서 일반 이미지 특징을 배운 EfficientNet
  → 특징 추출부를 고정하고 새 분류부만 15회 학습
  → 이 단계의 Validation 최고 모델을 불러옴
  → 후반부 30개 계층 중 BN을 제외한 부분을 낮은 학습률로 10회 조정
  → 두 단계 중 Validation 최고 모델을 보존
```

사전학습 후 분류부를 먼저 학습하고, 일부 계층을 낮은 학습률로 추가 조정하는 원리는 [Keras 전이학습·미세조정 안내](https://keras.io/guides/transfer_learning/)에 근거한다. BN은 Batch Normalization이며 이번에는 학습 중 통계가 바뀌지 않도록 고정했다.

**고정:** 데이터, 클래스 순서, Backbone, 입력 크기, Loss, Batch, Seed.

**주요 변경:** 특징 추출부 후반부를 학습 가능하게 함.

**동반 변경:** 추가 10 Epoch와 새 Adam 1e-5. 사전 특징을 과도하게 바꾸지 않으려는 설정이다. 학습 시간까지 늘어나므로 미세조정 한 요소만의 순수 효과를 분리한 실험은 아니다.

**실제 관찰:** Web Skin B0 256의 Stage 1 최고는 0.7039999961853027, Stage 2 최고는 0.7960000038146973이었다. 전체 기본 실험 5개에서 Stage 2 최고가 Stage 1 최고보다 높았다. Hair도 같은 2단계 설정으로 Clean 기준선을 구축했지만, 이 문서에서는 모든 Hair Stage 1 수치를 별도로 재계산하지 않았으므로 미세조정 단독 상승 폭을 새로 만들어 제시하지 않는다.

발표 문장: “일반 이미지에서 배운 특징을 그대로 사용하는 단계에 이어, 모델 후반부를 우리 피부·두피 영상에 맞게 조정했습니다. Web Skin에서는 이 단계의 성능 상승이 가장 뚜렷했습니다.”

## 5. 224→256 — 작은 특징을 덜 줄여서 보여주기

**왜 했나:** 같은 사진을 작게 줄이면 미세한 질감이 사라질 수 있다. 두피에서는 각질·비듬·피지 같은 특징, 얼굴에서는 작은 피부 변화가 영향을 받을 수 있어 해상도를 비교했다. 이는 검토할 가설이며 실제로 어느 영역 때문에 좋아졌는지는 따로 측정하지 않았다.

**무엇이 바뀌나:** 입력 위치 수가 224×224=50176에서 256×256=65536으로 늘어난다. 원본에 있던 정보를 덜 축소하는 실험이지, 없는 정보를 복원하는 초해상도 기술을 적용한 것은 아니다.

**고정:** B0, CE, 동일 Train/Validation/Test, Epoch, 학습률, 해제 범위, Seed, Batch.

**변경:** 입력 이미지 크기만 224→256. 메모리와 계산량은 이에 따라 달라질 수 있으므로 추후 함께 측정해야 한다.

| 대상 | 224 Validation | 256 Validation | 해석 |
|---|---:|---:|---|
| Hair | 0.7643769979476929 | 0.7699680328369141 | 기록에 대응하는 정답수 957→964/1252 |
| Web Skin | 0.794 | 0.796 | 정답 397→398/500 |

Hair의 Test 기록도 0.7763578274760383에서 0.7891373801916933으로 높아졌다. Web Skin은 224 모델의 Test를 추가 평가하지 않았다. Hair에서는 개선 방향이 관찰됐지만, Web Skin의 한 장 차이만으로 256의 우월성을 확정하지 않는다. Web Skin Macro F1은 224가 0.7917009497301795, 256이 0.7915394647566528로 224 쪽이 조금 높다.

발표 문장: “입력 해상도를 높였을 때 Hair에서 개선이 관찰됐지만 Web Skin의 차이는 작았습니다. 해상도를 높이면 무조건 좋아진다는 결론은 아닙니다.”

## 6. Label Smoothing 0.05 — 정답을 지나치게 확신하도록 학습시키지 않기

**왜 했나:** 비슷한 클래스가 많고 라벨 경계가 모호할 수 있어, 한 클래스에만 극단적으로 점수를 몰아주는 학습을 완화해 볼 목적이었다. 라벨 오류를 직접 고치는 방법은 아니다.

**원리:** 5개 클래스에서 일반 정답 벡터가 `[1,0,0,0,0]`이라면 Keras의 smoothing 0.05는 `[0.96,0.01,0.01,0.01,0.01]`처럼 바꿔 Loss를 계산한다. 정답 클래스를 다른 클래스로 바꾸는 것이 아니다. 계산 정의는 [Keras 확률적 Loss 문서](https://keras.io/api/losses/probabilistic_losses/)에 따른다.

**고정:** 256, B0, 데이터, 2단계 학습량·학습률, Seed, Batch, 증강 구성.

**변경:** CE의 label_smoothing을 0에서 0.05로 변경.

| 대상 | CE Validation | LS Validation | 결과 해석 |
|---|---:|---:|---|
| Hair | 0.7699680328369141 | 0.7739616632461548 | 정답수에 대응하면 964→969/1252 |
| Web Skin | 0.796 | 0.794 | 정답 398→397/500, 이번 실행에서는 개선 없음 |

Hair의 LS Test Accuracy는 CE보다 낮았다. 평균 최대 출력 점수가 낮아졌다는 기존 관찰도 있지만, 점수가 낮아졌다는 것과 점수가 실제 정답 가능성에 맞게 보정됐다는 것은 별개다. 점수 보정은 별도 평가가 필요하다.

발표 문장: “지나친 확신을 줄이는 Loss를 적용했지만 효과는 데이터마다 달랐습니다. Hair의 Validation은 개선됐고 Web Skin에서는 추가 이득이 관찰되지 않았습니다.”

## 7. Focal Loss — 어려운 사진의 학습 비중을 상대적으로 높이기

**왜 했나:** 이미 쉽게 맞히는 사진보다 반복적으로 헷갈리는 사진에 더 집중하면 클래스 구분이 좋아질 수 있다는 가설이었다. 이번 데이터는 대체로 균형이므로 불균형 해소만을 목적으로 한 실험은 아니다.

**원리:** 쉽게 맞히는 사진의 벌점을 더 줄이고 어려운 사진의 영향은 상대적으로 남기는 방식이다. 이번에는 gamma=1.5, alpha=1.0을 사용했다. 잘못된 라벨도 어려운 표본으로 보일 수 있으므로 라벨 문제를 자동 해결하지 않는다. [Keras Focal Loss 정의](https://keras.io/api/losses/probabilistic_losses/)를 참고했다.

**고정:** B0 256, 데이터, 학습량·학습률, Seed, Batch, 증강.

**변경:** CE→Focal. LS 실험을 이어 학습한 것이 아니라 같은 조건에서 별도로 시작했다.

| 대상 | CE Validation | Focal Validation | 해석 |
|---|---:|---:|---|
| Hair | 0.7699680328369141 | 0.7675718665122986 | 이번 Validation에서는 낮음 |
| Web Skin | 0.796 | 0.792 | 정답 398→396/500 |

Hair Focal의 Test Accuracy 0.7907348242811502와 Macro F1 0.7905122039602036은 6개 Hair 결과 중 가장 높았다. 그러나 후보 선정 지표인 Validation은 낮아서 현재 후보로 선택하지 않았다. 이 Test 결과를 근거로 계속 튜닝하지 않는다.

Focal의 Loss 값이 CE보다 낮다고 성능이 더 좋다는 뜻은 아니다. 계산식 자체가 다르므로 동일 Validation Accuracy/F1으로 비교해야 한다.

## 8. B0→B1 — 표현할 수 있는 특징의 용량을 늘려보기

**왜 했나:** 비슷한 클래스의 구분을 더 잘 표현할 수 있는지 확인하기 위해 모델 본체를 바꿨다. EfficientNet 계열은 모델 깊이·폭·해상도 등을 고려해 설계된 모델군이다. [EfficientNet 원논문](https://proceedings.mlr.press/v97/tan19a.html).

**고정:** 256 입력, LS 0.05, 분할, 분류부, 학습량·학습률, Batch, Seed.

**변경:** B0→B1. 실제 구조와 가중치 수는 함께 바뀐다. 두 모델 모두 마지막 30개 계층을 사용했어도 동일한 수의 파라미터를 조정한 것은 아니다. 이 실험은 두 모델의 입력을 256으로 맞춘 프로젝트 내 비교다.

| 대상 | B0 LS Validation | B1 LS Validation | 해석 |
|---|---:|---:|---|
| Hair | 0.7739616632461548 | 0.7763578295707703 | 정답수에 대응하면 969→972/1252 |
| Web Skin | 0.794 | 0.796 | 정답 397→398/500 |

B0 파라미터는 4055976개, B1은 6581644개다. B1에서 작은 Validation 개선은 관찰됐지만 Hair의 Test는 이 단계에서 낮아졌다. Web Skin에서는 B1이 B0 CE와 Accuracy 동점이므로 사전 동점 규칙에 따라 B0 CE를 유지했다. ‘큰 모델이 무조건 더 낫다’고 결론내리지 않는다.

## 9. 추가 5 Epoch — 아직 더 배울 여지가 있는지 확인하기

**왜 했나:** Hair B1은 기존 기록상 마지막 Epoch가 최고였고 Validation Loss도 내려가고 있어, 같은 학습을 조금 더 진행할 여지가 있는지 확인했다. Web Skin 자동 실험에는 동일한 학습량 비교 항목을 미리 포함했다.

**고정:** B1, 256, LS, 데이터, optimizer 상태, 학습률과 미세조정 범위.

**변경:** 추가 5 Epoch. 여러 설정을 한꺼번에 바꾸지 않았다.

| 대상 | 연장 전 최고 Validation | 연장 구간 자체 최고 | 최종 보존 결과 |
|---|---:|---:|---|
| Hair | 0.7763578295707703 | 0.7771565318107605 | 연장 모델 채택 |
| Web Skin | 0.7960000038146973 | 0.7900000214576721 | 부모 최고 모델 유지 |

Hair의 개선은 1252장 중 정답 1장에 해당한다. Web Skin은 추가 학습에서 최고 성능을 넘지 못했다. 두 결과 모두 같은 방식의 무제한 연장을 정당화하지 않는다.

Hair 노트북은 최고 체크포인트에서, Web Skin은 마지막 체크포인트에서 이어갔다. Hair 당시 최고가 마지막이라는 근거는 후보 ZIP의 source_training_config.json에 기록되어 있다. 이 조건을 확인하지 않고 일반적으로 두 연장 방식이 동일하다고 설명하면 안 된다. 두 방식 모두 학습 상태를 저장한 optimizer를 복원했다.

## 10. 무엇이 개선됐는지 한눈에 보기

| 실험의 목적 | Hair에서 관찰한 결과 | Web Skin에서 관찰한 결과 | 발표에서 말할 수 있는 결론 |
|---|---|---|---|
| 데이터 신뢰성 | 중복 정리와 Train-only 새 증강 | 기존 감사 통과 분할 유지 | 데이터별로 필요한 조치를 적용 |
| 도메인에 맞는 특징 조정 | Clean 2단계 학습 기준선 구축 | 모든 기본 실험에서 Stage 2 최고 상승 | Web Skin의 가장 뚜렷한 상승 구간 |
| 256 해상도 | Validation/Test 개선 방향 | Validation 한 장 증가 | 효과의 크기는 데이터별로 다름 |
| LS 0.05 | Validation 개선, Test는 감소 | 개선 없음 | 과도한 확신 완화가 정확도 향상을 보장하지 않음 |
| Focal | Test 기록은 높으나 Validation 낮음 | Validation 낮음 | 채택하지 않은 결과도 유효한 실험 성과 |
| B1 | Validation 소폭 상승, Test 감소 | B0 CE와 Accuracy 동점 | 모델 용량과 정확도는 단순 비례하지 않음 |
| 5 Epoch 추가 | Validation 한 장 증가 | 이전 최고 유지 | 더 오래 학습하는 것만으로 해결되지 않음 |

Hair의 정답수 환산은 원래 Validation Accuracy와 1252장에 대응하는 정수 개수를 설명용으로 사용했다. 원본 소수 성능을 반올림해 덮어쓴 값은 아니다. 차이의 통계적 유의성을 계산한 것도 아니다.

## 11. 해석의 한계와 올바른 비교 방법

Hair는 실험별 Test 결과를 여러 차례 확인했고 오답 감사에도 Test를 사용했다. 따라서 해당 결과는 탐색적 실험 기록으로 보존하고 이후 Test 오답에 맞춰 튜닝하지 않는다. Web Skin은 6개 Validation 후보 중 하나를 고정한 뒤 그 후보만 Test를 평가했다.

모델 선택은 당시 정한 기준대로 보존한다. 나중에 Macro F1을 더 중요하게 보고 싶다면 다음 연구의 기준으로 사전에 정하고 별도 실험으로 기록한다. 이번 Test를 본 뒤 선택 기준을 바꿔 ‘최종 최고 모델’을 다시 고르지 않는다.

Seed 한 개의 결과이므로 몇 장 차이의 재현성은 아직 확인되지 않았다. 같은 설정의 Seed를 달리한 반복 실험이나 새 독립 검증이 있어야 더 강한 주장을 할 수 있다. 실제 USB 현미경·웹캠 데이터가 없으므로 공개 데이터 점수를 실제 장비 정확도로 설명하지 않는다.

## 12. 보고서에 바로 사용할 종합 문단

> 본 연구에서는 데이터 검증 후 동일한 분할을 사용하여 부분 미세조정, 입력 해상도, Loss, Backbone 및 학습량을 단계적으로 비교하였다. Hair에서는 중복 문제로 Clean 데이터를 재구성한 뒤 256 해상도와 일부 설정에서 Validation 개선을 관찰했으며, Web Skin에서는 부분 미세조정의 상승이 가장 뚜렷했다. 이후 설정 변경의 효과는 작거나 지표별로 달랐고, 추가 학습 역시 항상 개선을 만들지 않았다. 따라서 모델의 크기나 학습 횟수를 늘리는 것보다 데이터 품질과 클래스별 오류를 함께 검토할 필요가 있음을 확인했다. 최종 후보는 사전에 정한 Validation 기준으로 선정하고 모델·전처리·평가 자료를 패키지로 보존했다.
