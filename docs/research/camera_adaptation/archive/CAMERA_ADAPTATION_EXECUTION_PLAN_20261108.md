2026-11-08 · 시험 촬영 이후 작업 순서

**먼저 웹캠 얼굴 사진에서 조명 변화가 피부 영역에도 나타나는지 확인한다.** 확인되면 그 변화를 기존 질환 학습 사진 일부에 적용하고, 같은 모델을 추가 학습해 비교한다. 현재는 [로드맵](../../../ROADMAP.md) 2단계의 초기 촬영을 마치고 3단계의 사진 특성 분석을 진행하는 중이다. 변화와 평가 조건이 정해지면 4·6단계의 추가 학습과 증강 실험으로 넘어간다. LLM·VLM은 이 작업 이후에 진행한다.

## 지금까지 확인한 것

참여자 4명의 사진 124장을 확보했다. 각 참여자의 세 분야에서 기준·변경 사진이 각각 최소 5장씩 있다. P02 피부는 사용자의 확인에 따라 앞 6장을 기준, 뒤 5장을 변경으로 분석한다. 이 정정은 `camera_capture/_review/p02_skin_s01_condition_corrections.json`에 기록했다. 추가 촬영 4장도 보관하며, 같은 사람의 반복 사진은 별도의 참여자로 세지 않는다.

| 분야 | 기준 / 변경 | 1차 확인 · 중앙부 밝기 변화(0~255) | 첫 실험에서의 위치 |
|---|---:|---|---|
| 웹캠 얼굴 `web_skin` | 22 / 20 | 네 사람 모두 변경 쪽이 `+16~+33` 밝음 | 얼굴 피부 영역에서 재확인할 첫 후보 |
| USB 현미경 피부 `skin` | 22 / 20 | 네 사람 모두 변경 쪽이 `−3~−1.5` 어두움 | 변화 폭이 작아 다른 촬영 특성도 확인 |
| USB 현미경 두피 `hair` | 20 / 20 | `−8~+26`으로 사람에 따라 방향이 다름 | 모발과 두피가 차지하는 비율을 먼저 확인 |

밝기 값은 사진별 중앙부의 밝기 중앙값을 구한 뒤, 같은 사람·분야·조건 안에서 다시 중앙값을 구해 `변경 − 기준`으로 비교한 것이다. 중앙부에는 피부 외 영역도 포함된다. `기준`과 `변경`은 촬영 때 선택한 조건이며, 사진의 밝기로 조건을 다시 붙이지 않는다. 참여자 사진은 촬영 특성을 조사하는 데 쓰고, 질환 정답은 미확인으로 유지한다. [초기 가이드라인](../CAMERA_ADAPTATION_GUIDELINE_20261108.md).

## 1. 촬영 사진 품질과 실제 변화 확인

- 전체 124장에서 초점, 잘림, 반사광으로 가려진 부분, 크게 달라진 구도를 먼저 확인한다. 비교에 쓰기 어려운 사진은 이유를 표시하고, 정상 범위 안의 추가 촬영분은 조건별 요약에 포함한다. 원본은 보관한다.
- 얼굴 사진 42장에서 이마나 볼처럼 비교할 수 있는 피부 영역을 표시한다. 같은 사람 안에서 가능한 한 동일 부위를 비교하고 눈·머리카락·배경을 피한다. 기준과 변경 각각의 밝기 중앙값과 너무 밝아 세부가 사라진 영역의 비율을 남긴다.
- 사람별 기준과 변경의 차이를 비교한다. 얼굴 피부에서도 일관된 변화가 확인되면 밝기를 첫 변수로 선택한다. 구도나 반사광 때문에 차이가 설명되거나 사람별 방향이 엇갈리면, 밝기 범위를 학습에 넣기 전에 촬영 자료를 다시 살펴본다. 특정 장비나 조명 설정이 원인이라고 단정하기 어려운 경우 관찰된 변화로 기록한다.
- 이 단계의 산출물은 **사진 품질 확인표, 사람별 밝기 변화표, 적용할 변수 한 가지와 선택 근거**다. 참여자 원본은 로컬 촬영 폴더에서 분석한다.

## 3. 밝기 변화만 넣어 추가 학습

첫 가설은 **실제 웹캠에서 관찰한 밝기 변화를 학습에 반영하면, 밝기가 변한 평가 사진의 분류 성능이 개선되고 원본 성능도 유지된다**는 것이다.

| 비교군 | 학습 조건 | 비교할 내용 |
|---|---|---|
| A · 현재 모델 | 기존 v2 저장본 그대로 | 현재 모델과의 비교 기준 |
| B · 추가 학습 | 같은 v2에서 시작해 기존 Train으로 추가 학습 | 추가 학습 자체의 효과 |
| C · 밝기 반영 | B와 동일하게 학습하며 Train 입력 일부에만 정한 밝기 변화 적용 | C와 B의 차이로 밝기 변화의 효과 확인 |

- **고정할 조건**은 시작 모델, 클래스와 순서, 데이터 버전과 분할, 사진을 뽑는 비율과 학습 횟수, 입력 크기·전처리, 모델에서 조정할 층, 학습률·손실 함수·배치 크기, 난수 설정이다. Web Skin의 네 출력 결합 방식과 RGB `float32` 0–255 입력을 유지한다. 모델 내부에 `/255`가 포함돼 있다. [모델 사용법](../../../../results/MODEL_USAGE.md).
- **바꿀 조건**은 C에서 밝기 변화를 적용하는 설정 하나다. 기존 증강에 밝기 변환이 이미 있다면 B는 기존 설정을 유지하고, C에서는 해당 밝기 범위만 바꾼다. 기존 Train의 일부에 시험 적용해 질환 특징이 가려지지 않는지 살펴본 뒤 강도와 적용 비율을 정한다. 실제 사진에서 측정한 차이를 모든 공개 이미지에 일률적으로 더하지 않는다.
- 비교군, 시작 모델과 결과 저장본, 데이터 버전·분할·클래스 순서, 코드 커밋과 미커밋 변경, 환경·난수·설정, 변환에 사용한 원본 ID와 적용 강도를 기록한다. 불가피한 동반 변경이 있다면 이유와 영향을 적는다.

## 4. Validation으로 선택하고 Test에서 최종 비교

| 평가 | 사용 방법 |
|---|---|
| 원본 Validation | 원래 사진의 성능이 유지되는지 확인한다. |
| 밝기 변화 Validation | 같은 Validation 사진의 복사본에 고정된 밝기 변환을 적용해 후보를 비교한다. |
| 원본 Test | 설정과 후보를 확정한 후 원래 성능을 최종 비교한다. |
| 밝기 변화 Test | 같은 Test 사진의 별도 복사본에 미리 확정한 변환을 적용해 최종 비교한다. |

세 모델 모두 같은 평가 이미지와 정답으로 비교한다. 주 지표는 클래스별 F1을 같은 비중으로 평균한 **Macro F1**이며, 정확도와 클래스별로 놓친 사례도 함께 확인한다. 변화 적용 Validation에서 C가 B와 A보다 개선되고 원본 Validation에서 허용 범위를 넘게 하락하지 않는지 본다. 허용 하락 폭과 최소 개선 폭은 실행 전에 적는다. 변화 범위와 모델 선택을 Validation에서 끝낸 뒤 Test를 최종 비교에 사용한다. 기존 Test가 과거에 평가된 자료라는 점도 기록한다.

원본과 밝기 적용 Test 결과는 별도 표로 보고한다. 결과가 개선되면 **실제 촬영을 참고한 밝기 변화를 적용한 공개 Test에서 성능이 개선됐다**고 표현한다. 실제 장비로 찍은 질환 사진에서의 성능은 추후 정답이 확인된 독립 자료가 있을 때 별도로 평가한다. [평가 범위와 채택 기준](../CAMERA_ADAPTATION_GUIDELINE_20261108.md).
