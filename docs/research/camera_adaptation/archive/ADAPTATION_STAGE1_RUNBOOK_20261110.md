# MediFlow 1차 카메라 적응 학습

> 2026-11-11 정리 상태: **대체된 계획·준비본, 현재 실행 지시 아님**. [현재 작업 안내](../../../README.md) · [전체 문서 대조표](../../../DOCUMENT_INDEX.md). 아래 본문은 작성 시점 기록이며, 본문·원본 JSON의 이전 경로는 정리 대조표로 추적한다.

1차는 피부·얼굴·두피에서 기본 방식과 선정 방식을 각각 조명 변화로 학습하는 여섯 실험이다.
결과는 같은 분야의 원본 Validation과 조명 변화 Validation으로 비교한다. 2차와 3차는
선택한 방식의 1차 시작 가중치에서 각각 시작한다.

## Colab 실행

1. 공통 ZIP (삭제한 이전 준비 자료)을
   Google Drive의 [내 드라이브 / mediflow_Project](https://drive.google.com/drive/folders/1JJyjQ9dvozWOim_VVNDRWk9wyrpOA9UG)
   바로 아래에 올린다.
2. 1차 노트북 (삭제한 이전 준비 자료)을
   Colab에 열고 GPU를 선택한다.
3. **모두 실행**을 누르고 Drive를 연결한다. 데이터셋은 `mediflow_Project/datasets`의 기존 ZIP을 읽는다.
4. 화면에 나온 `내 드라이브/MediFlow_adaptation_runs/<공통 ZIP 버전>/stage1`에서 결과를 확인한다.

1차는 복호화 키 없이 실행한다. `mediflow_Project`는 링크 공유 폴더이므로 공통 ZIP에는
실제 촬영 영상 배열을 AES-256-GCM으로 암호화해 담았다. 별도
[3차 복호화 키 파일](../../../../camera_capture/_review/MediFlow_Stage3_Target_Key_20261110.txt)은
개인 보관 위치에 둔다. 공유 폴더에 올리는 파일은 공통 ZIP 하나다. 같은 ZIP을 2·3차의 입력으로
사용할 수 있도록 확장 변환 설정과 암호화 영상의 형식을 포함했다. 후속 노트북은 각 단계에서 작성한다.

## 출발 모델과 비교 조건

| 분야 | 기본 | 선정 방식 | 출발점의 차이 |
|---|---|---|---|
| 피부 | B0·224·CE | B0·224·CE | 동일 ImageNet 초기화와 보존 원본으로 준비한다. 선정 방식 준비 중에만 확인된 원본의 증강 파생본을 교대로 사용한다. |
| 얼굴 | B0·256·CE | PMG+B0·256·CE | 두 방식 모두 현재 분할에서 ImageNet부터 준비한다. PMG는 기존 네 갈래 갱신을 유지한다. |
| 두피 | B0·224·CE | 기존 B1·384·Label Smoothing 0.05 | 기본 방식은 현재 Train으로 준비하고 선정 방식은 학습 ZIP 해시와 클래스가 일치하는 기존 5클래스 v2를 사용한다. |

피부·얼굴은 보수적인 제외 목록을 유지한다. 이미 학습한 모델에서 과거 평가 노출을 제거하기
어려워, 선정 모델의 기존 구조와 설정으로 출발 모델을 새로 만든다. 피부 선정 방식의 준비는
기존 증강 방식의 통제된 재구성이다. 같은 원본 수와 학습량을 유지하며, 검증된 파생본을 가진
원본만 회차별로 원본과 교대한다. 파생본이 검증·평가 자료와 유사하거나 충돌하면 제외한다.

새 출발 모델 다섯 개는 분류부 5 epoch와 후반부 3 epoch로 준비한다. 준비 결과의 원본
Validation Macro-F1로 체크포인트를 고른다. 준비량 40 epoch와 1차 조명 학습 18 epoch를
따로 표시한다. 5+3은 이전 15+10보다 짧은 이번 파일럿 준비 일정이다. 준비된 체크포인트를
`initial.keras`에 저장하고 같은 분야 두 방식 모두 보존된 **원본 Train**에 같은 조명 변화를
적용한다. 학습 중 변환 적용 확률 0.5, 조명 학습 3 epoch, seed 42, Adam 학습률 0.00001로
고정한다. 배치 크기는 피부 16, 얼굴·두피 8이다. 네 갈래 PMG의 갱신 횟수와 두피의 입력
해상도·손실 설정 차이는 모델 방식에 포함해 결과에 기록한다.

변환은 분야별 측정 조명 프로필을 사용한다. 피부는 밝기·대비, 얼굴은 밝기·대비·좌우 조명,
두피는 밝기가 달라진다. 코드가 모든 분야에 대비나 좌우 조명을 일괄 강제하지 않는다.
원본 이미지의 실제 평가 목록은 그대로 보존한다. Test 픽셀은 중복 검사에서 읽고 분류 평가에는
사용하지 않는다. 사람·병변·세션 정보가 없는 자료의 독립성 한계는 `data_audit.json`에 남긴다.

## 진행 표시와 중단 후 재실행

- 데이터 복사, 해시 확인, 중복 검사, 입력 캐시 준비, 모델 준비, 조명 학습, 검증, 저장을 표시한다.
- 각 학습 구간에서 `Epoch 1/3`과 현재 배치/전체 배치, 진행률, loss, 남은 학습 시간 추정치를
  출력한다. 각 epoch 뒤에 원본·조명 변화 Validation Macro-F1을 표시한다.
- 원본 RGB 0–255를 모델 입력 크기로 한 번 변환해 Colab 로컬 디스크에 캐시한다. 다음 배치를
  병렬로 준비하며, TensorFlow 그래프에서 학습·추론 계산을 실행한다. [TensorFlow 입력 최적화 안내](https://www.tensorflow.org/guide/data_performance)
- 매 epoch가 끝나면 검증 수치와 모델·옵티마이저 상태를 Drive에 저장한다. 같은 노트북과 ZIP으로
  다시 실행하면 저장된 마지막 완료 epoch를 복원한다. 저장 전에 중단된 epoch는 다시 수행한다.
  Colab을 재시작하면 로컬 입력 캐시는 다시 준비한다. 같은 ZIP의 학습은 한 Colab 세션씩 실행한다.
- 기존 Colab 기본 패키지와 버전이 맞지 않을 때는 별도 환경을 사용한다. 전체 데이터에서의
  GPU 속도와 메모리는 실제 실행 시 기록할 예정이다.

## 결과 파일

| 파일 | 내용 |
|---|---|
| `validation_comparison.csv` | 분야·모델별 원본/조명 Validation Accuracy와 Macro-F1, 최고 epoch |
| `selection.json` | 분야별 선택 방식과 `initial.keras`·1차 최고 모델의 경로 및 해시 |
| `<분야>/<모델>/lighting/history.json` | epoch별 손실, 두 검증 조건의 클래스별 지표, 혼동행렬, 학습·검증 시간 |
| `<분야>/data_audit.json`, `source_manifest.json` | 사용한 데이터와 중복·분할 점검 |
| `*.log`, `summary.json` | 실행 진행, 오류, 완료 여부 |

모델 선택 점수는 두 Validation Macro-F1 중 낮은 값이다. 동점은 원본 Validation Macro-F1,
그 점수도 같으면 기본 방식을 우선한다. 2차는 선택한 `initial.keras`에서 조명과 색·미세 질감·초점
변화를 함께 적용하고, 3차는 같은 출발점과 변환에서 MMD·CORAL 결합 손실을 추가한다.
정답이 없는 촬영 사진의 실제 장비 정확도는 후속 학습 결과에서도 산출할 수 없다.

## 준비 확인

Ruff 검사와 자동 테스트 173개를 통과했다. 그래프 관련 선택 검사 3개는 matplotlib이 없어
건너뛰었다. 최종 ZIP의 파일 해시, Colab 코드 문법, 실시간 로그 전달을 확인했다. 로컬에서
B0·224, PMG·256, 저장된 B1·384에 실제 입력 크기의 합성 배치를 넣어 가중치 갱신과 검증
출력을 확인했다. 중단 후 다음 epoch 복원은 작은 시험 모델로 확인했다. 실제 데이터 전체의
1차 학습과 GPU 소요 시간 측정은 사용자 Colab 실행에서 진행한다.
