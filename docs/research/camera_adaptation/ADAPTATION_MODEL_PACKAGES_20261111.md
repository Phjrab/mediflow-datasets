# 적응 후속 후보의 독립 사용 패키징 · 2026-11-11

## 현재 단계와 범위

1~4차 학습과 51개 Source Test 비교를 마친 뒤 사용자의 요청으로 패키징했다.
로드맵의 결과 정리·사용 계약 준비이며 10단계 공통 시스템 통합과 구분한다.
Validation에서 정한 피부 4차·얼굴 4차·두피 2차를 사용했다.
기존 공식 후보 색인과 원본 모델·결과는 보존했다.

## 파일과 입력·출력 계약

| 분야 | 모델 | 입력 처리 | 출력 계약 | 정상 클래스 |
| --- | --- | --- | --- | --- |
| skin | 4차 EfficientNet-B0 · 224 | 전체 RGB 리사이즈 | 10개 softmax 점수 | 없음 |
| web_skin | 4차 PMG · B0 · 256 | 중앙 정사각형 자르기 후 RGB 리사이즈 | 네 logit 합산 후 softmax, 5개 | 포함 |
| hair | 2차 EfficientNet-B1 · 384 · LS 0.05 | 전체 RGB 리사이즈 | 5개 softmax 점수 | 없음 |

클래스 순서는 원본 학습 결과와 고정 Test 계획에서 대조해 그대로 저장했다.
실제 순서는 각 ZIP의 `class_names.json`과 `model_card.json`, 공통 패키지 색인을 기준으로 한다.
피부와 두피는 정상 사진에도 질환 클래스 중 하나를 출력할 수 있다.
두피 패키지는 5클래스이며 별도 양호 포함 6클래스와 호환하지 않는다.

공통 입력은 RGB float32 0~255이고 모델 내부 Rescaling(1/255)을 사용한다.
외부 정규화를 추가하지 않는다. TensorFlow bilinear, antialias=False이며
고정 Test와 같이 EXIF 회전을 자동 적용하지 않는다.
PMG의 네 출력을 확률로 각각 바꿔 평균내는 방식을 사용하지 않는다.
학습용 카메라 변환은 모델 학습에 쓰인 것이며 실제 입력에 다시 적용하지 않는다.

단독 CLI는 `--image`를 받고 분야·모델 버전·모델 해시·예측 인덱스·클래스 이름·클래스별 점수의 JSON을 출력한다.
파이썬 사용 예시는 모델을 한 번 불러와 여러 장을 처리한다.
파일 없음·해독 실패·파일 해시 불일치·모델 구조 및 출력 불일치는 오류 종료로 처리한다.
입력 분야·부위·사진 품질·범위 밖 질환의 자동 판정이나 검증된 거절 임계값은 구현하지 않았다.
출력에 범위 확인 미실시와 정답 확률로 보정되지 않은 점수임을 명시했다.

## 포함한 평가와 출처

모델마다 원본 `.keras`, 학습 완료 기록, 실행 설정, 5 epoch 이력, Validation 선정 기록,
고정 Test 계획과 해당 분야 원본 Test JSON을 묶었다.
원본 보고서에 기록된 과거 경로는 출처 자료이며 패키지 실행 경로로 사용하지 않는다.
패키지의 실제 모델·메타데이터는 폴더 내부 상대 경로로 읽는다.

피부·얼굴은 `camera_adaptation_stage4_test_20261111`의 `stage4_revised` 5조건을 사용했다.
두피는 `camera_adaptation_final_test_20261110`의 `stage2_expanded` 3조건을 사용했다.
모델 SHA-256·평가 계획 해시·클래스 순서·Test 장수·실험 이름이 일치해야 기록을 채택한다.
두피 4차의 결과를 두피 2차 지표로 사용하지 않는다.
새 4차 조명·확장 조건의 두피 2차 점수는 미측정으로 명시했다.

Validation의 `expanded`는 4차 강도, Test의 `expanded`는 기존 2차 강도이므로
모델 설명에 조건별 의미를 따로 기록했다.
원본 지표의 수치를 다시 계산하거나 반올림해 덮어쓰지 않았다.
각 패키지 README의 표와 모델 설명에 저장된 Accuracy·Macro-F1을 그대로 담았다.
클래스별 Recall·혼동행렬은 원본 Test JSON에 보존돼 있다.

후보는 4차 학습의 공통 Validation에서 기본·2차·4차 중 고정한 것이다.
새 4차 조건에서 모든 다섯 모델을 비교해 다시 고른 것은 아니며 Test로 재선정하지 않았다.
Source Test는 이미 확인한 공개 데이터 평가이고 과거 체크포인트의 독립성·사람/병변/촬영 세션 분리는 완전히 확인되지 않았다.
4명의 124장은 질환 정답 없는 촬영 조사 자료이므로 실제 장비 질환 Accuracy는 만들지 않았다.

## 실행 확인

합성 RGB 가로 PNG와 세로 JPEG 두 장을 사용했다. 실제 질환 사진의 새 성능 평가가 아니다.
모든 분야에서 다음을 확인했다.

1. 원본 모델·학습 기록·클래스·입력 정책·고정 Test 계획을 대조했다.
2. 실제 저장 모델을 `compile=False, safe_mode=True`로 불러왔다.
3. 기존 평가 코드와 패키지 코드의 전처리 배열이 정확히 같았다.
4. 예측 클래스가 같고 점수는 절대 오차 1e-6·상대 오차 1e-5 허용 범위 안이었다.
5. 만든 ZIP을 실제로 풀어 모든 포함 파일의 해시와 CRC를 확인했다.
6. 프로젝트 모듈 없이 압축 해제본의 CLI와 사용 예시를 별도 프로세스로 실행했다.
7. 원본 모델·결과·고정 설정/분할 자료 23개와 기존 공식 후보 색인이 그대로임을 확인했다.

검사 환경은 Python 3.12.14·TensorFlow 2.20.0·Keras 3.13.2·NumPy 2.5.2, Windows CPU다.
별도 프로세스는 기존 가상환경의 라이브러리를 사용했으며 새 환경 설치나 실제 배포 장비 실행은 미검증이다.
클래스 순서 변경·손상된 모델·경로 이탈·두피 체크포인트/지표 혼동을 차단하는 자동 검사도 추가했다.
`ruff check src tests`는 통과했고 전체 `pytest`는 216개 통과·3개 건너뜀이다.
건너뛴 3개는 기본 환경에 없는 선택 라이브러리 matplotlib를 요구하는 기존 그래프 검사다.
패키징 전용 16개는 모두 통과했다. 상세 결과는 패키지 폴더의 `validation_results.json`을 따른다.
