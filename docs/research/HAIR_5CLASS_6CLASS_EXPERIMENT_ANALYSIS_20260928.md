# Hair 5클래스 v1·v2와 새 6클래스 실험 종합 분석

작성일: 2026-09-28  
대상: USB 현미경 두피 사진 분류의 **공개 데이터 연구 후보**. 실제 장비 사진 성능이나 의료 진단 성능을 뜻하지 않는다.

## 1. 먼저 구분할 버전 이름

이 프로젝트에는 서로 다른 두 버전 축이 있다. 기존 [`results/hair/selected_models/v1`](../../results/hair/selected_models/v1/MODEL_INFO.md)과 [`v2`](../../results/hair/selected_models/v2/MODEL_INFO.md)는 **5클래스 모델의 v1·v2**다. 이번 `public_candidate_6class_v1_...`의 v1은 **새 6클래스 후보의 첫 버전**이다. 따라서 새 6클래스 모델을 기존 5클래스 v2의 가중치를 이어 학습한 v3으로 설명하면 틀린다. 두 패키지 모두 ImageNet 사전학습 가중치에서 새 6클래스 출력층을 학습한 별도 모델이다.

| 구분 | 역할 | 현재 보존 상태 |
|---|---|---|
| 5클래스 v1 | 논문 기반 강화 이전에 선정한 B1·256 | 과거 선정 모델로 보존 |
| 5클래스 v2 | 이후 선정한 B1·384 | 기존 5클래스 통합 기준으로 보존 |
| 6클래스 성능 우선 v1 | 새 데이터에서 Validation 1위인 B1·384·원본 | 패키징 완료, 실제 장비 평가 전 |
| 6클래스 경량 대안 v1 | 같은 데이터에서 두 B0 중 Validation 우위인 B0·256·증강 | 별도 패키징 완료, 실제 장비 비용 측정 전 |

5클래스의 `CURRENT_VERSION.txt`는 여전히 5클래스 v2를 가리킨다. 새 6클래스 두 패키지는 별도 후보이며, 시스템 통합 버전을 자동으로 바꾸지 않았다.

## 2. 왜 6클래스를 만들었나: 데이터와 출력의 변화

기존 5클래스는 `모낭사이홍반·미세각질·비듬·탈모·피지과다` 중 하나를 출력한다. 새 데이터는 여기에 **`양호`**를 6번 인덱스가 아닌 **인덱스 5**로 추가한다. `양호` 사진에 대해서도 기존 모델은 다섯 질환 중 하나를 골라야 했지만, 새 모델에는 해당 데이터 범위 안에서 별도의 출력 선택지가 생겼다. 이 목적은 여섯 증상 값이 모두 0인 두피 사진을 기존 질환 사진과 구분해 보는 것이다. `양호` 출력이 모든 두피 질환의 부재를 증명하는 것은 아니다.

5클래스 Clean v1은 과거 분할 사이 완전 동일 이미지와 라벨 충돌을 찾아 원본을 다시 구성한 **12,536장**이다. Train 원본 10,032장, Validation 1,252장, Test 1,252장이다. Train 전용 증강본 5,015장을 합친 학습 선택지는 15,047장이다. [5클래스 데이터 재구성 기록](HAIR_EXPERIMENT_SUMMARY_20260907.md).

6클래스 Clean v2에서는 이 12,536장의 **분할을 그대로 유지**하고, 사용자가 여섯 증상 값을 모두 0이라고 확인한 새 `양호` JPG **534장**을 추가했다. 업로드 ZIP에서 확인된 파일명 기준 ID 105개를 묶어 `양호`를 Train 428장, Validation 53장, Test 53장으로 나눴다. 최종 원본 수는 **13,070장**이며, 분할별로 Train 10,460장·Validation 1,305장·Test 1,305장이다. 6클래스 증강 조건에는 Train에만 **7,155장**을 더해 총 **17,615장**을 사용한다. 이 7,155장 중 `양호` 파생 이미지는 **2,140장**이다. 원본 428장이 새 사람 2,140명으로 늘어난 것은 아니다. Validation과 Test는 모두 원본 사진만 사용했다. [6클래스 실험 계획](HAIR_SIX_CLASS_FOUR_EXPERIMENTS_PLAN_20260928.md), [실행 결과](HAIR_SIX_CLASS_FOUR_RESULTS_20260928.md).

| 데이터 버전 | 클래스 | Train 원본 | Train 증강 조건 | Validation 원본 | Test 원본 |
|---|---:|---:|---:|---:|---:|
| Hair Clean v1 | 5 | 10,032 | 15,047 | 1,252 | 1,252 |
| Hair Clean v2 | 6 | 10,460 | 17,615 | 1,305 | 1,305 |

두 원천 ZIP 사이의 **바이트 및 RGB 픽셀 완전 중복은 0건**이었다. 하지만 유사 이미지가 전혀 없다는 뜻은 아니다. 새 `양호`의 파일별 원천 JSON은 제공되지 않아 여섯 값 0이라는 라벨은 사용자 확인에 근거한다. 기존 다섯 질환의 파일명에서 사람·촬영 세션 ID가 복원되지 않아 그 단위의 분할 간 겹침은 확인되지 않았다. [교차 감사 기록](HAIR_GOOD_CROSS_AUDIT_REVIEW_20260928.md).

재현용 데이터 SHA-256은 5클래스 Clean v1 ZIP `2ac7260663cf69835ba50edb6ae8c7e7ac13be9c73b9f7ea24f60e0342e7e156`, 새 `양호` 원천 ZIP `d602fdaf3ff3b4dbe288603dd1684316f468702ace751dde1c5e1a3e3215b86f`, 최종 6클래스 `hair_clean_v2_6class_d6ac77b7d507.zip` `e2a6b4347d94bd7050d17bd3aca404161693083b12afb51d7e20aa9b284f0f93`이다. 최종 ZIP은 Drive의 `mediflow_Project/datasets`에 있다.

## 3. 5클래스 v1·v2는 어떻게 달랐나

둘 다 정제한 같은 5클래스 데이터와 **Train 원본+증강**을 사용한 ImageNet EfficientNet-B1이다. v1은 **256×256**, v2는 **384×384** 입력을 썼다. 두 모델 모두 Label Smoothing 0.05, head-only 15 epoch 이후 후반부 부분 미세조정 총 15 epoch 조건이다. v1의 마지막 5 epoch는 Stage 2의 마지막 Validation이 계속 좋아져 같은 모델의 학습을 연장한 결과다. v2는 별도 논문 기반 선별에서 384 입력을 포함한 후보들을 비교하고 Validation으로 선택했다. 따라서 v1→v2는 같은 5클래스 과제의 성능 이력으로 읽을 수 있지만, 두 모델의 모든 학습 경로가 해상도 한 변수만 다른 엄격한 인과 실험은 아니다. [v1 원본 설정](../../results/hair/candidates/public_candidate_v1_b1_256_ls005_20260907_120834/source_training_config.json), [v2 선정 기록](HAIR_FINAL_CANDIDATE_V2_20260921.md).

| 5클래스 선정 모델 | Backbone·입력 | Train | Validation Accuracy | Test Accuracy | Test Macro F1 | Test 수 |
|---|---|---|---:|---:|---:|---:|
| v1 | B1·256·LS 0.05 | 원본+증강 | 0.7771565318107605 | 0.7883386581469649 | 0.7885764577048346 | 1,252 |
| v2 | B1·384·LS 0.05·Adam | 원본+증강 | 0.7963258785942492 | 0.8003194888178914 | 0.8002222282821301 | 1,252 |

같은 5클래스 Test에서 v2가 v1보다 Accuracy **1.20%p**, Macro F1 **1.16%p** 높았다(표시용 소수 둘째 자리 반올림). 둘 다 5개 질환을 분류하며 새 6클래스 `양호` 라벨에 대한 평가는 포함하지 않는다.

## 4. 이번 6클래스 네 실험: 무엇을 고정하고 바꿨나

네 실험은 **같은 6클래스 데이터 버전·원본 분할·클래스 순서·seed 42·batch 32·ImageNet 사전학습·head-only 15 epoch + 후반 30개 층 미세조정 15 epoch**를 공통으로 썼다. 각 모델은 별도 초기 모델에서 시작했고 기존 5클래스 v1·v2를 불러와 이어 학습하지 않았다. 실험별 최고 체크포인트는 Validation Accuracy로 저장하고, 네 후보의 전체 1위는 Validation Macro F1(동률이면 Accuracy)로 고정했다.

| 실험 | 모델·입력 | Loss | Train | Validation Accuracy | Validation Macro F1 | 양호 Recall | 기록된 학습 시간 |
|---|---|---|---|---:|---:|---:|---:|
| 1 | B0·256 | CE | 원본 10,460장 | 0.7693486590038314 | 0.7729052037575177 | 0.8867924528301887 | 481.559초 |
| 2 | B0·256 | CE | 원본+증강 17,615장 | 0.7777777777777778 | 0.7819142733310591 | 0.8867924528301887 | 652.910초 |
| 3 | B1·384 | LS 0.05 | 원본 10,460장 | **0.7992337164750958** | **0.8144942091318823** | **0.9433962264150944** | 1153.481초 |
| 4 | B1·384 | LS 0.05 | 원본+증강 17,615장 | 0.7931034482758621 | 0.8019837806385383 | 0.9056603773584906 | 1683.803초 |

같은 B0 조건에서는 증강이 Validation Macro F1을 약 **0.90%p** 올렸고, 같은 B1 조건에서는 원본이 증강보다 약 **1.25%p** 높았다. 이는 이 실행의 관찰값이지 “증강은 B1에 해롭다”는 보편적 결론이 아니다. 증강 조건에서는 사진 수뿐 아니라 그 수로 계산한 클래스 가중치도 달라진다. B0와 B1을 비교할 때는 **Backbone·해상도·Loss가 동시에** 달라지므로 B1 구조만의 효과를 계산할 수 없다. 과거 v1과 조건이 가장 비슷한 새 6클래스 **B1·256·LS 0.05·증강**은 아직 학습하지 않았다.

표의 시간은 이 Colab 학습 실행에서 기록한 **학습 시간**이다. 배포 장비에서 사진 한 장을 분류하는 지연 시간과 혼동하지 않는다.

## 5. 패키징한 두 6클래스 후보

Validation 1위 `b1_384_original`의 `stage2_best.keras`를 **성능 우선 후보**로 Test 평가·패키징했다. 두 B0 중 Validation Macro F1이 더 높은 `b0_256_augmented`의 이미 학습된 체크포인트도 **실행 비용 비교용 경량 대안**으로 고정한 뒤 별도로 Test 평가·패키징했다. 두 평가 CSV의 **같은 Test 1,305장과 동일한 정답 라벨**을 확인했다. 두 ZIP은 무결성·파일 manifest·모델 SHA-256 검사를 통과했다. 이 두 후보는 서로 다른 배포 목적을 가진다. [패키지 대조 및 해시](HAIR_SIX_CLASS_LIGHT_HEAVY_COMPARISON_20260928.md).

Drive `mediflow_Project/2_results/hair/selected_models`의 성능 우선 ZIP은 `public_candidate_6class_v1_b1_384_original_20260928_024655.zip`, 경량 대안 ZIP은 `public_candidate_6class_light_b0_256_augmented_v1.zip`이다. 선정 모델 SHA-256은 각각 `5ee54f51e65d8656fc81e88de96ad82a6d119991aa74684f921e4cd7e8b7efbb`, `38e91fee1c514b75165d07f5dfbb0c52fdb7ac92313b40d47abb50c71367d432`이다.

두 후보 패키지의 로컬 사본도 `results/hair/candidates/`에 보존했다: [6클래스 B1·384 성능 우선 ZIP](../../results/hair/candidates/public_candidate_6class_v1_b1_384_original_20260928_024655.zip), [6클래스 B0·256 경량 ZIP](../../results/hair/candidates/public_candidate_6class_light_b0_256_augmented_v1.zip). 다운로드 폴더 원본과 각 ZIP의 SHA-256이 일치함을 확인했다. ZIP 자체의 SHA-256은 순서대로 `fc138d4615442605c1b6b8333a01cd70e5c07100401fee5d468fa938455b7293`, `a83be0946a929285f12431d50692e890f2913d4a539dd6142a95396f43505b23`이다. 위 문장의 *모델 SHA-256*은 ZIP 안의 `.keras` 파일을 가리키므로 ZIP 자체의 해시와 다르다.

| 6클래스 후보 | Test Accuracy | Test Macro F1 | 양호 F1 | 저장 모델 크기 |
|---|---:|---:|---:|---:|
| 경량 대안 B0·256·증강·CE | 0.7869731800766283 | 0.8021613486071133 | 0.9074074074074073 | 29,005,042 bytes |
| 성능 우선 B1·384·원본·LS 0.05 | **0.7915708812260537** | **0.8091500773460419** | **0.9245283018867925** | 47,234,592 bytes |

성능 우선 B1의 Test Accuracy는 B0보다 **0.46%p**, Macro F1은 **0.70%p** 높다. B0의 저장 모델 파일은 약 **38.6% 작고**, 입력 픽셀 수는 약 **55.6% 적다**. 이것은 실제 추론 지연 시간·최대 메모리·전력 소비의 측정값이 아니다. 두 모델 모두 `양호` Test **53장 중 49장**을 맞혔다. 반면 질환 사진을 `양호`로 예측한 건 B1 **4장**, B0 **6장**이다. `양호` Recall은 두 모델 모두 49/53이지만, 질환을 양호로 잘못 판단한 건수 때문에 B0의 양호 Precision/F1이 더 낮다.

## 6. 5클래스와 6클래스 성능을 어떻게 읽어야 하나

**전체 점수끼리 직접 향상률을 계산하지 않는다.** 5클래스 Test는 기존 질환 1,252장이고, 6클래스 Test는 그 사진에 `양호` 53장을 더한 1,305장이다. 출력 선택지도 5개에서 6개로 바뀌었다. 예를 들어 5클래스 v2 Macro F1 `0.800222...`와 6클래스 성능 우선 후보 `0.809150...`의 숫자 차이를 “클래스 추가로 성능이 개선됐다”라고 주장할 수 없다. 특히 `양호` 53장의 F1이 Macro F1 평균에 새로 들어간다.

더 직접적인 **기술적 점검**으로, 저장된 예측 CSV에서 동일한 옛 다섯 질환 Test 사진 **1,252장**만 골라 다시 계산했다. 세 패키지의 해당 사진 경로와 정답 집합이 일치한다. 6클래스 모델이 이 사진을 `양호`로 예측한 경우는 오답으로 계산하고, 다섯 질환에 대한 클래스별 F1만 평균했다. v1은 개별 예측 CSV 대신 보존된 분류 보고서의 전체 지표를 사용했다.

| 모델 | 기존 다섯 질환 1,252장 정답 | 해당 부분 Accuracy | 다섯 질환 Macro F1 | 질환→양호 예측 |
|---|---:|---:|---:|---:|
| 5클래스 v1 B1·256 | 987 | 0.7883386581469649 | 0.7885764577048346 | 해당 없음 |
| 5클래스 v2 B1·384 | 1,002 | 0.8003194888178914 | 0.8002222282821301 | 해당 없음 |
| 6클래스 성능 우선 B1·384 | 984 | 0.7859424920127795 | 0.78732934553366 | 4 |
| 6클래스 경량 대안 B0·256 | 978 | 0.7811501597444089 | 0.7823519039568939 | 6 |

따라서 이 **기존 질환 부분 집합**에서는 5클래스 v2가 두 6클래스 후보보다 정확도가 높았다. 그러나 6클래스 B1은 5클래스 v2와 비교해 `양호` 클래스뿐 아니라 **원본만 사용한 Train, 새 분할의 전체 구성, 새 출력층, 별도 학습 실행**이 다르다. 이 차이만으로 `양호` 클래스 추가가 질환 성능 저하의 원인이라고 결론낼 수 없다. 6클래스 B0는 Backbone·입력 크기·Loss도 다르다. 위 수치는 고정된 Test 결과를 **사후에 설명하는 분석**이지 Test를 다시 사용해 모델 설정을 고른 기록이 아니다.

기존 다섯 질환 부분 집합의 클래스별 F1을 보면 어느 부분이 변했는지 더 구체적으로 볼 수 있다. 6클래스 수치는 `양호` 53장을 제외하고 산출했다.

## 7. 발표·보고서에서 사용할 수 있는 핵심 설명

> 기존 Hair 5클래스 v1·v2는 분할 중복을 정리한 같은 데이터에서 모델 구조와 입력 해상도, 학습법을 개선하며 선정한 후보입니다. 이후 여섯 증상 값이 모두 0인 `양호` 사진 534장을 별도로 확보해 기존 다섯 질환의 분할을 유지한 6클래스 데이터셋을 만들었습니다. 동일 6클래스 데이터에서 B0·256과 B1·384의 원본·증강 조건 네 가지를 평가했고, Validation Macro F1로 B1·384 원본을 성능 우선 후보로 선택했습니다. B0·256 증강 모델은 저장 크기가 작은 비교 후보로 별도 패키징했습니다. 두 모델의 6클래스 Test Macro F1은 각각 0.8092와 0.8022입니다. 이 수치는 공개 데이터 평가이며, 실제 장비 지연 시간과 환자 사진 성능은 아직 검증하지 않았습니다.

## 8. 남은 검증과 재현 자료

1. **모델 사용 구분:** 5클래스 v1/v2와 6클래스 두 패키지의 클래스 순서·입력 크기를 섞지 않는다. RGB float32 픽셀 0–255를 넣고 외부 `/255`를 적용하지 않는다. 패키지별 `preprocessing.json`을 따른다.
2. **실제 장비 비용:** 동일 장비, 배치 1, 워밍업·반복 횟수·전처리 포함 범위를 고정해 지연 시간, 메모리, 처리량을 측정한다. 저장 모델 크기만으로 경량 후보가 실제로 빠르다고 확정하지 않는다.
3. **추가 학습 가설:** 과거 v1 방식과 가장 가까운 6클래스 B1·256·LS 0.05·증강 실험은 아직 없다. 실시한다면 같은 6클래스 분할에서 Validation으로 비교하고, 이미 확인한 Test에 맞춰 조건을 고르지 않는다.
4. **데이터 한계:** 새 `양호` 사진의 파일별 JSON 라벨, 기존 질환 사진과의 사람·세션 교차 ID, 유사 사진 수준 중복은 확인되지 않았다. 실제 USB 현미경 환자 사진에 대한 외부 검증도 남았다.
