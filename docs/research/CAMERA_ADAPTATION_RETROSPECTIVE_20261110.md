## 1. 실제 장비 데이터 수집

웹캠 얼굴 피부, USB 현미경 피부, USB 현미경 두피를 별도 과제로 관리했다. Windows 촬영 도구의 미리보기에서 장치와 해상도를 확인했다. DirectShow에서 당시 웹캠은 3번, 현미경은 2번으로 잡혔다. 장치 번호는 연결 상태에 따라 달라질 수 있으므로 장비 이름과 영상으로 구분했다.

| 과제 | 장비와 부위 | 저장 해상도 | 분석 기준 조건 / 변경 조건 | 실제 장수 |
|---|---|---|---:|---:|
| 피부 `skin` | USB 2.0 Camera 현미경, 팔 피부 | 640×480 | 22 / 20 | 42 |
| 얼굴 `web_skin` | HD Pro Webcam C920, 정면 얼굴 | 1280×720 | 22 / 20 | 42 |
| 두피 `hair` | USB 2.0 Camera 현미경, 머리 중앙 | 640×480 | 20 / 20 | 40 |
| 합계 | 참여자 P01~P04, 촬영 세션 S01 |  | 64 / 60 | **124** |

- 계획은 **4명 × 3분야 × 10장 = 120장**이었다. 사람마다 각 분야에서 기준 조명 5장과 변경 조명 5장을 찍었다. 피부와 얼굴에서는 각각 두 장이 더 수집됐다. 같은 사람의 여러 장을 사람 수로 세지 않았고, 사진 번호를 강제로 1대1로 맞추기보다 참여자·조건별 요약을 사용했다.
- 사진과 개별 촬영 기록은 프로젝트 내부 `camera_capture/<분야>/<참여자>/<세션>`에 PNG와 JSON으로 보관했다. 원본 기록에서 기준으로 잘못 찍힌 P02 피부의 마지막 5장은 분석 목록에서 변경 조건으로 바로잡았다. 피부의 원본 조건 기록은 27/15, 정정 반영 분석 목록은 22/20이다. 원본 사진과 원본 기록을 보존했다.
- 조명 단계·거리·배율·카메라 조작값을 입력할 칸은 준비했지만, 이번 원본 촬영 기록의 해당 메모는 비어 있었다. 기준/변경은 촬영 당시 조건을 뜻하며 언제나 변경 쪽이 더 밝다는 의미로 사용하지 않았다. 방향과 강도는 실제 픽셀을 다시 측정해 판단했다.
- 124장을 열어 실제 해상도, 프레임 잘림, 흐림, 밝은 영역, 구도를 확인했다. 픽셀이 완전히 같은 촬영본은 없었다. 얼굴은 양쪽 볼 영역을 모두 확인했고, 피부·두피는 일부 프레임에 초점이나 국소 밝은 영역의 차이가 있었다.
- 촬영 자료는 질환 정답이 없는 `calibration`으로 기록했다. 실제 촬영본에 정상·질환 라벨을 붙이지 않았다. 1·2차에서는 영상 변화 범위를 정하는 자료로, 3차에서는 비라벨 정렬 입력 및 특징 진단에도 사용했다.

## 2. 기존 사진과 실제 장비 사진의 차이 분석

### 예시 사진으로 먼저 확인한 것

`data_examples`의 개별 사진 20장과 실제 촬영 124장을 비교했다. 개별 예시는 얼굴 5장, 피부 10장, 두피 5장이었다. 화면에 사진 목록을 표시한 스크린샷은 구성 확인에만 썼다.

- **얼굴**은 기존 예시보다 실제 웹캠 프레임에 얼굴이 작고 배경이 넓었다. 얼굴 검출이 성공한 예시 4장의 얼굴 너비 비율 중앙값은 74.3%, 실제 42장은 27.2%였다. 16:9 영상을 그대로 정사각형으로 줄이는 경우 가로 비율이 눌려, 최종 적응 입력에는 중앙 정사각형 자르기를 사용했다. 중앙 자르기 이후에도 화면 내 얼굴 크기 차이는 남는다.
- **피부**는 기존의 병변 중심 확대 사진과 실제 팔 피부의 촬영 내용이 달랐다. 실제 팔 사진의 피부 무늬와 털, 상대적으로 노란 색감이 관찰됐다. 같은 병변을 두 장비로 찍은 비교가 없으므로 이 색이나 밝기 차이 전부를 장비 변화로 해석할 수 없다.
- **두피**는 예시와 실제 해상도가 같았고, 모발 배치·가림, 두피 노출 범위, 초점, 국소적으로 밝은 부분이 달랐다. 이후 전체 Train에서는 미세 경계량과 어두운 경계 비율이 실제 촬영본과 겹쳤다.

### Colab에서 원본 Train 전체를 분석한 것

기존 공개 질환 데이터를 Source, 실제 장비의 촬영 자료를 Target으로 구분했다. 피부와 얼굴의 Source는 각각 AI Hub 피부종양 이미지 합성 데이터와 안면부 피부질환 이미지 합성 데이터에서 구성했다. 두피는 기존 5클래스용 현미경 데이터의 원본 분할을 사용했다. 데이터 구성 이력은 [프로젝트 배경](PROJECT_BACKGROUND.md)에 있다.

분포를 처음 계산할 때 사용한 원본 Train은 **피부 7,249장, 얼굴 3,600장, 두피 10,032장**이었다. 얼굴 양쪽 볼과 현미경 이미지 중앙 영역에서 밝기·대비·Lab 색 성분·미세 경계량·좌우 조명 차이 등을 계산했다. 분위수·분산과 분포 그림을 남겼고, 얼굴 검출 영역의 크기·위치와 해상도도 별도로 봤다.

| 비교 항목 | Source Train 중앙값 | Target 참여자·조건 그룹 중앙값의 범위 |
|---|---:|---:|
| 얼굴 볼 밝기 | 170.89 | 82.14–138.75 |
| 얼굴 너비 / 화면 너비 | 0.74 | 0.22–0.30 |
| 피부 중앙 밝기 | 88.32 | 151.87–157.68 |
| 피부 중앙 대비 | 65.43 | 19.08–26.49 |
| 두피 중앙 밝기 | 158.91 | 161.75–188.35 |
| 두피 중앙 대비 | 63.77 | 145.20–189.65 |

표는 당시 전체 Train 검토 보고서에 표시된 영상 통계를 그대로 옮겼다. 얼굴의 볼 밝기는 Source 얼굴 검출에 성공한 3,048/3,600장 기준이다. 별도로 **같은 참여자 안의 기준과 변경 조건**을 비교했을 때, 얼굴은 네 사람의 양쪽 볼 밝기 중앙값이 모두 증가했고 차이는 `+10.5~+38`이었다. 얼굴은 Source 전체보다 어두웠지만 같은 참여자의 변경 사진은 더 밝을 수 있다. 최종 조명 범위는 전체 평균을 맞추기보다 같은 참여자의 조건 변화를 보수적으로 반영하는 쪽으로 정했다.

### 모델 특징에서도 차이를 재고 변환 전후를 검토

기존 모델에서 분류에 쓰는 특징을 추출해 PCA 그림과 분포 거리로 비교했다. 특징 분석은 전체 Train 픽셀 통계와 표본이 다르다. 사전 점검에서는 **클래스당 Source Train 8장**과 실제 촬영 전체를 비교했다.

| 분야 | Source 특징 / Target 특징 | 초기 점검 MMD² | 초기 점검 CORAL |
|---|---:|---:|---:|
| 피부 | 80 / 42 | 0.4044727225770509 | 0.26587995274001025 |
| 얼굴 | 40 / 42 | 0.13432076513630142 | 0.053143286354017716 |
| 두피 | 40 / 40 | 0.4097689881066474 | 0.18082970664770923 |

이 단계에서는 두 수치를 특징 차이 **측정용**으로 사용했다. 당시 값과 3차의 진단 값은 모델·Source 표본·거리 기준 설정이 달라 직접 차감하지 않는다. 변환 전후 점검용 원본 Train은 피부 240장, 얼굴 120장, 두피 120장으로 총 480장이었다. 픽셀 값이 범위 끝으로 몰리는 문제, 인공 테두리, 얼굴 비율 변화, 병변·모발 경계의 가시성을 확인했다. 점검 후 얼굴 인공 확대·축소와 테두리 합성은 제외했다.

## 3. 유사 이미지 후보와 데이터 분할 정리

파일·픽셀 해시, 기록된 증강 원본 정보, 64비트 dHash 해밍거리 3 이하를 이용해 다른 분할에 걸친 유사 후보를 확인했다. 초기 점검의 확정 파일·픽셀·기록 ID 문제는 0이었다. 유사 후보는 얼굴 **484쌍·159묶음**, 피부 **7,770쌍·1,618묶음**, 두피 **0쌍**이었다. 후보 수를 확정 중복 수로 해석하지 않았다.

피부·얼굴은 연결된 후보를 묶고, 원본 Test 보존을 우선했다. Test와 연결된 경우 Train·Validation 쪽 원본을 제외 목록에 넣었다. Train/Validation 사이에만 연결된 경우 Train에서 뺐다. 이 처리는 새 학습에서 읽을 목록에 적용했고, 원본 파일과 Test는 그대로 보관했다.

| 분야 | 초기 원본 Train | 제외한 Train | 실제 학습 Train | 실제 Validation | 원본 Test |
|---|---:|---:|---:|---:|---:|
| 피부 | 7,249 | 496 | **6,753** | **900** · 1,000장 중 100장 제외 | 700 |
| 얼굴 | 3,600 | 65 | **3,535** | **499** · 500장 중 1장 제외 | 400 |
| 두피 | 10,032 | 0 | **10,032** | **1,252** | 1,252 |

최종 적응은 세 분야 모두 **남겨진 원본 Train**을 썼다. 두피는 과거 선정 모델의 학습 이력을 고려해 원본과 증강 파일을 누수 점검 범위에 넣었다. 두피 점검 대상 30,087행 중 원본 연결 ID를 확인한 것은 25,072행이다. 저장된 3차 점검 기록에서 세 분야 모두 점검 규칙상 차단 문제·잔여 교차 분할 유사 후보·Source/Target 동일 픽셀 겹침이 0이었다. 사람·병변·촬영 세션 ID는 확인할 수 없었다. 기존 저장 모델이 과거에 현재 검증 사진과 유사한 자료에 노출됐을 가능성도 남으므로, 점수는 **탐색 검증**으로 기록했다.

## 4. 계획 변경과 최종 학습의 공통 조건

처음에는 얼굴 밝기만 보는 실험부터 검토했다. 이후 세 분야의 전체 Train 분석과 사전 점검을 거쳐 얼굴·피부의 대비와 방향 조명 등 근거가 있는 변화로 범위를 넓혔다. 별도 두피 학습본과 피부·얼굴 학습본도 준비했으나, 그 실행본으로 완료한 결과는 확보하지 못했다. 이전 9개 통합 실행에서는 두피 조명 조건의 1·2회차 기록을 확보한 뒤 중단했다. 해당 기록은 최종 결과와 분리해 보관했다.

최종 방식은 **1차 6개 → 2차 3개 → 3차 3개**다. 초기의 분류층 15회·후반 10회 준비 학습 대신 기존 `.keras` 저장본을 사용했다. 분야별 원본 ZIP 해시·클래스 순서·입력 정책과 과거 모델 파일의 해시를 고정했다. 공통 ZIP v3 하나를 Drive에 올려 단계별 노트북이 읽게 했다. 원본 공개 데이터 ZIP은 Drive에 두고 Colab 실행 공간에서 복사해 읽었다. 실제 촬영 입력은 공통 ZIP 안에 AES-256-GCM으로 암호화해 포함했다.

| 항목 | 고정 조건 |
|---|---|
| 공통 학습 | 모델당 5 epoch, seed 42, Adam 학습률 0.00001 |

## 7. 3차 · MMD·CORAL을 학습 손실에 추가

2차와 같은 출발 가중치·분할·사진 변환·갱신 횟수를 유지했다. 새 조건은 실제 촬영본을 일부 배치에 넣고 **분류 손실 + 가중치 × MMD + 가중치 × CORAL**을 줄이는 것이었다. MMD는 두 그룹의 특징 분포 차이, CORAL은 특징들이 얼마나 퍼지고 함께 변하는지 나타내는 공분산의 차이를 계산한다. 기존 Source 사진에서만 질환 분류 손실을 계산했다.

- 피부·두피는 분류 전 평균 풀링 특징을, 얼굴은 PMG의 결합 특징을 사용했다. 얼굴은 기존 네 갱신 중 마지막 결합 갈래에 정렬 손실을 더했다.
- 출발 모델의 클래스별 최대 8장인 원본 Source Train 표본으로 특징의 기준 좌표를 고정했다. 각 정렬 항의 가중치는 시작 분류 손실의 5%를 기준으로 조정하고 계수 상한 10을 적용했다.
- 실제 결과에서 분야마다 매 epoch **정렬 10배치, 촬영 입력 40장**을 사용했다. 각 정렬 배치는 참여자 네 명에게서 한 장씩 뽑았다. 촬영본이 42장인 분야에서도 참여자 균형을 맞춰 40장씩 썼다. 나머지 학습 배치에서는 Source 분류 갱신을 유지했다.
- 3차 전용 Colab 탭의 Drive 연결이 실패해, 이미 Drive가 연결된 GPU 세션의 임시 셀에서 업로드한 3차 코드를 대조해 실행했다. 가려진 입력으로 키를 전달했고 복호화한 사진은 메모리에서 사용했다. 3차 모델·비교표·그래프는 예정된 Drive `stage3`에 저장했다.
- 피부 **3회차**, 얼굴 **3회차**, 두피 **4회차** 모델을 저장했다. 3차의 검증 비교표에는 시작 저장본, 1차, 2차, 3차 네 모델이 함께 들어 있다.

## 10. 현재 결론과 남은 평가

1. **촬영과 분석**을 마쳤다. 실제 장비와 기존 Train의 밝기·대비·색·미세 질감·얼굴 구도 차이를 확인했다. 사람·부위·촬영 구성 차이도 포함될 수 있다.
2. **학습 비교**를 마쳤다. 현재 확장 Validation에서 피부는 네 모델이 동률, 얼굴은 학습 전 저장본이 가장 높고, 두피는 2차가 가장 높았다. MMD·CORAL을 함께 추가한 3차는 2차보다 두 특징 거리를 낮췄다.
3. **최종 Source Test 비교**가 남아 있다. 모델과 변환 설정을 먼저 고정하고 같은 원본 Test·조명 변환 Test·확장 변환 Test에 적용한다. 피부 700장, 얼굴 400장, 두피 1,252장의 원본 Test를 보존한다. 정확도·Macro-F1·클래스별 Recall·혼동행렬을 비교한다.
4. **실제 장비 성능 검증**에는 정답이 확인된 별도 실제 촬영 질환 사진이 필요하다. 기존 4명 자료는 장비 특성 조사 및 정렬용이다. 미사용 인물·세션의 정답 확인 자료로 평가할 때 실제 환경 성능을 판단할 수 있다.
5. **촬영 구도·범위**는 별도 변수로 남아 있다. 얼굴 크기와 자르기 범위, 현미경 거리·배율, 두피 가림을 이번 세 단계의 학습 변화와 구분한다. LLM·VLM은 촬영 적응 이후의 별도 범위다.
