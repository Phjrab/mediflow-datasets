# MediFlow 실제 카메라 적응 작업 가이드라인

2026-11-08 · 실행 계획 초안

이번 작업의 질문은 **실제 촬영에서 반복해서 관찰한 변화 한 가지를 기존 질환 학습 사진에 반영하면, 그 변화에 대한 모델의 대응이 좋아지는가?**이다. 먼저 [로드맵](../ROADMAP.md) 2~3단계에서 장비 사진을 수집하고 특성을 비교한다. 근거가 쌓이면 6단계의 증강 실험으로 이어간다. 증강은 기존 학습 사진에 밝기나 선명도 같은 변화를 주는 작업이다. LLM·VLM은 카메라 적응 이후에 진행한다. 교수님이 제안한 적응의 구체적인 범위는 확인 후 이 계획에 반영한다.

| 자료 | 이번 작업에서 쓰는 목적 |
|---|---|
| 실제 장비로 찍은 참여자 사진 | 사진 품질과 촬영 조건 차이를 조사한다. 질환명과 정상 여부는 미확인으로 두고, 모델 학습·선정·질환 정확도 계산에는 사용하지 않는다. |
| 기존 공개 질환 데이터 | 기존 정답을 사용해 추가 학습하고, 원본과 촬영 변화를 적용한 복사본에서 각각 모델을 비교한다. |
| 정답 근거가 확인된 실제 장비 질환 사진 | 추후 확보하면 사람과 촬영 세션이 겹치지 않는 별도 평가 자료로 사용한다. 이 평가가 있어야 실제 장비의 질환 분류 성능을 비교할 수 있다. |

## 1. 시험 촬영 · 먼저 30장

참여자 한 사람의 얼굴·피부·두피를 각각 **기준 5장 + 조건을 바꾼 5장**으로 찍는다. 한 쌍마다 같은 사람, 같은 부위, 같은 장비에서 기준과 변경 사진을 연달아 찍는다. 첫 시험은 조명 조건 하나를 바꾸는 것을 기본안으로 두고, 거리·배율·각도·초점·해상도는 가능한 한 고정한다. 변경 전후의 조건을 재현할 수 있게 기록한다. 카메라가 자동으로 노출이나 색을 조절하고 그 설정을 고정할 수 없다면, 그 영향이 포함된 **조명 조건 전체의 변화**로 해석한다.

| 분야 | 기준 촬영 | 먼저 확인할 점 |
|---|---|---|
| `web_skin` | 웹캠으로 정면 얼굴 전체. 카메라 높이와 얼굴까지 거리를 고정한다. | 얼굴이 잘리지 않는지, 그림자·역광·자동 노출에 따라 얼굴 밝기가 달라지는지 |
| `skin` | USB 현미경으로 두피가 아닌 동일 피부 부위. 부위와 촬영 범위를 기록한다. | 반사광에 가려진 부분이 있는지, 피부 표면이 선명한지 |
| `hair` | USB 현미경으로 동일 두피 부위. 가르마와 모발 위치를 가능한 한 유지한다. | 모낭 주변과 두피가 보이는지, 모발에 가려지거나 초점이 달라졌는지 |

- 사진마다 저장이 됐는지와 촬영 범위를 확인한다. 각 쌍에서 잘림, 심한 흐림, 반사광 등으로 비교가 어려운 사진을 표시하고 필요하면 그 쌍을 다시 찍는다. 제외 이유와 재촬영 횟수도 남긴다.
- 장비 이름과 원본 해상도는 파일이나 실제 설정에서 확인한다. 기존 `scripts/camera.py`는 특정 카메라 번호에 640×480을 요청하는 저장 도구다. 사용할 경우 연결된 장비와 저장 결과를 직접 확인하고 촬영 조건은 별도로 기록한다.
- 촬영과 보관·공유 범위에 대한 동의를 먼저 확인한다. 파일 이름은 참여자 번호로 만들고, 얼굴 사진은 동의 범위에 맞는 제한된 위치에 보관한다. 원본 참여자 사진은 Git에 올리지 않는다.
- 30장으로 촬영 방법이 재현되고 기록이 갖춰지면, 가능할 경우 **5명 × 2일 × 분야별 10장**으로 확대한다. 총 300장, 분야별 100장이 초기 조사 목표다. 같은 사람의 반복 사진은 별도 참여자 표본으로 세지 않는다.

최소 기록 예시. 실제 날짜·해상도·장비 설정을 입력하고 모르는 값은 `미확인`으로 적는다.

| 사진 ID | 참여자 · 촬영 세션 | 분야 · 부위 | 쌍 · 조건 | 장비 · 촬영 설정 | 확인 결과 |
|---|---|---|---|---|---|
| `P01_S01_web_skin_01_ref` | `P01` · `S01` · 촬영일 | `web_skin` · 정면 얼굴 | `01` · 기준 | 모델명, 실제 해상도, 거리, 조명, 초점/노출/색 자동 여부 | 비교 가능 · 질환 라벨 미확인 |
| `P01_S01_web_skin_01_alt` | `P01` · `S01` · 같은 촬영일 | `web_skin` · 정면 얼굴 | `01` · 조명 변경 | 동일 설정과 바꾼 조명 위치 또는 단계 기록 | 비교 가능 · 질환 라벨 미확인 |

현미경 사진은 배율 또는 장비의 배율 설정값을 추가한다. 참가자 이름 대신 번호를 쓰되, 원본 파일과 기록 표의 사진 ID를 연결할 수 있어야 한다.

## 2. 촬영 차이 분석 · 변화 한 가지 선정

1. **같은 부위의 사진 쌍을 먼저 본다.** 기준과 변경 사진을 나란히 놓고, 분야별로 같은 위치의 얼굴 피부·현미경 관찰 영역을 비교한다. 밝기의 중앙값, 너무 어둡거나 밝아 세부가 사라진 영역의 비율, 색 변화, 초점·노이즈·촬영 범위를 기록한다. 배경이나 머리카락이 차지하는 비율에 따라 전체 밝기가 바뀔 수 있으므로, 비교 영역과 판단 이유도 적는다.
2. **기존 공개 데이터와의 비교는 참고로 사용한다.** 조정 범위를 정할 때는 공개 Train에서 대표 사진을 확인한다. 사람과 부위, 피부색, 질환 구성, 저장 방식이 다르므로 두 자료의 평균 차이를 카메라 자체의 효과로 해석할 수 없다. 결과는 사진 쌍별 차이와 참여자·세션별 요약으로 남긴다.
3. **실제 사용에서 반복되고 학습 사진에서도 무리 없이 재현되는 변화 한 가지를 고른다.** 예를 들어, 초점과 촬영 범위가 같은 사진에서 밝기 저하가 반복되면 `밝기`를 첫 변수로 정한다. 장수, 변화 방향과 관찰 범위, 제외 사례를 남긴다. 색·흐림·노이즈는 각각 별도 실험으로 다룬다. 초점 실패나 화면 잘림으로 판별에 필요한 부분이 사라진 경우에는 촬영 방법을 먼저 개선한다.
4. **증강 세기는 Train 사진으로 확인한다.** 관찰한 범위의 후보값을 Train 사본에 적용하고, 피부색·홍반·각질 등 분류에 필요한 특징이 가려지지 않는지 확인한다. 강도·적용 비율·난수 설정을 적는다. 한 사람에게서만 차이가 보였거나 조건이 섞여 판단이 어렵다면 촬영을 보완한다. 장비가 바뀐 효과를 비교하려면 가능한 범위에서 같은 부위를 두 장비로 같은 조건에 찍는 비교가 별도로 필요하다.

## 3. 추가 학습 · 한 분야에서 시작

첫 실행은 촬영 차이가 명확하고, 기존 데이터와 선정 모델을 확인할 수 있는 **한 분야**에서 시작한다. 조건이 비슷하면 정면과 거리를 반복해서 맞추기 쉬운 `web_skin`을 우선 후보로 둔다. 이때 기존 Web Skin v2 PMG 모델을 기준으로 삼는다. Skin은 v1을 사용하고, Hair는 5클래스 v2와 별도의 6클래스 후보 중 어떤 과제를 평가할지 사전에 명시한다. Hair 5종과 6종 사이의 점수 차이로 적응 효과를 계산하지 않는다. [선정 모델 안내](../../results/SELECTED_MODEL_PATHS.md).

**첫 실험 가설 예시.** 실제 촬영에서 관찰한 범위의 밝기 저하를 Train에 반영하면, 같은 밝기 변화가 적용된 평가 사진에서 분류 성능이 좋아지고 원본 사진의 성능도 유지된다. 분석 전에는 밝기를 첫 시험 촬영 변수로만 사용한다.

| 비교군 | 실행 | 확인하는 것 |
|---|---|---|
| A · 현재 선정 모델 | 저장본 그대로 평가 | 현재 사용 후보의 성능 |
| B · 추가 학습 대조군 | 같은 저장본에서 시작해 기존 학습 조건으로 추가 학습 | 추가 학습만 했을 때의 변화 |
| C · 촬영 변화 반영 | B와 같은 조건에서 Train에 선정한 변화 한 가지만 추가 | C와 B의 차이로 해당 증강의 효과를 비교 |

- **고정할 것:** 시작 모델과 클래스 순서, Train·Validation·Test 목록, 입력 크기와 전처리, 추가 학습에서 조정할 층, 손실 함수, 학습률, 배치 크기, 학습 횟수와 난수 설정. B와 C는 같은 학습 사진을 같은 비율로 뽑고 학습 업데이트 횟수도 맞춘다. Web Skin PMG의 출력 결합 규칙과 기존 EfficientNet의 RGB 0–255 입력을 유지한다. 외부 `/255.0`은 적용하지 않는다. [모델 사용법](../../results/MODEL_USAGE.md).
- **바꿀 것:** C의 Train 입력에 선택한 변화를 적용하는 설정. 기존 증강에 같은 변환이 있다면 해당 변환의 기존 범위와 장비 관찰에 맞춘 범위를 비교하도록 바꿀 항목을 한 줄로 명시한다. 다른 설정을 불가피하게 변경하면 이유와 결과 해석에 미칠 영향을 기록한다.
- **학습 전 확인할 것:** 해당 모델의 데이터 버전과 ZIP 해시, 클래스별 개수, 분할 목록을 확인한다. 같은 사람·병변·세션 및 완전 동일·유사 사진과 증강 파생본이 여러 분할에 걸쳐 있는지 확인한다. 새 파생본은 원본과 같은 분할에 속한다. 기존 공개 데이터에서 ID가 없으면 확인한 범위와 미확인 항목을 나눠 기록한다. 중복이 확인되면 학습을 멈추고 처리 방식을 정한 뒤 원본을 보존한 별도 버전에서 재개한다. [기존 데이터 점검 절차](COMMON_COLAB_NOTEBOOKS_GUIDE.md).

## 4. 평가와 채택 기준

| 평가 자료 | 쓰는 시점과 목적 |
|---|---|
| 원본 Validation | 원래 공개 사진의 성능이 유지되는지 확인하고 후보를 선택한다. |
| 변화 적용 Validation | 원본 Validation의 별도 복사본에 사전에 정한 변환을 적용해 변화 대응을 비교한다. 모든 모델에 같은 사진과 설정을 사용한다. |
| 원본 Test | 설정과 후보를 고정한 뒤 최종 비교에 사용한다. 원본 파일과 분할을 보존한다. |
| 변화 적용 Test | 고정한 평가 변환을 Test의 별도 복사본에 적용하고 원본 Test 결과와 나눠 보고한다. |

평가에 쓸 변환과 강도, 모델 선택 기준은 Test 결과를 보기 전에 문서로 고정한다. 각 평가에서 클래스별 F1을 같은 비중으로 평균한 **Macro F1**을 주 지표로 쓰고, Accuracy, 클래스별 Recall, 혼동행렬과 평가 장수도 기록한다. 원본과 변환 복사본은 같은 사진에서 나온 짝이므로 각각 보고하고 하나의 표본 수로 합치지 않는다. 과거 결과가 이미 공개된 기존 Test의 사용 이력도 함께 적는다.

**첫 실험의 채택 기준 초안:** 변화 적용 Validation에서 C가 A와 B 모두보다 좋아지고, 원본 Validation에서 C가 A보다 사전에 정한 허용 범위를 넘게 하락하지 않을 때만 최종 비교 후보로 올린다. 시작 기준으로 원본 Macro F1 하락을 허용하지 않는 방안을 두고, 클래스별 허용 하락 폭과 최소 개선 폭은 학습 전에 확정한다. 소폭 개선이거나 일부 클래스에서 하락하면 같은 난수 설정을 B·C에 짝지어 추가 반복하거나 기존 모델을 유지한다. 반복을 계획했다면 설정과 판정법을 Test 전에 고정한다. 비교군과 후보의 저장본을 고정한 뒤 Test를 최종 1회 비교에 쓰고, Test 결과를 보고 강도나 후보를 다시 고르지 않는다.

보고서에는 비교 대상과 데이터 범위를 문장에 넣는다. 예를 들어 **“밝기 저하를 적용한 공개 평가 사진에서 Macro F1이 개선됐다”**는 해당 비교가 통과했을 때 쓸 수 있다. **“실제 웹캠의 질환 분류 성능이 개선됐다”**는 정답이 확인된 독립적인 실제 장비 평가에서 같은 기준으로 비교한 뒤에 판단한다. [촬영 변화 평가 예시, Hendrycks와 Dietterich](https://arxiv.org/abs/1903.12261), [실제 환경 분포 차이 평가, WILDS](https://proceedings.mlr.press/v139/koh21a.html).

| 단계 | 다음 단계로 넘어갈 때 남기는 자료 |
|---|---|
