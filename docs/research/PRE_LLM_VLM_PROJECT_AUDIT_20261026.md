# LLM과 VLM 착수 전 프로젝트 종합 점검

기준일: 2026-10-26. 로컬 저장소의 모델·평가 기록·실행 코드·문서·발표자료를 대조했다.
새로운 모델 학습이나 전체 Test 이미지 재추론은 수행하지 않았다. 이번에 새로 실행한 것은
저장 결과의 계산 검증, 파일 무결성 검사, 일곱 선정 모델의 샘플 추론과 자동 테스트다.

## 결론

**기존 분류 연구의 결과와 모델은 보존돼 있으며 LLM·VLM의 로컬 연구를 시작할 기반은 있다.**
직전에 해야 할 일은 재학습이 아니라 최신 선정 모델의 공통 추론 어댑터와 결과 형식 준비다.
현재 `mediflow-infer`는 초기 모델용이고, 최신 후보 실행은 `candidate_reproduction.py`의
검증용 함수와 문서 예제를 통해 이뤄진다. 이를 그대로 웹 서비스나 LLM 연동 완료로 해석하지 않는다.

이번에 모델 파일의 손상·선정 기록의 해시 불일치·저장 예측과 현재 지표의 불일치는 발견하지 않았다.
실제 촬영 성능과 장비 검증은 별도 과제로 남지만, 구조화 결과를 설명하는 LLM의 로컬 실험을
그때까지 미룰 필요는 없다.

뜻은 아니다. 다른 모델은 보관 ZIP에 들어 있거나, MedSigLIP처럼 외부 인코더가 필요한 구조다.
예시 사진은 40장이다. 이번 점검을 위해 원본 이미지나 선정 모델을 별도로 복사·압축해제하지 않았다.

## 2 지금까지 완료한 연구의 흐름

### 1차 초기 데이터와 첫 학습

AI Hub 원천에서 Skin 10종, Web Skin 5종, Hair 5종을 선별하고 촬영 영상의 차이에 따라
세 분류기로 나눴다. 원본 Train과 원본+증강 Train을 비교했고 Validation/Test는 원본으로 유지했다.
초기 ImageNet EfficientNet-B0·224의 분류층 학습 결과를 보존했다. YOLO 라벨링·crop 검토는
완성된 검출 성능 결과와 구분한다.

### 2차 데이터 검증과 v1

파일 내용·RGB 픽셀 중복을 검사해 Hair와 Skin을 정리했고 Web Skin은 확인한 완전 동일
교차 중복이 없었다. Clean 분할에서 학습을 다시 진행했다. 사람·병변·촬영 세션 식별이
충분하지 않아 모든 연관 사진의 누수를 배제한 것은 아니다.
Head-only 뒤 본체 일부를 낮은 학습률로 조정하는 2단계 학습, 224/256 해상도,
Label Smoothing, Focal Loss, B0/B1, 추가 epoch를 비교했다. 각 v1은 이 과정에서 선정된 정식 후보다.

### 3차 논문 기반 강화와 v2

Hair에서는 SupCon, DINOv2, EfficientNetV2-S, B1·384, SAM 및 저장 모델 앙상블을 검토했고
B1·384·Label Smoothing 0.05·Adam을 v2로 선정했다. Web Skin에서는 WS-DAN, PMG,
MixStyle과 PMG·B1·384를 비교해 성능·실행 비용을 고려한 PMG·B0·256을 v2로 보존했다.
MedSigLIP-448 고정 인코더+Linear 실험은 두 도메인에서 선별했지만 각각의 v2를 교체하지 않았다.
이는 이미지 표현 기반 분류 연구이며 대화형 VLM 개발·평가 완료가 아니다.

### 4차 Hair 6클래스와 실행 비용

양호 원본 534장을 추가한 별도 6종 데이터에서 B0·256·CE/B1·384·LS 0.05와
원본/증강 Train의 네 조합을 비교했다. Validation으로 성능 우선과 경량 후보를 고정하고
각각 Test 평가·패키징했다. 기존 Hair 5종과는 Test와 출력 구성이 다르다.
34개 저장 모델의 Colab 실행 비용은 측정했지만, 실제 현미경·웹캠·Jetson 성능 측정은 아니다.

전체 설명은 [단계별 상세 보고서](../MEDIFLOW_4_PHASE_DETAILED_REPORT_20260930.md),
실험별 방법·논문·결과는 [실험 대장](ALL_EXPERIMENTS_RATIONALE_AND_RESULTS_20260924.md),
발표 그림은 [발표 자료실](../../presentation/README.md)에 있다.

## 3 선정 모델과 사용 기준

| 과제와 버전 | 모델 | 입력 | 보존된 Test Macro F1 | 사용 구분 |
|---|---|---:|---:|---|
| Skin v1 | B0·CE·증강 | 224 | 0.9871314132317626 | 현재 후보 |
| Web Skin v1 | B0·CE | 256 | 0.8813822927981046 | 논문 강화 전 선정본 |
| Web Skin v2 | PMG·B0·CE | 256 | 0.9141049081029712 | 현재 후보 |
| Hair 5종 v1 | B1·LS 0.05·증강 | 256 | 0.7885764577048346 | 논문 강화 전 선정본 |
| Hair 5종 v2 | B1·LS 0.05·Adam | 384 | 0.8002222282821301 | 기존 통합 색인의 현재 후보 |
| Hair 6종 성능 우선 | B1·LS 0.05·원본 | 384 | 0.8091500773460419 | 별도 6종 후보 |
| Hair 6종 경량 | B0·CE·증강 | 256 | 0.8021613486071133 | 별도 6종 대안 |

수치는 기존 저장 평가값이다. 서로 다른 분류 과제를 한 순위로 세우지 않는다.
정확한 경로는 [선정 모델 경로](../../results/SELECTED_MODEL_PATHS.md)를 따른다.
Hair 6종을 사용하려면 별도 선정 색인의 항목을 명시적으로 선택한다. 기존 Hair 5종 색인을
몰래 바꾸거나 클래스 이름만 하나 더 붙여서는 안 된다.

모든 선정 EfficientNet 입력은 RGB `float32` 0–255이며 외부 `/255`를 추가하지 않는다.
최신 후보의 전처리는 TensorFlow decode/resize 기준이다. Web Skin PMG v2는 네 logit 출력을
합한 뒤 softmax를 한 번 적용한다. 일곱 후보의 실제 실행은 이 계약으로 확인했다.

## 4 LLM과 VLM 직전에 남아 있는 구현 공백

### 최신 후보용 실행 경로

`models.py`, `inference.py`, `cli.py`는 초기 Original/Augmented 모델용이다. 이 경로의
Pillow·EXIF 처리와 `confidence`·`probabilities` 출력 키를 최신 후보의 계약으로 복사하지 않는다.
README와 MODEL_USAGE는 이미 이 명령을 과거 연구용으로 구분하고 있다.
`candidate_reproduction.py`는 최신 기존 세 후보를 실행·검증하지만 서비스용 라우터는 아니다.
Hair 6종은 별도 색인을 직접 읽어야 하며 검증 명령의 기본 대상에는 없다.

후속 구현은 기존 초기 연구용 명령을 갑자기 바꾸기보다, 명시적 후보 선택·모델 재사용·전처리·
출력 결합·오류 처리를 제공하는 별도 공통 어댑터로 시작하는 것이 적절하다.

### 공통 결과 형식

현재 후보 검증 JSON은 존재하지만 LLM에 전달할 제품용 결과 형식과 검증 코드는 확정되지 않았다.
다음 필드를 갖는 형식을 먼저 제안·검증한다. 아래는 구현된 새 API 목록이 아니다.

| 정보 | 필요한 이유 |
|---|---|
| schema 버전, 검사·결과 ID | 여러 결과와 사용자 기록의 혼용 방지 |
| domain, task ID, device, body region | 얼굴/확대 피부/두피와 Hair 5종/6종 구분 |
| candidate ID, model SHA-256, 전처리 버전 | 실제 사용 모델 추적 |
| 클래스 순서, scores, 예측 index/label | 배열과 질환명 대응 유지 |
| status와 error | 오류를 유효한 분류 결과로 바꾸지 않기 |
| calibration 및 평가 범위 | 출력 점수와 확진 확률·실제 장비 성능 구분 |

장비와 촬영 부위를 모두 확인해 모델을 선택한다. LLM에 임의 임계값으로 만든 위험 등급을
넘기지 않는다. 각 모델의 클래스 범위는 실제 `class_names.json`과 일치시킨다.

### LLM과 VLM의 역할 및 평가 자료

현재 `src/`에 LLM 호출·프롬프트·RAG·대화형 VLM 런타임은 구현돼 있지 않다.
LLM은 검증된 분류 결과와 문진을 설명하는 역할로 먼저 평가하고,
VLM은 이미지에서 보이는 관찰을 별도 평가한다. VLM 생성문을 정답이나 자동 재라벨링에 쓰지 않는다.
실제 환자의 증상 설명과 검토된 시각 관찰 정답은 샘플 파일명만으로 대신할 수 없다.

## 5 아직 완료로 볼 수 없는 범위

- 정제 전 Test 사진을 다시 추론한 초기 6개 모델의 평가 재현. 원본 미보관으로 현재 수행 불가다.
- 사람·병변·세션 단위의 전체 누수 배제와 Hair 양호 사진의 파일별 원천 라벨 재확인.
- 실제 장비 촬영 사진의 독립 평가와 대상 장비의 지연·최대 메모리·전력 측정.
- LLM 설명 품질 및 VLM 관찰 품질 평가, 실제 시스템 배포.

이번에는 Drive를 다시 열거나 팀원 원격 GitHub의 최신 커밋을 조사하지 않았다.
[2026-09-13 저장소 검토](KIOSK_CORE_REVIEW_20260913.md)는 당시 코드 기록으로 유지한다.
새 진행 방향은 로컬 결과 형식과 LLM·VLM 실험 준비다. 실제 시스템의 실행 위치와 연결 범위는
그다음 구현에서 구체화한다.

## 6 이번에 수정한 문서 불일치

1. 로드맵의 이전 LLM·VLM 보류 방향을 날짜가 있는 과거 기록으로 구분하고, 새 13·14단계를 추가했다.
2. 이미 완료된 Hair 6종 데이터 계약·네 조건 학습을 완료로 표시했다. 사람·세션·원천 라벨 검증은 별도 유지했다.
3. 측정된 모델 파일 크기와 미측정 실행 메모리를 서로 다른 체크 항목으로 나눴다.
4. 재현 안내에 생성물로 적힌 `reference_source.py.txt`는 현재 코드가 생성하지 않아 안내를 정정했다.
5. 문서 첫 화면에서 1~4차 상세 보고서와 이번 사전 점검을 찾을 수 있게 연결했다.

모델·원본 보고 지표·이미지·노트북은 수정하지 않았다. 과거 실험 문서의 당시 결과도 덮어쓰지 않았다.

## 7 권장 진행 순서

**첫 작업은 최신 후보용 공통 추론과 LLM 입력 결과 형식 준비다.** 이를 통해 이후 LLM의 설명
오류와 분류기의 실행 오류를 구별할 수 있다. 우선 기존 세 후보와 별도 Hair 6종을 명시적으로
선택할 수 있게 준비하고, 실제 사용할 Hair 과제는 활성화 전에 정한다.

그다음에는 고정 결과·문진·질문 사례로 LLM을 평가한다. 결과 없음, 이미지 실패, 과제 불일치,
문진과 예측 불일치, 데이터 속 지시문, 모델 연결 실패 사례를 포함한다. 결과 수치·라벨 일치,
근거 없는 추가 주장, 응답시간과 비용을 기록한다. 특정 LLM이나 API는 아직 선정·호출하지 않았다.

VLM은 이미지+질문만 입력하는 방식과 이미지+분류 결과를 함께 입력하는 방식을 구분해 비교한다.
얼굴 사진과 현미경 피부·두피의 관찰 기준은 별도로 마련하고, 사진에서 확인할 수 없는 정보를
만드는지 평가한다. 실제 장비 자료 없이도 공개 자료의 기능 실험은 시작할 수 있지만,
그 결과를 실제 장비 성능으로 확대하지 않는다.
