# 카메라 적응 모델의 기존 데이터 최종 Test

로드맵 7단계의 기존 데이터 평가다. 질문은 **카메라 적응 전후의 성능이 같은 기존 Test에서
촬영 변화에 따라 어떻게 달라지는가**다. 이 문서는 실행 전에 고정한 비교 계획이다.

GPU 런타임으로 [최종 Test 노트북](../../notebooks/camera_adaptation/MediFlow_Adaptation_Final_Test_20261110.ipynb)을
열고 모두 실행한 뒤 Drive를 연결한다. Drive에 이미 있는 공통 ZIP v3, 원본 데이터 ZIP,
1·2·3차 저장 모델을 사용한다. 복호화 키 입력은 없다.

| 분야 | 원본 Test 장수 | Validation으로 고정한 후보 |
|---|---:|---|
| 피부 | 700 | 1차 조명 적응 |
| 얼굴 | 400 | 2차 확장 변환 |
| 두피 | 1,252 | 2차 확장 변환 |

세 조건의 Validation Macro-F1 중 가장 낮은 값이 큰 모델을 선택했다. 같으면 원본 점수가
큰 모델을, 다시 같으면 앞 단계 모델을 선택했다. 원래 비교표의 수치와 완료 기록을
대조하고, 출발 모델과 1·2·3차 모델의 파일 해시를 고정했다.
[사전 고정 계획](../../configs/adaptation_final_test_20261110.json) ·
[공통 Validation 표](../../results/camera_adaptation_stage3_20261110/validation_comparison.csv)

분야별로 학습 전·1차·2차·3차 모델을 원본, 조명 변환, 확장 변환에서 평가한다.
모든 모델에 동일한 사진, 정답, 클래스 순서, 변환 설정을 적용한다. 얼굴은 중앙 정사각형
자르기, 현미경 사진은 전체 리사이즈를 유지한다. 변환 난수는 Validation과 같은 seed 1707과
사진 경로로 고정한다. 같은 입력 조건에서 달라지는 것은 저장 모델이고, 같은 모델에서
달라지는 것은 사진 변환이다. Train과 Validation은 추론에 사용하지 않으며 Test 점수는
재학습이나 후보 재선정에 쓰지 않는다.

노트북은 원본 ZIP의 SHA-256, 원본 Test 목록과 정답 인덱스, 공통 설정과 모델 해시를 확인한다.
ZIP에서 사진을 읽어 원본과 두 변환을 메모리에 만들고, 입력 파일에는 쓰지 않는다. 결과는
Drive의 `MediFlow_adaptation_runs/4ae6e07eb4af1225/final_test_bc4d235c1354`에 저장한다.

- `test_comparison.csv`는 36개 비교의 정확도·Macro-F1과 학습 전 대비 차이를 담는다.
- `class_metrics.csv`는 모든 모델·조건의 클래스별 정밀도·재현율·F1과 표본 수를 담는다.
- 분야별 JSON은 클래스 이름·지원 표본 수·정밀도·재현율·F1·혼동행렬과 실행 환경을 담는다.
- `plots`는 전체 비교 그래프와 Validation으로 고른 후보의 세 조건 혼동행렬을 담는다.
- `code`는 실행한 평가 코드와 예측 코드의 사본을 담는다.
- `evaluation_plan.json`과 `summary.json`은 입력 버전과 평가 완료 상태를 기록한다.

완료하면 표와 그래프를 Colab에 표시하고 `MediFlow_Final_Test_Results_20261110.zip`을
다운로드한다. 같은 결과 ZIP은 Drive의 결과 폴더 바로 옆에도 저장한다. ZIP에는
평가 기록·표·그림·코드 사본을 넣는다. 원본 데이터와 모델 파일을 재포함하지 않는다.
환경 준비와 추론의 출력·오류를 화면으로 전달하며, 실행별 로그는 결과 폴더의 `logs`에
저장한다. 실패한 경우에도 실행 로그와 환경 준비 로그가 Drive에 남는다.

변환 Test는 실제 촬영 특성을 근사한 기존 데이터 평가다. 기존 체크포인트가 과거에 Test와
유사한 이미지에 노출됐는지는 확인되지 않았다. 실제 장비 성능은 독립적으로 수집해 정답을
확인한 사진에서 평가한다.

## 로컬 확인과 실제 실행 상태

최종 Test 원본에 대한 추론은 아직 실행하지 않았다. Drive 연결 도구의 파일당 256MiB
제한으로 원본 데이터 ZIP을 로컬에 내려받지 못해, Colab에서 기존 Drive 자료를 사용하도록
노트북을 구성했다. 노트북 자동 업로드는 목적 계정·폴더에 대한 명시적 승인 부족을 이유로
자동 승인 검토에서 거절됐다. 따라서 로컬 노트북을 Colab에서 열어 실행한다.

코드 스타일 검사 `ruff check src tests`를 통과했다. 관련 10개 검사는 Test의 파일·정답·
클래스 순서·원본 ZIP 고정, 모델 간 동일 입력, 짧은 마지막 배치, 변환 재현성, 기존 파일
보존을 확인했다. 전체 pytest는 기존 학습 검사에서 장시간 진행이 없어 중단했으며,
전체 통과로 기록하지 않는다. 실제 저장 모델 12개를 합성 입력으로 불러와 36개 비교와
완료 분야 재사용을 확인했다. 비교 그래프·혼동행렬의 생성과 배치는 합성 점수로 확인했다.

## 실행 오류 출력 수정

사용자가 공통 ZIP 확인 이후 `최종 Test가 완료되지 않았습니다`라는 안내만 전달했다.
기존 셀은 바깥 실행 프로세스의 표준 출력·오류를 Colab 출력으로 중계하지 않았다.
따라서 안내만으로 내부 실행 실패 원인을 특정할 수 없었다.

생성 코드와 노트북을 수정해 표준 출력과 오류를 실시간으로 중계하고, 종료 코드와
Drive 로그 경로를 실패 안내에 표시한다. 환경 준비도 같은 출력 중계 함수를 사용한다.
실패가 발생한 임시 작업 공간을 정리하기 전에 환경 로그를 Drive로 복사한다.
환경 준비 실패와 GPU 미선택 오류를 재현한 검사 2개를 추가했다. 관련 검사 12개가
통과했고 기존 학습 검사 1개는 이번 관련 검사 범위에서 제외했다. 코드 스타일 검사도
통과했다. 실제 Colab 실패의 원인은 수정본을 실행해 확보하는 로그에서 확인해야 한다.

추가 로그에서 TensorFlow 2.20.0·Keras 3.13.2 설치와 GPU 인식을 확인했다. 그 뒤
Matplotlib 설치 후 Keras를 불러올 때, 부모 Colab의
`MPLBACKEND=module://matplotlib_inline.backend_inline` 설정이 별도 환경으로 전달되어
`ValueError: Key backend`가 발생했다. 해당 실행은 Test 사진 예측 전에 멈췄다.

노트북 생성 코드에서 하위 프로세스 환경에 `MPLBACKEND=Agg`를 지정했다. 환경 준비부터
그래프 생성까지 이미지 저장용 출력 방식을 사용한다. Colab 전용 설정이 있는 부모
환경에서 시작해도 하위 프로세스가 Agg를 사용하는지 검사에 추가했고, 관련 검사 12개와
코드 스타일 검사를 통과했다. 사용자 요청에 따라 별도 셀을 추가하는 안내를 실행 수정본으로
대체했다. 연결된 로컬 노트북을 Colab에서 새로 열어 GPU를 선택하고 모두 실행한다.
첫 출력에 `MediFlow 최종 Test · 그래프 출력 설정 자동 처리 수정본`이 표시된다.
