## 측정 조건과 뜻

`environment.json` 기준 Python 3.13.15, TensorFlow 2.20.0, GPU 1개, 배치 1이다. 동일한 512×512 RGB 상수 이미지를 사용하고 모델마다 10회 준비 실행 후 각 지표를 30회 측정했다. `model_p50_ms`는 준비된 입력에서 분류 출력까지의 중앙값, `end_to_end_p50_ms`는 이미지 변환/크기 조정부터 분류 출력까지의 중앙값이며, 모델을 처음 불러오는 시간은 제외한다. `p95`는 느린 쪽 95백분위 지점이다. `load_seconds`는 별도로 기록됐다.

GPU **제품명**, 최대 GPU/RAM 사용량, 전력, Jetson 실행 시간은 기록되지 않았다. 따라서 이 수치를 Jetson 성능이나 실제 카메라 전체 처리 시간으로 부르지 않는다. 한 장의 상수 이미지에서 얻은 값이므로 실제 촬영 이미지의 크기·포맷 변화, 카메라 입력, 파일 읽기, 후처리, 동시 요청의 영향을 반영하지 않는다. 학습 시간은 이번에 같은 장비에서 재측정한 값이 아니라 각 과거 실행 기록이므로 모델 간 공정한 학습 속도 비교 근거가 아니다.

## 왜 이 지표들을 함께 봤나

Validation Accuracy만으로는 모델이 실제 실행 시 얼마나 기다려야 하는지 알 수 없다. 반대로 빠른 모델이라는 사실만으로는 분류가 충분히 정확한지 알 수 없다. 그래서 **같은 과제에서** 정확도와 지연 시간을 나란히 두어, 정확도를 더 얻는 데 시간이 얼마나 드는지 확인했다.

| 항목 | 읽는 방법 | 이번 기록에서 알 수 있는 것 |
|---|---|---|
| Validation Accuracy·Macro F1 | 높을수록 좋다. Macro F1은 각 클래스를 같은 비중으로 취급한다. | 과거 검증 분할에서 어느 조건이 앞섰는지. 새로 평가한 값은 아니다. |
| Model p50 | 입력이 준비된 뒤 모델을 실행하는 보통 시간. 낮을수록 빠르다. | 모델 계산 경로 자체의 실행 비용. |
| End-to-end p50 | 이미지 변환과 모델 실행을 포함한 보통 시간. 낮을수록 빠르다. | 이번 코드가 처리한 한 장의 전체 추론 시간. 모델 로드·카메라 촬영·파일 읽기는 제외된다. |
| End-to-end p95 | 반복 실행 중 느린 쪽의 시간. 낮을수록 좋다. | 보통 시간만 볼 때 놓칠 수 있는 지연의 꼬리. 30회 측정이므로 안정성 확정값은 아니다. |
| Training seconds | 과거 학습 기록. 낮으면 당시 실행이 짧았다. | 학습 비용의 대략적 기록. 실행 시점·장비가 다른 34개를 한 순위로 비교할 수 없다. |
| Checkpoint bytes·parameter bytes loaded | 저장 파일 크기와 로드된 가중치 메모리 크기. | 파일이 작다고 실제 메모리 사용량까지 작은 것은 아니라는 점. 활성화 메모리와 최대 사용량은 포함하지 않는다. |

`model_p50`과 `end_to_end_p50`의 차이는 이 코드에서 입력을 준비하는 비용을 보여준다. 하지만 두 값은 별도의 반복 측정에서 얻은 중앙값이므로 그 차이를 정확한 단일 이미지 전처리 시간으로 취급하지 않는다. `load_seconds`도 추론 지연 시간에 더하지 않았다. 일반적인 한 장 처리와 첫 요청의 체감 시간은 다를 수 있다.

MedSigLIP 두 조건의 실행 시간에는 `google/medsiglip-448` 영상 인코더와 저장된 선형 분류층이 **모두 포함**된다. `checkpoint_bytes` 약 25 KB는 분류층 파일만의 크기다. 실제 로드된 매개변수는 각 조건 878,306,103개, `parameter_bytes_loaded` 1,756,623,736바이트로 보고됐다. TensorFlow/Keras 모델과 MedSigLIP은 서로 다른 프레임워크 및 정밀도 경로를 사용하므로, 같은 Colab GPU에서 측정했더라도 순수한 모델 구조의 속도 차이로 해석하면 안 된다.

### Skin 10-class: 증강 유무와 과거 초기 모델

정제 후 같은 Skin 비교에서 증강 모델의 Validation Accuracy는 `0.982`, 원본 모델은 `0.973`이다. Macro F1도 각각 `0.9820008885656606`, `0.9730455448862949`다. End-to-end p50은 증강 `282.2758660004183 ms`, 원본 `283.30165099987425 ms`다. **이번 기록에서는 증강 모델이 검증 성능에서 앞서고 실행 시간은 거의 같다.** 학습 시 증강을 적용해도 저장된 모델의 입력 크기와 구조가 같기 때문에 실행 단계에 증강 처리 비용이 추가된다는 뜻은 아니다. 약 1 ms의 실행 차이를 증강의 속도 향상 효과로 해석하지 않는다.

초기 두 모델의 Validation Accuracy는 모두 `0.9950000047683716`이지만, 정제 후 두 모델과 분할이 달라 같은 축의 승패 비교에 쓰지 않는다. ### Web Skin 5-class: 정확도 상승에 필요한 실행 비용

PMG B1·384 연구 조건은 Accuracy `0.866`, Macro F1 `0.8643216544321994`로 이 데이터의 Validation 선두지만 p50은 `419.9053944998923 ms`다. ### Hair 5-class: 강화 방법과 실행 비용

같은 Clean 데이터에서 B1·256 기준선은 Validation Accuracy `0.7755591054313099`, Macro F1 `0.7746028470442391`, p50 `399.0923975006808 ms`다. SupCon B1·256은 각각 `0.7915335463258786`, `0.7910880666407202`, `398.9703649999683 ms`다. **이 비교에서는 SupCon의 검증 지표가 높고 추론 시간은 거의 같다.** SupCon의 추가 비용은 이 결과의 과거 학습 기록에서 보이지만, 저장 모델 추론 시 별도 단계를 반드시 실행하는 것은 아니다.

현재 5-class v2인 B1·384 Adam은 Accuracy `0.7963258785942492`, Macro F1 `0.7957146810115047`, p50 `407.29406550008207 ms`다. B1·256 기준선보다 Accuracy `0.0207667731629393` 높고 p50은 `8.20166799940127 ms` 길다. 다만 두 조건은 입력 크기뿐 아니라 학습 설계가 달라 이 차이를 해상도 하나의 효과로 단정하지 않는다. 같은 B1·384의 SAM 조건은 Accuracy가 동일하지만 Macro F1 `0.7954748920799393`으로 Adam의 `0.7957146810115047`보다 낮고 p50도 `411.79105699984575 ms`로 길다. **이 기록에서는 SAM을 채택할 근거가 늘지 않았다.**

DINOv2 Small은 p50 `232.0108845001414 ms`로 위 B1 조건보다 빠르지만 Accuracy `0.7699680511182109`다. EfficientNetV2S는 Accuracy `0.7691693290734825`, p50 `593.1725049999841 ms`로 이 비교에서는 정확도와 속도 모두 B1 기준선보다 유리하지 않다. MedSigLIP은 p50 `42.624430999694596 ms`지만 Accuracy `0.7699680511182109`이며 큰 기본 모델을 로드한다. 따라서 **가장 짧은 지연 시간 하나만으로 후보를 바꿀 근거는 없다.** [Hair 5-class 대시보드](../../results/runtime_benchmark_20260928_051423/hair5_dashboard.png)는 서로 다른 시기의 초기 모델까지 포함하므로 Clean 실험들에 초점을 맞춰 읽는다.

### Hair 6-class: 경량 후보와 성능 우선 후보

이 네 조건은 같은 6-class 데이터 버전에서 비교했다. B0·256에서 원본의 Validation Accuracy는 `0.7693486590038314`, 증강은 `0.7777777777777778`이다. B1·384에서는 원본 `0.7992337164750958`, 증강 `0.7931034482758621`이다. **증강이 B0에서는 유리했지만 B1에서는 유리하지 않았다.** 따라서 증강이 모든 모델을 일관되게 개선한다고 말할 수 없다. 두 입력 크기의 추론 시간 차이에 비해 같은 모델 내 원본·증강 간 시간 차이는 작다.

선정한 경량 B0·256·증강은 Macro F1 `0.7819142733310591`, p50 `288.73898249958074 ms`, 체크포인트 `29,005,042`바이트다. 성능 우선 B1·384·원본은 Macro F1 `0.8144942091318823`, p50 `409.83297050024703 ms`, 체크포인트 `47,234,592`바이트다. 후자는 Validation Accuracy가 `0.0214559386973180`, Macro F1이 `0.0325799358008232` 높은 대신 p50은 `121.09398800066629 ms` 길다. **이번 실험은 하나가 모든 면에서 우수한 결과가 아니라, 성능과 실행 비용에 따라 두 후보가 나뉜 결과**다. ## 그림 사용 안내

각 과제별 `*_dashboard.png`, `*_tradeoff.png`, `*_metrics_overview.png`가 [`results/runtime_benchmark_20260928_051423`](../../results/runtime_benchmark_20260928_051423/)에 있다. Hair 6-class의 네 조건은 같은 데이터 버전의 독립 비교라 발표용으로 가장 명료하다. Web Skin에서 초기 모델 두 조건과 다른 데이터 버전의 조건이 한 그림에 같이 있는 경우에는 비교 범위를 캡션에서 제한한다. 그림의 과거 학습 시간은 동일 장비 재측정값으로 표기하지 않는다.

- **Dashboard의 파란 막대:** 과거 Validation Accuracy. 같은 과제·분할일 때만 높낮이를 성능 차이로 읽는다. 값이 비어 있는 초기 Web Skin 조건은 실패나 0점이 아니라 기록이 없는 것이다.
- **Dashboard의 주황 막대 두 종류:** 이번 End-to-end p50과 p95. 같은 장비·코드에서 한 장을 처리하는 전형적인 시간과 느린 쪽 시간을 보여준다. 낮을수록 빠르다. 두 막대가 가깝다는 사실만으로 장기간 안정성이 입증되지는 않는다.
- **Dashboard의 초록 막대:** 과거 학습 시간이다. 일부 과거 조건에는 값이 없고, 서로 다른 날짜·환경의 학습 시간을 34개 전체의 학습 효율 순위로 해석하지 않는다.
- **Trade-off 산점도:** 오른쪽으로 갈수록 이번 지연 시간이 길고, 위로 갈수록 과거 Validation Accuracy가 높다. **같은 분할의 모델끼리** 왼쪽 위에 가까운 조건을 찾을 때 유용하다. 각 점은 하나의 저장 모델 조건이지, 반복 실험의 신뢰구간이 아니다.
- **Metrics overview 왼쪽 색 지도:** 열별 최솟값·최댓값으로 색을 정규화했다. 진한 파랑은 그 열에서 값이 높다는 뜻이며 **좋다는 뜻이 아니다**. Accuracy는 높으면 좋지만 지연 시간과 학습 시간은 낮을수록 비용이 적다. 서로 다른 열의 색 농도를 같은 단위로 비교하지 않는다.
- **Metrics overview 오른쪽 상자그림:** 한 과제에 포함된 **여러 모델의** 지연 시간 분포다. 단일 모델의 30회 반복 측정 변동이나 안정성을 뜻하지 않는다. 포함된 모델 종류에 따라 상자 모양이 달라진다.

## 남은 일

이번 결과로 로드 가능성과 동일 Colab 환경에서의 실행 시간 비교는 확인했다. 로드맵 12단계를 완전히 마치려면 GPU 제품명과 메모리 최대 사용량을 기록하고, 실제 사용할 장비가 정해졌을 때 같은 입력 처리 경로로 다시 측정해야 한다. 현재 후보 선정 자체를 이번 지연 시간만으로 바꾸지 않는다.
