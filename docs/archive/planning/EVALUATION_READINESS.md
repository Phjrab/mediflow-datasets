## 분할 검증의 한계

현재 전처리 스크립트에는 이미지 목록의 무작위 선택·분할과 Train 증강 코드가 있다.
그러나 이 코드만으로 저장 모델에 실제 사용된 데이터의 분할이 동일했다고 입증할 수 없다.
사람·병변·촬영 세션 식별 정보와 원본/증강 이미지의 연결 기록도 확보하지 못했다.

따라서 같은 사람이나 병변, 촬영 세션, 중복 이미지, 증강 파생 이미지가 학습용과
평가용에 함께 들어갔는지 아직 검증하지 못했다. 파일명이 다르거나 분할 후 증강했다는
사실만으로 이러한 겹침이 없다고 판단하지 않는다. 원본을 다시 무작위로 나누는 것은
원래 Test 세트 재현이 아니므로 이번에는 전처리를 실행하지 않았다.

## 평가 전에 맞춰야 할 처리 조건

세 학습 노트북은 `tf.keras.utils.image_dataset_from_directory`로 평가 이미지를 읽는다.
현재 `src/mediflow_datasets/evaluation.py`는 `inference.py`의 Pillow 기반 이미지 읽기,
EXIF 방향 보정, 크기 변경을 사용한다. 서로 다른 구현이므로 입력 픽셀이 동일하다고
가정할 수 없다. 실제 지표 차이는 아직 측정하지 않았다.

평가 재현 시에는 원래 노트북의 이미지 읽기와 크기 변경 조건을 맞추고, 결과 JSON의
클래스 순서를 유지해야 한다. 현재 저장 모델에는 내부 `Rescaling(1/255)`이 있으므로
외부에서 `/255.0`을 추가하지 않는다. 이번에는 실행 코드를 변경하지 않았다.

## 다음 실행 순서 — 아직 수행하지 않음

1. 원래 사용한 ZIP 또는 압축 해제 폴더의 접근 가능한 위치를 확보한다.
   분할 검증에는 Test뿐 아니라 Train/Validation과 식별·분할 기록도 필요하다.
2. 원본을 보존하면서 파일 목록, 클래스별 수량, 파일 내용의 식별값을 기록한다.
   original/augmented의 Test 동일 여부와 분할 간 중복을 점검하고 식별 정보의 한계를 남긴다.
3. 원래 평가 입력 처리와 현재 코드를 대조해 재현 경로를 맞추고 필요한 테스트를 실행한다.
4. 모델과 설정을 고정한 상태로 6개 모델을 평가해 새 보고서에 저장한다.
   기존 결과는 덮어쓰지 않고, 기존 보고서의 기록 정밀도를 고려해 차이를 설명한다.
   Test 결과를 보고 모델이나 설정을 반복 조정하지 않는다.

현재 막힌 지점은 원래 데이터에 접근할 수 없다는 점이다. 사용자가 해당 ZIP 또는
압축 해제 폴더의 로컬 경로나 접근 가능한 Drive 링크를 알려주면 데이터 확인을 이어갈 수 있다.
이번 점검에서는 평가·학습·성능 측정·커밋·푸시를 수행하지 않았다.
