# MediFlow 1차 프로젝트 정리

## 1. 발표 목적

이번 1차 작업의 목적은 기존 피부·두피 이미지 분류 연구 결과를 변경하지 않으면서,
앞으로 모델 성능 개선 실험을 안전하고 반복 가능하게 수행할 수 있는 프로젝트 기반을
만드는 것이다.

이번 단계에서는 모델을 새로 학습하지 않았다. 기존 모델이 정상적으로 동작하는지 확인하고,
추론·평가·전처리 코드를 협업 가능한 형태로 정리하는 데 집중했다.

## 2. 프로젝트 구성

MediFlow에는 입력 장비와 대상이 서로 다른 세 가지 EfficientNet-B0 이미지 분류 모델이 있다.

| 모델 이름 | 입력 환경 | 클래스 수 | 용도 |
|---|---|---:|---|
| `skin` | USB 현미경 | 10 | 피부 병변 분류 |
| `web_skin` | 웹캠 | 5 | 얼굴 피부 상태 분류 |
| `hair` | USB 현미경 | 5 | 두피 상태 분류 |

각 모델에는 Original과 Augmented 버전이 있으므로 현재 보존된 모델은 총 6개다.
세 모델은 촬영 장비와 클래스 구성이 다르기 때문에 하나의 클래스 목록으로 합치지 않고
각각 독립적으로 관리한다.

## 3. 기존 코드에서 확인한 문제

### 3.1 추론 입력의 이중 정규화

저장된 EfficientNet 모델 안에는 픽셀 값을 255로 나누는 `Rescaling(1/255)` 계층이 이미
포함되어 있다. 그런데 기존 팀 안내 문서에서는 이미지를 모델에 넣기 전에 다시 `/255.0`을
적용하고 있었다.

이 방식은 같은 정규화를 두 번 수행하기 때문에 학습 때와 다른 범위의 값이 모델에 들어갈 수
있다. 이번 작업에서는 외부 `/255.0` 처리를 제거하고, 0~255 범위의 RGB `float32` 데이터를
그대로 모델에 전달하도록 수정했다.

### 3.2 개인 컴퓨터 경로 의존

기존 전처리 스크립트에는 `C:\\...` 형식의 개인 PC 경로가 직접 적혀 있었다. 다른 팀원이
실행하려면 소스 코드를 직접 바꿔야 하므로 협업과 재현이 어려웠다.

이를 `--source`와 `--output` 명령행 옵션으로 변경했다. 이제 코드를 수정하지 않고 실행할 때
입력 폴더와 출력 폴더를 지정할 수 있다.

### 3.3 출력 폴더 자동 삭제 위험

기존 전처리 과정에는 결과 폴더를 삭제하고 다시 만드는 코드가 있었다. 실수로 기존 결과를
잃지 않도록 기본 동작에서는 삭제하지 않고, 사용자가 명시적으로 `--overwrite`를 입력한
경우에만 기존 출력 폴더를 삭제하도록 변경했다.

### 3.4 실행 및 검증 방법 부족

기존 연구 자료에는 모델과 노트북이 있었지만, 저장소 루트에서 설치하고 추론·평가·테스트하는
통일된 방법이 부족했다. 또한 모델 출력 개수와 클래스 순서가 일치하는지 자동으로 검사하는
테스트가 없었다.

## 4. 이번에 구현한 내용

### 4.1 단일 이미지 추론 CLI

이미지 경로와 모델 종류를 입력하면 예측 클래스와 확률을 JSON으로 반환하는 명령을 만들었다.

```powershell
mediflow-infer hair "이미지경로.jpg"
```

필요한 경우 Original 모델도 선택할 수 있다.

```powershell
mediflow-infer hair "이미지경로.jpg" --variant original
```

### 4.2 데이터셋 평가 CLI

클래스별 폴더로 구성된 Test 데이터를 지정하면 다음 항목을 계산하도록 구현했다.

- Accuracy
- Macro F1
- 클래스별 Precision, Recall, F1, 이미지 수
- Confusion Matrix
- 모델과 클래스 순서가 포함된 결과 JSON

```powershell
mediflow-evaluate hair "테스트데이터폴더" --variant augmented
```

평가 JSON도 `--overwrite`가 없으면 기존 파일을 덮어쓰지 않는다.

### 4.3 실행 환경 고정

기존 `.keras` 모델과의 호환성을 위해 다음 환경을 `pyproject.toml`에 기록했다.

- Python 3.10 이상, 3.14 미만
- TensorFlow 2.20.0
- Keras 3.13.2

### 4.4 자동 테스트와 GitHub Actions

다음 내용을 자동으로 확인하는 테스트를 추가했다.

- Original/Augmented를 포함한 모델 6개가 정상적으로 열리는지
- 각 모델의 출력 차원과 클래스 개수가 일치하는지
- 모델 내부에 정규화 계층이 있는지
- 추론 코드가 외부 `/255.0`을 적용하지 않는지
- 결과 JSON의 클래스 순서와 추론 결과의 순서가 일치하는지
- 평가 지표와 Confusion Matrix가 올바른 형태로 생성되는지

GitHub Actions도 추가하여 GitHub에 코드가 올라오면 정적 검사와 테스트를 자동으로 실행할
수 있도록 구성했다.

### 4.5 협업 문서

- 루트 `README.md`: 설치, 추론, 평가, 전처리, 테스트 방법
- `AGENTS.md`: Codex가 지켜야 할 데이터 보존 및 진행 보고 규칙
- `docs/ROADMAP.md`: 모델 개선 단계와 완료 기준
- `docs/TASK_PROMPT_TEMPLATE.md`: 다음 Codex 작업에 사용할 공통 프롬프트

## 6. 현재 상태와 한계

- 모델 재학습 및 Fine-tuning은 아직 수행하지 않았다.
- 기존 연구 결과에 기록된 Hair Augmented Test Accuracy `69.10%`는 앞으로 비교할 기준값이며,
  이번 작업에서 새로 측정한 성능이 아니다.
- 실제 장비로 새로 촬영한 소규모 검증 데이터는 아직 없다.
- 공개 데이터와 실제 장비 이미지 사이의 Domain Gap 분석도 아직 시작하지 않았다.
- 현재 변경 내용은 코드 기반을 정리한 1차 결과이며, 모델 성능 향상 결과가 아니다.

## 7. 다음 단계

우선 데이터 크기가 가장 작고 기존 성능 개선 여지가 확인된 `hair` 모델부터 실험한다.

첫 번째 실험에서는 비교 원인을 명확하게 하기 위해 한 가지 조건만 변경한다.

| 구분 | 설정 |
|---|---|
| 변경하는 조건 | EfficientNet 후반부 일부 Fine-tuning |
| 고정하는 조건 | 224 해상도, 데이터 분할, 증강, Loss, 평가 Test 세트 |
| 초기 모델 | 기존 Hair Augmented `best_model.keras` |
| 초기 학습률 후보 | `1e-5` |
| BatchNormalization | 고정 |
| 결과 저장 | 기존 파일을 덮어쓰지 않고 새 실험 폴더 사용 |

진행 순서는 다음과 같다.

1. Google Drive의 Hair 데이터 위치를 Colab에서 자동 확인한다.
2. ZIP 파일을 Colab 임시 공간으로 복사하고 코드가 자동 압축 해제한다.
3. 동일 Test 데이터에서 기존 모델 평가를 다시 실행한다.
4. 기존 Augmented 모델의 EfficientNet 후반부 일부만 학습 가능하게 변경한다.
5. 낮은 학습률로 Fine-tuning하고 가장 좋은 모델을 새 Drive 폴더에 저장한다.
6. 같은 Test 데이터에서 기준 모델과 새 모델을 비교한다.
7. 이후 224/256 해상도 비교와 증강·Loss·Backbone 실험을 각각 분리해 진행한다.

## 8. 발표용 핵심 요약

> 1차 작업에서는 기존 모델의 성능을 임의로 바꾸거나 재학습하지 않고, 연구 결과를 안전하게
> 재현할 수 있는 실행 기반을 구축했다. 이중 정규화와 개인 PC 경로 의존 문제를 수정했고,
> 세 종류의 모델을 한 줄 명령으로 추론·평가할 수 있게 만들었다. 6개 모델 로드와 클래스 순서,
> 입력 전처리를 포함한 자동 테스트 23개가 모두 통과했다. 다음 단계에서는 Hair 모델을 대상으로
> 다른 조건은 고정하고 부분 Fine-tuning만 적용해 기존 기준 성능과 비교할 예정이다.

## 9. 예상 질문과 답변

### Q. 이번에 모델 정확도가 올라갔는가?

아니다. 이번 단계는 성능 개선 전의 기반 정리 단계다. 추론 오류 가능성을 제거하고 동일한
방법으로 평가할 수 있는 환경을 먼저 만들었다.

### Q. 왜 `/255.0`을 제거했는가?

저장된 모델 내부에서 이미 같은 정규화를 수행한다. 외부에서도 나누면 학습 때보다 지나치게
작은 값이 입력되므로 제거했다.

### Q. 왜 Hair 모델부터 실험하는가?

Drive 데이터 ZIP이 세 데이터 중 가장 작아 Colab에서 반복 실험하기 쉽고, 기존 연구 결과의
Augmented Test Accuracy가 69.10%로 기록되어 있어 개선 여부를 확인할 여지가 크기 때문이다.

### Q. 왜 여러 개선 방법을 한꺼번에 사용하지 않는가?

Fine-tuning, 해상도, 증강, Loss를 동시에 바꾸면 어떤 변경이 성능에 영향을 줬는지 알 수 없다.
한 실험에서 하나의 조건만 바꿔야 결과를 설명하고 재현할 수 있다.

### Q. 기존 연구 자료는 안전한가?

기존 이미지, `.keras` 모델, 노트북, 결과 JSON/CSV는 삭제하거나 수정하지 않았다. 새 실험도
별도 폴더에 저장하여 기존 결과를 보존할 계획이다.
