# MediFlow 피부 두피 이미지 분류 연구 단계별 상세 보고서

기준일: 2026-09-30  
범위: 초기 데이터 수집과 첫 학습부터 데이터 정제, 논문 기반 개선, Hair 6클래스, 34개 저장 모델의 Colab 실행 비용 비교까지  
문서 성격: 기존 연구·실험 기록을 발표의 1~4차 흐름으로 재구성한 상세 보고서. 새로운 학습 또는 재측정 결과가 아니다.

이 보고서는 수행한 일을 날짜상 8주로 배분하지 않고 **연구 단계 네 개**로 설명한다. 초기에 정확한 작업 시작일과 달력상 주차가 모두 확인된 것은 아니므로, 1차부터 4차는 발표와 연구 전개의 순서를 뜻한다. 수치는 당시 보존된 보고서·평가 파일의 값이며 새로 계산하거나 반올림하지 않았다. 같은 과제의 모델은 Validation으로 선택하고 고정 Test로 평가한 기록을 구분한다. 현미경 피부 `skin`, 얼굴 사진 `web_skin`, 현미경 두피 `hair`는 서로 다른 입력·클래스·평가 과제다.

## 단계별 전체 흐름

## 1차 초기 데이터 선정과 첫 분류 모델

이 단계는 [1차 발표 자료](../presentation/1차/내용.md)의 범위와 같은 순서로 구성했다. Web Skin은 이 단계의 후반에 별도 분류 과제로 학습했고, Hair 6클래스나 정제 후 결과를 초기 계획에 소급하지 않았다.

### 데이터 조사와 분류 과제 확정

#### 목표와 판단 이유

기존 안구 모델을 피부·두피로 넓히려면 먼저 **사진 한 장에 무엇이 보이는가**를 분리해야 했다. USB 현미경 피부 병변에서는 작은 표면과 경계가 중요하고, 웹캠 얼굴에서는 얼굴 전체에 퍼진 색과 위치가 중요하며, USB 현미경 두피에서는 모발·모공·각질·피지의 확대 질감이 중요하다. 하나의 `skin` 모델로 세 입력을 처리하면 촬영 배율과 정답 클래스의 의미가 섞인다. 그래서 `skin` 10종, `web_skin` 5종, `hair` 5종을 별도로 정의했다. 실제 호출 때에도 **장비와 촬영 부위를 함께** 확인해야 한다.

#### 실제 수행 내용

| 대상 | 원천 및 당시 알려진 규모 | 초기 학습에 택한 범위 | 선별 판단 |
|---|---|---|---|
| Skin | [AI Hub 71864 피부종양 이미지 합성 데이터](https://www.aihub.or.kr/aihubdata/data/view.do?currMenu=115&topMenu=100&dataSetSn=71864), 15종·약 15,000장 | 10종, 각 900장, 합계 9,000장 | 사진을 직접 보며 구별이 어려운 원천 클래스를 제외 |
| Hair | [AI Hub 216 유형별 두피 이미지](https://aihub.or.kr/aihubdata/data/view.do?dataSetSn=216), 고유 이미지 101,027건으로 기록 | 증상 5종 × 2,900장 = 14,500장 | 중등도·중증 중심, 작은 클래스 수량에 맞춰 균형화. 모낭홍반/농포는 모낭사이홍반과 비슷해 제외 |
| Web Skin | [AI Hub 71863 안면부 피부질환 이미지 합성 데이터](https://www.aihub.or.kr/aihubdata/data/view.do?currMenu=115&topMenu=100&dataSetSn=71863), 정면·측면 포함 6종·약 12,000장으로 기록 | 1차 초기에는 후속 과제로 검토; 이후 정면 5종 × 900장 = 4,500장 | 얼굴 전체용 별도 분류기를 계획. 주사와 비슷해 보이는 지루성 피부염을 제외 |

Skin의 선택 클래스는 기저세포암·편평세포암·보웬병·광선각화증·지루각화증·흑색점·표피낭종·사마귀·피부섬유종·혈관종이다. 원천 15종 중 악성흑색종·멜라닌세포모반·피지샘증식증·화농육아종·비립종은 첫 학습에서 쓰지 않았다. Hair 5종은 모낭사이홍반·미세각질·비듬·탈모·피지과다다. Web Skin은 후속 첫 학습에서 건선·아토피·여드름·정상·주사를 사용했다. 이 시점에 **Hair `양호` 6클래스나 Web Skin 학습 완료를 소급해서 쓰지 않는다.**

#### 결과와 해석

촬영 방식이 다른 세 문제의 데이터 범위와 클래스 목록을 확정했다. 다만 원천 전체 ZIP은 현재 로컬에 없어 AI Hub의 원천 규모와 당시 선택 수량은 **기록된 값**이다. Skin의 각 클래스에서 쓰지 않은 약 100장에 대한 사진별 제외 사유도 남아 있지 않다. Hair 원천의 101,027건을 다섯 클래스에 단순 분배하거나 여러 증상 라벨을 합산해 고유 인물 수로 해석하지 않는다.

### 심화 기록 출처와 클래스 선정 과정

#### 1. 왜 피부 사진을 한 모델에 모두 넣지 않았는가

처음에는 기존 안구 AI의 이미지 분류 방식을 피부와 두피로 확장한다는 목표가 있었다. 하지만 피부라는 단어 하나로 모든 이미지를 묶으면 입력 단위가 달라진다. 현미경 피부 병변에서는 병변의 경계, 피부 표면의 질감, 각질, 색 변화가 한 화면에 크게 나타난다. 얼굴 정면 사진에서는 병변 하나보다 볼·코·이마의 분포, 넓은 홍반과 전체 피부색의 변화가 중요하다. 두피 현미경에서는 모발이 화면을 가로지르고, 모낭 주변 피부와 각질·피지의 세밀한 패턴이 관찰된다. 따라서 장비와 부위를 함께 식별해 각 과제의 클래스와 전처리를 분리했다. 이 구분은 학습 편의만이 아니라 이후 실사용 화면에서 잘못된 모델을 호출하지 않기 위한 계약이다.

데이터 조사 과정에서는 Kaggle과 AI Hub를 살펴봤지만 첫 학습의 세 원천은 앞 표의 AI Hub 데이터로 정리됐다. **원천 규모, 선별 후보 수, 실제 첫 Train/Validation/Test 사진 수는 서로 다른 값**이다. 예를 들어 Skin의 15종 약 15,000장은 원천 설명, 10종 9,000장은 처음 구성한 과제, 7,300/1,000/700은 그 과제의 분할이다. Hair의 101,027건 역시 처음 사용한 14,500장과 동일한 모집단 수가 아니다. 복수 증상 라벨이 가능한 원천을 클래스별 숫자로 단순 합산하지 않았다.

#### 2. Skin 열 클래스를 왜 골랐는가

Skin에서는 피부종양 이미지 합성 데이터의 원천 15종을 살펴본 후, 현미경 확대 사진에서 다룰 열 클래스를 골랐다. 악성흑색종·멜라닌세포모반·피지샘증식증·화농육아종·비립종 다섯 종은 첫 10종 과제에 포함하지 않았다. 당시 직접 사진을 검수하며 시각적으로 비슷한 항목을 제외한다는 판단을 했다. 다만 지금 남은 기록에는 **제외 사진 한 장마다 어떤 기준으로 뺐는지**를 표시한 검수표가 없다. 따라서 이 선택을 전문가 합의나 임상적 구분 가능성 검증으로 서술할 수 없다. 열 클래스 각각에서 약 900장을 사용한 첫 구성의 근거와 원천의 클래스당 약 1,000장 설명도 구분해서 쓴다.

#### 3. Hair와 Web Skin 범위를 왜 다르게 만들었는가

Hair 원천은 처음 여섯 증상 후보를 고려했지만 모낭홍반/농포와 모낭사이홍반의 사진이 유사하다는 검토 후 모낭홍반/농포를 제외했다. 다섯 클래스 수를 비듬 후보 2,900장에 맞춰 균형화했다. 이는 같은 수의 사진을 사용해 첫 분류 비교를 하려는 설계였지, 원천 각 증상의 실제 발생률이 같다는 뜻은 아니다. 뒤의 6클래스에서 추가된 `양호`는 여기서 제외한 모낭홍반/농포와 무관한 **새 정의와 새 사진 묶음**이다.

Web Skin 원천에는 정면과 측면 이미지가 있었지만 얼굴 전체 질환을 웹캠으로 본다는 사용 장면을 생각해 정면 중심 과제로 좁혔다. 주사와 지루성 피부염은 시각적으로 구분이 어렵다고 판단해 지루성 피부염을 첫 다섯 클래스에서 제외했다. 정면·측면을 함께 사용하면 동일 인물의 두 각도가 분할을 넘나들 가능성도 살펴야 했지만 당시 사람 식별 기록이 충분하지 않았다. **1차 데이터 선정 발표 장면에서는 Web Skin은 아직 후속 후보**라는 시간 순서를 유지한다. 첫 Web Skin 학습은 다음 단계의 결과다.

#### 4. 보고서에 남겨야 하는 확인 수준

AI Hub 소개 페이지의 데이터 규모를 그때의 실제 다운로드 파일 수나 지금 로컬에서 새로 계수한 수라고 쓰지 않는다. 동일 사람이 여러 파일에 있는지, 선택 사진의 전문가 재판독이 있었는지도 이 단계의 완료 항목이 아니다. 당시 클래스 선별과 첫 학습의 목적은 **분류할 영상 범위와 답의 종류를 정하는 것**이었다. 이후의 데이터 감사·현장 사진 검증이 이 선택의 품질을 더 확인해야 한다.

### 분할·증강 설계와 Skin 첫 모델

#### 목표와 방법

원본 사진을 Train·Validation·Test로 나눈 뒤 **Train에만 증강본을 추가**했다. 증강은 밝기·각도·색·초점 변화에 견디는지 시험하려는 변형이지 새로운 사람이나 병변을 확보하는 작업이 아니다. Validation과 Test는 원본 사진으로 두어 같은 평가 기준을 유지했다. 첫 모델은 [EfficientNet](https://proceedings.mlr.press/v97/tan19a.html) B0의 ImageNet 가중치를 출발점으로 하고, 기존 특징 추출부를 고정한 채 새 분류층을 학습했다. 이는 일반 사진에서 배운 특징을 제한된 의료 이미지에 옮기는 전이학습이다.

#### 실제 수행 내용

| 대상 | 초기 원본 Train / Val / Test | 초기 증강 Train | 구현한 변형 |
|---|---:|---:|---|
| Skin | 7,300 / 1,000 / 700 | 당시 설명과 현재 코드의 생성 수가 달라 첫 실행의 정확한 생성 장수 미확정 | 좌우 반전, ±10° 회전, 밝기·대비, 화이트밸런스·감마, 블러·노이즈·JPEG 열화·약한 원근 중 한 가지 |
| Web Skin | 3,600 / 500 / 400 | 원본 3,600 + 생성 3,600 = 7,200 | 반전·회전·색·밝기·블러·노이즈·JPEG·약한 확대에서 1~3개 조합 |
| Hair | 11,600 / 1,450 / 1,450 | 원본 11,600 + 생성 5,800 = 17,400 | 약한 회전·반전·밝기·대비·색·블러·노이즈·crop을 확률적으로 조합 |

초기 증강은 학습 중 실시간 생성이 아니라 **변형된 사진을 파일로 저장하는 오프라인 방식**이었다. Skin의 [전처리 코드](../scripts/preprocess_skin.py), [Web Skin 코드](../scripts/preprocess_web_skin.py), [Hair 코드](../scripts/preprocess_hair.py)에 변형 범위가 남아 있다. 예를 들어 Hair는 회전 ±8°, 밝기 0.82–1.18배와 대비 0.85–1.15배처럼 미세 단서가 사라지지 않도록 비교적 약하게 설정했다. `Original`은 원본 Train만, `Augmented`는 **원본과 생성본을 함께** 사용한다는 뜻이다.

Skin은 ImageNet B0·224에서 backbone을 고정하고 15 epoch 동안 분류층을 학습했다. 원본과 증강 조건 모두 당시 Validation Accuracy 약 `0.995`로 저장됐고 Test Accuracy는 각각 `0.9942857027053833`, `0.9957143068313599`였다. 이때의 높은 점수는 초기 분할의 기록이며, 뒤에 발견한 완전 동일 이미지 중복을 고려하면 최종 실사용 성능으로 제시할 수 없다. 또한 현재 보존 코드의 Skin 기본 생성 수와 당시 설명의 생성 수가 다르므로 하나로 합쳐 적지 않는다.

#### 방향 변경

한때 YOLO로 병변을 찾고 잘라 Skin 분류기에 넣는 방안을 검토했지만, 병변의 범위가 불분명하거나 얼굴 전체에 증상이 퍼진 경우를 작은 crop 하나로 설명하기 어렵고 라벨링도 실패·중단됐다. 따라서 **현미경 피부 Skin과 얼굴 전체 Web Skin을 별도 과제**로 유지했다. YOLO 검출 성능을 수치 실험으로 입증한 것은 아니다.

### 심화 기록 원본·증강본과 첫 학습 조건

#### 1. 세 분할의 역할

Train은 모델 가중치를 바꾸는 사진, Validation은 학습 중 모델·체크포인트를 고르는 사진, Test는 고정된 후보의 결과를 보고하는 사진으로 구분했다. 증강 사진은 Train 원본의 **파생본**이므로 처음부터 Val/Test에도 섞으면 새 원본을 평가한다는 목적이 흐려진다. 당시에는 먼저 분할하고 Train에서만 생성 파일을 만드는 오프라인 증강을 선택했다. 이후 정제 단계에서 과거 증강본의 출처가 불분명했던 것이 실제 문제가 되었으므로, 이 순서 자체와 증강본의 원본 연결 기록이 중요하다.

Skin 초기 분할은 10종 합계 원본 Train 7,300, Val 1,000, Test 700장이었다. 전처리 구현은 좌우 반전, ±10° 회전, 밝기 증감, 대비 0.85–1.15, 화이트밸런스, 감마, 가우시안·모션 블러, 노이즈, JPEG 압축 열화, 약한 원근 변형 중 한 변형을 무작위로 골랐다. 조명·각도·초점·이미지 압축에 따른 픽셀 변화를 연습시키려는 설정이다. 그러나 옛 서술의 `730 원본+470 생성=클래스당 1,200 Train`과 현재 코드 기본값 `730+730=1,460 Train`은 **동일한 실행의 확정된 한 수치가 아니다.** 초기 모델의 실제 증강 파일 목록을 지금 재계수할 manifest가 없어 표에는 생성 장수를 미확정으로 두었다.

Web Skin은 원본 Train 3,600, Val 500, Test 400을 사용했다. 증강 Train은 3,600장에 생성 3,600장을 더한 7,200장이다. 전처리에서는 회전 ±7°, 밝기 0.75–1.25, 대비 0.80–1.20, 채도 0.85–1.15, 색온도, 약한 blur·noise, gamma·JPEG, 1.02–1.08 크기의 확대/crop 등 서로 다른 변형 1~3개를 골랐다. 개수의 선택 가중치는 1개 45%, 2개 40%, 3개 15%였다. 여러 변형을 섞은 이유는 웹캠의 거리·조명·압축 환경을 한 가지만으로 표현하기 어렵기 때문이다. 다만 지나친 색 변형이 실제 병변 색을 바꾸거나 crop이 단서를 자를 수 있어 **효과는 Validation으로 확인해야 하는 가설**이었다.

Hair은 첫 원본 Train 11,600, Val 1,450, Test 1,450이고 증강 Train은 원본 11,600+생성 5,800=17,400장이었다. 구현된 변형은 회전 ±8°(적용 확률 65%), 반전 25%, 밝기 0.82–1.18(75%), 대비 0.85–1.15(65%), 색 0.90–1.10(35%), 약한 blur와 noise 각 25%, crop 30%를 조합하는 방식이었다. 두피 사진은 모낭과 작은 각질 입자의 존재가 분류 근거일 수 있어 강한 변형보다 약한 변형을 우선했다. 각 클래스의 원본과 파생 사진은 **이미지 파일 수로는 증가해도 독립 인물 수가 증가하지 않는다.**

#### 2. 첫 EfficientNet-B0가 실제로 한 일

첫 학습은 `ImageNet 사전학습 B0 → 기존 특징층 고정 → 새 분류층 학습`의 head-only 방식이었다. Skin·Web Skin·Hair의 출력층은 각각 10·5·5개 답에 맞게 새로 구성했다. 대부분의 저장 기록은 224×224, 배치 32, 15 epoch를 사용한다. 원본과 증강 Train의 모델은 **학습 사진 구성**이 다르며 같은 모델의 중간·최종 epoch가 아니다. Validation Accuracy가 최고인 시점의 가중치를 저장해 마지막 학습 회차가 우연히 나쁜 경우를 피했다. 일반 이미지 사전학습과 의료 사진 전이 사이의 목적은 [EfficientNet 원논문](https://proceedings.mlr.press/v97/tan19a.html)의 네트워크 크기 설계를 이용해 기준 분류기를 만드는 것이지 그 논문의 의료 성능을 따라 만든 것이 아니다.

첫 Skin 결과는 Original과 Augmented가 Validation Accuracy `0.9950000047683716`으로 같고, Test Accuracy는 Augmented가 `0.9957143068313599`로 조금 높았다. 그렇다고 당시 완전 동일 이미지 감사 전에 이를 실제 사진 일반화가 99.6%라고 해석할 수는 없다. 사진이 Train·Val·Test 사이에 반복되는지 다음 단계에서 별도로 확인해야 했다. Web Skin과 Hair에 대해서는 1차 후반에서 같은 구조의 초기 원본·증강 비교를 이어 설명한다.

#### 3. YOLO 제안이 왜 멈췄는가

Skin 병변을 YOLO로 찾아 자른 다음 10종 분류기를 적용하면 얼굴 사진에도 사용할 수 있지 않을까 검토했다. 그러나 넓게 퍼지는 얼굴 질환은 하나의 작은 사각형 경계로 표현하기 어렵고, 병변 표시는 실제 라벨링 과정에서 실패·중단됐다. 그래서 이 안을 성공한 객체 검출 실험으로 적지 않았다. 촬영 배율과 분류 범위가 다른 얼굴 사진은 후속 Web Skin 전문 모델로 이어졌다. 이 방향 변경은 **모델 구조와 데이터 정의를 다시 생각한 결과**다.

### Web Skin·Hair 첫 학습과 문제 정의

#### 목표와 실제 수행 내용

Skin에서 높은 저장 점수를 얻었지만 웹캠 얼굴과 두피 확대 사진은 특징이 다르므로 따로 학습했다. Web Skin은 정면 얼굴 5종에 대해 원본과 증강 Train의 B0·224 head-only 모델을 비교했다. Hair도 초기 5종에 원본과 증강 조건을 비교했다. 마지막 epoch만 쓰지 않고 Validation이 가장 좋았던 가중치를 보존했다. 초기 모델의 입력은 대체로 224×224, 배치 32, head-only 15 epoch였지만 Skin과 Web Skin/Hair의 학습률 기록이 같다고 가정하지 않는다.

| 초기 결과 | Validation Accuracy | Test Accuracy | Test Macro F1 | 읽을 수 있는 결론 |
|---|---:|---:|---:|---|
| Web Skin 원본 B0·224 | `0.6679999828338623` | `0.7850000262260437` | `0.7833125866587888` | 얼굴 분류가 Skin보다 어려운 과제로 나타남 |
| Web Skin 증강 B0·224 | `0.6880000233650208` | `0.8199999928474426` | `0.8195818185502844` | 같은 초기 분할에서는 증강 조건이 높음 |
| Hair 원본 B0·224 | 원본 보고서 참조 | `0.6841` | 원본 보고서 참조 | 유사한 두피 질감의 구별에 한계 |
| Hair 증강 B0·224 | 원본 보고서 참조 | `0.6910` | 원본 보고서 참조 | 증강만으로 큰 개선이 없음 |

Hair의 비듬·미세각질·피지과다 등은 가까운 질감으로 보였고 Web Skin은 얼굴의 넓은 색 변화와 국소 병변을 함께 봐야 했다. **서로 다른 분류기의 점수를 직접 우열로 비교하지 않는다.** 초기 Hair의 두 Test Accuracy는 [초기 결과 정리](../presentation/1차/내용.md)에 반올림되어 기록된 값이며 이 문서에서 더 정확한 자릿수를 만들지 않았다.

#### 얻은 결론과 다음 질문

첫 모델의 점수를 단순히 더 올리기 전에 **같은 사진이 학습과 평가에 함께 들어 있지는 않은지** 확인해야 했다. 동일·파생 사진이 분할을 넘나들면 점수가 높아도 처음 보는 사진에서 잘한다는 근거가 약해진다. 이 문제 제기가 다음 데이터 감사와 Clean 분할의 출발점이었다.

### 심화 기록 초기 여섯 모델의 수치와 오류 해석

#### 1. 원본 대 증강의 전체 초기 결과

각 도메인의 Original과 Augmented 총 여섯 모델은 아래처럼 기록됐다. 이 표는 **정제 전 첫 데이터 분할의 보존된 결과**로, 뒤의 Clean 모델 점수와 같은 Test 점수 차트에 올려 개선률을 계산하지 않는다.

| 초기 모델 | Val Accuracy | Test Accuracy | Test Macro F1 | 무엇을 관찰했나 |
|---|---:|---:|---:|---|
| Skin Original B0·224 | `0.9950000047683716` | `0.9942857027053833` | 저장 결과 없음 | 높은 숫자가 먼저 나왔으나 데이터 검사 전 |
| Skin Augmented B0·224 | `0.9950000047683716` | `0.9957143068313599` | 저장 결과 없음 | 차이는 작고 Test 누수 점검이 필요 |
| Web Skin Original B0·224 | `0.6679999828338623` | `0.7850000262260437` | `0.7833125866587888` | 얼굴 질환 구분 부족 |
| Web Skin Augmented B0·224 | `0.6880000233650208` | `0.8199999928474426` | `0.8195818185502844` | 증강 쪽이 낫지만 Val은 여전히 낮음 |
| Hair Original B0·224 | `0.7062069177627563` | `0.6841379310344827` | `0.6827345904185209` | 유사한 두피 미세 질감에서 낮음 |
| Hair Augmented B0·224 | `0.704827606678009` | `0.6910344827586207` | `0.6894861696407794` | Test는 소폭 높으나 Val은 오히려 소폭 낮음 |

Web Skin과 Hair는 같은 B0 계열이라고 해도 입력 영상의 크기, 답의 의미, 데이터 출처와 개수가 다르다. Skin이 높은 정확도이고 Hair가 낮다고 해서 **Skin 모델이 더 우수한 구조**라는 결론을 내릴 수 없다. Hair에서는 비듬·미세각질처럼 흰 조각과 피부 반사가 비슷하게 보였고, 피지과다도 조명 반사에 영향을 받는다는 분석을 남겼다. Web Skin에서는 얼굴 전체 분포와 작은 병변이 섞여 있고 얼굴 정면의 색 변화가 함께 작용한다는 점이 실험 설계의 출발점이 됐다. 이는 오류에 대한 가설이며 사람/촬영 조건별 실측 분석이 끝났다는 뜻은 아니다.

#### 2. 증강 효과를 어떻게 읽었는가

Web Skin에서는 같은 초기 분할에서 증강 모델의 Validation과 Test 정확도·Macro F1이 높았으므로 색·조명 변형이 도움될 가능성을 확인했다. Hair에서는 증강 Test가 Original보다 높아도 Validation은 낮았다. 따라서 어느 도메인에도 “증강을 넣으면 무조건 좋아진다”는 일반 결론을 내릴 수 없었다. 증강본을 늘리면 한 epoch의 업데이트 횟수도 달라지므로 학습 계산량과 데이터 변형의 효과가 완전히 분리된 엄격한 실험은 아니었다. 이후 Clean 분할에서 원본과 파생 관계를 더 명시해야 했다.

#### 3. Skin의 높은 점수도 다시 의심한 이유

초기 Skin 점수는 약 99%로 보여 우선 유지할 만했지만, Train에서 봤던 원본 사진이나 그 파생물이 Val/Test에 있다면 새 사진을 구별한 결과가 아닐 수 있다. 특히 한 사람이 같은 병변을 반복 촬영한 경우는 파일 바이트가 달라도 평가가 쉽게 나올 수 있다. 당시 결과의 저장 보고서에는 그런 개인·병변 ID 수준의 분할 보증이 없었다. 이 때문에 낮은 점수의 Hair·Web Skin뿐 아니라 Skin까지 감사 대상으로 넣었다.

#### 4. 그때 결정한 다음 실험의 순서

성능이 낮다고 곧바로 더 큰 모델로 바꾸지 않고, **① 분할 교차 중복 확인 → ② 깨끗한 같은 분할 고정 → ③ 같은 평가 기준에서 한 조건씩 학습법 변경** 순서로 바꿨다. 초기 원본 데이터 ZIP과 당시 Test 사진은 나중에 로컬에서 보존되지 않아 여섯 모델을 당시 사진으로 다시 돌리는 방식의 완전 재현은 불가능하다. 남아 있는 결과 표와 그래프는 옛 실험의 역사 자료로 보존하되, Clean 실험의 성능 향상을 산술로 증명하는 기준선으로 쓰지 않는다.

## 2차 데이터 검증과 전이학습 최적화

초기 결과의 평가 신뢰성을 확인하고, 정제된 분할에서 학습 조건을 한 가지씩 비교한 단계다. 초기 Test와 새 Clean Test는 구성 자체가 달라서 두 점수의 차이를 특정 학습법 하나의 효과로 해석하지 않는다.

### GitHub 기반 재현 정리와 데이터 중복 감사

#### 목표와 이유

기존 결과를 팀원과 같은 의미로 읽으려면 저장 모델, 클래스 배열 순서, 입력 처리와 평가 절차를 명시해야 했다. 저장된 EfficientNet에는 내부 `Rescaling(1/255)`이 있으므로 밖에서 다시 `/255`를 하면 학습과 다른 수치가 들어간다. 모델 경로를 개인 PC에 고정하거나 전처리 결과를 자동 삭제하는 실행 방식도 재현을 어렵게 했다. 이 부분을 저장소의 상대 경로·안전한 출력 규칙·사용 안내로 정리했다. **코드·문서 정리 자체는 재학습 성과가 아니다.**

#### 실제 데이터 검사

| 도메인 | 발견한 것 | 처리 후 원본 분할 |
|---|---|---|
| Hair | 초기 Original Train–Val `195`, Train–Test `178`, Val–Test `16`의 완전 동일 파일 **교차 쌍**과 일부 라벨 충돌 | 새 5종 Clean Train `10,032`, Val `1,252`, Test `1,252`, 합계 `12,536` |
| Skin | 완전 동일 이미지 `51장`, 교차 분할 RGB 중복 및 Train 내부 반복 | Clean Train `7,249`, Val `1,000`, Test `700`, 합계 `8,949` |
| Web Skin | 사용한 검사에서 완전 동일 바이트·RGB 사진의 교차 분할 중복 미발견 | 기존 Train `3,600`, Val `500`, Test `400` 유지 |

검사에는 파일 바이트와 디코딩 RGB 픽셀의 해시를 사용했다. Hair의 `195+178+16`은 **쌍별 겹침 수**여서 389장을 지웠다는 뜻이 아니다. Hair는 원본을 정리해 분할을 다시 만들고 새 Train 원본 `10,032`장에서만 증강 `5,015`장을 만들어 Train `15,047`장으로 구성했다. 원본이 새 Val/Test에 들어간 예전 증강본을 재사용하면 누수가 되살아날 수 있기 때문이다. Skin도 Clean Train `7,249`장에 파생 이미지 `7,249`장을 더해 증강 Train `14,498`장으로 비교했다.

사람·병변·촬영 세션 식별자가 충분하지 않아 **완전 동일 사진 미발견 = 관련 사진의 모든 누수 부재**는 아니다. 초기 Test와 Clean Test도 달라 초기 점수와 Clean 점수의 차이를 단일 학습법의 효과로 계산할 수 없다. 정제 전 초기 Test 사진 자체가 지금 보존되어 있지 않아 초기 6개 모델의 당시 Test 추론을 다시 실행하지 못했다. 저장 보고서의 내부 일치성 검토와 원래 사진에 대한 재추론은 다른 작업이다.

#### 단계별 산출물

Clean 데이터 버전과 감사 보고서, 샘플 모델 입력·출력 계약, 도메인별 재현 기준을 확보했다. 선정 모델의 클래스 배열과 RGB `float32` 0–255 입력, TensorFlow bilinear resize, 외부 정규화 금지 규칙은 [모델 사용법](../results/MODEL_USAGE.md)에 기록했다. [평가 재현 점검](research/public_data/EVALUATION_REPRODUCTION_AUDIT_20260927.md)은 검증된 것과 원본 미보관으로 할 수 없는 것을 나눈다.

### 심화 기록 누수 검사, Clean 재구성과 재현 규칙

#### 1. 파일명이 아니라 내용을 비교한 이유

같은 사진을 다른 이름으로 복사하면 파일명 비교는 중복을 놓친다. 따라서 파일의 SHA-256을 계산해 **완전히 같은 바이트**인지 확인했다. 또한 이미지로 디코딩한 RGB 픽셀 해시를 비교하면 저장 형식이나 메타데이터가 달라도 보이는 픽셀이 같은 경우를 찾을 수 있다. 완전 동일 사진이 서로 다른 클래스에 들어갔다면 라벨 충돌이며, Train과 평가 사이에 있으면 누수 가능성이다. 이 검사는 필요한 첫 단계지만 crop·재압축·회전된 근사 중복, 같은 사람의 다른 프레임까지 모두 탐지하는 방법은 아니다.

Hair의 세 교차 집계 Train–Val 195, Train–Test 178, Val–Test 16은 **겹친 이미지 쌍의 수**다. 동일 사진이 세 분할 모두에 나타나면 여러 쌍에 들어갈 수 있으므로 합계 389를 제거 사진 수로 적지 않는다. 처음 14,500장과 정제 후 12,536장의 차이 1,964장 역시 이 389쌍과 같지 않다. 정제할 때는 전체 원본을 합치고 중복·라벨 충돌을 정리한 뒤 클래스별로 다시 나눴다. 정제된 Original의 수량은 다음과 같다.

| Hair 5종 클래스 | Train | Validation | Test | 전체 |
|---|---:|---:|---:|---:|
| 모낭사이홍반 | `1,990` | `248` | `248` | `2,486` |
| 미세각질 | `2,050` | `256` | `256` | `2,562` |
| 비듬 | `1,929` | `241` | `241` | `2,411` |
| 탈모 | `1,965` | `245` | `245` | `2,455` |
| 피지과다 | `2,098` | `262` | `262` | `2,622` |
| **합계** | **`10,032`** | **`1,252`** | **`1,252`** | **`12,536`** |

Hair의 증강 경로는 Train 원본 10,032장에 **새로 만든** 파생 5,015장을 더해 15,047장이다. 기존 증강본의 원본 연결이 분명하지 않아 재사용하지 않았다. 새 증강본에는 원본과 변형 기록을 남겨 추적할 수 있게 했다. 이 값은 Clean v1 기준이며 처음의 11,600+5,800=17,400장과 다른 데이터 구성이다.

Skin에서는 초기 9,000장 중 완전 동일 사진 51장을 정리해 Clean 8,949장을 만들었다. Train 7,249, Validation 1,000, Test 700이고 새 증강 조건은 7,249+7,249=14,498장이다. 교차 분할 RGB 완전 중복으로 Train–Val 10그룹, Train–Test 5그룹, Val–Test 1그룹이 확인됐다. 과거 증강 Train에도 동일 사진 반복이 있었다. Web Skin에서는 당시 수행한 파일·RGB 픽셀 감사에서 교차 분할 완전 동일 사진과 라벨 충돌을 발견하지 못해 3,600/500/400의 원본 분할을 그대로 사용했다.

#### 2. 확인하지 못한 수준을 왜 적었는가

완전 동일 파일이 0건이어도 같은 사람의 동일 병변을 몇 초 뒤 다른 각도로 찍은 사진은 남을 수 있다. 피부·두피 과제에서는 환자·병변·촬영 세션 단위 중복이 평가를 왜곡할 수 있다. 원천의 충분한 식별 메타데이터가 없어 이 수준의 누수는 **배제했다고 주장하지 않았다**. 새 Hair 6종 사진의 ID 105개는 신규 사진 안의 분할에 활용했지만 기존 5종 사진까지 같은 ID 체계로 묶어 확인한 것은 아니다.

#### 3. 왜 과거 질환 분류기에서 추가 학습하지 않았는가

초기 Hair 가중치는 옛 Train/Val/Test 분할의 사진을 이미 보았을 가능성이 있다. 새 Clean Validation/Test의 일부가 그 옛 학습 과정에 노출됐다면 이 모델을 시작점으로 이어 학습하는 비교는 공정하지 않다. 게다가 초기 Skin/Hair/Web Skin 가중치는 서로 다른 데이터 이력을 갖는다. 그래서 Clean 실험은 같은 ImageNet 초기 가중치부터 다시 시작해 각 설정의 차이를 읽도록 했다. **ImageNet EfficientNet과 기존 Hair 분류 모델은 같은 B0/B1 구조라도 학습 이력이 다르다.**

#### 4. 재현 계약이 바뀐 부분

선정 EfficientNet은 입력 RGB `float32` 0–255를 받고 모델 내부에서 `/255`를 수행한다. 저장 모델 밖에서 다시 나누면 입력이 0–1이 되어 모델 내부에서 0–0.0039로 줄어들기 때문에 학습 당시와 다른 결과가 나온다. 재현용 이미지는 TensorFlow에서 RGB로 읽고 bilinear로 목표 크기로 맞추며 자동 EXIF 회전·crop/padding을 하지 않는다고 정리했다. 클래스 배열은 각 저장 폴더의 `class_names.json` 순서가 모델 출력의 인덱스다. 팀원이 결과에 다른 순서의 질환명을 붙이면 점수가 맞아도 결과 이름이 틀릴 수 있다. 모델 파일 해시와 입력 크기·출력 차원·점수 배열도 함께 확인하도록 했다.

초기 여섯 모델의 저장 보고서에 적힌 수치와 현재 보유 가중치의 메타데이터·클래스 계약을 검토한 것은 가능했다. 그러나 **정제 전 당시 Test 이미지가 없어서 동일 사진으로 초기 예측을 다시 생성하지 못했다.** 이 제한은 [평가 재현 감사](research/public_data/EVALUATION_REPRODUCTION_AUDIT_20260927.md)에 따로 남겼다. 새 Clean Test로 바꾸어 실행하면 다른 평가이므로 ‘초기 평가 완전 재현’이라고 쓰지 않는다.

### 2단계 전이학습과 v1 후보 선정

#### 목표: 새 Clean 분할에서 무엇을 바꾸면 나아지는가

초기 Hair 모델 가중치를 Clean 실험의 출발점으로 다시 쓰면 새 Val/Test 사진을 과거 학습에서 이미 보았을 가능성을 배제하기 어렵다. 따라서 ImageNet 사전학습 모델에서 다시 시작했다. [Keras 전이학습 안내](https://keras.io/guides/transfer_learning/)에 맞춰 Stage 1은 특징 추출부를 고정하고 새 분류층을 먼저 15 epoch 학습했다. Stage 2는 최고 Stage 1 가중치에서 본체 후반부 30층 중 BatchNormalization을 제외한 부분을 낮은 학습률로 열어 10 epoch 더 학습했다. 당시 설정은 분류층 `GlobalAveragePooling → Dropout(0.3) → Dense`, 학습률 `1e-4→1e-5`, seed 42, batch 32였다. Hair의 마지막 v1 조건에서는 Stage 2를 5 epoch 연장했다. **Stage 1→2 차이에는 학습층·학습률·추가 epoch가 함께 포함된다.**

#### 비교한 변수·논문 근거·관찰

| 비교 | 질문과 근거 | 실제 관찰과 판단 |
|---|---|---|
| B0·224→256 | 작은 각질·모공·얼굴 질감이 축소 중 사라지는가? [EfficientNet 크기 설계](https://proceedings.mlr.press/v97/tan19a.html) 참고 | Hair Val Accuracy `0.7643769979476929→0.7699680328369141`; Web Skin `0.794→0.796`으로 500장 중 정답 한 장 차이. 두 과제 모두에 큰 이득이라고 말하지 않음 |
| CE→Label Smoothing 0.05 | 과도한 정답 확신을 누그러뜨리는가? [Inception 연구](https://openaccess.thecvf.com/content_cvpr_2016/html/Szegedy_Rethinking_the_Inception_CVPR_2016_paper.html) 참고 | Hair `0.7699680328369141→0.7739616632461548`; Web Skin `0.796→0.794`. 효과는 도메인마다 다름 |

| Hair Stage 2 10→15 epoch | 같은 체크포인트를 조금 더 조정하면 나아지는가? | Hair 최고 Val `0.7771565318107605`; 연장 개선폭은 작지만 당시 v1 선정 규칙상 선두 |

Web Skin B0·256에서 Stage 1 최고 Val Accuracy `0.7039999961853027`, Stage 2 최고 `0.7960000038146973`으로 묶음 학습 절차 후 상승했다. Loss 함수 종류가 다를 때 **Loss 숫자의 절대 크기만으로** 모델 우열을 비교하지 않았다. 또한 Hair의 Focal이 일부 Test에서 높더라도 Test를 보고 사후에 선정 기준을 변경하지 않았다.

### 심화 기록 v1을 고르기까지의 학습법 비교

#### 1. 2단계 학습의 정확한 의미

Stage 1에서는 ImageNet EfficientNet의 기존 본체를 고정하고 `GlobalAveragePooling → Dropout(0.3) → Dense(새 클래스 수)`를 학습했다. 15 epoch 동안 학습한 여러 시점 중 **Validation에서 가장 높은 체크포인트**를 Stage 2의 시작 가중치로 골랐다. Stage 2는 본체의 후반 30층 중 BatchNormalization을 제외한 부분을 열고, 학습률을 `1e-4`에서 `1e-5`로 낮춰 10 epoch를 더 수행했다. 분류층을 먼저 안정화하고 마지막 특징을 조금 조정하는 순서는 [Keras의 전이학습 지침](https://keras.io/guides/transfer_learning/)과 연결된다. BatchNormalization을 고정한 까닭은 작은 배치에서 통계가 흔들리는 영향을 줄이기 위해서였다.

이 2단계를 **“똑같은 모델을 10회만 더 돌렸다”**고 설명하면 빠진 부분이 있다. 학습 가능한 층의 범위, 학습률과 optimizer 상태가 바뀌며 데이터 노출 횟수도 늘어난다. 반대로 Stage 2 후 Validation 상승을 ‘후반 30층을 열어서만 생긴 효과’라고 해석하는 것도 정확하지 않다. Web Skin B0·256의 Stage 1 최고 Val Accuracy `0.7039999961853027`과 Stage 2 최고 `0.7960000038146973`은 **묶음 절차 전후**의 관찰이다. Skin은 처음부터 높은 분류 성능을 보인 만큼 이 여섯 설정 전체를 반복하지 않고 Clean 원본·증강 Train의 head-only 비교를 실시했다.

#### 2. Hair의 여섯 설정: 무엇을 고정하고 무엇을 바꾸었는가

Hair은 Clean 5종 Original Val/Test 각 1,252장을 유지하며 아래 조건을 비교했다. 일반적인 순서는 `B0·224·CE 기준 → B0·256·CE → B0·256·LS → B0·256·Focal → B1·256·LS → B1의 Stage2 연장`이다. 같은 비교 쌍에서는 데이터·분할·평가 방법을 맞췄다. 설정 전부의 절대 점수를 하나의 원인 변화로 묶지는 않는다.

| Hair 5종 Clean 실험 | Val Accuracy | Test Accuracy | Test Macro F1 | 판단에 실제 사용한 근거 |
|---|---:|---:|---:|---|
| B0·224·CE | `0.7643769979` | `0.7763578275` | `0.7757408068` | Clean 2단계 기준 |
| B0·256·CE | `0.7699680328` | `0.7891373802` | `0.7886477230` | 같은 B0·CE에서 입력 확대 방향 확인 |
| B0·256·LS 0.05 | `0.7739616632` | `0.7867412141` | `0.7863134458` | Val 상승, Test가 CE보다 낮아 두 지표 역할 분리 |
| B0·256·Focal 1.5 | `0.7675718665` | `0.7907348243` | `0.7905122040` | Test는 높지만 Val 기준 선정에서는 밀림 |
| B1·256·LS·Stage2 10 | `0.7763578296` | `0.7787539936` | `0.7788123272` | B1 크기 증가만의 안정된 개선은 아님 |
| B1·256·LS·Stage2 15 | **`0.7771565318`** | `0.7883386581` | `0.7885764577` | Val 최고로 5종 v1 선정 |

입력을 224에서 256으로 늘린 이유는 두피의 작은 각질·모공 단서가 축소에서 사라질 수 있기 때문이다. 실제로 B0·CE 비교에서는 Val Accuracy가 올랐지만, 이것만으로 256의 모든 장비·데이터에서의 효과를 보장하지 않는다. Label Smoothing 0.05는 정답을 1.0으로 확신하도록 강제하는 경향을 누그러뜨리는 [Inception 연구의 아이디어](https://openaccess.thecvf.com/content_cvpr_2016/html/Szegedy_Rethinking_the_Inception_CVPR_2016_paper.html)를 응용했다. Hair에서는 Val이 올랐지만 Test는 CE보다 낮았다. **예측 점수가 덜 극단적이라는 것과 실제 정답 확률로 잘 보정됐다는 것은 다르다.**

Focal Loss gamma 1.5는 쉬운 표본보다 어려운 표본의 손실 비중을 높이는 [원 논문](https://openaccess.thecvf.com/content_iccv_2017/html/Lin_Focal_Loss_for_ICCV_2017_paper.html)의 방향을 유사 두피 클래스에 적용했다. 원 논문은 불균형한 객체 검출에 관한 것이고 이 실험은 균형에 가까운 두피 분류에서 **어려운 예 집중**이 도움되는지 본 응용이다. Hair Focal이 당시 Test Accuracy·Macro F1에서 높더라도 이미 여러 조건의 Test를 본 뒤 이를 근거로 최종 모델을 다시 고르면 선택 편향이 생긴다. 그래서 사전에 쓰던 Validation 기준을 유지했다. 다른 손실함수끼리는 loss 자체의 절대 숫자 크기로 성능을 비교하지 않았다.

B1 변경은 같은 256·LS에서 더 큰 모델의 표현 용량을 본 것이고, Stage 2 연장은 같은 B1 체크포인트의 학습을 5 epoch 더 했을 때 Val이 계속 나아지는지 확인한 것이다. Stage 2 연장 전 Val Accuracy `0.7763578295707703`, 연장 후 `0.7771565318107605`였으므로 **향상은 있었지만 작은 폭**이었다. v1은 결국 Validation 선두라는 당시 선정 규칙으로 고정됐다. Hair v1이 어떤 한 종류의 Loss나 큰 모델이라는 이유만으로 자동 선정된 것이 아니다.

#### 3. Web Skin의 여섯 설정과 선택 규칙

Web Skin은 정면 얼굴 원본 Train 3,600장과 증강 Train 7,200장을 가진 같은 5종 데이터에서 2단계 실험을 했다. Val은 원본 500장, Test는 원본 400장이다. 이 묶음의 비교는 다음과 같다.

| Web Skin 실험 | 바꾼 중심 질문 | Val Accuracy | Val Macro F1 | 결정 |
|---|---|---:|---:|---|
| B0·224·CE | 2단계 기준선 | `0.794` | `0.7917009497301795` | 첫 기준 |
| B0·256·CE | 224→256에서 얼굴 질감 보존? | **`0.796`** | `0.7915394647566528` | Accuracy 500장 중 한 장 증가, 당시 v1 |
| B0·256·LS 0.05 | 과신 완화? | `0.794` | `0.7892883497449976` | CE보다 낮음 |
| B0·256·Focal 1.5 | 어려운 얼굴 예 집중? | `0.792` | `0.7898148816790076` | CE보다 낮음 |
| B1·256·LS 0.05 | 더 큰 본체? | `0.796` | **`0.7931535064807589`** | Accuracy 동률, F1은 약간 높음 |
| B1 Stage2 +5 | 조금 더 미세조정? | `0.796` | `0.7931535064807589` | 부모의 최고를 넘지 못함 |

Web Skin에서 224→256의 Accuracy 차이는 **Validation 500장 중 정답 한 장**에 해당한다. Macro F1은 B0·224 `0.7917009497301795`, B0·256 `0.7915394647566528`로 사실상 동률이어서 256의 강한 보편적 이득이라고 말하지 않았다. B1·LS의 Macro F1이 B0·CE보다 조금 높았지만 당시 규칙은 Accuracy 우선, 동률이면 먼저 나온 실험 유지였다. 그래서 B0·256·CE를 v1으로 고정했다. 400장 Test Accuracy `0.8825`, Macro F1 `0.8813822927981046`은 그 다음에 보고한 결과다.

#### 4. Skin에서는 왜 같은 여섯 설정을 돌리지 않았는가

Skin Clean 데이터는 원본 Train 7,249장과 원본+새 증강 Train 14,498장을 **같은 B0·224·CE·head-only 15 epoch**에서 비교하는 것이 우선 질문이었다. Validation 1,000장에서는 Accuracy `0.973` 대 `0.982`, Macro F1 `0.9730455448862949` 대 `0.9820008885656606`이고 오분류는 27장 대 18장이었다. 증강 조건의 각 클래스 F1은 원본과 같거나 높았다. 이 조건을 Validation으로 고정하고 Test 700장에서 691장 정답, Accuracy `0.9871428571428571`, Macro F1 `0.9871314132317626`을 확인해 v1으로 패키징했다. 초기 약 99.6%와 Clean 약 98.7%의 수치 차이는 **평가 사진과 정제 조건도 함께 바뀌었기 때문에** 학습법 악화라고 주장하지 않는다.

#### 5. 왜 v1 결과를 최종 운영 성능이라 부르지 않았는가

Skin, Web Skin, Hair v1 모두 해당 공개 데이터 분할에서 선정한 후보였다. 사람·병변·촬영 세션 수준의 누수가 배제되지 않았고 실제 USB 현미경·웹캠 현장 사진은 없었다. 특히 Hair의 탐색에서는 여러 Test 결과가 보고된 이력이 있어 완전히 봉인된 마지막 독립 평가보다 제한이 크다. 이 한계를 숨기지 않고 뒤의 논문 실험에서는 방법을 Validation으로 선별하고 **고정 후보만 Test**에 올리는 절차를 분명히 했다.

## 3차 논문 기반 방법 선별과 v2 후보

논문은 새로운 분류 성능을 보장하는 근거가 아니라 **시험할 가설을 정하는 근거**로 사용했다. 두피의 미세 질감, 얼굴 사진의 국소 부위와 촬영 스타일을 각각 다르게 다뤘다.

### 두피·얼굴에 맞춘 논문 방법과 v2

#### 공통 실험 원칙

Hair의 미세각질·비듬 혼동과 Web Skin의 얼굴 안 국소 질환/색감 변화를 **서로 다른 연구 가설**로 다뤘다. 같은 과제에서는 Clean 분할과 클래스 순서를 유지하고 Validation에서 선택했다. 논문은 방법을 시험할 이유이지 MediFlow에서의 성능 보증이 아니다. Hair SupCon 효과를 읽을 때는 당시 같은 코드로 새 B1·256 기준선을 함께 학습했다. 기존 v1 수치만 가져오면 실행·구현 차이가 섞일 수 있기 때문이다.

#### Hair 5종: 표현·구조·해상도 실험

#### 의료 사전학습 표현의 별도 선별

[MedSigLIP-448 모델 카드](https://developers.google.com/health-ai-developer-foundations/medsiglip/model-card)를 참고해 의료 이미지 인코더가 ImageNet CNN보다 나은 특징을 제공하는지 확인했다. 본체는 고정하고 embedding 위에 Linear 분류층만 학습했다. Web Skin Val Accuracy/Macro F1은 `0.824`/`0.8195774288599683`, Hair 5종은 `0.7699680511182109`/`0.7687534259685547`이었다. 두 과제 모두 각 v2보다 낮아 Test 평가·최종 후보 패키징은 하지 않았다. 저장된 작은 분류층만으로 독립 추론할 수 없고 외부 인코더가 필요하다. **이 실험은 의료 영상 분류 표현 실험이지 대화형 VLM 구현이 아니다.** Skin v1은 이 단계에서 다시 학습하지 않았다.

### 심화 기록 각 논문 방법의 원리, 구현, 채택 근거

#### 1. 논문 방법을 고른 기준

새로운 기법을 숫자만 올리기 위해 무작위로 늘리지 않았다. Hair은 비듬·미세각질·피지과다처럼 **다른 답이 매우 가까운 확대 질감**이고, Web Skin은 얼굴 전체 안에서 **질환 위치·국소 피부 패턴·촬영 색감**이 섞이는 문제다. 그래서 Hair에서는 같은 클래스 표현을 모으는 SupCon, 사전학습 표현을 바꾸는 DINOv2·EfficientNetV2, 작은 신호를 보존하는 384 입력, 일반화를 보는 SAM을 선별했다. Web Skin에서는 중요한 영역을 찾는 WS-DAN, 세밀도별 조각을 보는 PMG, 스타일 통계를 섞는 MixStyle을 선별하고 선두 PMG의 크기만 추가 비교했다. 비교 과정에서 **방법 하나의 변화와 필수 동반 변화**를 따로 기록했다.

#### 2. Hair SupCon의 기준선이 왜 새로 필요한가

[Supervised Contrastive Learning](https://arxiv.org/abs/2004.11362)은 같은 라벨의 특징 표현을 가까이 모으고 다른 라벨의 표현을 멀어지게 학습한다. 비듬과 미세각질의 이미지가 비슷해도 표현 공간에서 분리될지 검토할 수 있다. 이 실험은 같은 데이터·같은 시기·같은 코드로 학습한 B1·256 분류 기준선 `Val Accuracy 0.7755591054313099, Macro F1 0.7746028470442391`과 짝을 지었다. 예전 v1과 비교하면 저장 체크포인트·구현·실행 시점이 섞일 수 있어 SupCon만의 차이를 더 공정하게 보려는 조치였다.

SupCon의 Val Accuracy `0.7915335463258786`, Macro F1 `0.7910880666407202`는 동시 기준선보다 높고 다섯 클래스 F1이 모두 올라갔다. 이는 **유사 클래스 표현을 새로 학습하는 방법이 현재 Clean Hair에서 유망했다**는 근거다. 그래도 뒤의 B1·384 단일 모델 Macro F1 `0.7957146810115047`보다는 낮았다. 두 예측을 1:1 평균한 앙상블도 Macro F1 `0.7942285283566071`로 단일 선두보다 낮아 채택하지 않았다. 추가 모델 호출을 요구하는 조합의 이득이 확인되지 않은 셈이다.

#### 3. Hair의 구조·입력·optimizer 비교

[DINOv2](https://arxiv.org/abs/2304.07193)는 라벨에 의존하지 않고 사전학습한 시각 표현이다. 우리 선별은 Small·224 인코더를 **고정**하고 새 분류층을 15 epoch 학습한 조건이므로 DINOv2 전체를 두피 데이터에 완전 미세조정한 실험이 아니다. Val Macro F1 `0.7705341251195019`로 기준선보다 낮았다. [EfficientNetV2-S](https://proceedings.mlr.press/v139/tan21a.html)는 학습 효율을 고려한 다른 CNN 계열이지만 우리 256 조건의 Val Macro F1 `0.7681559382466019` 역시 선두가 아니었다. 원논문의 일반 효율성과 우리 특정 데이터의 점수는 다른 주장이다.

EfficientNet-B1에 **384×384** 입력을 사용한 실험은 작은 각질·모낭 단서가 256으로 줄어들 때 손실되는지 묻는 것이었다. B1·384·LS 0.05·Adam의 Val Accuracy/Macro F1 `0.7963258785942492`/`0.7957146810115047`이 Hair 단일 모델 중 가장 높았다. 다만 B1 v1에서 v2로 갈 때 실제 학습 경로도 달라져 향상 전체를 해상도 하나의 인과 효과라고 단정할 수 없다. v1과 같은 5종 Test에서 v2는 Accuracy 약 **1.20%p**, Macro F1 약 **1.16%p** 높았다. 이는 같은 다섯 답을 두 데이터 분할에서 비교한 기록이 아니라 **같은 5종 Test**의 두 선정 모델 비교다.

[SAM](https://openreview.net/pdf?id=6Tm1mposlrM)은 가중치를 조금 흔들어도 손실이 크게 나빠지지 않는 해를 찾으려는 방법이다. 선두 B1·384 조건에 `rho=0.05`로 적용해 Adam과 비교했다. Val Accuracy는 두 조건 모두 `0.7963258785942492`였고 Macro F1은 Adam `0.7957146810115047`, SAM `0.7954748920799393`으로 SAM이 낮았다. 따라서 SAM을 쓰면 무조건 좋아진다고 설명하지 않고 이 설정에서는 **추가 채택 근거가 없다**고 정리했다. 최종 Hair v2는 B1·384·LS 0.05·Adam을 Validation으로 고정한 뒤 Test 1,252장에서 평가·패키징했다.

#### 4. Web Skin WS-DAN·PMG·MixStyle이 서로 다른 질문을 던진 방식

[WS-DAN](https://arxiv.org/abs/1901.09891)은 전체 라벨만으로 중요한 부분에 주목하고 확대하거나 가리는 attention을 사용한다. 얼굴 사진에서 피부 변화가 실제로 있는 위치를 모델이 더 잘 본다면 개선될 것이라는 가설이었다. 우리 구현은 8개의 attention map과 원본/attention crop 예측을 사용한 **논문 아이디어의 응용**이었다. Val Accuracy/Macro F1 `0.764`/`0.7546949301321499`로 이전 B0·256·CE `0.796`/`0.7915394647566528`보다 낮았다. 논문이 틀렸다는 뜻이 아니라 현재 데이터·본체·attention 설정에서 이득이 없었다는 결과다.

[PMG](https://arxiv.org/abs/2003.03836)는 서로 다른 크기의 조각으로 세밀한 국소 패턴을 점진적으로 학습하고 전체 정보와 결합한다. 얼굴 피부의 넓은 분포는 비슷해도 작은 질감이나 병변 크기에서 차이가 난다는 가설에 맞았다. 우리 구현은 학습 때 8·4·2 격자 기반 이미지 조각을 사용했고, 실제 예측 때는 **원본 얼굴 한 장**을 넣는다. 모델의 네 branch logits를 합한 다음 softmax를 **한 번** 적용하는 출력 계약을 둔다. B0·256 Val Accuracy/Macro F1 `0.85`/`0.8473279632397033`으로 이전 v1보다 각각 `0.054`/`0.0557884984830505` 높아 세 방법 중 선두였다.

[MixStyle](https://arxiv.org/abs/2104.02008)은 얕은 특징의 평균과 표준편차를 다른 학습 사진과 섞어 웹캠·조명·색감이 달라진 듯한 특징을 만든다. 이번 코드에서는 `alpha=0.1`, 적용 확률 `0.5`를 사용했다. 추론 때는 사진을 섞지 않으므로 새 입력 방식은 필요하지 않다. Val Accuracy/Macro F1 `0.806`/`0.8033767539683495`로 v1보다 조금 높았지만 PMG보다 낮았다. 실제 서로 다른 웹캠에서의 강건성을 별도 데이터로 확인한 결과는 아니다.

#### 5. Web Skin PMG의 크기와 실제 전달 후보

PMG가 세 방법의 선두였기 때문에 B1·384로 규모를 키우면 얼굴의 작은 병변을 더 보존할 수 있는지 따로 확인했다. 이때 B0→B1과 256→384가 **함께** 바뀌었고 GPU 메모리 때문에 batch 32→16도 필수로 바뀌었다. PMG B1·384 Val Accuracy/Macro F1 `0.866`/`0.8643216544321994`로 B0·256의 `0.85`/`0.8473279632397033`보다 높았다. 하지만 입력 픽셀은 2.25배, 저장 모델 파일 약 29% 증가, 기록된 학습 시간 약 2.49배였다. 이후 동일 Colab 측정에서 추론 p50도 B1·384가 훨씬 길었다. 따라서 **Validation 연구 선두와 실제 전달 후보를 분리**해 B1·384는 연구 비교로 보존하고 B0·256을 v2로 고정했다. v2만 Test 400장에 올려 Accuracy `0.915`, Macro F1 `0.9141049081029712`를 보고했다.

#### 6. MedSigLIP이 의료 모델인데도 채택되지 않은 이유

[MedSigLIP-448](https://developers.google.com/health-ai-developer-foundations/medsiglip/model-card)은 의료 이미지·텍스트 사전학습 표현이므로 일반 ImageNet 특징보다 얼굴·두피 이미지를 잘 구분할 가능성을 시험할 수 있었다. 수행한 것은 큰 인코더를 고정해 이미지마다 embedding을 만든 뒤, 그 위의 Linear 분류층만 학습하는 **frozen linear probe**였다. 전체 본체를 우리 데이터에 미세조정한 것도, 사용자가 사진에 질문하면 문장을 생성하는 VLM도 아니다. Web Skin의 Val Accuracy/Macro F1 `0.824`/`0.8195774288599683`, Hair의 `0.7699680511182109`/`0.7687534259685547`은 각각 PMG v2와 Hair v2보다 낮았다. 그래서 Test를 열거나 별도 최종 배포 모델로 패키징하지 않았다. 저장된 작은 Linear 파일만 받아서는 독립 실행이 되지 않아 외부 MedSigLIP 본체와 전처리가 필요하다는 점도 기록했다.

#### 7. 논문 실험의 결론을 과장하지 않는 방법

Hair에서는 SupCon이 동시 기준선보다 좋았고 최종은 B1·384 Adam이 더 높았다. Web Skin에서는 PMG가 이전 B0 기준을 뚜렷이 앞섰고 큰 PMG가 Validation 최고였지만 실행 비용을 함께 고려해 B0를 택했다. DINOv2·EfficientNetV2·WS-DAN·SAM·MedSigLIP은 **이번 구현과 데이터 조건에서** 선정 기준을 넘지 못했다. 성공과 실패 모두 연구 결과이며, 논문의 다른 구현 전체가 효과 없다는 결론은 아니다. 보존된 [논문 실험 곡선·성능 그림](../presentation/3차/시각자료)은 방법별 Validation과 클래스별 F1을 비교하고 선택한 후보의 Test만 표시하도록 정리했다.

## 4차 Hair 양호 클래스와 실행 비용 비교

Hair 6클래스는 출력 클래스와 Test 구성이 바뀐 **새 분류 과제**다. 저장된 모델들의 실행 비용은 Colab에서 측정했으며 실제 장비의 응답 시간으로 바꾸어 말하지 않는다.

### Hair `양호` 추가와 독립된 6클래스 실험

#### 목적과 데이터 정의

기존 Hair 5종 모델은 어떤 사진이 들어와도 다섯 증상 중 하나를 출력한다. 여섯 증상 항목이 모두 `0`이라고 사용자가 확인한 두피 사진을 **새 `양호` 클래스**로 구성했다. 이는 모든 질환이 없다는 의학적 확정이 아니라 이번 자료 정의의 클래스다. 처음 약 2,400장으로 보인 원천에서 파일명·사진을 수작업으로 살펴 **534장**을 업로드했다. 기존 Hair Clean ZIP과 신규 ZIP 사이 완전 동일 바이트/RGB 픽셀 중복은 0건이었다. 다만 유사 사진·동일 사람/촬영 세션·개별 원천 JSON 확인은 완료되지 않았다.

신규 사진은 파일명에서 식별한 105개 ID를 묶어 Train `428`, Val `53`, Test `53`장으로 나눴다. 기존 5종 Clean 분할은 보존했다. 새 6종 원본은 Train `10,460`, Val `1,305`, Test `1,305`, 합계 `13,070`장이다. 증강 Train은 원본 `10,460` + 파생 `7,155` = `17,615`장이다. `양호` 파생 사진은 `2,140`장이지만 새로운 사람 2,140명이 아니다. Val/Test에는 증강을 넣지 않았다.

#### 네 학습 조건

같은 6종 데이터 ZIP, 분할, 클래스 순서, seed 42, ImageNet 초기 가중치와 Stage 1 15 + Stage 2 15 epoch를 고정했다. 비교는 **B0·256·CE와 B1·384·LS 0.05라는 두 모델 묶음** × **원본/증강 Train**이었다. B0↔B1에는 구조·해상도·Loss가 함께 바뀌므로 그 차이를 B1 하나의 효과로 주장하지 않는다. 같은 묶음 내 증강 비교에는 Train 사진 수와 클래스 가중치 변화가 동반된다.

| 조건 | Train | Val Accuracy | Val Macro F1 | Val `양호` Recall |
|---|---:|---:|---:|---:|
| B0·256·CE 원본 | `10,460` | `0.7693486590038314` | `0.7729052037575177` | `0.8867924528301887` |
| B0·256·CE 증강 | `17,615` | `0.7777777777777778` | `0.7819142733310591` | `0.8867924528301887` |
| **B1·384·LS 0.05 원본** | `10,460` | **`0.7992337164750958`** | **`0.8144942091318823`** | **`0.9433962264150944`** |
| B1·384·LS 0.05 증강 | `17,615` | `0.7931034482758621` | `0.8019837806385383` | `0.9056603773584906` |

B0 안에서는 증강이 Val Macro F1을 높였고 B1 안에서는 원본이 높았다. Validation 선두 B1·384 원본을 **성능 우선**, 두 B0 중 높은 B0·256 증강을 **경량 대안**으로 고정한 뒤 같은 6종 Test 1,305장에서 평가했다.

| 고정 후보 | Test Accuracy | Test Macro F1 | `양호` F1 |
|---|---:|---:|---:|
| B1·384 원본 | `0.7915708812260537` | `0.8091500773460419` | `0.9245283018867925` |
| B0·256 증강 | `0.7869731800766283` | `0.8021613486071133` | `0.9074074074074073` |

두 모델은 `양호` Test 53장 중 각각 49장을 맞혔다. 하지만 기존 5종 Test 1,252장과 새 6종 Test 1,305장, 출력 5개와 6개는 다른 평가 과제다. **5종 대비 Macro F1 숫자 차이를 클래스 추가의 개선 효과로 말하지 않는다.** 향후에는 양호 원천 라벨과 사람/세션 단위 독립성, 유사 이미지 겹침을 추가로 검증해야 한다.

### 심화 기록 Hair 6종 데이터와 동일 Test 오분류 분석

#### 1. `양호` 원본 534장은 어떻게 마련했는가

사용자가 처음 살펴본 약 2,400장에는 같은 파일명이 반복됐고, 단순히 파일명만 보고 모두 다른 사람·다른 사진이라고 볼 수 없었다. 직접 사진도 살펴 겹친 항목을 정리한 뒤 Drive에 534장을 업로드했다. 당시 여섯 증상 값이 모두 0이라는 확인은 사용자의 원천 검토에 근거한다. 업로드된 파일마다 원래 JSON 라벨을 대조한 증거가 따로 제공된 것은 아니므로 **라벨 근거의 수준**을 분명히 했다. Skin에 적절한 새 정상 원천을 확보했다는 결과로 확대하지도 않았다.

새 원천 ZIP과 기존 Hair 5종 Clean ZIP을 교차 검사했을 때 바이트·RGB 픽셀 완전 중복은 0건이었다. 다만 같은 사람의 연속 촬영·각도 변화·압축 차이 등 근사 중복을 완전히 배제하지 못했다. 신규 파일명에서 복원한 ID 105개를 한 분할에만 들어가도록 묶어 `428/53/53`으로 분리했다. 기존 다섯 질환 사진에는 같은 수준의 사람·세션 식별자가 없어서 **새 자료 내부의 ID 분리와 전체 6종 과제의 사람 단위 누수 부재는 다른 주장**이다.

기존 5종 원본 12,536장에 신규 534장을 더한 6종 원본 13,070장의 두 데이터 버전은 별도 ZIP으로 보존했다. 새 6종 증강 조건의 파생 파일 7,155장 가운데 `양호` 2,140장은 원본 Train 428장에서 나왔다. 따라서 `양호`의 학습 파일 수를 다른 질환 클래스와 가깝게 늘렸더라도 독립 원본은 여전히 428장이다. Val/Test의 양호 표본은 각각 53장이라 클래스별 점수의 변동도 작은 샘플 수를 염두에 두어야 한다.

#### 2. 왜 5종 모델을 이어 학습하지 않았는가

기존 5종 모델의 출력은 다섯 증상이고 새 과제는 여섯 답이다. 저장된 5종 후보에 분류층 하나를 덧붙여 급히 이어 학습하면 새 `양호` 데이터의 영향과 기존 가중치 이력의 영향을 분리하기 어렵다. 이번 네 조건은 **ImageNet 사전학습 B0 또는 B1에서 새 6종 head를 학습**했다. 이는 Hair 5종 v1/v2 뒤에 이어진 v3 훈련이 아니라 6종 과제의 첫 독립 모델들이다. 5종 v1/v2와 6종 성능 우선/경량 v1이라는 **두 버전 축**을 문서와 폴더에서 구분했다.

#### 3. 네 조건에서 무엇이 동반해 바뀌었는가

같은 B0 모델 안에서는 원본 대 증강 Train을 비교할 수 있고, 같은 B1 안에서도 이를 비교할 수 있다. 이때 증강 조건은 사진의 변형 유무만 다른 것이 아니라 **Train 파일 수와 클래스 가중치**도 달라진다. B0 묶음과 B1 묶음 사이에는 backbone·입력 해상도·Loss가 동시에 달라져 단일 변수의 인과 효과를 읽을 수 없다. 따라서 B1 원본의 Validation 선두는 **그 모델 묶음이 네 선택지 중 가장 높았다**는 뜻이며 B1이라는 구조 하나가 성능 차이를 만들었다는 증거는 아니다.

6종 네 조건은 Stage 1 15 epoch, Stage 2 15 epoch와 동일한 데이터 분할·seed 42·batch 32를 사용했다. 모델별 최고 체크포인트는 Validation Accuracy로 저장했고 네 조건 가운데 종합 1위는 Validation Macro F1(동률이면 Accuracy)로 정했다. B1·384 원본의 Val Macro F1 `0.8144942091318823`이 가장 높았고 B0 묶음 안에서는 증강의 `0.7819142733310591`이 원본 `0.7729052037575177`보다 높았다. **B1 원본과 B0 증강은 각각 성능 우선과 경량 대안이라는 다른 역할**로 패키징했다.

#### 4. 같은 6종 Test에서 확인한 사실

두 패키지의 Test는 동일한 사진 1,305장과 동일한 정답 라벨을 사용한다. B1 성능 우선 Test Accuracy `0.7915708812260537`, Macro F1 `0.8091500773460419`; B0 경량 Test Accuracy `0.7869731800766283`, Macro F1 `0.8021613486071133`이었다. B1이 각각 약 0.46%p·0.70%p 높다. 저장 `.keras`의 바이트 수는 B1 `47,234,592`, B0 `29,005,042`이고 B0는 입력 픽셀 수도 작다. 저장 크기만으로 실제 장비 메모리·전력·체감 속도를 확정할 수 없어 4차의 동일 Colab 실행 비용 측정을 따로 했다.

`양호` 53장 중 두 모델 모두 49장을 맞혔다. 반대로 질환 이미지를 `양호`로 잘못 부른 수는 B1 4장, B0 6장이었다. 따라서 같은 `양호` Recall이라도 Precision과 F1은 B1이 더 높다. 분류기가 질환을 양호라고 잘못 고르는 사례는 발표에서 무시할 수 없는 오류다. 성능 우선 B1의 6종 전체 Test에서는 **비듬 241장 중 45장을 미세각질**로 불렀다. 새로운 양호 답이 생겨도 비듬·미세각질의 오래된 혼동이 해결됐다고 말할 수 없다.

### 34개 저장 모델의 실행 비용 비교

#### 왜 실행 비용을 비교했나

분류 성능만 높아도 사진 한 장의 처리 시간이 길거나 모델이 크면 향후 장비에서 선택이 달라질 수 있다. 저장된 **34개 실험 조건**을 Skin 4, Web Skin 12, Hair 5종 14, Hair 6종 4개로 나누어 동일 Colab 런타임에서 로드해 실행했다. 512×512 합성 RGB 사진 한 장, batch 1, 준비 실행 10회 후 반복 30회였다. `model p50`은 준비된 입력의 모델 계산 중앙값, `end-to-end p50`은 이번 측정 코드 안의 이미지 변환과 추론 중앙값, `p95`는 느린 쪽 95백분위다. 모델 로드 시간은 별도이고 카메라·화면·네트워크·전체 서비스의 응답 시간은 포함되지 않는다.

|---|---:|---:|---:|
| Skin 10종 v1 B0·224 | `0.9871314132317626` | `282.2758660004183 ms` | `17,198,406 bytes` |
| Web Skin 5종 v2 PMG B0·256 | `0.9141049081029712` | `304.2439384998943 ms` | `36,377,179 bytes` |

**같은 Hair 6종 과제 안에서** B0 경량 대안은 성능 우선 B1보다 Test Macro F1이 약 0.70%p 낮고 이번 Colab p50은 약 121.094 ms 짧았다. 이것이 관찰된 성능–실행 비용 교환 관계다. 서로 다른 Skin/Web Skin/Hair 과제의 Macro F1을 한 순위로 세우지 않는다. 과거 학습 시간은 서로 다른 Colab 실행 기록이므로 34개를 동일 GPU에서 재학습한 속도 표처럼 읽지 않는다. 이번 34개 실행은 **실제 Jetson·USB 현미경·웹캠 장비 측정이 아니며**, GPU 제품명·최대 메모리·전력은 기록되지 않았다. 장비가 없어서 이렇게 했다는 인과 설명은 원본 발표자료의 기록에 없다.

### 심화 기록 실행 시간 지표와 모델 선택

#### 1. 정확도와 실행 비용을 함께 본 이유

공개 데이터에서 정확한 모델이 향후 장비에서도 적절한 응답 시간을 보장하지 않는다. 반대로 실행이 빠른 모델이 충분히 구분하는지도 정확도 없이 판단할 수 없다. 이전 안구 발표에서 학습 시간, latency와 accuracy–latency trade-off 형태의 자료를 사용했기에, 피부·두피의 **저장된 실험 모델 전체**에도 비슷한 질문을 던졌다. 하지만 이번 실행은 과거 모델을 다시 학습한 것이 아니라 **보존된 34개 모델을 한 Colab 런타임에서 불러와 한 장 처리 시간만 새로 측정**한 것이다. Accuracy·Macro F1·training seconds는 이전 실험 기록을 가져왔고, 새로운 수치는 이번 실행의 지연 시간이다.

측정한 34개는 Skin 4, Web Skin 12, Hair 5종 14, Hair 6종 4개다. 각 조건의 모델과 필요한 경우 외부 인코더를 로드했다. MedSigLIP 두 조건의 지연시간 측정은 작은 Linear 분류층뿐 아니라 **외부 영상 인코더를 포함**한다. 다만 `checkpoint_bytes` 열에는 분류층 파일 크기만 들어간 행이 있어 이를 전체 MedSigLIP 용량이라고 하면 틀리다. 기록된 `parameter_bytes_loaded`는 각 MedSigLIP 조건 `1,756,623,736`바이트다. TensorFlow/Keras와 MedSigLIP은 다른 프레임워크·정밀도 경로를 사용해 구조만의 순수 속도 우열을 이 수치 하나로 판단할 수도 없다.

#### 2. `p50`, `p95`, 학습 시간과 모델 크기의 뜻

`model_p50_ms`는 전처리가 끝나 입력이 준비된 뒤 모델 계산 시간의 중앙값이다. `end_to_end_p50_ms`는 이번 측정 코드가 이미지 크기를 조정하는 지점부터 출력까지의 중앙값이다. 두 값은 별도 반복 측정에서 얻은 중앙값이므로 둘의 차이가 **정확한 단일 사진 전처리 시간**은 아니다. `p95`는 이번 30회 측정에서 느린 쪽 95백분위 지연 시간이다. p95가 p50과 가깝더라도 장기간 운영 안정성이 보증되지는 않는다. 모델을 처음 불러오는 `load_seconds`는 별도로 기록했고 매 사진 추론의 p50에 더하지 않았다.

`training_seconds`는 모델마다 예전에 각기 다른 날·환경에서 기록한 학습 시간이어서 **34개 모델의 공정한 학습 속도 순위**가 아니다. `checkpoint_bytes`는 저장 파일의 크기이며 실행 중 활성화 메모리, 프레임워크 메모리, 최대 GPU/RAM 사용량을 포함하지 않는다. 따라서 가벼운 파일이라고 실제 장비 전력까지 적다고 확정할 수 없다. 이번 환경은 Python 3.13.15, TensorFlow 2.20.0, Colab GPU 1개로 기록됐지만 GPU **제품명은 저장되지 않았다.** 입력은 같은 512×512 RGB 상수 이미지 한 장, batch 1, 모델별 준비 10회·반복 30회였다. 카메라 촬영, 파일 읽기, 네트워크, 화면·서버·PDF, 여러 동시 사용자, Jetson 전력·메모리는 이 측정의 범위가 아니다.

#### 3. 각 과제의 그래프에서 실제로 읽은 것

**Skin:** 같은 Clean 분할의 B0·224 원본과 증강 모델은 Val Accuracy `0.973` 대 `0.982`, Macro F1 `0.9730455448862949` 대 `0.9820008885656606`이었다. Colab end-to-end p50은 원본 `283.30165099987425 ms`, 증강 `282.2758660004183 ms`로 거의 같다. 학습 때 증강을 해도 저장 모델의 구조·입력이 같으니 추론에 증강 계산이 더 붙는 것은 아니다. 약 1 ms 차이를 증강이 속도를 높였다는 효과로 해석하지 않는다. 초기 Skin 두 조건의 Val `0.9950000047683716`은 다른 분할이라 이 비교 축에서 제외한다.

**Web Skin:** 같은 데이터의 일반 B0·256·CE는 Val Accuracy `0.796`, Macro F1 `0.7915394647566528`, Colab p50 `282.837166999343 ms`였다. MixStyle B0·256은 Val Accuracy `0.806`, p50 `283.4444615000393 ms`로 이번 측정에서 지연 시간이 비슷했다. PMG B0·256 v2는 Val Accuracy `0.85`, Macro F1 `0.8473279632397033`, p50 `304.2439384998943 ms`여서 분류 성능을 얻는 대신 일반 B0보다 계산 시간이 늘었다. PMG B1·384 연구 조건은 Val Accuracy `0.866`, Macro F1 `0.8643216544321994`, p50 `419.9053944998923 ms`로 B0 PMG보다 Accuracy `0.016` 높고 p50은 약 `115.6614559999980 ms` 길었다. 그래서 PMG B0·256을 성능–비용 균형의 기존 전달 후보로 유지했다. WS-DAN은 이 설정에서 Val Accuracy `0.764`와 p50 `582.8272369999468 ms`였으므로 채택 근거가 생기지 않았다.

**Hair 5종:** 같은 연구 묶음의 B1·256 기준선은 Val Accuracy `0.7755591054313099`, Macro F1 `0.7746028470442391`, p50 `399.0923975006808 ms`; SupCon은 `0.7915335463258786`, `0.7910880666407202`, `398.9703649999683 ms`였다. 이 비교에서는 SupCon이 학습 방법을 바꾸어 Val을 높였지만 **저장 모델의 추론 시간은 거의 같았다.** B1·384 Adam v2는 Accuracy `0.7963258785942492`, Macro F1 `0.7957146810115047`, p50 `407.29406550008207 ms`로 여전히 Val 선두였다. 같은 B1·384의 SAM은 Accuracy가 같고 F1은 `0.7954748920799393`, p50 `411.79105699984575 ms`라 추가 선택 이유가 없었다. DINOv2 Small p50 `232.0108845001414 ms`와 MedSigLIP p50 `42.624430999694596 ms`가 짧다고 해서 Val 성능·필요한 모델 전체 자원·다른 실행 경로를 무시하고 후보를 바꾸지는 않았다.

**Hair 6종:** 같은 6종 데이터의 B1·384 원본은 Val Accuracy `0.7992337164750958`, Macro F1 `0.8144942091318823`, p50 `409.83297050024703 ms`였다. B0·256 증강은 `0.7777777777777778`, `0.7819142733310591`, `288.73898249958074 ms`였다. 분류 지표를 더 중시하면 B1, 같은 Colab 조건에서 처리 시간을 줄이면 B0라는 **서로 다른 선택**을 제시할 수 있다. 이 둘은 본체·입력·Loss·Train 구성이 함께 다르므로 어느 한 요소의 효과로 설명하지 않는다. 6종 Test에서도 B1과 B0의 Macro F1 `0.8091500773460419`와 `0.8021613486071133`을 각각 기록했다.

#### 4. 시각자료의 읽는 법과 함정

[실행 비용 지표 설명 그림](../presentation/4차/시각자료/04_runtime_metrics_explained.png)은 측정 범위와 빠진 카메라·Jetson 부분을 먼저 알려준다. [선정 후보 비교](../presentation/4차/시각자료/04_selected_models_runtime_cost.png)에서는 같은 과제 안에서 빠르고 정확한 후보의 교환 관계를 설명한다. [정확도–지연시간 산점도](../presentation/4차/시각자료/04_accuracy_latency_tradeoff.png)는 왼쪽일수록 이번 Colab 코드에서 빠르고 위쪽일수록 **과거 Validation 성능이 높다**. 서로 다른 Skin/Web Skin/Hair의 점수를 같은 순위표로 읽지 않는다. 34개 전체 지연시간 그림에는 초기 데이터 모델도 있지만 정확도–지연시간 비교 그림은 비교 가능한 정제 후 조건으로 좁혔다.

`metrics_overview`의 색 지도는 **열마다 따로 최솟값·최댓값으로 색을 정규화**했다. 진한 색이 모든 열에서 ‘좋다’는 뜻이 아니다. Accuracy가 높으면 좋은 반면 지연 시간과 과거 학습 시간은 낮을수록 적은 비용이다. 옆 상자그림은 **한 모델의 30회 분포가 아니라 한 과제 안 여러 모델들의 지연 시간 분포**다. 그래프에 있는 과거 학습 시간 막대는 같은 GPU에서 34개를 재훈련한 값이 아니다. 이 해석은 [런타임 상세 분석](research/public_data/RUNTIME_BENCHMARK_REVIEW_20260928.md)에 기록했다.

## 연구 결과의 현재 해석

Skin v1, Web Skin v1·v2, Hair 5클래스 v1·v2, Hair 6클래스 성능 우선·경량 후보는 각각의 데이터 버전과 평가 기준 아래 선택된 저장 모델이다. 서로 다른 촬영 도메인의 Macro F1은 한 줄의 순위로 비교하지 않는다. 초기 모델과 Clean 모델은 Test 사진 구성이 달라 단순 수치 차이를 성능 개선폭이라고 부르지 않는다. 5클래스와 6클래스도 출력과 Test 수가 달라 직접 뺄 수 없다.

완료한 범위는 공개 데이터 기반 모델 선별·패키징, Colab에서의 실행 비용 비교, 실험 근거·발표자료 정리다. 실제 현미경·웹캠 사진의 독립 검증과 최종 장비의 지연·메모리·전력 측정은 이 보고서의 완료 성과에 포함하지 않는다.

## 향후 연구 계획

아래 항목은 이미 달성한 결과가 아니라 다음에 검증할 계획이다. 우선순위와 완료 기준은 [로드맵](ROADMAP.md)에 맞춰 갱신한다.

### 동일 과제 안의 여러 분류 구조 비교

[로드맵 11단계](ROADMAP.md)의 다음 연구는 Skin 10종, Web Skin 5종, Hair 6종에서 **각각** 여러 경량/중형 분류 구조를 같은 과제 안에서 비교하는 것이다. 과제별 데이터 ZIP·클래스 순서·Train/Validation/Test·평가 코드를 고정하고, 구조별 입력 크기·권장 전처리·필요한 동반 변경은 분리해 기록한다. Validation Accuracy뿐 아니라 Macro F1, 각 클래스의 Recall/F1, 혼동행렬과 모델 크기·속도를 함께 본다. 후보를 Validation으로 고정한 뒤 해당 데이터 버전의 Test를 평가한다. Hair 5종과 6종을 동일 과제의 기준선처럼 직접 뺄 수 없다.

### 실제 촬영 데이터와 장비 검증

사용 장비와 촬영 부위를 구분해 소규모 익명 데이터의 사람·병변·촬영 세션 ID, 배율, 조명, 거리, 해상도, 날짜와 라벨 근거를 기록한다. 학습에 섞지 않은 검증셋에서 공개 데이터 대비 Accuracy·Macro F1·클래스별 오류를 확인해 **도메인 차이**를 분석한다. Hair `양호` 원천의 증상값 0 확인을 파일별 메타데이터 또는 별도 검토 기록과 대조한다. 유사 사진과 같은 촬영 세션이 서로 다른 분할에 있는지 재검사한다.

최종 장비가 정해지면 실제 카메라 입력→전처리→모델→결과 화면의 p50/p95 지연, 최대 RAM/GPU 메모리, 전력, 안정성을 같은 프로토콜로 측정한다. 기존 Colab 수치는 가설을 좁히는 사전 비교로만 보존한다. 이 단계가 끝나야 장비 탑재 적합성과 실제 입력에서의 성능을 주장할 수 있다. 장비 작업은 현재 사용자 담당 범위에서는 보류되어 있다.

### Hair 양호 데이터와 클래스 범위 점검

Hair `양호` 534장의 원천 메타데이터에서 여섯 증상 항목이 모두 0인지 파일별로 재확인하고, 사람·촬영 세션 단위의 겹침과 유사 이미지 겹침을 추가 검사한다. 현재 증강 사진의 수는 독립 인물의 수가 아니다. Skin에 새로운 클래스를 더하려면 별도로 정의와 원천 라벨을 확보한 뒤 기존 10종 평가와 구분해 새 데이터 버전으로 다룬다.
