# 촬영 환경 적응 모델 사용 패키지 · 2026-11-11

피부 4차·얼굴 4차·두피 2차를 각각 단독으로 실행하는 ZIP이다.
Validation으로 고정한 후속 검토 후보를 묶었고 기존 공식 후보 색인은 유지했다.

| 분야 | 사용 ZIP | 입력 | 클래스 | 정상 클래스 |
| --- | --- | --- | ---: | --- |
| 현미경 피부 | [skin · 4차](skin_camera_adaptation_stage4_20261111.zip) | 224×224 RGB, 전체 리사이즈 | 10 | 없음 |
| 웹캠 얼굴 | [web_skin · 4차](web_skin_camera_adaptation_stage4_20261111.zip) | 256×256 RGB, 중앙 정사각형 자르기 | 5 | 포함 |
| 현미경 두피 | [hair · 2차](hair_camera_adaptation_stage2_20261111_5class.zip) | 384×384 RGB, 전체 리사이즈 | 5 | 없음 |

세 분야의 클래스와 입력 장비·촬영 부위가 다르므로 필요한 ZIP을 직접 선택한다.
두피 6클래스 패키지는 기존 자료에서 별도로 관리한다.

## 사용 순서

1. 사용할 분야의 ZIP을 압축 해제한다.
2. 그 폴더의 `README.md`에 따라 Python 환경과 의존성을 준비한다.
3. 해당 폴더에서 `python inference.py --image "실제사진경로.jpg"`를 실행한다.
4. 여러 사진은 `python example_usage.py "사진1.jpg" "사진2.jpg"`로 처리한다.

각 ZIP에 모델·클래스 순서·전처리·실행 코드·사용 예시·환경 목록·모델 설명·원본 학습 및 평가 기록이 있다.
원본 모델은 바이트 그대로 복사했다. 외부 `/255`를 추가하지 않는다.
얼굴 PMG는 네 logit을 합산한 후 softmax를 적용한다.
학습용 밝기·색·흐림 변환을 실제 입력 사진에 다시 적용하지 않는다.

파일이 없거나 해독할 수 없을 때, 패키지 해시·모델 구조·출력 계약이 다를 때 오류를 반환한다.
읽을 수 있는 범위 밖 사진을 자동으로 거부하는 기능은 없으므로 점수를 정답 확률로 해석하지 않는다.

## 검사와 기록

- [패키지 색인](package_index.json): ZIP 크기·SHA-256·모델 SHA-256·클래스·전처리·실행 검사 결과.
- [패키징 확인](packaging_verification.json): 원본 모델·보고서·분할 자료 23개와 공식 후보 색인 보존 확인.
- [전체 코드 검사](validation_results.json): 검사 항목·통과 수·환경·코드 해시.
- 각 ZIP 옆 `.zip.sha256`: 전달 파일의 SHA-256.
- ZIP 안 `contract_verification.json`: 합성 입력 두 장으로 확인한 원본/패키지 전처리·예측 비교.
- [패키징 보고서](../../docs/research/camera_adaptation/ADAPTATION_MODEL_PACKAGES_20261111.md): 사용 계약·평가 출처·확인 범위.

검사는 Windows CPU의 Python 3.12.14·TensorFlow 2.20.0·Keras 3.13.2 환경에서 수행했다.
프로젝트 모듈을 불러오지 않는 압축 해제본의 별도 프로세스로 CLI와 사용 예시를 실행했다.
새 가상환경의 설치나 다른 배포 장비에서의 실행까지 확인한 것은 아니다.

Source Test 지표는 모델 파일에 대응하는 기존 결과를 그대로 담았다.
두피 2차에는 기존 원본·조명·확장 3조건만 있으며 새 4차 조건의 두피 4차 점수를 섞지 않았다.
실제 참여자 사진에는 확인된 질환 정답이 없어 실제 장비 질환 정확도는 미측정이다.
이번에는 새 학습·Test 정확도 재측정·공통 라우팅/API·장비 통합을 진행하지 않았다.

원본 학습 데이터·실제 참여자 사진·복호화 키를 포함하지 않는다.
검사용 압축 해제 복사본은 완료 후 정리하고 전달용 ZIP과 기록만 이 폴더에 보관한다.
