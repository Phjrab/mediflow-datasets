# 피부·두피 질환 분류 AI 시스템

> 안구 질환 AI를 기반으로 피부와 두피까지 분석 범위를 확장하고, **촬영 장비와 영상 특성에 따라 전문화된 AI 분류 모델**을 구축하는 프로젝트

---

## 1. 프로젝트 개요

본 프로젝트는 기존에 개발한 AI 기반 안구 질환 판별 시스템을 확장하여 **안구·피부·두피를 함께 분석할 수 있는 다중 질환 스크리닝 시스템**을 구축하는 것을 목표로 한다.

초기에는 피부와 두피를 하나의 통합 모델로 분류하는 방안을 고려했지만, 실제 데이터를 조사하면서 다음과 같은 차이를 확인하였다.

- 피부 현미경 이미지: 병변의 세부적인 형태와 표면 특징이 중요
- 두피 현미경 이미지: 각질, 피지, 모낭, 홍반, 모발 등의 미세 구조가 중요
- 웹캠 피부 이미지: 얼굴 전체의 홍반, 피부색, 질환의 전반적인 분포 등 거시적 특징이 중요

따라서 최종적으로 **입력 장비와 분석 대상에 따라 전문 모델을 분리**하는 방향으로 설계하였다.

현재 구축 대상은 다음 3개의 피부·두피 전문 모델이며, 기존 안구 질환 모델까지 포함하면 최종적으로 4개의 전문 영상 분류 모델 구조를 목표로 한다.

```text
                    [입력 영상]
                         |
          +--------------+--------------+
          |              |              |
        웹캠          USB 현미경      USB 현미경
          |              |              |
       얼굴 피부       피부 확대       두피 확대
          |              |              |
          v              v              v
   EfficientNet-B0  EfficientNet-B0  EfficientNet-B0
          |              |              |
       피부 5-class    피부 10-class   두피 5-class
```

# 3. 첫 번째 모델: USB 현미경 기반 피부질환 분류

## 3.1 데이터 조사

처음에는 Kaggle과 AI-Hub 등에서 피부질환 데이터를 조사하였다.

초기 피부 데이터는 일반적인 얼굴 전체 사진보다는 **특정 피부 병변이 확대되어 촬영된 이미지**가 많았다.

따라서 이 데이터는 웹캠보다는 USB 현미경 또는 근접 촬영 장비를 이용한 분석에 적합하다고 판단하였다.

이 과정에서 처음부터 모델 구조를 정해 놓은 것이 아니라, **실제 데이터의 특성을 확인한 후 촬영 방식과 모델의 역할을 결정**하였다.

## 3.2 초기 10-class 구성

초기 현미경 피부 모델은 다음 10개 질환을 분류 대상으로 구성하였다.

3. 보웬병
4. 사마귀
5. 지루각화증
6. 편평세포암
7. 표피낭종
8. 피부섬유종
9. 혈관종
10. 흑색점

## 3.3 데이터 전처리

원본 데이터를 직접 수정하지 않고 별도의 작업용 데이터셋을 생성하였다.

주요 전처리 과정:

- 폴더 구조 정리
- 클래스명 통일
- 파일명 정리
- 이미지 확장자 확인
- Train / Validation / Test 분리
- Original 데이터셋 생성
- Augmented 데이터셋 생성
- 데이터 개수 검증

초기 데이터에서는 클래스당 약 800장의 Train과 100장의 Validation을 기준으로 구성하고, Train에서 Test를 별도로 분리하여 최종적으로 클래스당 Train 730장, Validation 100장, Test 70장 구조를 만들었다.

# 4. Original / Augmented 데이터 설계

프로젝트 전반에서 **Original 모델과 Augmented 모델을 비교하는 실험 구조**를 사용하였다.

```text
Original
├── train
├── val
└── test

Augmented
├── train
├── val
└── test
```

핵심 원칙은 다음과 같다.

```text
Original Train
    = 원본

Augmented Train
    = 원본 + 증강

Validation
    = 원본

Test
    = 원본
```

즉 **Validation과 Test는 증강하지 않는다.**

이렇게 해야 Original과 Augmented 모델이 동일한 원본 평가 데이터에서 비교되므로 데이터 증강이 일반화 성능에 미치는 영향을 보다 공정하게 확인할 수 있다.

초기 10-class 실험에서는 클래스당 730장의 원본 Train에 470장의 증강 데이터를 추가하여 클래스당 1,200장의 Train 데이터를 구성하기도 하였다.

---

# 5. 데이터 증강 전략

증강은 단순히 이미지 수를 증가시키기 위한 것이 아니라 실제 촬영 환경의 변화를 모델이 경험하도록 하는 것을 목적으로 하였다.

주요 증강:

- 밝기 변화
- 대비 변화
- 색상 변화
- 미세 회전
- 좌우 반전
- 확대 및 Crop
- Blur
- 노이즈
- 촬영 조건 변화

특히 실제 USB 현미경 사용을 고려하여 조명, 초점, 촬영 위치 등의 변화에 대한 강건성을 확보하는 방향으로 증강을 설계하였다.

# 6. EfficientNet-B0 기반 모델

피부 및 두피 분류 모델의 기본 backbone으로 **ImageNet pretrained EfficientNet-B0**를 사용하였다.

기본 입력 크기는 224×224, Batch Size는 32로 설정하였다.

```text
피부/두피 이미지
      ↓
  224 × 224
      ↓
EfficientNet-B0
(ImageNet pretrained)
      ↓
Global Average Pooling
      ↓
Dropout
      ↓
Dense
      ↓
Softmax
      ↓
질환/상태 분류
```

# 7. Early Stopping을 고려한 과정

초기에는 Validation 성능이 일정 기간 개선되지 않을 경우 학습을 자동 종료하는 **Early Stopping**을 적용하는 방법을 고려하였다.

그러나 Original과 Augmented 모델을 공정하게 비교하기 위해 동일한 학습 조건을 유지하는 것이 중요하다고 판단하였다.

따라서 최종적인 Web Skin 학습에서는 Early Stopping을 사용하지 않고 **15 Epoch를 동일하게 수행**하였다.

다만 마지막 Epoch 모델을 무조건 사용하는 것은 아니며, 각 Epoch의 Validation Accuracy를 기록하고 **Validation Accuracy가 가장 높았던 Best Model을 저장**하였다.

---

# 8. 초기 현미경 피부 모델 결과

초기 10-class 피부질환 모델을 실제 학습한 결과 약 **99% 수준의 높은 정확도**를 확인하였다.

그러나 이 결과를 그대로 실제 웹캠 환경에 적용하기에는 문제가 있었다.

학습 데이터는:

> 병변이 크게 확대된 이미지

였지만 실제 웹캠은:

> 사람의 얼굴을 상대적으로 먼 거리에서 촬영

하기 때문이다.

즉 학습 데이터와 실제 사용 환경 사이에 **Domain Gap**이 존재하였다.

따라서 높은 Test Accuracy만으로 실제 웹캠에서도 동일한 성능을 보장할 수 없다고 판단하였다.

# 9. YOLO + 병변 Crop 방식 검토

처음에는 기존 10-class 피부 모델을 웹캠에서도 활용하기 위해 다음 구조를 고려하였다.

```text
웹캠
 ↓
얼굴/피부 촬영
 ↓
YOLO
 ↓
피부 병변 검출
 ↓
병변 Crop
 ↓
EfficientNet-B0
 ↓
10-class 피부질환 분류
```

그러나 실제 피부질환 이미지를 다시 분석하면서 이 방법의 한계를 발견하였다.

피부질환은 항상 하나의 독립적인 작은 병변으로 존재하지 않는다.

- 넓은 영역에 퍼지는 홍반
- 여러 병변의 동시 발생
- 얼굴 전체에 나타나는 색 변화
- 경계가 명확하지 않은 병변

등이 존재하기 때문이다.

따라서 하나의 병변만 Crop할 경우 오히려 **질환 판단에 중요한 주변 영역과 공간적 분포 정보를 제거할 가능성**이 있었다.

결과적으로 YOLO + Crop 방식은 현재 단계에서 사용하지 않기로 하였으며, **10-class 현미경 피부 모델은 그대로 유지하고 웹캠에는 별도의 얼굴 전체 분류 모델을 구축**하기로 방향을 변경하였다.

# 10. 두 번째 모델: 웹캠 기반 피부질환 분류

## 10.1 모델 목적

웹캠 모델은 현미경 모델과 목적을 다르게 정의하였다.

### 현미경 피부 모델

세부 병변 특징을 확대하여 분석

### 웹캠 피부 모델

일상적인 환경에서 얼굴 전체를 촬영하여 피부 상태를 1차적으로 분류

따라서 웹캠 모델은 병변 하나를 Crop하여 분류하는 것이 아니라 **얼굴 전체 이미지에서 나타나는 질환의 전반적인 특징을 학습**하도록 설계하였다.

# 12. JSON 라벨링 데이터 분석

AI-Hub 데이터에는 이미지뿐만 아니라 JSON 형태의 라벨링 데이터도 존재하였다.

JSON에는 다음과 같은 정보가 포함되어 있었다.

- identifier
- diagnosis_name
- bodypart
- photograph.file_path
- 이미지 크기
- bbox
- lesion area

이러한 정보는 단순 이미지 분류뿐만 아니라 향후 병변 위치 정보나 데이터 검증 등에 활용할 가능성이 있다고 판단하였다.

다만 현재 Web Skin 모델에서는 detection/segmentation 구조를 추가하지 않고 **정면 얼굴 전체 이미지 분류에 집중**하였다.

# 13. 정면 / 측면 데이터 검토

웹캠 데이터에는 정면과 측면 이미지가 모두 존재하였다.

처음에는 측면 이미지까지 추가하여 모델이 다양한 시점의 질환 특징을 학습하도록 하는 방안을 검토하였다.

그러나 실제 데이터 확인 결과 정면과 측면 이미지가 명확하게 동일 대상의 Pair로 구성되어 있다고 보기 어려웠다.

따라서 정면과 측면을 단순히 하나의 데이터셋에 합칠 경우 오히려 학습에 혼란을 줄 가능성이 있다고 판단하였다.

최종적으로:

- 정면 데이터 → 학습에 사용
- 측면 데이터 → 별도 보관

으로 결정하였다.

# 14. 주사와 지루성 피부염 데이터 검토

웹캠 데이터에서는 **주사와 지루성 피부염의 구분 문제**도 확인하였다.

정면 이미지를 수십 장씩 직접 확인한 결과 다음과 같은 특징이 서로 유사하게 나타나는 경우가 있었다.

- 붉은색 변화
- 홍반
- 피부 자극
- 얼굴 중심부의 색 변화

사람이 직접 보더라도 명확히 구분하기 어려운 이미지가 존재했기 때문에, 이러한 데이터를 서로 다른 클래스로 강제할 경우 **label noise와 class ambiguity**가 증가할 수 있다고 판단하였다.

따라서 지루성 피부염은 현재 Web Skin 모델에서 제외하고 별도로 보관하였다.

# 15. 최종 Web Skin 5-class

최종 Web Skin 모델의 클래스는 다음과 같다.

1. 정상
2. 건선
3. 아토피
4. 여드름
5. 주사

Web Skin 모델은 전문적인 병변 확대 분석 모델이 아니라 **일반적인 얼굴 정면 사진을 대상으로 하는 일상 환경의 1차 피부질환 분류 모델**로 정의하였다.

# 16. Web Skin 데이터 분할

클래스당 Train 800장, Validation 100장을 확보한 후 Train에서 80장을 Test로 분리하였다.

최종 데이터:

| Split | 클래스당 | 전체 5-class |

# 20. 세 번째 모델: USB 현미경 기반 두피 상태 분류

두피는 얼굴 피부와 달리 각질, 피지, 모낭, 홍반, 모발 등의 미세한 구조를 관찰해야 하기 때문에 USB 현미경 기반의 별도 전문 모델로 구성하였다.

초기에는 다음 6개 클래스를 사용하였다.

1. 모낭사이홍반
2. 모낭홍반농포
3. 미세각질
4. 비듬
5. 탈모
6. 피지과다

원천 데이터는 다음과 같은 심각도 구조를 가지고 있었다.

```text
[질환명]_0.양호
[질환명]_1.경증
[질환명]_2.중등도
[질환명]_3.중증
```

프로젝트 목적에 따라 양호와 경증은 제외하고 **중등도와 중증 데이터를 활용**하였다.

중등도와 중증을 서로 다른 클래스로 나누지 않고 질환명 자체를 하나의 클래스로 통합하였다.

---

# 21. 두피 6-class 초기 학습과 문제 발견

초기 6-class 데이터로 학습했을 때 성능이 기대보다 좋지 않았다.

처음에는 데이터 수가 부족한 것이 주요 원인이라고 생각하였다.

그러나 데이터를 직접 확인하는 과정에서 더 중요한 문제가 발견되었다.

**모낭사이홍반과 모낭홍반농포가 사람이 보기에도 매우 유사한 이미지가 많았다.**

즉 서로 다른 클래스라고 정의되어 있었지만 실제 이미지에서 충분히 명확한 시각적 경계가 존재하지 않는 경우가 있었다.

이러한 경우 모델이 두 클래스를 안정적으로 구분하기 어렵고, label ambiguity가 증가할 수 있다.

---

# 22. 두피 데이터 재구성: 6-class → 5-class

두 클래스의 유사성을 확인한 후 모낭홍반농포를 제외하기로 결정하였다.

그 대신 다른 클래스에는 충분한 데이터가 존재했기 때문에 클래스별 데이터를 균형화하는 방향으로 재구성하였다.

최종 원본 데이터 수:

| 클래스 | 원본 데이터 |
|---|---:|
| 모낭사이홍반 | 4,275 |
| 미세각질 | 2,936 |
| 비듬 | 2,900 |
| 탈모 | 4,872 |
| 피지과다 | 3,746 |

가장 적은 클래스인 비듬의 **2,900장**을 기준으로 모든 클래스를 동일하게 맞췄다.

따라서 최종 Hair 데이터셋은:

> **5 classes × 2,900장 = 14,500장**

으로 구성하였다.

최종 클래스:

1. 모낭사이홍반
2. 미세각질
3. 비듬
4. 탈모
5. 피지과다

- Test: 290

# 29. 현재의 핵심 문제점

현재 Web Skin과 Hair는 모두 baseline 모델이 완성되었지만 성능 개선의 여지가 있다.

특히 현재까지는 EfficientNet-B0 pretrained feature를 기반으로 한 비교적 단순한 학습 전략을 사용했기 때문에, 다음 단계에서는 **학습 방법 자체를 개선**할 필요가 있다.

주요 원인은 다음과 같이 판단한다.

1. 촬영 환경과 학습 데이터 사이의 Domain Gap
2. 질환별 시각적 특징의 유사성
3. 작은 영역에 존재하는 미세한 판별 특징
4. 224×224 입력으로 인한 세부 특징 표현의 한계 가능성
5. Pretrained backbone의 feature가 해당 도메인에 충분히 적응하지 않았을 가능성

# 30. 향후 학습 방법 개선

## 30.1 Partial Fine-tuning

현재의 baseline에서 더 발전하여 EfficientNet-B0의 후반부 일부 layer를 해제하고 **Partial Fine-tuning**을 적용할 예정이다.

```text
ImageNet pretrained EfficientNet-B0
              ↓
       초기 Backbone Freeze
              ↓
        Classification Head 학습
              ↓
    후반부 일부 Layer Unfreeze
              ↓
      낮은 Learning Rate 적용
              ↓
         Fine-tuning
```

이를 통해 ImageNet에서 학습된 일반적인 특징을 피부/두피 영상에 맞는 특징으로 미세조정하는 것을 목표로 한다.

---

## 30.2 입력 해상도 비교

현재 224×224 입력을 사용하고 있으나 두피 현미경 이미지에서는 미세한 각질이나 모낭 주변 변화가 중요한 특징이 될 수 있다.

따라서 향후:

- 224×224
- 256×256
- 필요 시 더 높은 해상도

를 비교하여 미세한 특징 보존 효과를 확인할 예정이다.

---

## 30.3 Loss Function 개선

Fine-tuning과 해상도 변경 후에도 특정 클래스의 성능이 낮을 경우 Focal Loss 등 다른 Loss Function을 추가로 검토한다.

현재는 클래스당 데이터를 동일하게 맞췄기 때문에 단순한 class imbalance보다는 **class separability 문제를 우선적으로 해결**하는 것을 목표로 한다.

---

## 30.4 데이터 증강 전략 개선

현재의 증강은 실제 촬영 환경을 고려하여 구성했지만, 향후 실제 USB 현미경과 웹캠으로 촬영한 데이터를 확보하면 실제 장비에서 발생하는 변화에 맞춰 증강 강도와 종류를 다시 조정할 예정이다.

특히 실제 장비의:

- 조명
- 색감
- 초점
- 센서 노이즈
- 촬영 거리
- 배율

등을 반영하는 방향으로 개선한다.

# 34. 연구의 핵심 의의

본 프로젝트의 핵심은 단순히 피부와 두피 이미지를 AI로 분류하는 데 있지 않다.

연구 과정에서 실제 데이터를 확인하고, 데이터의 특성과 모델 성능을 분석하여 **모델 구조와 데이터 구성을 반복적으로 수정했다는 점**에 의미가 있다.

초기에는 병변을 검출하여 기존 10-class 모델에 입력하는 방법을 고려했지만, 피부질환이 넓은 영역이나 여러 병변으로 나타날 수 있다는 점을 확인하고 Crop 방식의 한계를 발견하였다.

또한 정면과 측면 데이터를 함께 사용하는 multi-view 접근도 검토했지만 명확한 Pair 관계를 확인하기 어려워 현재 단계에서는 정면 데이터에 집중하였다.

주사와 지루성 피부염 역시 사람이 직접 데이터를 확인한 결과 정면 이미지에서 명확한 시각적 경계를 찾기 어려워 지루성 피부염을 제외하였다.

두피에서도 초기 6-class 학습 성능이 좋지 않은 상황에서 단순히 데이터 부족만을 원인으로 보지 않고 모낭홍반농포와 모낭사이홍반의 시각적 유사성을 직접 확인하여 데이터셋을 5-class로 재구성하였다.

결국 본 연구는 다음과 같은 반복적인 개발 과정으로 진행되었다.

```text
데이터 수집
   ↓
데이터 전처리
   ↓
Baseline 모델 구축
   ↓
학습
   ↓
성능 평가
   ↓
실제 이미지 직접 분석
   ↓
문제점 발견
   ↓
클래스/데이터/모델 구조 수정
   ↓
재학습
   ↓
향후 학습 전략 개선
```

따라서 본 프로젝트는 **데이터의 양만 증가시키는 것이 아니라, 실제 촬영 환경과 클래스 간 판별 가능성을 고려하여 전문화된 AI 모델을 설계하는 과정**을 중심으로 발전하고 있다.
