### 발표 대본

## PPT 7쪽. 장치 관리와 스윕 실험의 조건

**핵심:** AI를 비교하려면 장치와 모델 상태, 실행 조건을 함께 관리해야 한다.

### 페이지 설명

노드는 실제 추론을 수행하는 장치로 이해하면 된다. 관리 화면은 장치 연결과 모델 설치 상태, 코드·모델 동기화, 서버 시작·종료를 구분한다. 스윕은 여러 설정 조합을 차례로 시험하는 자동화다. 각 장치에 모델 사본을 두고 요청을 나누는 방식과 한 모델 자체를 여러 장치에 나누는 방식은 다르다.

### 발표 대본

왼쪽은 장치 연결과 모델 상태를 확인하는 관리 화면이고, 오른쪽은 비교 실험의 조건을 설정하는 화면입니다. 모델을 바꿔 비교할 때는 모델 이름뿐 아니라 양자화 방식과 입력·출력 길이, 동시에 처리하는 요청 수도 기록해야 합니다. 스윕 기능은 이런 설정 조합을 순서대로 실행해 반복 설정을 줄이고 결과를 모으는 방식입니다. 관리 기능과 실제 장치에서 얻은 성능 수치는 구분해 정리했습니다.

### 화면에서 짚을 부분

왼쪽은 상태 확인, 오른쪽은 실험 조건 설정이라는 차이를 먼저 말한다.

### 다음 장 연결

이렇게 실행한 결과를 안전하게 보존하고 실제 서비스와 분리하는 구조도 필요합니다.

### 발표자 확인 메모

노드 화면은 보고서에서 테스트 데이터 기반 UI 시연이라고 명시한다. 모든 장치의 실제 실행 완료 화면으로 소개하지 않는다.

**근거:** 박하준 2~7·16~17쪽

연습 분량: 약 55초. 실제 측정 시간이 아니며 영상 시간 제외.

## PPT 8쪽. 운영·연구 경로 분리와 결과 관리

**핵심:** 서비스를 사용하는 경로와 설정을 바꾸며 실험하는 경로를 구분한다.

### 페이지 설명

연구 중 모델·설정을 바꾸는 작업이 서비스 실행과 충돌하지 않게 역할을 분리하려는 구조다. 첫 토큰 시간은 답이 처음 나타날 때까지, 전체 응답 시간은 답변이 끝날 때까지의 대기다. 처리량은 일정 시간에 처리한 요청이나 토큰의 양이다. 미측정과 0은 다르므로 실패·제외와 함께 관리한다.

### 발표 대본

AI를 실제 서비스에 사용하는 운영 경로와, 모델이나 조건을 바꿔 비교하는 연구 경로를 분리하는 구조를 검토했습니다. 연구 실험이 운영 서비스에 영향을 주지 않도록 하기 위한 것입니다. LLM 성능은 첫 답변이 나타나는 시간과 응답이 끝나는 시간, 처리량을 나눠 봤습니다. 실험 조건과 실패·제외 기록도 함께 남기고, 측정하지 못한 값을 임의로 0으로 넣지 않는 방식으로 결과를 관리했습니다.

### 화면에서 짚을 부분

가운데 그림에서 운영과 연구의 두 경로를 짚은 뒤 하단 지표를 설명한다.

### 다음 장 연결

소프트웨어 구조 외에 여러 장치를 실제로 배치하는 구조도 검토했습니다.

### 발표자 확인 메모

분리 구조의 구현·검토와 모든 장치 조합에서의 운영 독립성 검증 완료는 같은 뜻이 아니다.

**근거:** 박하준 7~11·17쪽

연습 분량: 약 50초. 실제 측정 시간이 아니며 영상 시간 제외.

## PPT 9쪽. 임베디드 장치 배치와 적층 케이스 설계

**핵심:** 여러 장치를 설치할 물리적 구조를 설계하고 예비 검토했다.

### 페이지 설명

Jetson과 Raspberry Pi를 함께 배치할 때 공간·배선·고정 구조를 고려한다. 적층 구조는 여러 층에 장치를 나누어 두는 방식이다. PLA 예비 구조해석은 설계 단계의 검토이며 완성 제작물의 하중·발열·안전성이 모두 검증됐다는 의미가 아니다.

### 발표 대본

## 예상 질문과 답변

### 키오스크·LLM 분야는 정확히 무엇을 한 건가요?

이 보고서는 주로 검사 선택과 기록 관리, 로컬 LLM 실행 환경, 장치 관리·스윕·측정·결과 보존 구조를 다룹니다. LLM 자체의 의료 문답 추가 학습과 동일한 작업이라고 묶지는 않습니다.

### 여러 장치에 LLM을 연결하면 모델 하나가 나눠서 계산되나요?

각 장치에 사본을 두고 요청을 분산하는 방식과 한 모델을 나눠 계산하는 방식은 다릅니다. 실제 어떤 방식의 결과인지 조건을 확인해 설명해야 합니다.

### 첫 토큰 시간과 전체 시간은 어떻게 다른가요?

처음 답이 보이기까지의 대기와 답변이 완성되기까지의 대기입니다. 입력·출력 길이와 동시성을 함께 기록해야 비교할 수 있습니다.

### 보고서의 여러 장치 시험은 이번 기간에 모두 새로 한 건가요?

박하준 보고서는 별도 보존된 8월 21일의 실장비 기능 검증도 검토합니다. 이것을 이번 1~7주차에 새로 수행한 성능 실험으로 바꿔 설명하지 않습니다.

### VLM과 YOLO는 중복 아닌가요?

VLM은 약통 종류·자세·잡을 부위를 판단하고 YOLO는 사진에서 약통 위치를 검출합니다. 목적과 정답 형식이 다릅니다.

### 585장은 YOLO 학습 사진 수인가요?

17쪽 상단의 585장은 VLM 선정 사진 수입니다. 하단 YOLO 학습 설명과 같은 데이터 수로 읽지 않습니다.

### ACT와 VLM의 학습 자료가 왜 다른가요?

VLM은 정지 사진과 속성 정답을, ACT는 시간에 맞춘 영상·관절·행동 시연을 사용하기 때문입니다.

### Episode와 step이 같은 횟수인가요?

아닙니다. Episode는 한 번의 시연 단위이고 step은 학습 파라미터 갱신 횟수입니다.

### mAP 0.995면 자동 분류가 완성된 건가요?

단일 약통 위치 검출의 작은 평가에서 얻은 지표입니다. 종류 구분이나 전체 로봇 작업 성공률은 아닙니다.

### Loss가 줄었는데 실제 동작은 왜 실패하나요?

시연의 행동 예측과 실제 환경의 관측·좌표·관절 추종·접촉은 다릅니다. 시작 자세나 제어 문제를 분리해 확인해야 합니다.

### Tracking Gate는 새 AI 모델인가요?

여기서는 목표와 실제 관절 상태를 확인하며 다음 동작 진행을 제어하는 방식입니다. 새 분류 모델이나 ACT 대체 모델이라고 소개하지 않습니다.

### 그래프의 0.79는 성공률 79%인가요?

아닙니다. 추종 오차를 허용 한계로 나눈 비율이며 1 이하라는 기준을 통과했다는 뜻입니다.

### 보정 RMS가 작으면 실제 그리퍼도 그 오차로 움직이나요?

보정 자료의 잔차와 실제 끝점 도달 오차는 다릅니다. 다른 시험이 필요합니다.

### 현재 약통이 바구니까지 자동으로 들어가나요?

자료에는 파지 사례와 접근 경로 검토가 있으나 안정적인 투입과 전체 통합은 남아 있다고 구분합니다.

### 시연 영상은 바로 재생할 수 있나요?

검토한 PPT 64·65쪽에는 영상이 삽입돼 있지 않습니다. 실제 파일을 넣고 발표 PC에서 재생과 조건을 확인해야 합니다.
