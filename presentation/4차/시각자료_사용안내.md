# 4차 발표 그림 사용 안내

## 추천 순서

기존 [네 실험 학습곡선](시각자료/hair6__four_training_curves.png) 다음에 아래 1번을 사용한다. 실행 비용 설명은 **2번 지표 설명 → 3번 선정 후보 비용 → 4번 정확도–지연시간** 순서가 자연스럽다. 5번 전체 34개 지연시간은 부록이나 질의응답용으로 권장한다.

1. [Hair 6종 성능 종합](시각자료/04_hair6_model_performance_dashboard.png): 네 조건의 Validation Accuracy·Macro F1 막대, 클래스별 Validation F1, 선정된 두 후보의 고정 Test 결과를 한 장에 모았다. LS는 Label Smoothing 0.05다. Test를 실행하지 않은 두 조건의 점수는 만들지 않았다.
2. [실행 비용 지표 설명](시각자료/04_runtime_metrics_explained.png): Model·End-to-end, p50·p95, 학습 시간, 파일 크기, 정확도와 실행 시간의 교환 관계를 설명한다. 그림의 처리 경로는 이번 측정 코드 범위다.
3. [선정 후보 실행 비용](시각자료/04_selected_models_runtime_cost.png): Skin v1, Web Skin v2, Hair 5종 v2, Hair 6종 성능 우선·비용 대안의 지연시간·파일 크기·과거 학습 시간을 비교한다. 파일 크기는 측정 당시 checkpoint bytes이며 이후 다른 형식으로 패키징한 ZIP 크기가 아니다.
4. [정확도–지연시간 관계](시각자료/04_accuracy_latency_tradeoff.png): 정제 후 28개 조건을 Skin 2 / Web Skin 10 / Hair 5종 12 / Hair 6종 4개로 나눠 그렸다. 가로축은 이번 p50, 세로축은 과거 Validation Accuracy다. 작은 점이 실제 좌표이고 번호가 붙은 원은 범례를 연결하는 표식이다. 초기 6개는 분할이 다르거나 Validation 기록이 없어 제외했다. 점별 값은 [그림 원자료](정확도_지연시간_그림_원자료.csv)에 있다.
5. [34개 전체 지연시간](시각자료/04_all34_latency_comparison.png): Skin 4 / Web Skin 12 / Hair 5종 14 / Hair 6종 4개, 총 34개를 모두 표시한다. 파랑 선 끝은 p50, 주황 점은 p95이며 전체 패널의 시간축은 같다. MedSigLIP은 보라색이고 영상 인코더와 분류층을 함께 실행한 값이다.

## 결과를 보고 말할 수 있는 내용

Hair 6종의 B1·384 원본은 Validation Macro F1 `0.8144942091318823`, B0·256 증강은 `0.7819142733310591`이다. 후보를 고정한 뒤 Test Macro F1은 각각 `0.8091500773460419`, `0.8021613486071133`이었다. Colab p50은 각각 `409.83297050024703 ms`, `288.73898249958074 ms`다. B1은 분류 성능, B0는 짧은 실행 시간이라는 장점이 있어 두 후보의 용도를 나눴다고 설명할 수 있다. 모델 구조·입력·Loss·Train 구성이 함께 다르므로 한 요소만의 효과로 설명하지 않는다.

Web Skin PMG B1·384는 Validation Accuracy `0.866`, PMG B0·256은 `0.85`다. p50은 각각 `419.9053944998923 ms`, `304.2439384998943 ms`이므로 높은 Validation 점수에 더 긴 실행 시간이 따른다는 점을 보여준다. 최종 전달 후보는 PMG B0·256이다.

Skin Clean 원본·증강 모델은 구조가 같고 p50도 비슷하다. 증강은 학습 데이터 구성의 차이이며 저장 모델의 추론 때 같은 증강을 실행한다는 뜻이 아니다. 짧은 시간 차이를 증강 덕분의 속도 개선으로 주장하지 않는다.

Hair 5종은 단일 B1·384 Adam이 선정 후보다. SupCon은 비교 기준 B1·256보다 Validation이 높으면서 추론 시간은 비슷했다. DINOv2와 MedSigLIP이 더 빠르게 측정됐다는 사실만으로 분류 성능·메모리·통합 비용까지 모두 낫다고 판단하지 않는다.

## 측정 범위와 지표

- 환경: Colab GPU 1개, Python 3.13.15, TensorFlow 2.20.0. GPU 제품명은 저장되지 않았다.
- 입력: 같은 합성 RGB 512×512 이미지, 배치 1, 워밍업 10회, 지표별 30회 측정.
- p50은 중앙값, p95는 느린 쪽 95백분위다. p95는 최대값이 아니다.
- End-to-end는 이번 코드의 이미지 변환부터 분류 출력까지다. 모델 로드·카메라·파일 읽기·네트워크·전체 앱은 제외됐다. Model 시간과 End-to-end 시간은 따로 반복 측정했으므로 둘의 중앙값 차이를 정확한 전처리 시간으로 해석하지 않는다.
- 과거 학습 시간은 각 원래 실험의 기록이다. 같은 GPU에서 34개를 재학습해 얻은 공정 속도 순위가 아니다.
- 파일 크기·가중치 바이트와 최대 GPU/RAM 사용량은 다르다. 전력·최대 메모리·Jetson 실행 시간은 측정하지 않았다.
- MedSigLIP은 외부 본체까지 실행했지만 작은 분류층 파일만 checkpoint bytes로 잡힌 경우가 있다. 프레임워크·정밀도 경로도 다른 모델들과 다르다.
- 반복 30회의 개별 원시 시간은 이 보고서에 없다. p50·p95로 히스토그램이나 한 모델의 실행별 상자그림을 추정하지 않았다. 기존 `metrics_overview`의 상자그림은 **여러 모델 사이의 시간 분포**다.
- 정확도–지연시간 그림의 y축 범위는 과제별로 다르다. 다른 도메인의 점수를 직접 빼거나 전체 성능 순위로 읽지 않는다.
