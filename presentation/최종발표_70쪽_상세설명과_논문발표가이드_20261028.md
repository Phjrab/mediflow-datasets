## 1. 자료에 대한 종합 의견

발표의 큰 흐름은 잘 잡혀 있다. 데이터 예시와 초기 학습을 보여준 다음, 데이터 검사, 미세조정, 논문 아이디어 응용, 양호 클래스 확장, 실행 비용 측정, 최종 후보 선정으로 이어진다. 특히 결과가 좋았던 실험만 나열하지 않고 채택하지 않은 실험도 포함해 **무엇을 근거로 선택했는지** 설명할 수 있다.

다만 슬라이드를 많이 확보한 것과 발표를 듣는 사람이 이해하는 것은 별개의 문제다. 모든 그래프의 모든 숫자를 읽으면 핵심이 흐려진다. 의료 AI 부분의 중심 문장은 다음과 같이 잡는 것이 좋다.

> “처음에는 같은 EfficientNet으로 원본과 증강 데이터를 비교했습니다. 점수의 신뢰성을 확인하기 위해 데이터를 정리했고, 그다음 특징 학습과 입력 조건을 바꾸었습니다. 이후 두피와 얼굴 사진의 특성에 맞는 논문 아이디어를 비교한 뒤, 검증 성능과 실행 비용을 함께 보고 후보를 선정했습니다.”

### 숫자를 설명하는 기본 규칙

- **Train**: 모델이 답을 보며 배우는 사진이다.
- **Validation**: 학습 설정과 저장할 모델을 고를 때 사용하는 사진이다.
- **Test**: 후보를 정한 뒤 성능을 확인하는 별도 사진이다. Validation 점수와 같은 것으로 읽지 않는다.
- **Accuracy**: 전체 사진 중 맞힌 비율이다.
- **Macro F1**: 클래스별 F1을 같은 비중으로 평균한 값이다. 특정 클래스의 표본 수가 많다고 그 클래스가 평균을 독점하지 않게 한다.
- **%p**: 두 비율의 차이다. 79.60%에서 85.00%는 5.40%p 상승이다.
- **p50 지연**: 반복 실행 시간의 중앙값이다. **p95**는 느린 쪽 꼬리를 보는 95백분위 값이다.
- **양호**: 이번 Hair 추가 데이터의 라벨 정의다. 모든 두피 질환이 없다는 의학적 판정을 뜻하지 않는다.

## 2. 페이지별 상세 설명과 발표 대본

각 장의 ‘발표 대본’은 그대로 읽을 수 있는 예시다. 팀원이 수행한 키오스크·로봇팔 작업은 첨부 PPT에 적힌 범위로 설명했다. 해당 팀원의 원래 로그·개인보고서를 이번에 모두 확보해 재검증한 것은 아니므로, 추가 질문에서 실험 조건을 새로 만들어 답하지 않는다.

### 1쪽. 표지

**역할:** 팀명과 발표 범위를 소개하는 시작이다.

**발표 대본:** “안녕하세요. Papyrus 팀의 자율설계 연구 진행 내용을 발표하겠습니다. 저희는 검사 서비스를 제공하는 키오스크와 의료 이미지 분류 모델, 약통을 인식하고 옮기는 로봇팔을 각각 개발하고 있습니다. 이번 발표에서는 각 기능을 어떻게 만들었는지와 실험을 통해 무엇을 확인했는지 중심으로 말씀드리겠습니다.”

**설명:** 여기서부터 모든 기능이 완전히 연결됐다고 선언할 필요는 없다. 최종 통합 목표와 현재 완료한 개별 기능을 구분하면 뒤의 한계·향후 계획과 자연스럽게 이어진다. 표지의 ‘중간’과 실제 발표 목적은 먼저 통일한다.

### 2쪽. 목차

**역할:** 많은 실험을 네 덩어리로 묶어 청중에게 길을 알려준다.

**발표 대본:** “먼저 전체 연구 범위를 설명하고, 키오스크·의료 AI·로봇팔의 개발 과정을 소개하겠습니다. 이후 데이터 검사와 학습 방법 변경, 후보 비교 결과를 말씀드리고 마지막으로 남은 통합 과제를 정리하겠습니다.”

**설명:** ‘개발 및 학습’은 무엇을 만들었는지, ‘개선 실험’은 왜 바꿨고 결과가 어땠는지에 해당한다. 두 장의 차이를 이렇게 잡으면 반복되는 느낌이 줄어든다. 목차의 ‘실제 장비 검증’은 로봇팔 등 해당 부분에 적용되며, 피부·두피 모델의 공개 데이터 평가 전체를 실장비 평가라고 묶지 않는다.

### 6쪽. 사용자 기록과 검사 기능

**역할:** 검사 결과가 사용자 기록으로 남는 서비스 흐름을 보여준다.

**발표 대본:** “사용자는 안구·피부·두피 중 검사 항목을 선택하고, 한 번의 검사 기록에 문진과 이미지, 결과 보고서를 연결하도록 구성했습니다. 이전 결과를 새 결과로 덮어쓰지 않고 보존해야 이후 검사와 비교할 수 있기 때문에 이력과 중복 관리도 함께 고려했습니다.”

**설명:** 사용자, 검사 세션, 이미지, 보고서는 서로 연결되지만 같은 데이터는 아니다. 화면은 UI와 데이터 관리 기능을 보여주는 예시다. 이 화면 자체가 진단 성능을 증명하지는 않는다. 질문을 받으면 ‘어떤 기록이 연결되는가’를 설명하면 된다.

### 7쪽. 장치 관리와 스윕 실험

**역할:** 모델을 바꿔가며 시험할 때 실행 조건을 관리하는 이유다.

**발표 대본:** “모델의 성능을 비교하려면 모델 이름만 바꾸는 것으로는 부족합니다. 장치 연결 상태와 모델 파일을 확인하고, 양자화 방식이나 입력·출력 길이, 동시에 처리하는 요청 수 같은 조건도 함께 기록해야 합니다. 이 화면은 그러한 실험 조건을 설정하고 상태를 확인하는 관리 기능입니다.”

**용어:** 스윕은 여러 설정을 순서대로 바꿔 시험하는 것이다. 양자화는 가중치 등의 수치 표현 정밀도를 낮추는 기술이다. 일반적으로 메모리를 줄일 수 있지만 이 프로젝트에서의 정확도·속도 효과는 실제 측정으로 판단해야 한다.

### 8쪽. 운영·연구 경로와 결과 관리

**역할:** 실제 서비스 사용과 연구 실험을 구분한다.

**발표 대본:** “서비스를 사용하는 경로와 설정을 바꿔 성능을 비교하는 연구 경로를 구분했습니다. LLM은 첫 글자가 나오기까지 걸리는 시간과 답변을 끝낼 때까지의 시간이 다르므로 따로 측정해야 합니다. 실패한 실행이나 측정하지 못한 값도 남기고, 미측정값을 0으로 넣어 성능이 좋아 보이게 만들지 않도록 했습니다.”

**설명:** 출처 ID는 71864다. 사진을 보고 새로운 진단을 내린 것이 아니라 제공된 라벨을 학습에 사용한 것이다. 현미경 적용을 목표로 한 Skin 모델과 공개 원천 사진의 실제 촬영 장비를 동일시하지 않는다. 다음 장의 얼굴 피부 과제와 라벨 체계도 다르다.

**발표 대본:** “Web Skin은 얼굴 전체 사진에서 건선·아토피·여드름·정상·주사를 구분하는 5종 과제입니다. AI Hub 안면부 피부질환 이미지 합성 데이터에서 사용 범위를 정했습니다. 피부 병변이 사진 전체에서 차지하는 비중이 작고 얼굴·머리카락·배경도 함께 보이기 때문에 Skin과 별도 모델로 다뤘습니다.”

**설명:** 출처 ID는 71863이다. ‘웹캠용’은 목표 사용 방식이다. 이 예시들이 모두 우리가 웹캠으로 새로 촬영한 검증 사진이라는 뜻은 아니다. 증상 이름의 의학적 정의보다 국소 병변과 촬영 스타일이라는 뒤의 실험 가설로 연결한다.

### 12쪽. Hair 데이터 예시

**발표 대본:** “Hair는 확대된 두피 사진에서 모낭사이홍반·미세각질·비듬·피지과다·탈모를 분류하는 5종 과제입니다. 유형별 두피 이미지에서 프로젝트에 사용할 자료를 선별했습니다. 서로 다른 클래스라도 흰 각질이나 붉은 색감이 비슷하게 나타나기 때문에 단순히 사진 수를 늘리는 것 외에 특징을 구분하는 학습이 필요했습니다.”

### 13쪽. 초기 데이터 구성

**역할:** 사진 수와 증강의 위치를 명확히 보여준다.

**발표 대본:** “처음 준비한 원본은 Skin 9,000장, Web Skin 4,500장, Hair 14,500장이었습니다. 원본을 Train·Validation·Test로 먼저 나누고 Train에만 변형본을 추가했습니다. 예를 들어 Hair는 원본 Train 11,600장에 5,800장을 추가해 17,400장으로 학습했습니다. Validation과 Test에는 증강본을 추가하지 않았습니다.”

**설명:** Skin은 7,300+1,000+700=9,000, Web Skin은 3,600+500+400=4,500, Hair는 11,600+1,450+1,450=14,500이다. ‘원본’은 추가 증강 전의 프로젝트 이미지라는 뜻이며, 합성 원천 사진까지 모두 실제 환자 촬영 원본이라는 뜻은 아니다. 분할 후 증강했다는 사실만으로 초기 중복 문제가 없었다고 말하지 않는다. 뒤에서 동일 사진 검사를 설명한다.

### 14쪽. 초기 모델 설정

**발표 대본:** “처음부터 복잡한 모델을 만들기보다 ImageNet으로 일반적인 이미지 특징을 배운 EfficientNet-B0를 출발점으로 사용했습니다. 입력은 224×224이고 특징 추출부는 고정한 채 새 분류층만 15회 학습했습니다. 원본만 사용한 경우와 증강본을 더한 경우를 같은 모델 조건에서 비교했습니다.”

**설명:** 특징 추출부는 사진의 패턴을 숫자 특징으로 바꾸는 부분, 분류층은 그 특징을 질환 라벨에 연결하는 부분이다. 이 단계와 이후 일부 특징 추출부까지 바꾸는 ‘부분 미세조정’이 다르다. ImageNet 가중치를 불러온 것이며 이전에 학습한 Hair 모델을 반드시 이어 학습한 것은 아니다.

### 15쪽. 로봇팔의 인식·판단·동작 분리

**발표 대본:** “로봇팔은 약통이 무엇이고 어떻게 놓여 있는지 판단하는 기능, 위치를 찾는 기능, 관절을 움직이는 기능으로 구분했습니다. VLM은 사진의 속성을 판단하고 YOLO는 위치를 검출하며, ACT는 시연한 동작을 학습합니다. 현재는 각 기능을 개발·평가하고 연결을 준비하는 단계입니다.”

**설명:** VLA 목표와 현재 개별 모델 구성을 혼동하지 않는다. 통신 주체를 정리했다는 것과 연속 영상·관절 데이터가 완전히 정상 수집됐다는 것도 별개다. 이 장의 기존 발표자 노트에는 의료 AI 방법 설명이 섞여 있어 사용하지 않는 것이 좋다.

### 16쪽. 이미지 라벨과 시연 데이터의 차이

**발표 대본:** “VLM은 사진과 함께 약통 종류·자세·파지 부위 같은 정답 라벨을 사용합니다. ACT는 한 장의 사진보다 동작의 연속성이 중요하므로 카메라 영상과 관절 상태, 행동을 시간에 맞춰 함께 기록합니다. 따라서 같은 로봇 연구에 쓰이더라도 두 데이터의 형식과 관리 기준은 다릅니다.”

### 17쪽. 데이터 검수와 위치 검출 학습

**발표 대본:** “초기 이미지·레코드에서 중복과 잘못된 라벨을 검수한 뒤 사용할 자료를 선정했습니다. 선정 585장은 Train 375장, Validation 99장, Test 111장으로 나뉩니다. 위치 검출에서는 작업대와 바구니의 마커 ID를 구분하고, YOLO11n을 입력 640·배치 8 조건으로 학습했습니다.”

### 23쪽. 초기 Validation 요약

**발표 대본:** “초기 실험을 Validation 기준으로 모으면 Skin은 매우 높고 Web Skin과 Hair에는 개선 여지가 있었습니다. 그래서 Skin은 먼저 높은 점수의 데이터 신뢰성을 확인하고, Web Skin과 Hair는 데이터 검사 뒤 학습 방법을 바꾸기로 했습니다. 이후의 초기 대비 변화는 이 표의 원본 조건을 출발점으로 읽겠습니다.”

**설명:** 여기의 초기 기준은 모두 B0·224·분류층만 15회 학습이다. 초기 증강 모델을 기준으로 바꾸면 변화량도 달라진다. ‘○쪽’ 참조 문구는 실제 파일 순서에 맞춰 수정한다.

### 24쪽. Skin 중복 검사

**발표 대본:** “다른 분할에 동일한 사진이 있으면 모델이 이미 본 사진으로 평가받을 수 있습니다. Skin에서도 정리할 동일 사진이 확인돼 초기 점수를 그대로 최종 결과로 사용하지 않았습니다. 화면의 사진 쌍은 왜 데이터 검증을 먼저 해야 했는지 보여주는 사례입니다.”

**설명:** 같은 사진이 여러 위치에 있는 것과 같은 사람의 서로 다른 사진이 있는 것은 다른 문제다. 이번 사례는 동일 사진 검사로 확인한 범위다. 이후 Skin 원본은 51장 줄었지만 이 숫자를 모든 형태의 누수를 완전히 제거했다는 뜻으로 읽지 않는다.

### 25쪽. Hair 동일 파일 겹침

**발표 대본:** “Hair는 SHA-256으로 파일 내용이 같은지를 검사했습니다. Train–Validation 195건, Train–Test 178건, Validation–Test 16건의 겹침이 있었습니다. 한 사진이 세 분할에 걸치면 여러 쌍에 잡힐 수 있으므로 이 숫자를 단순 합산해 삭제 사진 수라고 말하지 않았습니다.”

**설명:** SHA-256은 파일 바이트가 같을 때 같은 값이 나오는 내용 지문이다. 파일 이름이 같아서만 잡은 검사가 아니다. 다만 다른 형식으로 재저장한 같은 장면이나 같은 사람의 연속 촬영까지 해시 하나로 모두 찾을 수 있는 것은 아니다. 사람·세션 단위 검수는 별도의 확인이다.

### 26쪽. 정리 후 데이터 구성

**발표 대본:** “정리 후 Skin 원본은 8,949장, Web Skin은 4,500장을 유지했고, Hair는 12,536장이 됐습니다. 세 과제 원본 합계는 28,000장에서 25,985장으로 줄었습니다. Hair 감소량에는 중복과 라벨 정리 등이 포함되므로 모두 단순 중복 삭제라고 부르지는 않았습니다.”

**숫자 읽기:** Hair Train 10,032·Validation 1,252·Test 1,252이며, 추가 증강은 5,015장이다. 증강 포함 Train은 15,047장이다. Skin 증강 포함 Train은 14,498장이다. 표의 ‘추가 증강’은 원본 합계에 더해 원천 데이터 수라고 부를 수 없다.

### 27쪽. 데이터 검사 이후 실험 설계

**발표 대본:** “세 과제에 똑같은 변경을 일괄 적용하지 않았습니다. Skin은 정리 후에도 증강이 유리한지 확인했고, Hair는 고정된 특징의 한계를 줄이기 위해 부분 미세조정과 입력·손실·모델 크기를 비교했습니다. Web Skin은 같은 분할에서 여섯 조건을 비교했습니다.”

**설명:** 여기서 부분 미세조정을 한 문장으로 정의한다. ‘먼저 새 분류층을 안정시키고, 그다음 사전학습 모델 후반부 일부도 작은 학습률로 조정하는 방법’이다. 추가 10회라는 숫자가 성능을 보장하는 것이 아니라 학습 가능한 부분이 달라진다는 것이 핵심이다.

### 28쪽. Skin Clean 원본·증강

**발표 대본:** “같은 정제 데이터에서 원본 Train과 증강을 포함한 Train을 다시 비교했습니다. Validation Accuracy는 원본 97.30%, 증강 98.20%였고 증강 모델을 Skin v1으로 남겼습니다. 초기 99.50%보다 숫자가 낮아졌지만, 데이터 검사 후의 결과를 기준으로 후보를 고정한 것입니다.”

**설명:** 초기와 정제 후 데이터 구성이 다르므로 ‘성능이 1.3%p 악화됐다’라는 단독 결론은 적절하지 않다. 같은 Clean 비교 안에서는 97.30→98.20%가 증강 조건의 차이다. Skin은 이후 별도 v2가 만들어진 것이 아니다.

### 29쪽. Hair 입력 224와 256

**발표 대본:** “두피의 작은 각질과 모낭 주변 특징이 축소 과정에서 사라질 가능성을 보고 입력 크기를 비교했습니다. 같은 B0·CE 조건에서 Validation Accuracy는 224 입력 0.7644, 256 입력 0.7700으로 올라갔습니다. 큰 입력이 도움이 될 수 있다는 첫 근거였지만, 이 단계에서 상승 폭은 크지 않았습니다.”

**설명:** 224·256은 사진의 가로·세로 픽셀 수다. 사진을 더 크게 찍는 장비 변경과 다르고, 원래 없는 세부 정보를 복원한다는 뜻도 아니다. 저장 모델을 사용할 때는 해당 입력 크기로 전처리해야 한다.

### 30쪽. Label Smoothing과 Focal Loss

**발표 대본:** “다음에는 모델 구조보다 틀린 예에 주는 학습 신호를 바꿨습니다. Label Smoothing 0.05는 정답을 무조건 1로 강하게 맞추는 학습을 완화하고, Focal Loss 1.5는 쉬운 예보다 어려운 예에 더 집중하도록 합니다. Hair Validation에서는 LS가 0.7740으로 CE의 0.7700보다 높았고 Focal은 0.7676이었습니다.”

**설명:** Loss는 모델의 예측이 정답과 얼마나 다른지 학습 중 계산하는 값이다. 손실 함수가 바뀌면 숫자의 정의도 달라지므로 CE loss와 Focal loss의 절댓값 크기만 비교해 우열을 정하지 않는다. Focal이 원래 검출 불균형 문제에서 제안됐다고 해서 우리 균형 데이터가 불균형이었다고 말하지 않는다.

### 31쪽. B1과 추가 5회 학습

**발표 대본:** “B0에서 B1으로 모델 용량을 높이고 Label Smoothing을 유지했습니다. 이후 미세조정 5회를 더해 검증 개선이 이어지는지 확인했습니다. Validation Accuracy는 B1 기본 0.7764에서 연장 후 0.7772로 소폭 높아졌습니다. 따라서 학습을 더 하면 무조건 크게 좋아진다는 결과는 아니었습니다.”

**설명:** v1은 B1·256·LS 0.05·Stage 2 총 15회 조건이다. ‘+5회’는 기존 미세조정을 이어간 것이며 새 클래스나 새 데이터 버전이 아니다. 다른 Test 점수가 더 높은 모델이 있더라도 Test를 보고 되돌아가 선택하지 않았다는 원칙을 설명한다.

### 33쪽. Web Skin 여섯 조건 학습곡선

**발표 대본:** “Web Skin도 같은 분할을 유지하면서 입력 크기, Label Smoothing, Focal Loss, B1과 학습 연장을 비교했습니다. 학습곡선을 보면 Train 점수는 올라가지만 Validation이 같은 폭으로 좋아지는 것은 아니어서, 더 큰 모델이나 더 긴 학습만으로 선택하지 않았습니다.”

**설명:** 여섯 개 곡선을 순서대로 읽을 필요는 없다. 예시 하나로 Train과 Validation의 차이를 짚고 다음 큰 막대그래프에서 결과를 비교한다. 사진이 많아 보인다고 각 칸을 별도의 추가 학습으로 중복 집계하지 않는다.

### 34쪽. Web Skin v1 선정

**설명:** B1의 Macro F1이 조금 더 높지만 그때의 우선 선정 기준이 아니었다. 따라서 ‘B0가 모든 지표에서 최고’라고 말하면 안 된다. +5회 행은 새 연장 모델이 부모 최고를 넘지 못해 이전 최고가 유지된 값이다.

### 36쪽. 논문 기반 추가 실험의 질문

**발표 대본:** “기본 학습 이후에도 남은 혼동을 해결하려고 데이터 특성에 맞는 아이디어를 찾았습니다. Hair는 비슷한 질감을 특징 공간에서 분리하는 방법과 다른 사전학습 표현을, Web Skin은 작은 병변을 여러 크기로 보거나 촬영 스타일에 덜 의존하는 방법을 비교했습니다. 의료 사전학습 특징도 별도 후보로 확인했습니다.”

**설명:** 논문 이름을 먼저 외우게 하기보다 문제→방법 순서로 말한다. ‘원논문 전체를 똑같이 재현했다’가 아니라 ‘해당 원리를 프로젝트 모델에 응용했다’가 정확하다. 세부 소개는 3절의 논문 설명을 사용한다.

### 37쪽. Hair SupCon·DINOv2·V2-S·B1 384

**발표 대본:** “SupCon은 같은 클래스의 특징은 모으고 다른 클래스는 떨어뜨리는 학습입니다. DINOv2는 다른 방식으로 사전학습된 특징을 고정해 비교했고, EfficientNetV2-S는 다른 CNN 구조의 가능성을 봤습니다. B1·384는 두피의 작은 특징을 더 큰 입력에서 학습하는 조합입니다. 이 페이지는 그 학습 경과이며 최종 판단은 뒤의 Validation 비교로 하겠습니다.”

**설명:** DINOv2 15회는 고정 인코더의 분류층 학습이고, 다른 실험의 전체 학습 단계·횟수와 같지 않을 수 있다. 다양한 방법을 빠르게 선별한 비교이며 모두 같은 계산량으로 통제한 정밀 비교라고 말하지 않는다. 그림마다 학습 대상·축·단계를 확인한다.

### 38쪽. Hair SAM 후속 비교

**발표 대본:** “B1·384가 유망해 같은 구조에서 학습하는 방법을 한 번 더 바꿨습니다. SAM은 현재 파라미터 한 지점뿐 아니라 주변에서도 손실이 낮은 방향을 찾는 방법입니다. 검증 정확도는 Adam과 같았지만 Macro F1은 Adam이 조금 높아 최종 모델을 바꾸지 않았습니다.”

**설명:** SAM과 Adam은 모델 구조 이름이 아니다. 같은 B1·384 구조에서 가중치를 갱신하는 경로를 비교한 것이다. 일부 클래스 혼동이 감소했다고 전체 모델이 개선됐다고 결론내리지 않고 전체 지표를 함께 본 사례다.

### 39쪽. Web Skin WS-DAN·PMG·MixStyle·확대 PMG

**발표 대본:** “얼굴 사진에는 중요한 병변이 작은 영역에 있을 수 있어, WS-DAN으로 중요한 위치를 찾고 확대하는 방법을 비교했습니다. PMG는 사진을 여러 크기의 조각으로 나눠 세부 특징과 전체 구조를 학습하고, MixStyle은 특징의 스타일 통계를 섞어 촬영 조건 의존을 줄이려는 방법입니다. 이후 유망한 PMG를 B1·384로 확대했습니다.”

**설명:** 이 네 조건은 서로 다른 논문 네 편이 아니다. 새 방법 세 가지와 PMG 규모 확대 한 가지다. PMG Train Accuracy가 1에 가까워도 Validation이 같은 수준이라는 뜻이 아니다. PMG의 Train loss와 Validation loss는 계산 구성이 달라 두 선의 절댓값 차이를 일반 CE 그래프처럼 해석하지 않는다.

### 40쪽. Hair MedSigLIP Linear 학습

**발표 대본:** “일반 이미지 사전학습 대신 의료 이미지에 맞춰진 특징이 도움이 되는지도 확인했습니다. MedSigLIP 본체를 고정하고 사진의 특징 벡터를 추출한 다음, 새 선형 분류층만 학습했습니다. 입력은 448이고 분류층 학습은 최대 50회 조건입니다.”

### 46쪽. Hair 양호 추가와 6종 구성

**발표 대본:** “후반에는 양호 사진 534장을 추가해 Hair 6종 과제를 만들었습니다. 기존 5종의 분할은 유지하고, 새 사진은 파일명에서 얻은 ID를 묶어 Train 428장, Validation 53장, Test 53장으로 나눴습니다. 증강 포함 Train은 17,615장이고 양호 Train에는 변형본 2,140장을 추가했습니다.”

**설명:** B0와 B1 사이에는 모델·입력·손실 설정 차이가 함께 존재한다. 따라서 네 조건을 순수 Backbone 하나만 바꾼 비교라고 부르지 않는다. 각 모델 설정 안의 원본/증강 쌍과 두 모델 구성의 종합 비교를 나눠 읽는다.

### 48쪽. Hair 6종 Validation 비교

**발표 대본:** “B1 원본 조건이 Accuracy 0.7992, Macro F1 0.8145로 가장 높았습니다. B0에서는 증강이 원본보다 좋아졌지만 B1에서는 오히려 증강 조건이 낮았습니다. 그래서 증강을 무조건 많이 하는 것이 항상 좋은 것은 아니며, 성능 우선 후보는 B1 원본으로 선정했습니다.”

**설명:** 네 조건의 Macro F1은 0.7729·0.7819·0.8145·0.8020이다. 여기서 Macro F1이 Accuracy보다 큰 것은 계산이 잘못됐다는 뜻이 아니다. 클래스별 수와 정답·오답 분포가 달라 두 지표는 다르게 움직일 수 있다. 5종 점수와 6종 점수를 빼서 ‘정상 추가로 몇 % 개선’이라고 해석하지 않는다.

### 49쪽. 34개 저장 조건 실행 시간 측정

**발표 대본:** “분류 성능을 확인한 뒤에는 저장된 34개 조건을 다시 학습하지 않고 실행 시간만 측정했습니다. 같은 512×512 RGB 상수 이미지와 배치 1을 사용했고, 준비 실행 10회 뒤 각 지표를 30회 측정했습니다. 전처리와 추론, 출력 동기화까지의 지연을 기록했습니다.”

**설명:** 34는 저장 모델 조건의 수이며 전체 연구에서 수행한 모든 시도 수와 반드시 같지 않다. 측정에는 모델 로드·촬영·통신·전체 앱이 포함되지 않는다. GPU는 한 개로 기록됐지만 제품명은 보존되지 않았다. 실제 사진 정확도를 다시 평가한 실행도 아니다.

### 50쪽. Skin 성능·시간 대시보드

**발표 대본:** “파란 막대의 검증 정확도와 시간 지표는 얻어진 시점이 다릅니다. 정확도는 과거 저장된 평가이고 지연은 후속 실행 측정입니다. 같은 정제 Skin 비교에서 증강 모델의 검증 성능이 높았고 추론 지연은 원본 모델과 비슷했습니다.”

**설명:** 학습에서 증강 사진을 더 사용했다고 저장 모델을 실행할 때 그 사진들을 다시 만들어야 하는 것은 아니다. 과거 학습 시간은 당시 실행 환경이 서로 달라 공정한 속도 순위로 읽지 않는다. 막대의 색마다 단위와 좋고 나쁜 방향을 먼저 말한다.

### 51쪽. Skin 정확도–지연·지표 요약

**발표 대본:** “왼쪽은 같은 과제에서 정확도와 지연이 어떤 관계인지 보여줍니다. 같은 정제 데이터 조건끼리 보면 증강의 성능 이점을 유지하면서 지연이 크게 늘지 않았습니다. 오른쪽은 여러 지표를 한 번에 찾기 위한 요약이며, 시간 열은 작을수록 좋다는 점을 구분해야 합니다.”

**설명:** 초기 모델 두 개는 다른 분할에서 얻은 과거 성능이다. 모든 점을 한 정확도 순위로 경쟁시키지 않는다. 상자그림은 여러 저장 모델 조건 사이의 실행 비용 분포다. 단일 모델의 30회 반복 지연 분포와 같지 않다.

### 52쪽. Web Skin 성능·시간 대시보드

**발표 대본:** “Web Skin은 PMG B1·384가 검증 성능은 가장 높지만 실행 시간도 더 길었습니다. PMG B0·256은 기존 기본 모델보다 성능을 높이면서 B1보다 실행 비용이 작아 최종 후보로 유지했습니다. 이처럼 정확도만으로 결정하기 어려운 경우 시간 지표가 선택 이유를 보완합니다.”

**설명:** B1이 느리다는 것이 모든 하드웨어에서 같은 비율로 느리다는 뜻은 아니다. 이 측정 환경의 같은 경로에서 나타난 결과다. 정확도와 시간의 절충을 영어로 trade-off라고 한다.

### 53쪽. Web Skin 정확도–지연 관계

**발표 대본:** “PMG B0·256의 지연 중앙값은 약 304ms, PMG B1·384는 약 420ms였습니다. B1은 Validation Accuracy가 1.6%p 높았지만 지연이 약 116ms 더 길었습니다. 저희는 이 차이와 저장 크기를 고려해 B0를 사용 후보, B1을 검증 성능 선두 연구 조건으로 구분했습니다.”

**설명:** 위 시간은 발표용 근사 표현이며 정확한 값은 각각 304.2439384998943ms, 419.9053944998923ms다. 상자그림의 떨어진 점은 다른 모델 조건일 수 있으므로 특정 모델이 자주 실패한다는 뜻으로 읽지 않는다. 다른 프레임워크의 MedSigLIP 속도도 단순 구조 순위로 비교하지 않는다.

### 54쪽. Hair 5종 성능·시간 대시보드

**발표 대본:** “Hair 5종에서도 기존 Validation과 후속 지연 측정을 함께 확인했습니다. 빠른 모델이 반드시 정확한 것은 아니고, 복잡한 학습법이 반드시 무거운 추론을 만드는 것도 아니었습니다. 최종 후보 B1·384 Adam의 검증 성능과 실행 비용을 이 표에서 함께 확인했습니다.”

**설명:** SupCon과 SAM은 주로 학습 경로를 바꾸므로 학습 때 추가 계산을 했다는 사실만으로 추론 때도 똑같은 추가 계산이 있다고 말할 수 없다. 저장된 실제 추론 구조를 기준으로 판단한다.

### 55쪽. Hair 5종 정확도–지연 관계

**발표 대본:** “SupCon은 기준선과 비슷한 지연에서 더 높은 Validation을 보였고, B1·384 Adam은 약 407ms의 측정 지연과 가장 높은 단일 모델 검증 성능을 보였습니다. SAM은 후보를 바꿀 만큼 전체 지표를 개선하지 못했기 때문에 기존 Adam 모델을 유지했습니다.”

**설명:** 지연의 정확한 값은 407.29406550008207ms다. 서로 다른 저장 조건의 분포를 한 모델의 안정성으로 읽지 않는다. ‘빠른 대안이 있나’와 ‘최고 정확도 후보가 무엇인가’를 나눠 답한다.

### 56쪽. Hair 6종 성능·시간 대시보드

**발표 대본:** “6종은 B1 원본 조건이 검증 성능 선두였고 B0 증강 조건은 실행 비용이 낮았습니다. 증강은 학습 시간과 사진 수를 늘렸지만, 저장된 모델 한 장 추론에 증강 사진을 다시 넣는 것은 아닙니다. 두 후보는 성능 우선과 경량 대안이라는 역할로 나눴습니다.”

**설명:** B0와 B1의 차이에는 구조·해상도·Loss·Train 종류가 함께 있으므로 원본/증강 하나의 효과로 설명하지 않는다. 원래 5종 최종 경로를 6종으로 자동 교체한 것도 아니다.

### 57쪽. Hair 6종 절충 관계

**발표 대본:** “B1·384 원본의 지연 중앙값은 약 410ms이고 B0·256 증강은 약 289ms였습니다. B1은 검증 Macro F1이 0.8145로 높고, B0는 0.7819지만 더 짧은 지연을 보였습니다. 따라서 사용 환경에서 어느 쪽을 우선할지 선택할 수 있도록 두 후보를 보존했습니다.”

**설명:** 정확한 지연은 409.83297050024703ms, 288.73898249958074ms다. 가중치 파일 크기와 최대 GPU 메모리는 다르다. 이 측정에서 최대 GPU 메모리나 전력은 얻지 않았으므로 ‘저전력 검증’이라고 말하지 않는다.

### 58쪽. 현재 남긴 후보와 역할

### 59쪽. 고정 후보의 최종 Test

**발표 대본:** “후보를 정한 뒤 별도 Test에서 확인했습니다. Skin은 700장 Accuracy 98.71%, Web Skin은 400장 91.50%, Hair 5종은 1,252장 80.03%였습니다. Hair 6종은 같은 1,305장 Test에서 성능 우선 79.16%, 경량 78.70%였습니다. 이는 각 공개 데이터 분할의 결과입니다.”

**설명:** F1은 Skin 0.9871, Web Skin 0.9141, Hair5 0.8002, Hair6 성능 우선 0.8092·경량 0.8022다. Web Skin Test가 Validation보다 높은 것은 두 평가 집합의 난이도가 다를 수 있기 때문이다. 서로 다른 사진 집합 점수를 비교해 누수가 없다는 증명이나 잘못된 평가라는 단정을 할 수는 없다. 현장 촬영 검증과 구분한다.

### 60쪽. 약통 VLM 속성별 결과

**발표 대본:** “약통 VLM은 종류·자세·파지 부위의 정확도를 따로 평가했습니다. 후속 학습에서 자세와 파지 판단은 높아졌지만 약통 종류는 상대적으로 어려웠습니다. 한 항목이 높다고 세 항목을 동시에 모두 맞힌 비율도 같다고 볼 수 없어 속성별 오류를 분리해 보았습니다.”

**설명:** 23.4→36.9%는 종류, 42.3→79.3%는 자세, 61.3→81.1%는 파지의 표기 기록이다. 이중 어댑터 행의 종류는 별도 평가 대상이다. 같은 평가 세트였는지·모든 조건이 고정됐는지는 팀원 원본 기록으로 확인하고 답한다. 의료 이미지 MedSigLIP 실험과 이 VLM은 별개다.

### 61쪽. YOLO 위치 검출 결과

**발표 대본:** “YOLO는 약통이 어디에 있는지를 한 클래스로 검출했습니다. 작은 Validation과 smoke Test에서 높은 수치를 보였지만, A·B·C 약통 종류를 자동 분류한 결과는 아닙니다. 평가 사진 수가 작아 독립 환경의 오검출률과 실제 작업 정확도는 더 확인해야 합니다.”

**설명:** Precision은 검출한 것 중 실제 약통인 비율, Recall은 실제 약통 중 찾아낸 비율이다. mAP50은 겹침 기준 0.5에서, mAP50–95는 여러 엄격한 겹침 기준에서 검출을 종합한 값이다. smoke Test는 우선 실행이 되는지 확인하는 소규모 시험이다. mAP 0.995를 전체 로봇 작업 성공률 99.5%라고 읽지 않는다.

### 62쪽. ACT 학습과 실제 구동

**발표 대본:** “ACT는 시연 데이터로 학습한 뒤 Jetson에서 실행을 시험했습니다. 그래프상 학습 손실이 내려갔지만 실제 약통 C 동작에는 실패가 있었습니다. 학습과 모델 로딩이 끝난 것, 로봇이 실제 작업을 안정적으로 성공하는 것은 다른 단계라는 점을 확인했습니다.”

**설명:** 그림은 A·B·C 세 카메라 정책의 초기 10,000스텝 손실이다. 다른 약통의 100K 후속 기록과 섞지 않는다. 서로 다른 정책 loss의 절대값이 낮은 순서가 반드시 파지 성공 순서라는 뜻도 아니다.

### 63쪽. 로봇 구동 오류와 후속 개선

**발표 대본:** “실제 구동에서는 시작 자세 차이, 팔보다 먼저 열리는 그리퍼, 중단 때의 토크 처리, 좌표 기준 혼용 같은 문제가 드러났습니다. 각각 데이터 전처리, 목표와 실제 관절 상태를 비교하는 Tracking Gate, 종료 동작 수정, 좌표 기준 분리로 대응했습니다. 적용 여부와 실장비 효과 확인 여부를 표에서 나눴습니다.”

**설명:** Tracking Gate는 목표 동작을 충분히 따라왔는지 확인하며 다음 동작 진행을 제어하는 장치로 설명하면 된다. PIN과 GRASP의 TCP는 같은 기준점이 아니다. 코드 수정·비동작 시험 완료와 실제 반복 동작 검증을 구분한다.

### 64쪽. 시연 1 자리

**발표 대본 예시:** “이 영상은 초기 개발 단계에서 약통에 접근하고 파지를 시도한 과정입니다. 영상에서 목표 위치에 접근하는 부분과 실제로 안정적으로 잡고 옮기는 부분을 구분해서 보겠습니다.”

**확인 필요:** 현재 파일에는 재생할 영상이 삽입돼 있지 않다. 영상이 준비된 뒤 실제 보이는 장면에 맞게 대본을 확정해야 한다. 현재 상태에서 파지 성공 횟수·물체 이동·완료 시점을 지어 말할 수 없다. 영상이 없다면 앞뒤 설명만 이어서 발표한다.

### 65쪽. 시연 2 자리

**발표 대본 예시:** “다음은 앞선 시연에서 확인한 문제를 수정한 후의 사례입니다. 어떤 동작이 달라졌는지와 여전히 남은 한계를 비교하겠습니다.”

**확인 필요:** 이 장도 영상 파일과 연결 정보가 없다. 첫 번째와 두 번째 영상의 실험 조건이 무엇인지, 같은 약통·시작 자세인지 확인해야 한다. 영상 한 사례의 성공을 반복 성공률로 바꾸어 말하지 않는다.

### 66쪽. 로봇팔의 현재 도달 단계

**발표 대본:** “접근 경로와 관절 추종, 좌표 보정 기록을 확인했고 파지 사례도 있습니다. 다만 그래프의 0.79는 성공률 79%가 아니라 관절 추종 오차를 허용 한계로 나눈 값입니다. 1 이하라는 조건을 통과한 것이며 안정적인 파지·이동·바구니 투입은 반복 검증이 남아 있습니다.”

**설명:** 이 전환에서는 지금까지의 모든 수치를 다시 반복하지 않는다. 무엇을 확보했고 무엇이 다음인지에 집중한다.

## 3. 논문 기법을 발표하는 방법

### 3.1 공통 설명 순서

이름과 학회명을 먼저 길게 읽기보다 다음 네 문장을 준비한다.

1. **문제:** “두피에서는 각질이 비슷해 클래스 사이가 잘 나뉘지 않았습니다.”
2. **논문의 아이디어:** “같은 클래스 특징은 가깝게, 다른 클래스는 멀게 학습하는 방법을 참고했습니다.”
3. **우리 적용:** “B1·256과 같은 Validation을 유지하고 특징 학습을 SupCon으로 바꿨습니다.”
4. **관측 결과와 결정:** “정답이 20장 늘었지만 최종 B1·384보다 낮아 보조 비교 결과로 남겼습니다.”

모든 방법을 합쳐 최종 모델에 넣었다고 설명하면 안 된다. **서로 다른 후보를 비교한 실험**이며, Hair 최종 모델은 SupCon·DINOv2·SAM을 모두 쌓은 구조가 아니다. Web Skin PMG 모델도 WS-DAN과 MixStyle을 함께 적용한 모델이 아니다.

### 3.2 EfficientNet과 입력 크기

**원문:** Tan & Le, *EfficientNet: Rethinking Model Scaling for Convolutional Neural Networks*, ICML 2019. [공식 학회 원문](https://proceedings.mlr.press/v97/tan19a.html)

**한 문장 설명:** 모델의 깊이·너비·입력 해상도를 균형 있게 확장하는 CNN 계열이다.

**우리 실험:** ImageNet 사전학습 B0/B1을 불러와 분류층을 학습하고 후반부를 부분 미세조정했다. 작은 두피 특징을 보존할 가능성을 보고 224·256·384 입력을 비교했다.

**발표 표현:** “EfficientNet에서 모델 크기와 해상도가 중요한 축이라는 점을 참고해 후보를 구성했습니다.” 원논문이 ‘두피는 B1·384가 최적’이라고 제안했다는 뜻은 아니다. B1·384는 프로젝트에서 선택한 조합이다.

**질문 대비:** B1이라는 모델 이름과 ‘프로젝트 후보 버전 v1/v2’는 다르다. EfficientNetV2-S도 Hair v2라는 버전명과 다르다.

### 3.3 전이학습과 부분 미세조정

**공식 구현 참고:** [Keras 전이학습·미세조정 가이드](https://keras.io/guides/transfer_learning/)

**한 문장 설명:** 일반적인 이미지 특징을 배운 모델을 재사용하고, 새 과제에 맞춰 일부 가중치를 조정하는 방법이다.

**코드 관점:** 처음에는 Backbone을 학습 불가로 두고 새 분류층을 학습한다. 그다음 후반부 일부를 학습 가능하게 바꾼 뒤 더 낮은 학습률로 다시 학습한다. 현재 EfficientNet은 내부 Rescaling을 포함하므로 외부에서 무조건 `/255`를 추가하는 방식으로 설명하지 않는다.

**발표 표현:** “추가 10회라는 숫자 자체보다 학습하는 범위를 넓힌 것이 핵심입니다.” 이 방법은 새로운 논문을 직접 발명한 것이 아니라 널리 쓰이는 전이학습 절차를 적용한 것이다.

### 3.4 Label Smoothing

**원문:** Szegedy et al., *Rethinking the Inception Architecture for Computer Vision*, CVPR 2016. [원문](https://arxiv.org/abs/1512.00567)

**한 문장 설명:** 정답을 100%로만 강하게 맞추는 학습을 완화하는 규제 방법이다.

**우리 적용:** Categorical Crossentropy의 `label_smoothing=0.05`를 사용했다. K개 클래스에서 정답 성분은 `1−0.05+0.05/K`, 나머지는 `0.05/K`가 된다. 5종에서는 정답 0.96, 나머지 각 0.01이다.

**결과:** Hair B0·256에서 CE 0.7700보다 LS 0.7740의 Validation이 높았다. Web Skin에서는 CE보다 높지 않았다.

**발표 표현:** “유사한 클래스에서 과도한 확신을 완화할 가능성을 검토했습니다.” 실제 예측 점수가 정확히 보정된 확률이 됐다고 말하지 않는다.

### 3.5 Focal Loss

**원문:** Lin et al., *Focal Loss for Dense Object Detection*, ICCV 2017. [원문](https://arxiv.org/abs/1708.02002)

**한 문장 설명:** 쉬운 표본의 학습 기여를 줄여 어려운 표본에 상대적으로 더 집중한다.

**우리 적용:** `gamma=1.5`, `alpha=1.0` 설정을 분류 과제에 적용했다. 원래 논문이 다룬 검출의 전경·배경 불균형과 프로젝트의 질환 분류 문제는 다르다. 우리 목적은 클래스 수 불균형 해결보다 어려운 유사 예의 구분 가능성 확인이었다.

**결과:** Hair와 Web Skin v1 Validation에서 LS나 CE보다 앞서지 않아 최종 v1으로 선택하지 않았다.

**발표 표현:** “원논문의 어려운 표본 집중 원리를 분류 손실에 적용했지만, 이번 조건에서는 선택 지표를 개선하지 못했습니다.”

### 3.6 SupCon

**원문:** Khosla et al., *Supervised Contrastive Learning*, NeurIPS 2020. [원문](https://arxiv.org/abs/2004.11362)

**한 문장 설명:** 정답 라벨을 이용해 같은 클래스 특징은 모으고 다른 클래스 특징은 떨어뜨린다.

**우리 적용:** Hair B1·256의 특징 학습 후 분류기를 학습했다. 같은 데이터와 Validation을 사용한 기준선과 비교했다. 보통 분류 손실은 최종 답의 맞고 틀림을 직접 학습하고, SupCon은 그 앞의 특징 배치도 바꾸려는 차이가 있다.

**결과:** 기준선 정답 971/1,252에서 991/1,252, Macro F1 0.7746→0.7911. 미세각질↔비듬 혼동은 74→69건이었다.

**발표 표현:** “특징 분리 가설에 도움이 되는 결과를 얻었지만 최종 B1·384의 전체 성능이 더 높았습니다.” 최종 Hair가 SupCon 모델이라고 소개하지 않는다.

### 3.7 DINOv2

**원문:** Oquab et al., *DINOv2: Learning Robust Visual Features without Supervision*, 2023. [원문](https://arxiv.org/abs/2304.07193)

**한 문장 설명:** 대규모 자기지도 사전학습으로 얻은 범용 시각 특징을 활용한다.

**우리 적용:** Small 인코더와 224 입력을 사용하고 인코더는 고정한 채 새 분류층만 학습했다. 우리가 원논문의 대규모 자기지도 사전학습을 직접 수행한 것이 아니다.

**결과:** Validation Accuracy 0.7700, Macro F1 0.7705로 현재 Hair 최종 후보보다 낮았다.

**발표 표현:** “현재 고정 인코더 선형 분류 조건에서는 이득이 없었습니다.” ‘Transformer는 두피에 맞지 않는다’로 일반화하지 않는다.

### 3.8 EfficientNetV2-S

**원문:** Tan & Le, *EfficientNetV2: Smaller Models and Faster Training*, ICML 2021. [공식 학회 원문](https://proceedings.mlr.press/v139/tan21a.html)

**한 문장 설명:** 학습 효율과 파라미터 효율을 고려해 설계한 다른 CNN 계열이다.

**우리 적용:** V2-S 사전학습 구조를 Hair 256 입력 후보로 비교했다. 원논문의 모든 학습 정책과 원천 데이터를 재현한 실험은 아니다.

**결과:** Validation Accuracy 0.7692, Macro F1 0.7682였다.

**발표 표현:** “더 새로운 구조가 같은 데이터에서 자동으로 더 좋은 것은 아니어서 채택하지 않았습니다.” 원논문의 속도 이득을 우리 장비에서 그대로 검증한 것처럼 말하지 않는다.

### 3.9 SAM

**원문:** Foret et al., *Sharpness-Aware Minimization for Efficiently Improving Generalization*, ICLR 2021. [원문](https://arxiv.org/abs/2010.01412)

**한 문장 설명:** 한 지점의 손실뿐 아니라 주변 파라미터에서도 손실이 낮은 해를 찾는다.

**우리 적용:** B1·384의 같은 Stage 1을 출발점으로 Adam과 SAM `rho=0.05`를 비교했다. 학습 시 주변 가중치에서 손실을 다시 계산하는 추가 과정이 들어간다.

**결과:** Accuracy는 둘 다 0.7963, Macro F1은 Adam 0.7957, SAM 0.7955였다. 일부 혼동 감소가 전체 개선으로 이어지지 않아 Adam을 유지했다.

**발표 표현:** “현재 조건에서 추가 최적화 비용에 비해 전체 지표 이득을 얻지 못했습니다.” 아주 작은 F1 차이를 큰 통계적 우위로 강조하지 않는다.

### 3.10 WS-DAN

**원문:** Hu et al., *See Better Before Looking Closer: Weakly Supervised Data Augmentation Network for Fine-Grained Visual Classification*, 2019. [원문](https://arxiv.org/abs/1901.09891)

**한 문장 설명:** 구분에 유용한 위치를 attention으로 찾아 그 영역을 활용한 학습을 한다.

**우리 적용:** Web Skin B0·256에서 attention 기반 표현과 확대 영역을 활용했다. 별도 병변 박스 라벨 없이 작은 피부 단서를 활용하려는 가설이었다. 원본과 attention 확대 영역의 예측을 결합하는 경로가 있다.

**결과:** Accuracy 0.7640, Macro F1 0.7547로 기준선보다 낮았다.

**발표 표현:** “이번 attention 설정은 이 데이터에서 유리하지 않았습니다.” 잘못된 위치에 집중했을 가능성은 추가 검증 가설이지 attention 지도를 확인하지 않고 확정한 원인은 아니다.

### 3.11 PMG

**원문:** Du et al., *Fine-Grained Visual Classification via Progressive Multi-Granularity Training of Jigsaw Patches*, ECCV 2020. [원문](https://arxiv.org/abs/2003.03836), [학회 PDF](https://www.ecva.net/papers/eccv_2020/papers_ECCV/papers/123650154.pdf)

**한 문장 설명:** 여러 크기의 조각으로 나눈 사진을 단계적으로 학습해 세부와 전체 특징을 함께 활용한다.

**우리 코드:** 학습 때 8×8·4×4·2×2 jigsaw 분기를 차례로 갱신하고 원본의 결합 분기를 학습한다. 추론은 사진 한 장을 넣어 세 분기와 결합 분기의 logits를 합친 뒤 softmax를 적용한다. 원논문 Backbone 대신 프로젝트 EfficientNet을 사용한 응용이다.

**결과:** B0·256의 Accuracy 0.8500, Macro F1 0.8473. 규모 확대한 B1·384는 0.8660, 0.8643이었다.

**발표 표현:** “여러 크기의 국소 특징을 학습하는 방법이 Web Skin에서 가장 유망했고, 실행 비용을 고려해 B0를 전달 후보로 남겼습니다.”

**곡선 주의:** 현재 코드의 Train loss는 여러 분기 손실과 가중한 결합 손실의 합이고 Validation loss는 결합 분기 CE다. 두 손실은 계산 정의가 다르다. Train loss가 Validation보다 크다는 이유만으로 모델 이상이라고 판단하지 않는다. Train Accuracy가 높아도 Validation은 별도다.

### 3.12 MixStyle

**원문:** Zhou et al., *Domain Generalization with MixStyle*, ICLR 2021. [원문](https://arxiv.org/abs/2104.02008)

**한 문장 설명:** 학습 표본의 특징 평균·표준편차를 섞어 스타일 다양성을 늘린다.

**우리 적용:** Web Skin의 조명·색감 같은 촬영 조건에 덜 의존할 가능성을 확인하려고 B0·256의 학습 특징에 혼합을 적용했다. 단순히 다른 사진의 라벨을 섞는 MixUp과 다르다. 실제 추론에서 사용자가 두 사진을 같이 찍을 필요도 없다.

**결과:** Accuracy 0.8060, Macro F1 0.8034로 기준선보다 소폭 높았으나 PMG보다 낮았다.

**발표 표현:** “스타일 혼합이 현재 공개 Validation에서 소폭 유리했지만, 실제 웹캠 Domain Gap을 해결했다고 확인한 실험은 아닙니다.”

### 3.13 MedSigLIP

**공식 근거:** Google, [MedSigLIP-448 모델 카드](https://huggingface.co/google/medsiglip-448)

**한 문장 설명:** 의료 이미지와 텍스트를 숫자 표현으로 바꾸는 사전학습 모델이다.

**우리 적용:** 영상 인코더를 고정하고 embedding에 Linear head를 학습했다. 이미지→특징→새 분류층 경로다. 문진 답변을 생성하거나 텍스트 프롬프트로 zero-shot 분류한 실험과 다르다.

**결과:** Web Skin 0.8240/0.8196, Hair 0.7700/0.7688의 Validation Accuracy/Macro F1으로 현재 후보를 바꾸지 않았다.

**발표 표현:** “의료 사전학습 특징의 선형 분리 가능성을 비교했지만 이번 조건에서는 기존 후보보다 낮았습니다.” 작은 분류층 파일만 전체 모델이라고 부르지 않는다.

### 3.14 앙상블: 보충 질문용

여러 저장 모델의 예측을 합치는 후속 비교이며 새로운 분류기를 다시 학습한 실험은 아니다. Hair SupCon과 B1·384의 softmax 출력을 1:1 평균했을 때 Validation Accuracy 0.7947, Macro F1 0.7942로 단일 B1·384보다 낮았다. 이 PPT의 주요 방법 막대에는 별도로 보이지 않으므로 ‘지금 표에 모든 추가 검토가 다 들어 있다’고 말하지 않는다. 질문을 받으면 **단순 평균은 채택하지 않았다**고 설명한다.

## 4. 논문 출처를 PPT와 보고서에 넣는 방법

### 4.1 본문에서는 짧게, 부록에서는 완전하게

방법 페이지 하단에는 `Khosla et al., Supervised Contrastive Learning, NeurIPS 2020.`처럼 저자·제목·학회·연도를 넣는다. 길면 방법명·학회·연도만 표시하고 완전한 정보와 링크는 마지막 참고문헌 장 또는 발표자 노트에 둔다. QR코드는 선택 사항이고, 링크만 남겨도 된다.

권장 연결은 다음과 같다.

| 설명 페이지 | 대표 출처 |
|---|---|
| 14·27·29·31 | EfficientNet 2019, Keras 전이학습 가이드 |
| 30 | Label Smoothing의 Inception 논문, Focal Loss 논문 |
| 37·44 | SupCon 2020, DINOv2 2023, EfficientNetV2 2021, EfficientNet 2019 |
| 38·44 | SAM, ICLR 2021 |
| 39·43 | WS-DAN 2019, PMG ECCV 2020, MixStyle ICLR 2021 |
| 40~42 | Google MedSigLIP 공식 모델 카드 |

외부 논문의 성능 표와 우리 실험 표는 구분한다. 논문에 있는 정확도를 우리 데이터의 성능인 것처럼 옮기지 않는다. 논문 그림을 가져올 때도 출처를 붙이고, 직접 그린 설명도라면 ‘○○의 방법을 바탕으로 재구성’이라고 적는다.

### 4.2 연구 발표에서 내 기여를 설명하는 문장

> “새로운 알고리즘을 제안한 연구는 아닙니다. 기존 방법을 그대로 이름만 붙인 것이 아니라, 피부·두피 영상의 특징에 따라 가설을 세우고 동일한 검증 분할에서 적용 가능성을 비교했습니다. 그 결과 맞지 않는 방법은 제외하고, 분류 성능과 실행 비용을 함께 고려해 사용 후보를 선정했습니다.”

이 프로젝트의 근거는 데이터 버전·분할, 실제 구현 범위, 저장된 예측·평가, 채택·미채택 판단이다. 유명한 논문을 많이 나열하는 것만으로 연구의 설득력이 높아지는 것은 아니다.

### 4.3 보고서를 학술 논문 형태로 발전시킨다면

1. **문제 정의:** 확대 피부, 얼굴 피부, 두피는 입력 특성과 분류 체계가 다른 별도 과제라고 정의한다.
2. **데이터:** 원천 출처, 실제 사용한 부분집합, 원본/변형본, 정리 전후 장수, 분할 기준을 적는다. 원천 전체 장수와 선별본을 구분한다.
3. **방법:** 공통 전처리·전이학습 뒤 각 방법이 어느 부분을 바꾸는지 설명한다. 인코더·손실·학습 경로·추론 규칙을 구분한다.
4. **실험 설계:** 고정 조건과 바뀐 조건, 불가피한 동반 변경을 적는다. PMG B1·384는 Backbone·해상도·배치가 함께 바뀐 조합 비교다.
5. **결과:** 같은 Validation 안의 비교로 후보를 선정하고, 고정 후보의 Test 결과를 따로 제시한다. Hair5/6은 별도 표로 둔다.
6. **분석:** 전체 평균뿐 아니라 미세각질↔비듬, 아토피·여드름 같은 클래스별 오류와 지연 비용을 함께 설명한다.
7. **제한과 다음 검증:** 사람·세션 단위 확인, 실제 촬영 평가, 목표 장비의 측정 등 아직 검증하지 않은 부분을 구분한다.

엄격한 논문 제출을 목표로 할 때는 반복 실험·불확실성·공정한 계산 예산 등의 추가 요구가 생길 수 있다. 현재 발표에서 하지 않은 검증을 했다고 채우지 않는다. 이번 사용자 요청은 기존 발표자료의 설명과 점검이므로 새 학습·새 평가를 수행한 것은 아니다.

## 5. 자주 받을 질문과 답변 예시

### 왜 모델을 세 개로 나눴나요?

“입력 부위와 촬영 방식, 정답 라벨이 다르기 때문입니다. 얼굴 전체 피부와 확대 병변, 두피 질감은 다른 특징을 보며 같은 이름의 피부 문제로 하나로 묶기 어렵습니다. 실제 연결 시에는 장비와 촬영 부위를 함께 사용해 맞는 모델을 선택해야 합니다.”

### 증강 사진을 늘렸는데 왜 모두 좋아지지 않나요?

“변형이 실제 사진 변화와 맞으면 도움이 되지만, 병변의 색이나 질감을 너무 바꾸면 필요한 정보가 약해질 수 있습니다. 증강이 새로운 독립 사람을 확보하는 것도 아닙니다. 그래서 같은 평가 세트로 확인했고 Hair6 B0와 B1에서 효과가 다르게 나타났습니다.”

### 추가 10회 학습이 미세조정인가요?

“횟수만 늘리는 것과는 다릅니다. 처음에는 새 분류층만 학습하고, 다음에는 특징 추출부 일부도 낮은 학습률로 조정했습니다. 추가 횟수는 그 단계를 수행하기 위한 설정이고 성능을 보장하지는 않습니다.”

### B1은 원래 240 입력인데 왜 384를 썼나요?

“B1이라는 구조 이름과 이번 실험 입력은 구분됩니다. 공간 크기를 바꿔 사용할 수 있는 구성에서 384를 별도 연구 조건으로 시험했고, 그 설정의 가중치와 전처리를 함께 저장했습니다. 실제 추론에서도 해당 모델의 384 전처리를 적용해야 합니다.”

### 왜 Web Skin 86.60% 모델을 안 썼나요?

“검증 성능은 B1·384가 선두지만, 이번 측정에서 B0 PMG보다 지연이 길었습니다. B0 PMG도 기본 조건보다 개선됐기 때문에 실행 비용을 고려한 전달 후보로 남겼습니다. B1 결과를 버린 것이 아니라 연구 후보로 보존했습니다.”

### Hair의 79.63%와 80.03% 중 무엇이 맞나요?

“79.63%는 모델 선택에 쓴 Validation, 80.03%는 고정 후보의 Test Accuracy입니다. 사진 집합과 목적이 달라 둘 다 해당 평가의 올바른 값입니다.”

### Test가 Validation보다 높아도 되나요?

“서로 다른 사진 집합이라 난이도와 분포에 따라 다를 수 있습니다. 높은 쪽만 골라 말하지 않고 각각의 장수와 역할을 표시했습니다. 모델 선택은 Validation으로 하고 Test는 고정 후 확인했습니다.”

### Skin이 초기보다 낮아진 이유가 뭔가요?

“그 사이 동일 사진과 데이터 구성을 정리했습니다. 따라서 숫자의 감소 전체를 학습 방법 악화라고 볼 수 없습니다. 같은 Clean 비교에서는 증강이 원본보다 좋았고, 그 결과를 기준으로 후보를 선정했습니다.”

### 데이터 누수를 완전히 없앴나요?

“완전 동일 파일과 확인 가능한 데이터 문제는 검사·정리했습니다. 하지만 식별 정보가 없는 기존 자료의 사람·병변·세션 단위 겹침까지 모두 배제했다고 말할 수는 없습니다. 확인한 검사와 남은 검증을 구분했습니다.”

### Hair 양호는 몇 명의 데이터인가요?

“534장은 사진 수입니다. 파일명에서 105개 ID를 묶어 분할했지만 그것이 독립적으로 확인된 사람 105명이라는 뜻은 아닙니다. 사람 수는 원천 식별 정보가 있어야 확정할 수 있습니다.”

### 5종보다 6종 Macro F1이 높은데 더 좋은 건가요?

“클래스와 평가 사진이 다른 과제라 전체 F1만으로 직접 우열을 말할 수 없습니다. 양호가 추가되면서 평균 구성도 바뀝니다. 같은 6종의 네 조건끼리 비교해 후보를 선정했습니다.”

### 34개를 새로 모두 학습했나요?

“이번 시간 측정에서는 저장된 34개 조건을 불러 실행했습니다. 같은 모델을 다시 학습하거나 Test를 다시 평가한 것이 아닙니다. 기존 정확도 기록과 새 지연 측정을 함께 정리했습니다.”

### 지연 300ms면 실제 기기에서도 그 정도인가요?

“이 실행 환경의 코드 범위에서 얻은 지연입니다. 촬영·통신·모델 로드·전체 앱을 포함한 실제 기기의 시간은 별도로 측정해야 합니다. GPU 모델명도 보존되지 않아 특정 제품 성능으로 소개하지 않습니다.”

### 학습 시간이 짧은 모델이 가장 효율적인가요?

“학습 시간은 각기 다른 시점의 기록이어서 동일 장비 속도 비교로 쓰기 어렵습니다. 실제 사용에서는 저장 모델의 추론 지연과 성능을 함께 봤습니다. 학습 방식만 복잡하고 추론 구조는 같은 경우도 있습니다.”

### PMG Train이 99%인데 왜 Validation은 85%인가요?

“학습 사진에 대한 적합과 새 사진의 구분은 다르기 때문입니다. 현재 학습 데이터에는 잘 맞지만 일반화의 차이가 남은 것입니다. 마지막 모델 대신 저장된 최고 Validation 체크포인트를 사용했습니다. 손실은 Train과 Validation의 계산 구성도 다르므로 절댓값을 그대로 비교하면 안 됩니다.”

### 왜 의료 모델 MedSigLIP을 채택하지 않았나요?

“이번에는 본체를 고정한 특징에 선형 분류층만 학습했습니다. 그 설정에서 기존 후보보다 낮아 바꾸지 않았습니다. 의료 사전학습 모델의 모든 활용 방식이 나쁘다는 뜻은 아닙니다.”

### 가장 중요한 결과 하나만 말한다면?

“모든 과제에 더 큰 모델이나 더 많은 기법을 일괄 적용하지 않고, 데이터 특성과 같은 Validation의 결과를 보고 선택한 것입니다. Web Skin은 PMG, Hair는 B1·384 조합이 유리했고 실행 비용까지 포함해 후보 역할을 나눴습니다.”

## 6. 발표 시간과 연습 순서

70장을 모두 상세히 설명하면 상당한 시간이 필요하다. 발표 시간이 짧다면 파일을 당장 삭제·재구성하기보다 **어느 장을 자세히 말하고 어느 장을 경과 확인용으로 짧게 넘길지** 먼저 정한다.

의료 AI의 핵심 설명 장은 10~14, 23~27, 32·34·35·36, 43·44·45, 46·48·49, 58·59다. 학습곡선 모음은 대표적인 변화 하나를 짚고 요약 비교 장으로 연결한다. 시간 대시보드 여덟 장을 모두 같은 길이로 설명하지 말고 49쪽의 측정 정의, Web Skin의 B0/B1 선택, Hair6의 성능/경량 구분을 중심으로 말한다.

논문 방법 설명은 먼저 다음 세 개만 자연스럽게 말할 수 있도록 연습하면 좋다.

- **SupCon:** 비슷한 두피 질감을 특징 공간에서 나눠보려 했다. 기준선보다 좋아졌으나 최종 B1·384보다 낮았다.
- **PMG:** 얼굴의 작은 피부 단서를 여러 크기로 학습하려 했다. 이번 Web Skin에서 가장 유망했고 B0를 비용 고려 후보로 선택했다.
- **SAM:** 이미 좋은 B1·384를 더 안정적인 해로 개선하려 했다. 전체 Macro F1 이득이 없어 Adam을 유지했다.

그다음 DINOv2·V2-S·MixStyle·WS-DAN·MedSigLIP을 각각 ‘확인한 가설과 채택 여부’ 한 문장으로 덧붙인다. 질문이 깊어지면 3절의 구현 범위와 출처를 사용한다.

- Hair/Web Skin v1·v2, Skin v1, Hair6 후보 메타데이터와 결과 문서의 주요 수치 대조.

## 8. 이번 작업 상태

1. **현재 단계:** 완료한 모델 실험과 실행 비용 결과를 설명하는 발표 준비. ROADMAP의 기존 모델 연구 결과를 정리하고 13·14단계 LLM/VLM 준비로 이어가는 구간.
2. **이번에 한 일:** 이 발표자 가이드 1개를 새로 작성. 원본 발표자료는 보존.
3. **확인 결과:** 70장 내용·화면과 주요 수치를 검토했고, 페이지·노트 불일치 및 영상 미삽입을 확인. 파일 구조 검사는 통과했으나 실제 PowerPoint 자동 열기는 오류.
4. **다음 단계:** 표시 번호·참조·잘못된 노트를 정리하고 영상·논문 출처를 준비한 뒤 발표 시간을 재며 연습.
5. **사용자가 할 일:** 발표 목적·제목·활동 기간 확인, 시연 영상 확보, 발표 PC에서 실제 열기·재생 확인. 의료 AI 부분은 43·44·58·59쪽의 선택 이유와 Validation/Test 차이를 우선 연습.
