# 2차 · 데이터 검증과 전이학습 최적화

> 1차의 성능 숫자만 올리는 것이 아니라, **평가를 믿을 수 있게 만들고 개선 원인을 분리해서 확인**한 단계다. GitHub 저장소 연결·추론 규칙 정리, 데이터 감사, Clean 분할, 2단계 전이학습, 해상도·손실함수·Backbone 비교가 이어졌다. 세부 실험은 [실험표 CSV](최적화_실험표.csv)와 원본 JSON·CSV에서도 확인할 수 있다.

## 왜 다시 시작했나

초기 Hair·Web Skin 성능이 기대보다 낮았다. 먼저 사진 중복과 평가 분할을 점검했다. 같은 사진이 Train과 Validation/Test에 동시에 있으면 모델의 일반화 점수가 과대평가될 수 있다. 그 뒤 데이터 분할을 고정하고 학습법을 한 조건씩 바꿔 효과를 살폈다.

초기 자료를 GitHub 저장소에 연결한 뒤에는 모델·클래스 순서·전처리·평가 코드를 협업 가능한 형태로 정리했다. 저장된 EfficientNet에는 내부 `Rescaling(1/255)`이 있어 추론 코드의 외부 `/255`를 제거했고, 개인 PC 고정 경로와 기존 출력 자동 삭제도 수정했다. **이는 모델 재학습이 아니라 재현·전달 기반을 만드는 작업**이었다. 기존 문서 [GitHub 연결 단계 정리](../../docs/presentations/1차.md)의 ‘1차’는 이 폴더의 **GitHub 연결 전 1차**와 시기 이름이 다르므로 혼동하지 않는다.

## 데이터 검사·재구성

| 대상 | 확인된 사실 | 조치 | 최종 원본 분할 |
|---|---|---|---|
| Hair | 초기 Original의 완전 동일 이미지 교차 분할 쌍: Train–Val **195**, Train–Test **178**, Val–Test **16**. 이는 **쌍 수**이며 389장 삭제를 의미하지 않는다. 라벨 충돌도 감사했다. | 완전 동일 사진과 증강본의 원본 연결을 기준으로 새 Clean 5종 분할 생성. 증강은 Train에만 적용. | Train 10,032 / Val 1,252 / Test 1,252 = 12,536 |
| Skin | 완전 동일 중복 이미지 **51장** 확인 | Clean 데이터로 재구성 | Train 7,249 / Val 1,000 / Test 700 = 8,949 |
| Web Skin | 사용한 검사에서 교차 분할 완전 동일 바이트·픽셀 사진 미발견 | 기존 분할 유지 | Train 원본 3,600 / Val 500 / Test 400 |

Hair Clean 증강 Train은 원본 10,032장 + 생성 5,015장 = **15,047장**이다. Web Skin 증강 Train은 **7,200장**이다. Skin의 Clean 후 증강 비교는 원본과 같은 Val/Test를 사용했다. 바이트·픽셀 완전 동일 검사는 **유사 사진·같은 사람·같은 병변·같은 촬영 세션의 중복이 없다는 증명은 아니다.** 식별자가 없는 영역은 미검증으로 남겼다. Clean 전후 Test가 달라서 초기 점수와 Clean 점수를 하나의 인과적 개선률로 표현하지 않는다.

## 왜 이런 학습법을 시험했나

| 순서 | 고정한 것 | 바꾼 것과 이유 | 확인된 결과 |
|---|---|---|---|

| 224→256 | B0, CE, 데이터·학습 절차 | 작은 질감이 리사이즈 중 덜 소실되는지 시험. | Hair Val Accuracy **0.7643769979476929→0.7699680328369141**. Web Skin **0.794→0.796**(500장 중 한 장 차이); Web Skin Macro F1은 거의 동률이라 256의 보편적 우위를 주장하지 않음. |

| B0→B1 | 256, LS 0.05 등 | [EfficientNet](https://proceedings.mlr.press/v97/tan19a.html) 계열의 더 큰 특징 표현이 도움이 되는지 시험. | Hair Val **0.7739616632461548→0.7763578295707703**, Web Skin **0.794→0.796**. 모델 크기 확대만으로 큰 이득은 확인되지 않음. |

해상도·Loss·Backbone 비교는 각 비교의 분할과 기본 설정을 맞춰 검토했지만, 서로 다른 실험 묶음의 절대 점수 차이를 단일 원인으로 단정하지 않는다. 특히 B1 변경은 파라미터 수도 함께 바뀐다. Hair의 가장 높은 Test 점수를 사후 기준으로 후보를 바꾸지 않고 Validation에서 정한 후보를 보존했다.

## 저장소를 먼저 정리한 이유

초기에는 도메인별로 학습 파일과 모델이 따로 있었고, 저장 모델을 팀원이 정확히 불러오는 규칙도 분명하지 않았다. 저장된 EfficientNet 안에는 픽셀 값을 255로 나누는 층이 이미 있는데 기존 팀 안내 코드가 외부에서 다시 `/255`를 하면 **학습과 다른 입력**이 된다. 그래서 RGB `float32` 0–255를 입력하고 클래스 배열 순서를 보존하는 추론·평가 계약을 정리했다. 전처리 스크립트의 개인 PC 경로와 기존 출력 폴더 자동 삭제도 바로잡아 재현 가능한 실행 기반을 만들었다. 이것은 **모델을 새로 학습한 결과가 아니라** 그 뒤의 실험이 같은 의미로 비교되도록 돕는 코드 정리다. [당시 정리 보고서](../../docs/presentations/1차.md)에는 이 과정을 상세히 적었다.

## 데이터 감사: 무엇을 검사했고 무엇을 못 검사했나

데이터 누수는 학습에서 본 것과 동일하거나 매우 비슷한 사진이 평가에 들어가 점수가 좋아 보이는 문제다. 파일명이 달라도 사진 내용은 같을 수 있으므로 기존 감사에서 파일 바이트와 디코딩한 RGB 픽셀 기준의 해시를 비교했다. Hair 초기 Original의 Train–Val 195, Train–Test 178, Val–Test 16은 **교차 분할 중복 쌍 수**다. 동일 사진이 셋 이상의 분할에 있는 경우 여러 쌍으로 셀 수 있어 이를 더해 ‘삭제한 389장’이라고 설명하면 틀리다. 서로 다른 클래스에 붙은 동일 사진의 라벨 충돌도 문제였다.

Hair에서는 원본을 다시 모으고 완전 동일 이미지·라벨 충돌을 정리해 12,536장으로 만들었다. 분할을 다시 정한 뒤 **Train 원본 10,032장에만** 새 증강 이미지 5,015장을 만들고 원본–증강 연결을 manifest로 기록했다. 기존 증강본을 그대로 복사해 쓰지 않은 이유는 원본이 새 Validation/Test에 들어간 파생 이미지가 Train에 남으면 누수가 다시 생길 수 있기 때문이다. 초기에 고른 14,500장과 Clean 원본 12,536장의 차이는 1,964장이지만, 이것도 교차 중복 쌍 합계로 설명할 수 없다.

Skin에서는 Train–Val 10그룹, Train–Test 5그룹, Val–Test 1그룹의 완전 동일 RGB 중복이 확인됐다. Train 내부의 중복 그룹·초과 복사본도 있었고, 과거 증강 Train 안에서도 같은 사진의 반복이 발견됐다. 원본 9,000장에서 51장을 정리해 8,949장으로 만들고, Clean Train 7,249장 각각에 새 증강본 한 장을 만들어 **증강 Train 14,498장**으로 구성했다. 생성된 새 증강본의 픽셀 해시 중복·라벨 충돌 검사 기록은 0이었다. [Skin 감사 보고서](../../docs/research/SKIN_DATA_AUDIT_20260909.md)에 검사 범위가 남아 있다.

Web Skin의 당시 감사에서는 읽을 수 없는 이미지, 완전 동일 파일·RGB 사진의 교차 분할 중복, 라벨 충돌을 발견하지 못해 기존 원본 분할을 유지했다. 그러나 어느 도메인이든 사람 ID·병변 ID·촬영 세션 ID가 충분하지 않았다. **같은 사람이 다른 각도에서 찍힌 사진, 연속 촬영 이미지, crop이나 재압축된 근사 중복까지 없다고 증명한 것은 아니다.** 이후의 공개 데이터 점수는 이 제한을 동반한다.

## 왜 기존 질환 모델에서 이어 학습하지 않았나

특히 Hair에서는 초기 학습 당시 본 사진 일부가 새 Clean Validation/Test에 들어갔을 가능성이 있었다. 그 모델을 출발점으로 삼으면 새 분할에서의 공정한 평가 목적이 약해진다. 또한 모델마다 기존 학습 이력이 다르면 해상도·Loss·Backbone의 효과를 비교하기 어렵다. 그래서 **ImageNet에서 출발하는 새 EfficientNet**으로 각 실험을 시작했다. 같은 EfficientNet-B0라는 구조라도 ImageNet 가중치와 과거 Hair 분류 가중치는 학습 이력이 다른 모델이다.

## 2단계 학습을 쉽게 설명하면

Stage 1에서는 일반 사진에서 배운 특징 추출부를 고정하고 `GlobalAveragePooling → Dropout(0.3) → Dense(클래스 수)` 형태의 새 분류층을 15 epoch 학습했다. Stage 2에서는 Stage 1의 Validation 최고 체크포인트를 불러와 본체 후반 30층 중 BatchNormalization을 제외한 부분만 열고, 학습률을 `1e-4`에서 `1e-5`로 낮춰 10 epoch를 더 학습했다. Hair의 마지막 선정 실험에서는 Stage 2를 5 epoch 더 연장했다. 분류층을 먼저 안정화한 다음 일부 특징을 낮은 학습률로 조정하는 취지는 [Keras의 전이학습·미세조정 지침](https://keras.io/guides/transfer_learning/)과 일치한다.

왜 후반부만 여는가? 처음부터 전체 본체를 크게 변경하면 사전학습에서 얻은 유용한 경계·색·형태 특징이 급히 변할 수 있어서다. 왜 BatchNormalization을 고정하는가? 작은 배치의 통계 변동으로 추론 행동이 흔들리는 일을 줄이려는 설정이었다. Stage 2의 성능 상승에는 **학습 가능한 층 증가뿐 아니라 추가 학습량·낮은 학습률·새 optimizer**가 함께 들어가므로 “30층을 풀기만 해서 오른 점수”라고 말하지 않는다. Web Skin B0·256에서 Stage 1 최고 Validation Accuracy `0.7039999961853027`, Stage 2 최고 `0.7960000038146973`이 이 묶음 절차의 효과를 보여준다.

모든 저장 EfficientNet 후보의 입력은 RGB `float32` 0–255다. 크기에 맞게 TensorFlow bilinear로 리사이즈하고 외부 `/255`를 적용하지 않는다. seed 42, batch 32, 동일 클래스 순서와 데이터 버전을 기록했고, 각 실험에서 Validation Accuracy 최고 체크포인트를 보존했다.

## 각 방법에서 왜 그 변수만 바꿨나

**224→256**은 작은 각질·모공·얼굴 질감이 축소로 소실되는지 묻는 실험이었다. 같은 B0·CE와 분할을 유지했다. Hair Validation은 `0.7643769979476929`에서 `0.7699680328369141`로 올랐지만 Web Skin은 `0.794`에서 `0.796`으로 500장 중 정답 한 장 차이였다. Web Skin의 Macro F1은 오히려 B0·224 `0.7917009497301795`, B0·256 `0.7915394647566528`로 거의 같았다. 큰 입력이 모든 과제에서 이득이라고 결론내리지 않았다.

**Label Smoothing 0.05**는 정답 클래스에 1.0을 몰아주는 학습을 완화하는 방법이다. [Inception 연구](https://openaccess.thecvf.com/content_cvpr_2016/html/Szegedy_Rethinking_the_Inception_CVPR_2016_paper.html)를 참고해 비슷한 클래스 사이의 과신을 줄일 수 있는지 시험했다. B0·256을 고정했을 때 Hair Validation은 `0.7699680328369141`→`0.7739616632461548`로 올랐고 Web Skin은 `0.796`→`0.794`로 내려갔다. 따라서 라벨 스무딩은 항상 좋아지는 스위치가 아니다. 점수가 덜 극단적으로 나왔다고 실제 정답 확률로 잘 보정됐다는 뜻도 아니다.

**Focal Loss gamma 1.5**는 쉬운 예보다 어려운 예의 손실을 상대적으로 크게 남기는 [원 논문](https://openaccess.thecvf.com/content_iccv_2017/html/Lin_Focal_Loss_for_ICCV_2017_paper.html)의 아이디어를 분류에 응용한 것이다. 원 논문은 dense detection을 다뤘고 우리 과제의 클래스 불균형 자체가 주된 이유는 아니었다. Hair의 비슷한 두피 상태가 더 잘 구분되는지 검토했으나 Validation은 CE보다 낮았다. Hair Focal의 Test는 높았지만 Test를 보고 선정 규칙을 바꾸지 않았다. 서로 다른 Loss 함수의 숫자값 자체는 같은 척도로 비교하지 않는다.

**B0→B1**은 더 큰 모델 용량이 세밀한 특징을 표현할 수 있는지 확인했다. 이때 입력 256과 LS 0.05는 유지했지만 구조·파라미터 수가 함께 바뀌었다. Hair Validation Accuracy는 B0 `0.7739616632461548`에서 B1 `0.7763578295707703`으로 소폭 상승했다. Web Skin은 B0 LS `0.794`, B1 LS `0.796`이었다. B1이 무조건 배포에 더 낫다고 볼 정도의 큰 차이는 아니었다.

**Hair B1의 Stage 2 +5 epoch**는 Validation이 계속 개선되는지 확인한 연장 실험이다. 부모 모델 최고 `0.7763578295707703`, 연장 후 최고 `0.7771565318107605`로 차이가 작았다. 같은 모델의 미세조정을 연장했지 새 데이터셋이나 새 클래스의 모델이 아니다. Web Skin B1의 같은 5 epoch 연장은 부모 최고 `0.796`을 넘지 못했다.

## 세 도메인은 어떻게 선정했나

Hair에서는 여섯 설정 중 **Validation Accuracy가 가장 높은** B1·256·LS 0.05·Stage2 총 15 epoch를 v1으로 고정했다. Test 1,252장에서 Accuracy `0.7883386581469649`, Macro F1 `0.7885764577048346`이었다. Focal의 Test 수치가 이 묶음에서 약간 더 좋았더라도 Test를 선정 기준으로 바꾸지 않았다. 다만 탐색 과정에서 Hair의 여러 Test가 이미 확인됐다는 점은 완전히 봉인된 독립 최종 Test보다 근거력이 약하다는 제한이다.

Web Skin은 B0·256·CE와 B1·256·LS가 Validation Accuracy `0.796` 동률이었다. B1의 Macro F1이 `0.7931535064807589`로 B0의 `0.7915394647566528`보다 높았지만 당시 규칙은 **Accuracy 우선, 동률이면 앞선 실험 유지**라 B0를 v1으로 선정했다. Test 400장에서 Accuracy `0.8825`, Macro F1 `0.8813822927981046`이었다. B1 연장 실험을 새 후보로 세지 않은 이유도 부모 최고를 넘지 못했기 때문이다.

Skin은 이미 높은 저장 점수가 있었기 때문에 Hair·Web Skin의 여섯 설정을 그대로 반복하지 않았다. Clean 데이터에서 **B0·224·CE·head-only 15 epoch**를 고정하고 Train 종류만 원본 7,249장과 원본+증강 14,498장으로 비교했다. Validation Accuracy는 `0.973` 대 `0.982`, Macro F1은 `0.9730455448862949` 대 `0.9820008885656606`이었다. 증강 후보를 고정한 뒤 Test 700장에서 Accuracy `0.9871428571428571`, Macro F1 `0.9871314132317626`, 정답 **691장**을 확인하고 v1으로 패키징했다. Test가 초기 약 99.6%보다 낮더라도 평가 사진과 정제 정도가 바뀌었으므로 단순한 성능 악화가 아니다.

## 그림에서 무엇을 읽고, 무엇은 읽지 말아야 하나

감사 그림은 데이터 버전이 왜 바뀌었는지 설명한다. 세 도메인의 학습곡선에서는 파란/주황 선이 Train/Validation, 세로 경계가 head-only에서 부분 미세조정으로 넘어가는 시점을 나타낸다. 그래프가 오른다고 항상 일반화가 좋아진 것은 아니므로 Validation 선과 오차/혼동행렬을 함께 본다. 후보 대시보드는 **2차 당시 선택**을 보여주므로 3차 논문 강화 이후 최신 Web Skin·Hair 후보를 설명할 때는 3차 자료로 넘어간다.

> “먼저 같은 사진이 학습과 평가에 섞이지 않았는지 검사했습니다. Hair와 Skin은 정제한 뒤 일반 영상 사전학습 모델을 같은 분할에서 다시 시작했습니다. 학습층 일부를 조정하고 해상도·Loss·모델 크기를 차례로 시험해 Skin v1, Web Skin v1, Hair 5종 v1을 선정했습니다. 향상 여부는 그때의 Validation 기준으로 판단했습니다.”
