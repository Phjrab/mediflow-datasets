# 1차 · GitHub 연결 전: 데이터 수집부터 첫 분류 모델까지

> 이 문서는 **첫 데이터 수집·전처리·학습 당시**를 설명한다. 뒤에 발견한 데이터 중복이나 2단계 미세조정 결과를 이 시점의 성과로 소급하지 않는다. 수치는 초기 `results/*/1_training/`의 저장 JSON과 당시 연구 문서에 근거한다. 원천 데이터 사이트의 규모는 당시 문서에 기록된 규모이며, 원천 전체 ZIP은 현재 로컬에 없어 새로 계수한 값이 아니다.

## 발표 흐름

1. Kaggle·AI Hub를 조사했으나 최종 첫 학습에 사용한 세 출처는 아래 AI Hub 데이터다.
2. 현미경 피부와 얼굴 전체, 두피 확대 영상은 촬영 방식과 보이는 특징이 달라 전문 분류기를 분리했다.
3. 원천 클래스를 직접 살펴 분류할 범위를 골랐다. 이후 원본 Train과 원본+증강 Train을 비교했다. Validation·Test에는 증강을 넣지 않았다.
4. Skin 첫 성능은 높았으나 Web Skin·Hair는 낮았다. 이 점이 2차 데이터 검사와 학습법 변경으로 이어졌다.

| Hair | [AI Hub 216 유형별 두피 이미지](https://aihub.or.kr/aihubdata/data/view.do?dataSetSn=216) | 고유 이미지 101,027건 | 5종 × 2,900장 = 14,500장 | 확대 두피·모발 |
| Web Skin | [AI Hub 71863 안면부 피부질환 이미지 합성 데이터](https://www.aihub.or.kr/aihubdata/data/view.do?currMenu=115&topMenu=100&dataSetSn=71863) | 6종 × 정면·측면 각 약 1,000장 = 약 12,000장 | 처음 데이터 선정 발표 시점에는 **후속 후보**. 이후 정면 5종 × 900장 = 4,500장으로 첫 학습 | 얼굴 정면 전체 |

**Skin 10종:** 기저세포암, 편평세포암, 보웬병, 광선각화증, 지루각화증, 흑색점, 표피낭종, 사마귀, 피부섬유종, 혈관종. 처음 원천 15종 중 악성흑색종·멜라닌세포모반·피지샘증식증·화농육아종·비립종은 미선택이다. 이미지를 직접 검수하며 시각적으로 비슷한 항목을 제외했다는 당시 판단이 기록되어 있다. 다만 **클래스별 제외 판정표나 각 1,000장 중 학습에 쓰지 않은 100장의 개별 사유는 남아 있지 않다.**

**Hair 5종:** 모낭사이홍반, 미세각질, 비듬, 탈모, 피지과다. 중등도·중증 증상을 중심으로 선별하고 적은 클래스인 비듬 2,900장에 맞춰 수량을 균형화했다. 모낭홍반/농포는 모낭사이홍반과 시각적으로 유사하다고 판단해 제외했다. 2026-09-28의 6클래스 `양호`는 이 초기 단계에 포함되지 않는다.

**Web Skin 5종(후속 첫 학습):** 건선, 아토피, 여드름, 정상, 주사. 정면 얼굴 기준으로 선택했다. 지루성 피부염은 주사와 구분이 어렵다는 검토 후 제외했다. 초기 데이터 선별 그림을 발표할 때는 아직 Web Skin을 학습하지 않았다는 시간 순서를 지킨다.

## 분할과 증강을 실제 어떻게 했나

| 도메인 | 첫 원본 Train / Val / Test | 증강 Train | 구현된 증강 |
|---|---|---:|---|
| Skin | 7,300 / 1,000 / 700 | 실행 버전에 따라 클래스당 원본 730장에 생성 470장을 더한 1,200장 또는 별도 전처리의 730장 추가안이 기록됨. **서로 다른 버전을 한 수치로 합치지 않는다.** | 좌우 반전·회전·밝기·대비·화이트밸런스·감마·가우시안/모션 블러·노이즈·JPEG 압축·원근 변형 중 무작위 선택 |
| Web Skin | 3,600 / 500 / 400 | 원본 3,600 + 생성 3,600 = 7,200 | 좌우 반전, 회전, 밝기·대비·채도·색온도, 블러·노이즈, 감마·JPEG, 확대/크롭 중 1~3개를 무작위 조합 |
| Hair | 11,600 / 1,450 / 1,450 | 원본 11,600 + 생성 5,800 = 17,400 | 약한 회전·좌우 반전·밝기/대비/색·블러·노이즈·약한 크롭/확대의 확률적 조합 |

Hair 증강의 구현 예: 회전 ±8°, 밝기 0.82–1.18배, 대비 0.85–1.15배, 색 0.90–1.10배, 약한 crop 0.92–1.0배를 확률적으로 사용했다. 실제 수치는 [초기 Hair 전처리 코드](../../scripts/preprocess_hair.py), Skin의 변형 목록은 [Skin 코드](../../scripts/preprocess_skin.py), Web Skin의 조합 규칙은 [Web Skin 코드](../../scripts/preprocess_web_skin.py)에 있다. 증강의 목적은 조명·초점·자세 변화에 대한 일반화 가능성을 시험하는 것이었다. **증강 이미지 수는 독립 인물 수가 아니다.**

첫 학습은 ImageNet 사전학습 EfficientNet-B0를 가져와 특징 추출부를 고정하고 분류층을 학습했다. 원본 학습과 증강 학습을 비교하면서 Validation 최고 가중치를 보존했다. Skin은 초기 약 99% 수준으로 보고됐으나 그 숫자만으로 실제 현미경 촬영 성능을 보장할 수 없었다. Web Skin 초기 결과는 Validation 최고 66.80%, Test 78.50%, Hair 5종 초기 결과는 원본 Test 68.41%, 증강 Test 69.10%였다. 이 숫자는 **정제 전의 각 초기 평가 기록**이며 Clean 데이터 결과와 직접 상승률을 계산하지 않는다.

당시 YOLO로 병변을 찾아 잘라낸 뒤 Skin 분류기에 넣는 안도 검토했지만, 질환이 넓게 분포하거나 병변 경계가 일정하지 않아 단일 crop만으로 표현하기 어렵다고 판단했다. 따라서 확대 피부 Skin과 얼굴 전체 Web Skin을 별도 분류기로 두었다. 이는 분류기 구조를 정한 판단이며 YOLO 검출 성능을 수치 검증했다는 뜻은 아니다.

### 그림 사용 순서

`시각자료/`의 `initial_skin_hair_data_selection` → `02_initial_data_split` → `03_initial_augmentation_plan` → `04_initial_training_plan` 순서가 자연스럽다. 첫 그림은 **Web Skin 사용 전** 상태를 나타낸다. 뒤에서 Web Skin을 설명할 때는 이 시점 이후 첫 학습으로 전환되었다고 말한다.

첫 학습곡선은 도메인별 한 장으로 합쳤다: [Skin 4곡선](시각자료/skin__initial_four_training_curves.png), [Web Skin 4곡선](시각자료/web_skin__initial_four_training_curves.png), [Hair 4곡선](시각자료/hair__initial_four_training_curves.png). 세 그림 모두 **ImageNet 사전학습 EfficientNet-B0, 입력 224×224, 분류층 학습 15 epoch**를 제목 아래에 명시했다. 각 그림의 윗줄은 원본 Train, 아랫줄은 원본+증강 Train이고, 왼쪽은 Accuracy·오른쪽은 Loss다. 파란색은 Train, 주황색은 Validation이다. **개별 곡선과 혼동행렬 원본은 `results/<도메인>/1_training/`에 보존돼 있으며 발표 폴더에는 통합 그림만 넣었다.** 이 그림은 Clean 데이터 정제 전 결과이므로 2차 이후 곡선과 같은 검증셋의 직접 비교처럼 배치하지 않는다.

## 왜 세 분류기로 나누었나

처음에는 피부와 두피를 하나의 의료 영상 문제로 생각할 수 있었다. 그러나 현미경 피부 사진에서는 병변의 경계·표면·색과 각질 같은 **작은 부위의 특징**이 크고, 웹캠 얼굴 사진에서는 홍반이 퍼진 **위치와 얼굴 전체 분포**가 중요하다. 두피 확대 사진은 모공 주변 홍반, 비듬·미세각질, 피지 반사와 모발 밀도라는 또 다른 특징을 가진다. 그래서 촬영 **장비**와 촬영 **부위**를 함께 기준으로 `skin`(확대 피부), `web_skin`(정면 얼굴), `hair`(확대 두피)의 분류 대상과 클래스 순서를 분리했다. 이 판단은 나중에 팀원 시스템에 모델을 연결할 때도 그대로 유지해야 하는 입력 계약이다.

이 순서는 한 번에 확정되지 않았다. Skin 10종으로 먼저 높은 저장 점수를 얻은 뒤, 웹캠에서 같은 모델을 바로 쓸 수 있는지 검토했다. 병변 검출 후 잘라내는 YOLO 안은 라벨링이 실패·중단됐고, 얼굴 전체에 퍼지는 증상은 작은 사각형 하나로 설명하기 어렵다고 판단했다. 따라서 얼굴 정면 사진 전용 `web_skin`을 별도로 구성했다. Hair에서는 초기 여섯 증상 후보 중 모낭홍반/농포와 모낭사이홍반이 매우 비슷해, 전자를 제외하고 다섯 증상으로 정의했다. **2026-09-28에 추가한 여섯 번째 `양호`는 이때 제외한 모낭홍반/농포와 다른 클래스**다.

## 데이터 선정이 실제로 뜻하는 것

Skin 원천의 15종 약 15,000장과 첫 모델에 사용한 10종 9,000장은 다른 숫자다. 15종 중 10종을 고른 뒤 선택된 각 클래스에서 900장씩 첫 분할에 넣었다. 당시 직접 이미지를 검수해 시각적으로 구분이 어렵다고 본 클래스를 제외했지만, 왜 선택된 각 원천 클래스의 남은 약 100장을 쓰지 않았는지 **사진 단위 선별 기록은 없다**. 따라서 “1만 장을 모두 학습했다”거나 “나머지 100장은 품질 불량이었다”고 말하지 않는다.

Hair 원천의 고유 이미지 101,027건은 다섯 클래스의 합계가 아니다. 한 두피 사진에 여러 증상 라벨이 붙을 수 있어 증상별 원천 건수를 단순 합산하면 안 된다. 프로젝트에서는 중등도·중증 사진을 중심으로 다섯 범주를 고르고, 가장 적은 비듬 후보 2,900장에 맞춰 각 범주를 균형화했다. 이때의 **14,500장**은 중복 정리 전 첫 데이터 구성이다.

Web Skin 원천은 여섯 클래스의 정면·측면 사진이 있었지만, 실제 첫 학습은 **정면 얼굴 다섯 클래스**를 사용했다. 정면과 측면을 모두 넣으면 같은 사람·병변의 두 각도가 서로 다른 분할에 들어갈 수 있는지도 검토해야 했다. 식별 정보가 충분하지 않아 처음에는 정면만 사용한 것이다. 처음 데이터 선정 발표 그림은 Web Skin을 아직 사용하기 전 장면이므로, 이 설명을 시간상 뒤에 놓는다.

## 원본·증강본은 어떻게 만들었나

증강은 학습 도중 매번 새 이미지를 만드는 방식이 아니라 전처리 코드가 변형 이미지를 **파일로 저장하는 오프라인 증강**이었다. 먼저 Train/Validation/Test를 분리하고, 학습용 Train에서만 파생 사진을 만들었다. Validation과 Test가 원본인 까닭은 모델이 새 원본 사진을 구분하는지 같은 기준에서 비교하기 위해서다. 여기서 `Original 모델`은 원본 Train으로 학습한 모델, `Augmented 모델`은 **원본 Train과 새 증강본을 함께** 사용한 모델이다.

| 대상 | 코드에 기록된 생성 방법 | 왜 선택했나 | 해석할 때 주의 |
|---|---|---|---|
| Skin | [전처리 코드](../../scripts/preprocess_skin.py)는 좌우반전, ±10° 회전, 밝기 ±25, 대비 0.85–1.15, 화이트밸런스, 감마, 가우시안·모션 블러, 노이즈, JPEG 열화, 약한 원근 변형의 **11가지 중 한 가지**를 무작위 적용한다. | 현미경 조명·촬영 각도·초점·압축 차이의 가능성을 연습시키려 했다. | 당시 서술은 클래스당 730 원본+470 생성=1,200 Train, 현재 코드 기본은 730+730=1,460 Train이다. 첫 모델의 실제 증강본 수는 당시 데이터 manifest가 없어 확정할 수 없다. |
| Web Skin | [전처리 코드](../../scripts/preprocess_web_skin.py)는 반전, ±7° 회전, 밝기 0.75–1.25, 대비 0.80–1.20, 채도 0.85–1.15, 색온도, 블러, 약한 노이즈, 감마, JPEG, 1.02–1.08 확대/크롭에서 서로 다른 변형 **1–3개**를 고른다. 선택 개수 가중치는 45%/40%/15%다. | 얼굴 거리·조명·웹캠 압축의 변화를 흉내 내되 얼굴 구조를 지나치게 손상하지 않으려 했다. | 원본 3,600장에 생성 3,600장을 더한 학습 파일 7,200장은 새 사람 7,200명이 아니다. |
| Hair | [전처리 코드](../../scripts/preprocess_hair.py)는 ±8° 회전 65%, 반전 25%, 밝기 0.82–1.18 75%, 대비 0.85–1.15 65%, 색 0.90–1.10 35%, 약한 블러·노이즈 각 25%, 크롭 30%를 조합한다. | 모공·각질 신호가 사라지지 않도록 변형을 약하게 두면서 현미경 각도·조명 차이를 연습하려 했다. | 첫 Train 원본 11,600장에 생성 5,800장을 더해 17,400장을 썼다. 뒤의 Clean Hair 증강 규칙과 수량은 별개다. |

이미지에 변형을 줬다고 실제 장비의 모든 환경 차이가 재현되는 것은 아니다. 지나친 crop이나 블러가 오히려 병변 단서를 없앨 수도 있으므로, 이 선택은 당시 가설이며 효과는 **같은 원본 평가 분할에서 비교한 저장 결과**로 판단한다.

## 첫 모델을 어떻게 학습했고 무엇을 얻었나

모델은 일반 사진 특징을 미리 학습한 **ImageNet EfficientNet-B0**에서 출발했다. 특징 추출부를 고정하고 새 클래스 분류층을 학습하는 `head-only` 방식이다. 저장 결과에는 대체로 입력 224×224, 배치 32, 15 epoch가 남아 있다. Skin 과거 코드는 학습률 1e-3, Web Skin/Hair 기록은 1e-4여서 세 도메인의 조건이 모두 같았다고 단정하지 않는다. 각 모델은 마지막 epoch를 무조건 고르지 않고 Validation Accuracy가 가장 높았던 시점의 가중치를 사용했다. [EfficientNet 원논문](https://proceedings.mlr.press/v97/tan19a.html)은 모델 깊이·너비·입력 해상도의 균형을 논의한다. 여기서 그 논문의 의료 성능을 재현했다는 뜻은 아니다.

| 초기 모델 | Validation Accuracy | Test Accuracy | Test Macro F1 | 당시 얻은 결론 |
|---|---:|---:|---:|---|
| Skin Original | `0.9950000047683716` | `0.9942857027053833` | 저장 결과에 없음 | 매우 높게 보고돼 우선 Skin 경로를 유지 |
| Skin Augmented | `0.9950000047683716` | `0.9957143068313599` | 저장 결과에 없음 | 당시 Test 정확도는 높았으나 뒤에 중복을 발견해 최종 근거로 사용하지 않음 |
| Web Skin Original | `0.6679999828338623` | `0.7850000262260437` | `0.7833125866587888` | 얼굴 질환 간 구분 부족 |
| Web Skin Augmented | `0.6880000233650208` | `0.8199999928474426` | `0.8195818185502844` | 증강 쪽이 높았으나 Validation은 낮아 추가 학습법 검토 |
| Hair Original | `0.7062069177627563` | `0.6841379310344827` | `0.6827345904185209` | 작은 두피 특징 구분이 어려움 |
| Hair Augmented | `0.704827606678009` | `0.6910344827586207` | `0.6894861696407794` | Test는 조금 높지만 큰 개선은 아님 |

이 표의 초기 Test는 **정제 전의 옛 사진 분할**에 대한 기록이다. 나중에 Hair·Skin에서 Train과 평가 사이 완전 동일 사진을 발견했다. 따라서 Skin의 거의 100% 숫자도 실제 장비 성능이나 새 환자 성능으로 발표하지 않는다. 초기 데이터 ZIP은 현재 보존되지 않아 그때의 Test 사진으로 초기 여섯 모델을 다시 추론하는 재현도 끝나지 않았다.

## 다음 차수로 넘어간 이유와 발표 문장

단순 증강만으로 Hair와 Web Skin에서 원하는 구분력이 나오지 않았다. Skin의 높은 성능도 **데이터 중복이 없는지** 확인하기 전에는 신뢰성에 의문이 남았다. 그래서 다음 차수에서는 파일명만 보지 않고 실제 이미지 내용을 비교해 분할을 감사하고, 정제된 분할에서 학습 방법을 바꾸기로 했다.

> “처음에는 데이터 원천과 촬영 방식을 조사해 세 분류 문제를 나눴습니다. 원본과 Train 증강을 비교한 첫 모델에서 확대 피부의 저장 점수는 높았지만 얼굴·두피 분류는 낮았습니다. 그래서 다음 단계에서 분할 중복을 확인하고, 같은 기준으로 다시 학습했습니다.”
